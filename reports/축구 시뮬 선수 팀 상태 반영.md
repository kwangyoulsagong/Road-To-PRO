# 상태는 승률이 아니라 선택·실행·부상을 바꾼다

축구 게임과 실제 데이터를 함께 보면 하나의 구조가 나온다. 선수·팀 상태는 **"승률에 직접 더하는 보너스"가 아니라 판단(무엇을 고를지)·실행(성공할지)·가용성(뛸 수 있는지)을 바꾸는 계수**로 들어갈 때 현실과 가장 잘 맞는다. Football Manager(FM), EA SPORTS FC, eFootball은 공개 설명 기준으로 모두 "정신 = 선택·타이밍", "기술 = 실행 정확도", "신체 = 도달 범위·피로 감쇠", "역할·스타일 = 공 없는 기본 위치", "트레잇·PlayStyle = 특정 선택의 확률 편향"으로 층을 나눈다. 실제 데이터는 상태 변수마다 효과 크기가 크게 다르다고 말한다. 홈 이점(경기당 +0.3~0.4골)과 퇴장(수적 열세 팀 득점 강도 −30%)은 뚜렷하다. 피로와 일정 밀집은 경기력보다 **부상 위험**에 강하게 걸린다. 반면 득점 후 모멘텀, 감독 교체 바운스, "함께 뛴 기간" 같은 조직력 효과는 통제하면 거의 사라진다. Road To PRO에는 이것이 세 가지 설계로 이어진다. 첫째, 능력치와 상태를 경기 시작 때 한 번 **파생 파라미터 스냅샷**으로 바꾸고 엔진은 그 스냅샷만 읽는다. 둘째, 효과는 근거가 강한 곳(홈→판정, 퇴장→팀 형태, 피로→부상)에 크게, 근거가 약한 곳(사기·모멘텀·날씨)에 작게 건다. 셋째, 경기 결과는 경기 후 동적 상태로만 되먹이는 비순환 그래프(DAG)를 지킨다. 한계도 분명하다. 이 보고서는 공개 자료만 썼다. 게임사가 공개한 정량 수치는 EA의 역할 숙련도 비율(위치 계산의 10~40%) 정도이고, FM·eFootball의 사기·컨디션·트레잇 효과 크기는 공식 수치가 사실상 없다. 따라서 아래 수치 대부분은 `[제안]` 또는 `[미정]`이며, 우리 엔진의 대량 시뮬로 정해야 한다.

## 세 게임 모두 능력치를 '선택·실행·한계' 3층으로 나눈다

FM의 속성 설명은 공식 툴팁 원문을 찾지 못해 커뮤니티 가이드에 의존한다. 그래도 구조는 일관된다. Decisions는 "공 유무와 관계없이 올바른 선택(패스·스루패스·압박·슈팅·드리블)을 고르는 능력", Anticipation은 남보다 빠른 반응, Positioning은 **수비 위치 선정에만 쓰이고 공격에서는 쓰이지 않는** 속성이다. Concentration은 경기 내내 실수를 줄이고, Composure는 압박 아래 판단과 마무리 일관성에 작용한다 ([passion4fm](https://www.passion4fm.com/football-manager-player-attributes/)). 신체 쪽에서 Stamina가 낮으면 빨리 지치고 **지칠수록 실행 품질이 떨어진다**. Natural Fitness는 경기 중 효과가 아니라 경기 간 회복·노화 속도에 쓰인다(같은 출처). 이를 정리하면 정신 속성은 "무엇을 언제 할지", 기술 속성은 "얼마나 정확히 할지", 신체 속성은 "어디까지 갈 수 있는지"를 정한다.

개성을 만드는 장치는 능력치가 아니라 **선택 확률 편향**이다. SI 공식 포럼 직원은 "Teamwork가 높은 선수는 팀 지시를 따를 가능성이 높고, 낮은 선수는 전술 지시보다 자기 PPM(트레잇)을 택할 가능성이 높다"고 썼다 ([SI Community](https://community.sports-interactive.com/forums/topic/555046-team-instructions-vs-player-instructions)). 커뮤니티 가이드도 트레잇을 "추가 능력이 아니라 특정 상황의 의사결정 영향"으로 설명한다. 지시와 맞는 트레잇은 그 행동을 더 자주 하게 만들고, 충돌하는 트레잇은 지시 준수를 떨어뜨린다 ([passion4fm traits](https://www.passion4fm.com/football-manager-player-traits/)). 즉 FM은 Teamwork 하나로 "팀 구조 vs 개인 성향"의 혼합 비율을 개인화한다. 시나리오가 조종하는 3~5명과 개인 버릇 사이에서 줄타기를 해야 하는 Road To PRO에 거의 그대로 옮길 수 있는 장치다.

EA는 이 분리를 공식 문서로 가장 명확히 설명한 곳이다. FC 25 FC IQ에서 Work Rate와 선수 지시를 없애고 **역할 31개(포커스 포함 52조합)**로 바꿨다. 역할은 "모든 선수가 공 없이 생각·행동·움직이는 방식"을 정하고, 포커스는 역할 특성을 +, =, −로 조정한다. 숙련도는 기본·Role+·Role++ 세 단계다. 공개된 정량 수치도 하나 있다. 숙련도는 **위치 선정 계산에서 Positioning 또는 Defensive Awareness와 함께 쓰이며 결과의 10~40%를 차지**한다. 숙련도가 낮을수록 공수 전환이 느리다 ([EA FC IQ Deep Dive](https://www.ea.com/en/games/ea-sports-fc/fc-25/news/pitch-notes-fc-25-fc-iq-deep-dive)). 공 있는 쪽은 PlayStyles가 맡는다. "Opta 실데이터 등으로 최적화"된 특기 플래그이고, PlayStyle+는 같은 효과를 월드클래스 수준으로 키운 것이다 ([EA FC 24 PlayStyles](https://www.ea.com/games/ea-sports-fc/pitch-notes/news/fc-24-playstyles-deepdive)). 같은 문서는 GK PlayStyle이 일반 모드에서 "과거 Traits와 비슷한 CPU AI 행동 효과"만 낸다고 적었다. Traits가 원래 AI 행동 편향 장치였다는 공식적 시사다. eFootball도 Konami 공식 해설은 찾지 못했지만 2차 자료 기준으로 같은 3층 구조다. Playing Style은 공 없는 움직임, AI Playing Style은 CPU가 조종할 때 공 가진 행동 빈도, Player Skills는 특정 기술의 가능 여부를 맡는다 ([fifplay](https://www.fifplay.com/efootball-2027-playing-styles/)).

공개 테스트는 경고 신호도 준다. FM-Arena 운영자는 Acceleration·Pace 같은 속성은 "큰 차이를 만들고", Teamwork·Off the Ball은 "거의 차이가 없다"고 요약했다 ([FM-Arena FM2021](https://fm-arena.com/find-tactic-result/9/852/)). 7개 속성을 각 +3 하면 시즌 승점이 약 64에서 94로 오른다는 글도 있다. 다만 "이 테스트 전술 기준"이라는 단서가 붙어 있다 ([FM-Arena Zippo](https://fm-arena.com/profile/6-zippo/find-posts/page-15/)). 해석은 두 갈래다. 실행 판정이 공간·도달 시간에 크게 의존해 속도가 지배적일 수 있다. 또는 정신 속성 효과가 "선택 분포·타이밍"이라 승점으로 잘 드러나지 않을 수 있다. 공개 자료로는 둘을 가를 수 없다. 우리에게 주는 교훈은 분명하다. 속성별 민감도를 **승점과 행동 통계(침투 타이밍, 패스 선택 분포, 지시 이탈률) 양쪽으로** 측정하지 않으면 "속도만 강한 엔진"이 되어도 알아채지 못한다.

## 컨디션은 세 개의 시계로 돌고, 피로는 경기력보다 부상에 걸린다

FM은 FM21부터 하나의 %였던 값을 **경기 컨디션(Condition)**과 **경기 감각(Match Sharpness)**으로 나눴다. 감각은 출전으로 오르고 결장하면 떨어지며, 장기 결장 시 35%까지 내려간다 ([RealSport101](https://realsport101.com/article/football-manager-202-conditioning-overhauled-ahead-of-release-match-sharpness-draining-fatigue)). 여기에 장기 누적 **피로(Fatigue/Jadedness)**와 부상 위험 툴팁(경기 부하·훈련 부하·부상 취약성·피로)이 붙는다 ([RealSport101](https://realsport101.com/football-manager/football-manager-21-condition-fatigue-sharpness-changes-tooltip-injury-risk/)). 커뮤니티는 "감각 영향 큼 > 컨디션 중간 > 피로는 과하지만 않으면 됨"으로 요약하지만 원 수치는 확인하지 못했다 ([fm-arena](https://fm-arena.com/find-comment/45840/)). FC 커리어도 Fitness와 Sharpness 2축이고, 완전히 샤프한 선수는 경기마다 약간의 스탯 부스트를 받는다 ([Dexerto](https://dexerto.com/ea-sports-fc/best-training-plans-ea-fc-25-career-mode-sharpness-fitness-2913374)). FC 25·26에서는 샤프니스가 10이나 80에 고착되는 버그 보고가 이어졌다 ([EA Forums](https://forums.ea.com/discussions/fc-25-game-modes-en/fc25-sharpness/7856987)). 자동 회복 규칙은 경계 조건에서 쉽게 고착된다는 교훈이다. eFootball은 다른 길을 택했다. 경기 전 **컨디션 화살표 5단계**는 휴식·결과와 무관한 가중 추첨이고, 선수별 "Condition Fitness" 등급이 분산을 정한다. 킥오프 전에 고정되어 경기 중에는 바뀌지 않는다 ([GameMarket](https://gamemarket.gg/news/efootball/efootball-condition-arrows-explained-how-player-form-works)). 결정론 엔진에서 시드로 재현하기 가장 쉬운 형태다.

스포츠과학은 경기 내 피로가 두 성분이라고 말한다. 하나는 **점진 누적**이다. Mohr 등(2003)은 수준·포지션과 무관하게 마지막 15분 고강도 달리기가 첫 15분보다 35~45% 적다고 보고했다. 다른 하나는 **일시 피로**다. 가장 격렬한 5분 직후 5분은 경기 평균보다 12% 적다. 교체 투입 선수는 마지막 15분 고강도 거리가 25% 더 많았다 ([PubMed 12848386](https://read.qxmd.com/read/12848386/match-performance-of-high-standard-soccer-players-with-special-reference-to-development-of-fatigue)). 다른 엘리트 연구의 감소폭은 18%였다 ([academia.edu](https://www.academia.edu/12782253)). Bradley 등(2009, EPL 370명)은 포지션별 경기당 고강도 거리를 냈다. **윙 미드 3,138m부터 센터백 1,834m까지 약 1.7배 차이**이고, 초고강도 구간 사이 회복 시간은 마지막 15분에 28% 더 길었다 ([Sunderland SURE](https://sure.sunderland.ac.uk/id/eprint/3478/)). 기술 저하의 근거는 엇갈린다. Rampinini 등은 경기 피로 후 짧은 패스 테스트의 오류가 늘었다고 보고했다 ([PubMed 18408603](https://www.pubmed.gov/18408603/)). 반면 Harper 등(2014)은 신체 피로가 있어도 세리에A 기술 지표의 약 3/4이 전후반에 비슷했다고 썼다 ([Harper et al.](https://eprints.hud.ac.uk/29346/1/Harper%20et%20al%202014%20-%20Plos%20One.pdf)). 피로가 판단 정확도를 얼마나 떨어뜨리는지에 대한 축구 경기 데이터 기반 수치는 찾지 못했다.

경기 간 회복과 일정 밀집에서 근거가 가장 강하다. 회복 시간은 지표마다 24~72시간으로 다르다 ([Nédélec 2012](https://hal-insep.archives-ouvertes.fr/hal-01660950)). Silva 등(2018) 메타분석에서 스프린트는 72시간 안에 회복되지만 점프와 근손상 지표(CK)는 72시간에도 남아 있었다 ([Silva et al.](https://cifi2d.fade.up.pt/files/acuteandresidual.pdf)). 일정 밀집의 효과는 경기력보다 부상에서 뚜렷하다. Dupont 등(2010)은 **주 2경기 시 부상률 25.6/1000h 대 주 1경기 4.1/1000h**를 보고했는데, 신체 퍼포먼스는 유의한 차이가 없었다 ([PubMed 20400751](https://pubmed.ncbi.nlm.nih.gov/20400751/)). Bengtsson 등(2013, UCL 27팀 11시즌)에서 회복 ≤4일이면 근육 부상 **RR 1.32(95% CI 1.15–1.51)**였고, 팀 성적에는 영향이 없거나 매우 제한적이었다 ([PubMed 23851296](https://pubmed.ncbi.nlm.nih.gov/23851296/)). 메타분석도 일정 밀집이 총 주행거리에 영향을 주지 않는다고 결론 냈다 ([Julian et al. 2020](https://link.springer.com/article/10.1007/s40279-020-01359-9)). 기준 부상률은 경기 27.5/1000h, 훈련 4.1/1000h, 선수당 시즌 약 2건이다 ([Ekstrand BJSM 2009](https://bjsm.bmj.com/content/early/2009/06/23/bjsm.2009.060582.full.pdf)). 질병은 선수당 약 2시즌에 1회이고, 호흡기 58%, 위장관 38%, 4주 초과 중증 2%다 ([OSTRC](https://klokavskade.no/en/about-us/news/illness-is-not-a-major-contributor-to-illness-in-male-professional-football)). ACWR >1.5는 위험 신호로 널리 쓰이지만, "0.8~1.3 스위트 스팟"이 부상을 줄인다는 근거는 없다는 비판 리뷰가 있다 ([PMC8138569](https://pmc.ncbi.nlm.nih.gov/articles/PMC8138569/)). 이미 확정된 "감기 → 부상 확률 상승"도 축구 특화 배수 근거는 찾지 못했다. 게임 디자인 값으로 남겨야 한다.

## 사기·케미·감독 효과는 게임에서 크고 데이터에서 작다

FM은 사기·조직력·전술 숙련도가 매치 엔진에 영향을 준다고 **정성적으로만** 밝힌다. FM27 공식 소개는 조직력이 맞지 않으면 "선수들이 같은 구역에 겹치고 잘못된 판단을 하는" 모습이 드러날 수 있다고 썼다. 스쿼드 내 관계가 조직력을 돕거나 해친다고도 했다 ([FM27 Match Engine](https://www.footballmanager.com/node/1108)). 사기 단계별 효과 크기는 공개된 수치가 없다. 대표 테스트 커뮤니티인 FM-Arena는 아예 **모든 선수의 사기·컨디션을 최대로 고정**해 변수에서 빼고 측정한다 ([FM-Arena](https://fm-arena.com/find-comment/5014/)). 효과가 무시할 수준은 아니라는 간접 증거이지만 크기는 모른다. 같은 커뮤니티는 5,760경기 테스트의 RNG 잡음을 약 ±1~1.5점으로 보고했다 ([FM-Arena](https://fm-arena.com/find-comment/33673/)). 우리 대량 시뮬 검증의 표본 규모 기준으로 쓸 만하다.

EA는 "숨은 감쇠"보다 **보이는 보너스** 쪽으로 움직였다. FUT 케미스트리는 FIFA 23부터 선수당 0~3점이고, 점수에 따라 케미 스타일의 능력치 부스트가 소·중·대로 열린다. 0점이어도 기본 능력치는 그대로다 ([GamesRadar](https://gamesradar.com/fc-24-chemistry-styles)). 교체 투입 선수는 케미 부스트 없이 뛴다 ([FUT.GG](https://fut.gg/news/new-fifa23-chemistry-system-explained-how-to-gain-chemistry-points-and-more)). FC 27 커리어는 폼·사기·경기 체력으로 OVR 숫자 자체가 바뀌는 "Dynamic OVR"을 도입했다고 3자 가이드들이 전한다 ([Dexerto](https://www.dexerto.com/wikis/ea-fc-27/dynamic-overall-explained/)). eFootball은 개인 컨디션을 "능력치 전반의 완만한 배율"로, 팀 스피릿(최대 99)을 전술 지시 수행·연계 품질로 설명한다 ([Operation Sports](https://operationsports.com/pes-2021-team-spirit-guide-understand-chemistry-on-a-new-level)). 케미가 AI 포지셔닝을 바꾼다는 공식 근거는 어느 쪽에서도 찾지 못했다.

실제 데이터는 이런 효과 대부분을 작게 만든다. Le Coz 등(2025)은 19,721경기에서 전력을 통제하자 "함께 뛴 경험"의 독립 영향이 없었다고 보고했다. 대신 1,602경기 패스 수준에서는 **성공한 상호작용이 있는 공유 경험**이 패스 성공을 예측했다 ([Le Coz et al. 2025](https://library.kab.ac.ug/Record/doaj-art-73fa02071c92416dad6ac592ea1c885d)). 감독 교체 직후 반등은 반복적으로 **평균 회귀**로 설명된다. 1986~2004년 18시즌 에레디비시에서 경질한 팀과 하지 않은 팀의 하락·회복 패턴이 거의 같았다 ([van Ours & van Tuijl 2016](https://link.springer.com/article/10.1007/s10645-016-9277-0); [Tinbergen 25054](https://papers.tinbergen.nl/25054.pdf)). 득점 후 모멘텀도 찾기 어렵다. EPL에서 연무·연패·경기 내 득점의 모멘텀 증거는 없었다 ([Griffith](https://research-repository.griffith.edu.au/items/0675b98f-a106-4a29-812f-6eaed7800ee3)). 분데스리가에서는 베터들이 동점골 직후 팀에 약 40% 더 걸었지만 득점 순서가 승률에 영향을 준다는 증거는 없었다 ([arXiv 2211.06052](https://www.arxiv.org/pdf/2211.06052)). 압박 효과는 있지만 **고압 단일 행동**에 몰려 있다. 메이저 대회 승부차기 409킥에서 "실축하면 패배"인 킥의 성공률은 52%, "성공하면 승리"인 킥은 93%였다. 대회 중요도가 높을수록 성공률이 낮았다(월드컵 71%, 유로 85%) ([The Conversation/Yahoo](https://sg.news.yahoo.com/win-penalty-shootout-according-science-173327986.html)). 유럽 약 5만 개 경기 중 PK 성공률은 약 82%다 ([arXiv 2310.04797](https://arxiv.org/pdf/2310.04797v1)). 사기가 경기력에 주는 인과 효과를 정량화한 신뢰할 만한 실증 논문은 이번 조사에서 찾지 못했다.

이 비대칭은 선수 한 명의 커리어 게임에 오히려 유리하다. 사기·연애·유흥·자기관리는 **팀 승률이 아니라 주인공 개인의 판단 잡음·실행 계수·컨디션 평균**을 움직이는 작은 보정이면 충분하다. 감독 교체는 팀 반등이 아니라 "주전 재경쟁·신뢰도 리셋" 같은 개인 서사로 다루는 편이 현실과 게임성 모두에 맞는다.

## 맥락 효과는 경로가 다르다: 홈은 판정으로, 퇴장은 대형으로

홈 이점은 크고 측정이 잘 되어 있지만 줄어드는 중이다. 잉글랜드 1부 홈 승점 점유율은 19세기 말 약 68%에서 1990~2000년대 약 61%로 떨어졌다는 2차 요약이 있다 ([The Factball](https://thefactball.substack.com/p/home-advantage)). 63개 리그 홈 승률은 2015~2020.3 기간 **44.3%**였고 무관중 이후 42.2%로 내려갔다. 평균 골 차는 +0.31에서 +0.24가 됐다 ([CIES WP304](https://football-observatory.com/IMG/sites/b5wp/2020/wp304/en/)). 분데스리가 2016/17~2023/24는 홈승 45.5%, 원정승 30.2%, 무 24.3%, 홈 득실 +0.38골이었다 ([arXiv 2411.12509](https://arxiv.org/html/2411.12509v1)). 경로가 중요하다. 17개국 6,481경기를 본 Bryson 등(2020)은 무관중이면 원정팀이 받는 카드가 줄어 **홈·원정 경고 차가 약 1/3장 좁혀진다**고 보고했다 ([Bryson et al. 2020](https://discovery.ucl.ac.uk/10115454/1/Bryson%20et%20al%202020%20Econ%20Letters.pdf)). 판정 편향은 사라졌지만 "관중이 홈 이점의 주된 요인은 아닌 것 같다"는 반대 결론도 있다 ([PMC8011816](https://pmc.ncbi.nlm.nih.gov/articles/PMC8011816)). 분데스리가 2021/22에서 관중 25~75% 경기는 75% 초과 경기보다 홈 득점이 0.38골 적고 홈승이 11.8%p 낮았다 ([arXiv 2411.12509](https://arxiv.org/html/2411.12509v1)). 홈 보정을 "능력치 +x"가 아니라 **판정 확률 + 관중 비율에 비례하는 작은 실행 보정**으로 쪼개야 하는 이유다.

퇴장은 근거가 가장 뚜렷한 경기 내 사건이다. 네덜란드 340경기 분석에서 퇴장 후 11명 팀의 득점 강도는 **+88%**였다 ([IZA DP10174](https://docs.iza.org/dp10174.pdf)). 3,039경기·레드카드 715장을 본 최근 연구는 수적 열세 팀의 득점 강도가 **30% 감소**했다고 보고했다 ([arXiv 2605.16066](https://arxiv.org/pdf/2605.16066)). 베팅시장은 레드카드에 내재 승률을 약 12%p 낮춘다 ([arXiv 2505.21275](https://arxiv.org/pdf/2505.21275)). 퇴장 효과는 시점에 따라 다르며 늦은 퇴장일수록 약하다 ([IZA DP2158](https://repec.iza.org/dp2158.pdf)). 우리 엔진은 이 효과를 승률 계수로 덧씌울 필요가 없다. 팀 형태 레이어가 10명으로 라인·간격을 다시 잡으면 공간이 생기고, 그 결과로 나와야 한다. 대량 시뮬이 −30%·+88% 근처를 재현하는지가 엔진 품질 검증이 된다.

날씨와 고도는 근거가 약하거나 논쟁 중이다. McSharry(2007)는 남미 1,460개 A매치에서 고도 차 1,000m당 고지대 팀 득실이 약 +0.5골이라고 보고했다 ([ScienceDaily](https://www.sciencedaily.com/releases/2007/12/071221094837.htm)). 하지만 팀 전력이 섞였다는 반론이 있다 ([NESN](https://nesn.com/2011/03/how-high-is-too-high-for-soccer)). 챔피언스리그 기상 분석에서는 기온·습도·바람 가운데 기온만 "역습 슈팅"에 유의했다(OR 0.55) ([PMC11474995](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC11474995/)). 비·눈·바람이 득점·패스 정확도에 주는 효과를 다룬 동료평가 연구는 찾지 못했다. 날씨는 결과 승수가 아니라 체력 소모·볼 물리·패스 정확도에 작은 보정으로만 넣는 것이 근거 수준에 맞다.

## 승률은 11명을 공·수 지수로 접어 Poisson으로 내고, 엔진 결과로 다시 맞춘다

경기 전 승률의 표준 도구는 레이팅과 골 모델이다. World Football Elo는 `Rn = Ro + K·G·(W−We)`에 홈 +100점, 골 차 배수 G(1 / 1.5 / (11+N)/8)를 쓴다 ([Wikipedia](https://en.wikipedia.org/wiki/World_Football_Elo_Ratings)). Pi-rating은 홈·원정 레이팅을 따로 두고 골 차 오차로 갱신한다(λ=0.035, γ=0.7) ([CRAN piratings](https://cran.r-project.org/web/packages/piratings/refman/piratings.html)). EPL 그리드 서치 최적값은 λ=0.06, γ=0.6이었다 ([vignette](https://cran.r-project.org/web/packages/piratings/vignettes/README.html)). 골 모델의 기본형은 Maher식 독립 Poisson `λ = exp(공격 + 상대수비 + 홈)`이다. Dixon–Coles는 0-0·1-0·0-1·1-1에 τ 보정을 더한다. EPL 2017/18 적합값은 **ρ≈−0.13, 홈 이점 로그 0.29(득점 기대 ×1.34)**였다 ([dashee87](https://dashee87.github.io/football/python/predicting-football-results-with-statistical-modelling-dixon-coles-and-time-weighting/)). τ 보정은 무승부 확률을 올린다(예: 0.167 → 0.186). 독립 Poisson은 저득점 무승부를 과소평가하기 때문이다. 이 수치는 블로그 적합값이므로 출발점으로만 써야 한다.

11명 능력치를 팀 강도로 접는 공식은 상용 게임 쪽에 공개된 것이 없다. FIFA 08 개발 블로그가 "35개 능력치, 70개 트레이트, 65개 이상의 추가 필드"와 **포지션마다 다른 OVR 공식**이 있다고 밝힌 정도다 ([GamesRadar](https://www.gamesradar.com/fifa-08-360ps3-developer-blog-5/3)). 팀 OVR은 커뮤니티 추정뿐이다(18인 평균 + 보정, 선발 가중) ([fifauteam](https://fifauteam.com/fifa-17-squad-rating-guide/)). 데이터 업계의 SPI는 실제 골, 보정 골, 슈팅 xG, 비슈팅 xG를 섞어 "중립 경기장에서 평균 팀 상대로 기대되는 득점"을 공격력으로 정의한다 ([FiveThirtyEight](https://fivethirtyeight.com/features/how-our-club-soccer-predictions-work)). 원문 접근이 막혀 가중치는 확인하지 못했다. 그래서 "역할별 관련 파생 파라미터 가중합 → 라인별 점수 → 팀 공격 지수 A·수비 지수 D → Poisson λ"로 이어지는 구조는 우리가 직접 정하고 엔진으로 적합해야 한다.

평가 기준은 공개되어 있다. 2017 Soccer Prediction Challenge 상위 모델은 평균 RPS 약 0.205~0.206, 정확도 약 52%였다. 1위는 pi-rating 등 레이팅을 입력으로 쓴 XGBoost였다 ([arXiv 2403.07669](https://arxiv.org/pdf/2403.07669); [Machine Learning editorial](https://link.springer.com/article/10.1007/s10994-018-5763-8)). 실제 축구는 최고 모델로도 절반 정도만 맞힌다. 게임의 경기 전 승률을 엔진 결과로 RPS 평가했을 때 0.20 근처가 나오면 "축구다운" 불확실성이고, 크게 낮으면 결과가 너무 뻔하다는 신호다. 이 밴드는 이번 리서치의 추론이다. 인플레이 승률은 남은 시간 비율로 줄인 잔여 득점률 `λ_rem = λ_pre · (남은 분/90) · r_card`에 현재 스코어를 더해 계산할 수 있다. 하이라이트 장면의 WPA(승률 변화)로 중요도를 매기는 데 쓸 수 있다.

데이터 표준도 같은 방향을 가리킨다. SPADL(액션당 12필드, 22개 타입), StatsBomb의 `under_pressure`, Football CDF 온톨로지(클래스 18개)는 모두 **경기 사실(Match·Team·Player·Event·좌표·시간)**을 기록하는 데 초점을 둔다 ([socceraction SPADL](https://socceraction.readthedocs.io/en/latest/documentation/spadl/spadl.html); [FCDF](https://semsys.ai.wu.ac.at/football-cdf/core/)). 능력치·성향·컨디션 같은 시뮬레이션 내부 상태를 다루는 공개 표준은 없다. 상태 계층의 좋은 참고는 RoboCup rcssserver다. 정적 "이종 선수 타입 파라미터"(최고 속도, 스태미나 회복, 킥 노이즈)와 매 사이클 상태를 분리한다. 매 사이클 상태는 stamina(단기), recovery(경기 내 비가역, 1.0→최소 0.5), capacity(경기 총량)의 3단이며, 모든 상수를 설정 파일로 빼 둔다 ([rcssserver](https://rcsoccersim.readthedocs.io/en/latest/soccerserver.html)). 베이지안 네트워크 pi-football은 관측 강도에 부상·피로·동기 같은 주관 노드를 붙여 홈/무/원정 확률을 낸다 ([QMRO](https://qmro.qmul.ac.uk/xmlui/handle/123456789/8404)). "강도 사전값 × 보정 노드 → λ"라는 우리 구조의 원형이다.

## 공개 자료만으로 알 수 없는 것

이 보고서는 공식 문서(EA Pitch Notes, SI 공식 포럼·블로그), 동료평가 논문, 공개 데이터 표준, 커뮤니티 가이드·테스트만 썼다. 상용 게임을 디컴파일하거나 데이터를 추출한 자료는 의도적으로 배제했다. 그 결과 가장 큰 공백은 **게임사 공식 수치**다. 공개 정량값은 EA의 숙련도 비율(10~40%)과 수비 라인 높이 범위 정도다. 다음 값들은 모두 비공개이거나 커뮤니티 추정이다. FM 사기 단계별 효과, 트레잇의 선택 확률 증가폭, 숨은 속성(Consistency·Important Matches)의 엔진 효과, EA PlayStyle의 정확도 %, 케미 부스트 수치, 팀 OVR 공식, eFootball 화살표별 배율. FM-Arena 원문 표 상당수는 404로 열지 못했고, ClubElo·SPI 원문도 접근에 실패했다. 실제 데이터 쪽에서도 사기→경기력 인과 효과, 피로→판단 정확도, 질병→부상 배수, 날씨→득점은 신뢰할 만한 정량 근거를 찾지 못했다. 무승부 약 25%는 분데스리가 24.3%로 뒷받침되지만, 여러 리그를 통합한 최신 1차 집계는 확보하지 못했다. 따라서 아래 적용안의 효과 크기는 "현실이 이렇다"가 아니라 "이 범위에서 시작해 우리 엔진 대량 시뮬로 맞춘다"는 뜻이다.

## 결론

가장 중요한 발견은 상태 변수마다 "어디에 거느냐"가 "얼마나 거느냐"보다 중요하다는 점이다. 홈 이점은 판정에, 퇴장은 팀 형태에, 피로와 일정 밀집은 부상에, 압박은 PK 같은 단일 행동에, 조직력은 선수 쌍의 패스 성공에 걸 때 실제 데이터와 맞는다. 같은 효과를 승률 승수 하나로 뭉치면 숫자는 맞춰도 하이라이트에서 원인이 보이지 않는다. 시나리오 기반 엔진은 이 점에서 유리하다. 공 주변 3~5명의 선택과 실행에 상태를 주입하면, 팀 결과는 계수를 따로 곱하지 않아도 부산물로 나온다.

두 번째 함의는 게임과 현실이 다른 지점을 의도적으로 고르라는 것이다. 사기·라이프의 효과를 현실 근거보다 크게 잡는 것은 커리어 게임에서 정당한 선택이다. 다만 그 효과를 팀 승률이 아니라 주인공 개인의 판단 잡음과 컨디션 평균에 가둬야 결정론·밸런스·설명 가능성을 함께 지킬 수 있다. FM-Arena식 "한 변수만 바꾼 대량 시뮬"을 회귀 테스트로 두면, 그 선택이 의도한 크기를 넘지 않는지 계속 감시할 수 있다.

## 우리 엔진에 적용할 것

전제: 순수 C# 결정론 엔진, 결정 10Hz·물리 100Hz, 능력치 내부 0~100/표시 1~20, 역할 27·성향 14축·버릇 15, 시나리오 268개 기반 + Utility 폴백, 대량 시뮬 평균 득점 2.5~3.0, 저장은 경기 전·후만. 아래 내용은 리서치 기반 제안이다. 기획서(`docs/index.html`)와 대조한 뒤 스펙에서 확정해야 하며, 역할·성향·버릇의 실제 정의와 1:1 대응은 이 보고서에서 대조하지 않았다.

**근거 등급**: **A** = 동료평가 논문·대규모 실데이터 / **B** = 게임사 공식 문서(정성 설명이거나 자사 엔진 한정 수치) / **C** = 커뮤니티 테스트·팬 가이드·블로그·2차 요약 / **D** = 이번 리서치의 설계 추론(직접 근거 없음).
**상태 표기**: `[확정]` = CLAUDE.md 확정 결정 / `[제안]` = 근거로 시작값을 제안하되 대량 시뮬로 조정 / `[미정]` = 근거 없음, 스펙에서 정하거나 시뮬로 적합 / `[검증목표]` = 엔진 출력이 맞춰야 할 현실 기준.

### C. 인과 순서 (DAG, 엔진이 읽는 순서)

```
[경기 전, 1회, 순수 함수, 고정소수점]
Catalog + Static + Dynamic + Context
  → ① 경기 편차 샘플: consistency·Condition Fitness형 분산으로 시드 1회 추첨 (eFootball식)
  → ② EngineParams(선수별) =
        f(Attributes)                         // 능력치 → 파생 파라미터 변환 테이블
      × g(condition, sharpness, residualDamage) // 가용 체력·감각
      × h(morale, form, lifeModifiers)        // 개인 심리·라이프 (작게, 상한 [미정])
      + 역할 숙련도 혼합(위치 계산)
  → ③ TeamIndex A·D = Σ(역할 슬롯 가중 × EngineParams) × familiarity  → λ, μ (+홈 h)
  → ④ PreMatchWinProb (Poisson + DC τ, 엔진 결과로 재보정한 테이블)

[경기 중, 10Hz]
  → ⑤ 팀 형태 레이어 (Tactics, Role, 인원수, EngineParams.speed/stamina)
  → ⑥ 시나리오 선택 (게임 상태, Tactics, 역할 슬롯, Tendency, Habit)
  → ⑦ 지시 vs 버릇 선택 (teamwork류 속성 × 버릇 강도)
  → ⑧ 액션 실행 판정 (기술 파라미터, 압박, InMatch 피로, decisionNoise, 고압 순간이면 composure·bigMatch)
  → ⑨ 판정(파울·카드) (Context.home·crowdRatio, referee)
  → 실패·붕괴 시 Utility 폴백 → Event 기록 → InMatch 상태 갱신

[경기 후, 1회]
  → ⑩ Event 집계 → 평점·form·morale·fatigue·residualDamage·sharpness·PairChemistry 갱신
  → ⑪ 부상·질병 확률 판정 → Dynamic(다음 경기)   ← 유일한 되먹임
```

규칙: Static·Context는 경기 중 바뀌지 않는다. Derived는 경기 중 불변 스냅샷이다. 경기 결과가 같은 경기의 Derived로 되돌아가는 간선은 없다. 경기 중 사기 변동을 넣더라도 InMatch 계층 안에서만 돌고 Static·Dynamic을 건드리지 않는다.

### G. 결정론 규칙

| 규칙 | 내용 | 이유 |
|---|---|---|
| 입력 스냅샷 | Static·Dynamic·Context를 킥오프 전에 불변 구조체로 고정하고 시드와 함께 저장 | 경기 전·후 저장 `[확정]`, 경기 중 종료 시 재현 |
| 고정소수점 | JSON 실수는 로드 시 정수(예: ×1000)로 변환. 변환 곡선·`exp`·`10^x`는 룩업 테이블 | 플랫폼 간 부동소수점 차이 제거 |
| RNG 하위 스트림 | 경기 시드에서 용도별 스트림 분기: 경기 편차 / 시나리오 선택 / 실행 판정 / 판정(심판) / 부상 | 한 계산을 바꿔도 다른 계산의 난수 순서가 밀리지 않음 |
| 순회 순서 | 선수·엔티티는 문자열 ID 사전순, 딕셔너리 순회 금지 | 순서 의존 제거 |
| DAG 강제 | 경기 결과 → Dynamic은 경기 후 1회만. 같은 경기 Derived로의 되먹임 금지 | 틱 순서 무관한 평가 |
| 파생 비저장 | EngineParams·TeamIndex·승률은 저장하지 않고 매번 재계산 | 튜닝 변경 시 세이브 호환 |
| 버전 기록 | 리플레이·통계에 엔진 버전 + 튜닝 해시 + 카탈로그 `schemaVersion` | 재현·회귀 비교 |
| 모드 DSL | 효과는 (target, op ∈ add/mul/set, value) 화이트리스트만, 로드 시 JSON Schema 검증 실패하면 해당 모드만 비활성화 | 임의 코드 실행 차단 |
| 장기 루프 검증 | 시즌 N회 시뮬 후 condition·sharpness·morale 분포가 고착·발산하지 않는지 회귀 테스트 | FC 샤프니스 고착 버그 사례 (C) |
| 코어 위치 | Derived·InMatch 계산은 UnityEngine 비참조 `MatchEngine`/`Core`에서 | 레포 규칙 |
