# 스펙 주도 개발 (SDD) — 항상 적용

모든 기능은 **스펙 → 플랜 → 태스크 → 구현** 순서로 간다. 앞 단계가 사용자 승인을 받기 전에는 다음 단계로 가지 않는다.

```
docs/index.html, docs/scenarios.html   ← 기획 (무엇을 왜, 게임 디자인)
        ↓ 추출
specs/NNN-<slug>/spec.md               ← 요구사항·수용 기준 (무엇을)   /spec
specs/NNN-<slug>/plan.md               ← 설계·모듈·데이터·테스트 전략 (어떻게)   /plan
specs/NNN-<slug>/tasks.md              ← 체크박스 작업 목록 (순서)   /tasks
        ↓
코드 + 테스트                            ← 태스크 하나씩   /implement
        ↓
specs/NNN-<slug>/evidence/              ← 증거 리포트(로직·결정론·벤치·스크린샷)   /verify
```

## 규칙
- **코드는 승인된 `tasks.md`의 태스크로만 쓴다.** 태스크에 없는 코드는 쓰지 않는다. 필요하면 먼저 태스크를 추가하자고 제안한다.
- 스펙 번호는 3자리 순번(`001-match-rng`). 브랜치 이름은 `feat/NNN-<slug>`.
- 각 문서 맨 위 `상태:` 줄 — `초안 → 승인됨 → 완료`. 사용자가 "승인"이라고 하기 전에는 `초안`.
- spec.md에는 구현 방법을 쓰지 않는다 (클래스명·라이브러리 금지). plan.md에서 정한다.
- 수용 기준은 테스트로 옮길 수 있게 쓴다: `AC-01: <조건>이면 <결과>`. 각 AC는 tasks.md의 테스트 태스크와 연결된다.
- 기획서의 수치·공식은 출처(문서·섹션)를 달아 인용한다. 기획서에 없는 수치는 `[미정]`으로 남기고 지어내지 않는다.
- 구현 중 스펙이 틀렸거나 부족하면 코드를 우회하지 말고 멈추고 스펙 수정을 제안한다. 스펙·플랜·코드는 항상 일치해야 한다.
- 구현이 끝나면 tasks.md 체크박스를 갱신하고 spec.md 상태를 `완료`로.

## 검증 횟수 (긴 실행은 스펙 끝에 한 번)
`farm.py art`(Blender 전체 ≈ 7분)·`bench`·EditMode 전체(≈ 13분)는 **스펙 마지막에 각 1회**만 돌린다. 프로필 매트릭스(`smoke`·`full`)는 2026-11-11 폐지(2026-11-11 사용자 결정) — 돌리지 않는다. 태스크 중간·화면을 보며 고치는 반복에서는 범위를 좁힌다.
- 화면 확인: 고치는 장면 스크린샷만 `mac-m1-1600p` 1프로필로 찍는다(`farm.py shot --scenario <장면>`, 기준 비교 없음).
- Blender: 생성기 1회(또는 측정 스크립트). 결정론·시드·잘못된 인자까지 도는 `farm.py art`는 마지막에.
- EditMode: 바뀐 테스트 클래스만 필터.
- 마지막 순서: 커밋 → `art`·EditMode 전체·`bench` 각 1회 → 장면 스크린샷 육안 승인 → 승인 기록만 바뀌면 전체 재실행 전에 사용자에게 묻는다.
- 긴 실행 전에는 예상 시간과 "마지막 1회인지"를 한 줄로 알린다.
- tasks.md 중간 태스크의 `검증:`에는 좁힌 명령을 적는다. `farm.py art` 전체·EditMode 전체·벤치는 마지막 검증 태스크에만.
(2026-11-05 057에서 수정마다 전체 세트를 5번, full을 3번 돌려 약 2시간이 걸린 뒤 추가)

## 완료 정의 (버그 0 · 성능 통과)
스펙은 아래가 **전부** 충족되고 증거가 남았을 때만 `완료`다. 말로 "됐다"고 하지 않는다. 증거를 보여준다.
1. 모든 AC가 검증 종류(`[로직]` `[E2E]` `[성능]` `[결정론]`)를 가지고, 그 검증이 통과한다.
2. 로직: EditMode 테스트 실패 0. 테스트 리포트를 렌더링한 스크린샷이 `evidence/`에 있다.
3. 화면(`[E2E]`): AC가 말하는 장면의 스크린샷을 `mac-m1-1600p` 1프로필로 찍고, 내가 직접 열어 확인한 뒤 **사용자 육안 승인**을 받는다. 프로필 매트릭스·기준 이미지 비교는 하지 않는다(2026-11-11 사용자 결정으로 폐지). 기존 스펙에 적힌 프로필 목록은 `mac-m1-1600p` 하나로 읽는다.
4. 성능: CPU 예산은 IL2CPP 벤치(D17)로 판정하고 회귀(+10%)면 실패. GPU·내장 GPU 프레임 예산은 개발 맥 측정값을 기록만 하고, 판정은 실기기 확보 후로 미룬다.
5. 콘솔 에러·경고 0, 예외 0, 컴파일 경고 신규 0.
6. 코어 모듈 변경이면 결정론 테스트 통과 + `determinism-reviewer` 리뷰.
7. `/verify NNN` 리포트(`evidence/report.html`)를 아티팩트로 발행해 링크를 남긴다 (회사 등 밖에서도 확인 가능하게).
- `specs/`는 에이전트가 읽고 diff로 리뷰하는 작업 문서라 **Markdown**이다. 사람이 보는 기획·리서치 문서는 계속 `docs/*.html` 아티팩트.
