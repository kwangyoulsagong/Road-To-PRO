# 스펙 주도 개발 (SDD) — 항상 적용

모든 기능은 **스펙 → 플랜 → 태스크 → 구현** 순서로 간다. 앞 단계가 사용자 승인을 받기 전에는 다음 단계로 가지 않는다.

```
docs/index.html, docs/scenarios.html   ← 기획 (무엇을 왜, 게임 디자인)
        ↓ 추출
specs/NNN-<slug>/spec.md               ← 요구사항·수용 기준 (무엇을)   /spec
specs/NNN-<slug>/plan.md               ← 설계·모듈·데이터·테스트 전략 (어떻게)   /plan
specs/NNN-<slug>/tasks.md              ← 체크박스 작업 목록 (순서)   /tasks
        ↓
코드 + 테스트                            ← 태스크 하나씩   /implement
        ↓
specs/NNN-<slug>/evidence/              ← 증거 리포트(로직·결정론·벤치·스크린샷)   /verify
```

## 규칙
- **코드는 승인된 `tasks.md`의 태스크로만 쓴다.** 태스크에 없는 코드는 쓰지 않는다. 필요하면 먼저 태스크를 추가하자고 제안한다.
- 스펙 번호는 3자리 순번(`001-match-rng`). 브랜치 이름은 `feat/NNN-<slug>`.
- 각 문서 맨 위 `상태:` 줄 — `초안 → 승인됨 → 완료`. 사용자가 "승인"이라고 하기 전에는 `초안`.
- spec.md에는 구현 방법을 쓰지 않는다 (클래스명·라이브러리 금지). plan.md에서 정한다.
- 수용 기준은 테스트로 옮길 수 있게 쓴다: `AC-01: <조건>이면 <결과>`. 각 AC는 tasks.md의 테스트 태스크와 연결된다.
- 기획서의 수치·공식은 출처(문서·섹션)를 달아 인용한다. 기획서에 없는 수치는 `[미정]`으로 남기고 지어내지 않는다.
- 구현 중 스펙이 틀렸거나 부족하면 코드를 우회하지 말고 멈추고 스펙 수정을 제안한다. 스펙·플랜·코드는 항상 일치해야 한다.
- 구현이 끝나면 tasks.md 체크박스를 갱신하고 spec.md 상태를 `완료`로.

## 검증 범위 (2026-11-12 경량화 — 바뀐 것만, 한 번만)
긴 실행은 **그 스펙이 건드린 곳에 해당할 때만, 스펙 마지막에 1회** 돌린다. 프로필 매트릭스(`smoke`·`full`)는 2026-11-11 폐지.

| 검증 | 언제 돌리나 | 명령 |
|---|---|---|
| EditMode 로직 | 항상. 단 **바뀐 것만** — 바뀐 모듈 + 그 모듈을 쓰는 테스트 | `farm.py logic --spec NNN --scope auto`: main 이후 바뀐 파일로 범위를 자동으로 정한다. MatchEngine·튜닝 → `match`(Core+MatchEngine+하이라이트 실경기 픽스처), Presentation·UI → `presentation`, 검증 드라이버·E2E 데이터 → `verification`, Core·asmdef·패키지·설정·규칙 없는 새 모듈 → 전체. "전체 회귀"를 따로 돌리지 않는다 |
| IL2CPP 벤치 | 스펙에 IL2CPP 성능 예산이 있고 **시뮬 틱 경로를 바꿨을 때만** | `farm.py bench --spec NNN` |
| `farm.py art` (≈ 7분) | Blender 스크립트를 바꿨을 때만 | `farm.py art --spec NNN` |
| 장면 스크린샷 | `[E2E]` AC가 있거나 화면에 보이는 걸 바꿨을 때 | `farm.py shot --scenario <장면>` (`mac-m1-1600p` 1프로필, 기준 비교 없음) |
| 결정론 | 코어 모듈을 바꿨을 때 | `Determinism` 카테고리가 로직 범위 안에 들어가면 같이 돈다 + `determinism-reviewer` |

- 태스크 중간: 바뀐 테스트 클래스만 필터(`--filter`), 장면 1개, Blender 생성기 1회. 범위를 손으로 정할 땐 `--scope match` 등.
- 마지막 순서: 커밋 → 위 표에서 해당하는 것만 각 1회 → 장면 육안 승인 → 증거 커밋 **1번**.
- **증거·문서만 바뀌면 다시 돌리지 않는다.** `farm.py`는 `specs/`·`docs/`·`reports/` 변경을 "커밋 안 된 코드 변경"으로 보지 않는다. 코드·데이터·튜닝을 고쳤을 때만 그 범위를 다시 돌린다.
- 로직 리포트 PNG는 만들지 않는다(`report.html` 표로 충분). 필요하면 `--png`.
- 긴 실행(auto가 전체로 나온 EditMode·벤치·art) 전에는 예상 시간과 "이 스펙에서 왜 필요한지"를 한 줄로 알린다. 다른 일을 할 수 있으면 백그라운드로 돌린다.
- tasks.md 마지막 검증 태스크에는 위 표에서 해당하는 명령만 적는다.
(2026-11-05 057: 수정마다 전체 세트를 돌려 ≈ 2시간 → "스펙 끝 1회" 추가. 2026-11-12 010: 증거 커밋마다 logic 5회·shot 3회 재실행, 벤치 3회 → "바뀐 것만" 개정, 사용자 결정)

## 완료 정의 (버그 0 · 성능 통과)
스펙은 아래가 **전부** 충족되고 증거가 남았을 때만 `완료`다. 말로 "됐다"고 하지 않는다. 증거를 보여준다.
1. 모든 AC가 검증 종류(`[로직]` `[E2E]` `[성능]` `[결정론]`)를 가지고, 그 검증이 통과한다.
2. 로직: 바뀐 모듈 범위(위 "검증 범위")의 EditMode 테스트 실패 0. 결과는 `evidence/report.html`에 있다 (PNG 렌더는 2026-11-12 폐지).
3. 화면(`[E2E]`): AC가 말하는 장면의 스크린샷을 `mac-m1-1600p` 1프로필로 찍고, 내가 직접 열어 확인한 뒤 **사용자 육안 승인**을 받는다. 프로필 매트릭스·기준 이미지 비교는 하지 않는다(2026-11-11 사용자 결정으로 폐지). 기존 스펙에 적힌 프로필 목록은 `mac-m1-1600p` 하나로 읽는다.
4. 성능: 시뮬 틱 경로를 바꾼 스펙만 CPU 예산을 IL2CPP 벤치(D17)로 판정하고 회귀(+10%)면 실패. 안 바꿨으면 벤치를 돌리지 않고 리포트에 "틱 경로 변경 없음"이라고 적는다. GPU·내장 GPU 프레임 예산은 개발 맥 측정값을 기록만 하고, 판정은 실기기 확보 후로 미룬다.
5. 콘솔 에러·경고 0, 예외 0, 컴파일 경고 신규 0.
6. 코어 모듈 변경이면 결정론 테스트 통과 + `determinism-reviewer` 리뷰.
7. `/verify NNN` 리포트(`evidence/report.html`)를 아티팩트로 발행해 링크를 남긴다 (회사 등 밖에서도 확인 가능하게).
- `specs/`는 에이전트가 읽고 diff로 리뷰하는 작업 문서라 **Markdown**이다. 사람이 보는 기획·리서치 문서는 계속 `docs/*.html` 아티팩트.
