# /verify — 디바이스팜 증거 리포트

설계 원문: `specs/000-verification-harness/spec.md`. 000이 구현되기 전에는 이 스킬을 쓸 수 없다고 알리고, 가능한 부분(로직 테스트)만 한다.

1. `specs/NNN-*/spec.md`의 AC 목록과 검증 종류, 성능 예산, E2E 시나리오 id, 대상 프로필을 읽는다.
2. 로직: `.claude/scripts/unity-test.sh EditMode` (필터: 해당 스펙 테스트) → 결과 XML을 HTML로 렌더링하고 헤드리스 Chrome으로 `evidence/logic.png`를 찍는다.
3. E2E: 프로필별로 플레이어 빌드를 해당 해상도·품질·테마로 실행, 시나리오 단계마다 스크린샷 + 프레임 시간 샘플. 기준 이미지와 픽셀 차이 비교.
4. 성능: Performance 테스트 결과 + E2E 프레임 샘플을 `evidence/perf.json`으로 모으고 예산·이전 측정과 비교.
5. `evidence/report.html` 생성 → Artifact로 발행(같은 스펙은 같은 파일 경로로 재발행) → 링크를 사용자에게.
6. 하나라도 실패하면 `완료`로 바꾸지 않는다. 실패 항목·스크린샷·수치를 그대로 보고한다.
7. 기준 이미지가 없으면 첫 실행 결과를 "기준 후보"로 보여주고 사용자 승인 후에만 기준으로 채택.
8. 생성된 스크린샷은 Read로 직접 열어 눈으로 확인한다. 깨진 레이아웃·빈 화면·잘린 텍스트가 보이면 차이 임계값과 무관하게 실패.
