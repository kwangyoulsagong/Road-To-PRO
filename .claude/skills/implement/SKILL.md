# /implement — 태스크 구현

1. `tasks.md`가 `상태: 승인됨`인지 확인. 브랜치가 `feat/NNN-*`인지 확인.
2. 지정 태스크, 없으면 첫 번째 `[ ]` 태스크 **하나만** 한다. 같이 하면 편해 보여도 다음 태스크를 미리 하지 않는다.
3. 관련 spec의 FR/AC, plan의 해당 섹션을 다시 읽는다.
4. 구현. 테스트 태스크면 먼저 실패하는 테스트를 쓴다.
5. 검증: 태스크에 적힌 방법으로 (`/unity-test` 등). 실패하면 고치거나, 원인이 스펙·플랜이면 멈추고 보고.
6. 코어 모듈을 건드렸으면 `determinism-reviewer`로 리뷰.
7. UI·프레젠테이션 태스크면 해당 E2E 시나리오를 디바이스팜 기본 프로필 1개로 돌려 스크린샷을 직접 확인한다(Read로 이미지 열기). 눈으로 보지 않은 화면을 됐다고 하지 않는다.
8. 체크박스를 `[x]`로, 결과(테스트 통과 수 등)를 한 줄 덧붙인다. 커밋은 사용자가 요청할 때만.
9. 다음 태스크가 뭔지 알려주고 멈춘다.
