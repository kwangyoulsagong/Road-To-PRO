# /pipeline — 연속 구현

`/implement`는 태스크 하나마다 멈춘다. `/pipeline`은 같은 절차를 **남은 태스크 전부에** 반복하고, 승인 지점에서만 멈춘다.

## 시작 조건
1. `specs/NNN-*/tasks.md`가 `상태: 승인됨`, 브랜치가 `feat/NNN-*`. 아니면 멈추고 알린다 (스펙·플랜·태스크 승인은 건너뛰지 않는다).
2. 작업 트리 상태를 확인한다. 다른 스펙의 커밋 안 된 변경이 섞여 있으면 알린다.

## 반복 (첫 번째 `[ ]` 태스크부터 마지막까지)
각 태스크마다 `/implement`의 3~8단계를 그대로 한다:
- spec FR/AC·plan 해당 섹션을 다시 읽는다 → 테스트 태스크는 실패하는 테스트 먼저 → 구현 → 태스크에 적힌 방법으로 검증.
- 검증은 좁게: 중간 태스크는 바뀐 테스트 클래스·장면 하나·프로필 하나만. `farm.py art` 전체·EditMode 전체·`bench`는 마지막 검증 태스크에서 각 1회 (프로필 매트릭스는 폐지) (`.claude/rules/05-sdd.md` "검증 횟수"). 태스크 칸에 전체 실행이 적혀 있어도 중간이면 좁혀서 돌리고 결과 줄에 그렇게 적는다.
- 코어 모듈 변경이면 `determinism-reviewer` 리뷰, UI·프레젠테이션이면 스크린샷을 Read로 직접 확인.
- 체크박스 `[x]` + 결과 한 줄. 플랜과 달라진 점(파일 분리 등)도 그 줄에 적는다.
- 태스크 사이에 사용자에게 확인을 묻지 않는다. 긴 작업 중에는 한 줄 진행 상황만 알린다.

## 멈추는 지점 (이때만 사용자에게 묻는다)
- 스펙·플랜이 틀렸거나 부족해서 코드로 우회해야 할 때 → 스펙 수정 제안.
- 태스크에 없는 코드가 필요할 때 → 태스크 추가 제안 (작고 명백한 수정은 `TNNa` 태스크로 추가하고 결과 줄에 사유를 남기고 계속해도 된다).
- 장면 스크린샷 육안 승인, 성능 기준 갱신, `Packages/manifest.json`·`ProjectSettings/*.asset` 변경 (스펙에서 이미 승인된 건 제외).
- 같은 검증이 3회 고쳐도 실패할 때 → 원인과 로그를 보고.
- 커밋·푸시는 요청받을 때만 (`00-workflow.md`).

## 끝
- 마지막 태스크(`/verify NNN`)까지 가면 리포트 링크와 함께 요약: 완료 태스크 수, 테스트 통과 수, 추가된 태스크, 남은 승인 항목.
- 중간에 멈췄으면 멈춘 태스크·이유·다음 할 일을 남긴다. 재실행하면 첫 `[ ]`부터 이어간다.
