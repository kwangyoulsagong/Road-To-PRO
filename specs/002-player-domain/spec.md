# 002 — 선수 도메인 모델: 능력치 · 포지션 · 성격 · 숨김값

상태: 초안
브랜치: feat/002-player-domain
기획 출처: docs/index.html § 기획서 4.1(선수 생성 항목), § 4.2(능력치 체계, "엔진 계산 1:1 연결" 원칙), § 6(수만 명 단위 선수 DB), research[3] 03 B1~B4·B8(능력치 목록·엔진 매핑·컨디션·포지션 적합도·CA/PA), research[1] 01 B-9(운동학 파라미터 범위)

## 배경
게임의 모든 숫자(성장, 시장가치, 경기 결과)는 선수 능력치에서 나온다. 기획서 원칙은 "각 능력치는 경기 엔진의 특정 계산에 1:1로 연결되고, 연결되지 않은 장식용 스탯은 두지 않는다"이다. 이 스펙은 선수를 표현하는 데이터(능력치, 숨김값, 발, 체격, 포지션, 성격, CA/PA, 경기 상태)와 능력치 → 엔진 파라미터 변환을 정의한다. 플레이어는 1~20 숫자로 보지만 엔진은 연속값을 쓴다. 이 둘이 어긋나면 "능력치 20인데 왜 느리지?" 같은 신뢰 붕괴가 생긴다.

## 범위
- 포함:
  - 선수 신원(고유 id, 이름, 국적, 생년월일, 주발·약발, 키·체중)
  - 능력치 5그룹: 신체 8, 기술 12, 정신 12, GK 8, 숨김 9 (research[3] 03 B2)
  - 내부값(0~100 연속)과 표시값(1~20) 변환
  - 능력치 → 엔진 파라미터 매핑 표와 "연결 없는 능력치 금지" 검사
  - 포지션: 주 포지션 1 + 부 포지션 최대 2, 포지션 적합도, 익숙함(Familiarity)
  - 성격 특성 (기획서 4.1)과 숨김값의 관계
  - CA(현재 능력 예산) / PA(잠재력, 숨김) 계산과 PA 범위 힌트 데이터
  - 경기 시작 시 유효 능력치 계산: 경기 폼, 일관성, 빅매치, 피로 배수 (research[3] 03 B3)
  - 직렬화 가능한 값 표현
- 제외:
  - 역할·성향·버릇 (003)
  - 성장·노화 공식 적용 (026), 부상·질병 (027), 생성 분포 (020, 023)
  - 피로 곡선 자체 (005가 에너지 모델 제공), 화면 표시 (038)
  - 저장 형식 (022)

## 사용자 시나리오
1. 내 선수 화면에서 가속 16, 최고속도 14가 보인다. 경기에서 그 선수가 상대보다 빨리 출발하는 게 눈에 띈다 (능력치 → 엔진 1:1).
2. 잠재력은 "★★★★ ~ ★★★★★" 같은 범위로만 보이고, 스카우트 리포트가 쌓일수록 범위가 좁아진다.
3. 부 포지션 RB로 처음 출전하면 위치 선정이 어색하다. 몇 경기 뛰고 나면 익숙해진다 (Familiarity 상승).
4. 일관성이 낮은 선수는 어떤 경기는 펄펄 날고 어떤 경기는 부진하다 (경기 폼 분산).

## 요구사항

### 신원 · 체격
- FR-01: 선수는 저장·로드·이적을 거쳐도 바뀌지 않는 고유 id를 가진다. 결정론 순회 기준(001 FR-90)으로 쓰인다.
- FR-02: 이름은 가상 이름만 담는다 (`.claude/rules/01-legal.md`). 실명 정책은 결정 대기이므로 이 스펙은 이름 출처를 정하지 않는다.
- FR-03: 국적(주 국적 1, 이중 국적 `[제안]` 최대 1), 생년월일(001 게임 날짜), 주발(왼/오), 약발 1~5, 키(cm), 체중(kg) (research[3] 03 B2 "Height/Weight 생성 시 고정", "WeakFoot 1–5").
- FR-04: 약발 사용 시 정확도 σ 배수 = 1 + 0.6·(5−WF)/4 (research[3] 03 B2). 이 배수는 002가 계산해 제공하고, 액션 모델(008)이 쓴다.

### 능력치
- FR-10: 능력치 목록 (research[3] 03 B2·B8):
  - 신체: TopSpeed, Acceleration, Agility, Balance, Strength, Stamina, Recovery, Jumping
  - 기술: FirstTouch, ShortPass, LongPass, Crossing, Finishing, LongShots, Dribbling, Heading, Tackling, Shielding, SetPiece, Penalty
  - 정신: Decisions, Vision, Anticipation, Composure, Positioning, OffBall, WorkRate, Concentration, Teamwork, Aggression, Bravery, Leadership
  - GK: Reflexes, Diving, Handling, OneOnOne, CommandArea, Sweeping, Distribution, GKPositioning
  - 숨김: Consistency, BigMatch, InjuryProneness, Professionalism, Determination, Ambition, Temperament, Adaptability, Versatility
- FR-11: 내부값은 0~100 연속값, 정규화 s = attr/100 (research[3] 03 B1). 내부값은 항상 [0,100]로 클램프된다.
- FR-12: 표시값은 1~20 정수 (기획서 4.2). 변환 규칙 `[제안]`: 표시 = clamp(ceil(내부/5), 1, 20). 표시값 경계(예: 내부 50.0 → 10, 50.01 → 11)는 테스트로 고정한다.
- FR-14: **정규화 규약 (모든 스펙 공통, 002 소유)**: 엔진 수식의 능력치 입력은 s = 내부값/100 ∈ [0,1] 하나뿐이다. 다른 스펙의 수식·AC에 나오는 "능력치 N"(표시값 N)은 대표 내부값 (N−1)/19 × 100을 뜻한다 (표시 1 → s 0, 표시 15 → s ≈ 0.737, 표시 20 → s 1). 이 대표값은 FR-12 변환으로 다시 N이 된다. 다른 스펙은 자체 정규화(예: (attr−1)/19, attr/20, attr/100)를 따로 정의하지 않고 이 규약을 참조한다.
- FR-13: 숨김 능력치는 플레이어 화면에 숫자로 노출하지 않는다. 노출 정책(힌트·이벤트)은 038·030 몫이고, 002는 "숨김 여부" 속성만 제공한다.

### 능력치 → 엔진 파라미터 (1:1 연결)
- FR-20: **매핑 등록부**: 002는 능력치마다 "어느 스펙이 어떤 엔진 파라미터로 쓰는지"를 등록부로 소유한다. 수식 자체는 그 계산을 하는 스펙이 소유한다 (같은 수식을 두 스펙이 따로 정의하지 않는다). research[3] 03 B2의 매핑 수식은 소유 스펙에 후보값으로 옮겼다.

  | 능력치 | 소유 스펙 · 엔진 파라미터 |
  |---|---|
  | TopSpeed, Acceleration, Agility | 005 FR-01~03 (최고속도, 초기 가속·τ, 횡가속·감속·피벗) |
  | Balance | 005 FR-04 (접촉 속도 손실) · 008 (경합 후 넘어짐 `[미정]`) |
  | Stamina, Recovery | 005 FR-05 (피로 누적률·회복률) |
  | Anticipation, Concentration | 005 FR-06 (인지 지연) · 010 FR-26 (집중 저하) |
  | Strength, Jumping, Heading | 008 FR-22 (공중볼 경합) · 008 FR-40 (태클 경합) |
  | FirstTouch, ShortPass, LongPass, Crossing, Finishing, LongShots, Dribbling, Tackling, Shielding, SetPiece, Penalty | 008 (실행 오차·터치·경합·슈팅) |
  | Decisions, Vision, Composure, OffBall, WorkRate, Aggression, Bravery | 010 (softmax 온도 FR-20, 후보 탐색 FR-02, 평가 노이즈 FR-21, 오프더볼·활동량·공격성 가중치 `[미정]`) |
  | Positioning, Teamwork | 009 FR-37 (슬롯 추종 오차) · FR-25 (국면 전환 보간) · FR-43 (라인 일체성) |
  | Leadership | 010 (팀 사기·지시 전파 `[미정]`) · 030 (이벤트) |
  | Reflexes, Diving, Handling, OneOnOne, CommandArea, Sweeping, Distribution, GKPositioning | 011 FR-70 |
  | 숨김 9개 | 002 FR-60~61 (Consistency·BigMatch) · 027 (InjuryProneness) · 026 (Professionalism·Determination·Ambition·Adaptability·Versatility) · 003·012 (Temperament) |

  `[미정]` 표시 항목은 소유 스펙 플랜에서 수식을 확정해 등록한다.
- FR-21: 매핑 표는 튜닝 레지스트리(001 FR-80)에 등록된다. 매핑 표에 없는 능력치가 있거나, 어떤 엔진 계산에도 쓰이지 않는 능력치가 있으면 자동 검사가 실패한다 (기획서 4.2 원칙).
- FR-22: 매핑 결과(유효 엔진 파라미터 묶음)는 경기 시작 시와 피로 갱신 시 계산해 캐시한다 (research[3] 03 B8 DerivedEngineParams). 경기 중 매 틱 다시 계산하지 않는다.
- FR-23: 운동학 매핑(v_max 범위 등)은 005가 소유한다. research[3] 03 B2(7.0~9.6 m/s)와 research[1] 01 B-9(7.2~9.7 m/s)의 차이는 005 미정에 둔다.

### 포지션
- FR-30: 포지션 종류: GK, CB, FB(좌/우), DM, CM, AM, W(좌/우), ST (research[3] 03 A8 FormationSlot.BasePos, 좌우 구분은 `[제안]`).
- FR-31: 주 포지션 1개 + 부 포지션 최대 2개 (기획서 4.1). 중복·3개 초과는 거부.
- FR-32: 포지션 점수 PosRating[p] = Σ w_{p,a}·attr_a 정규화 (가중치는 역할 KeyAttributes 합집합, 003 제공) (research[3] 03 B4).
- FR-33: 익숙함 Familiarity[p] ∈ [0,1]. 유효 적합도 = PosRating × (0.85 + 0.15·Familiarity) (research[3] 03 B4). 낮은 익숙함이 슬롯 추종 오차(009)와 결정 온도(010 FR-23)를 늘리는 배수는 각 소유 스펙이 정한다. 익숙함 증감 규칙(출전 시 상승, 미출전 시 감쇠)의 수치는 026이 정하고, 002는 값과 경계만 보장한다.

### 성격
- FR-40: 기획서 4.1 성격 특성(프로의식, 야망, 침착성, 리더십, 다혈질)은 별도 값을 새로 만들지 않고 기존 능력치에 대응시킨다 `[제안]`: 프로의식=Professionalism, 야망=Ambition, 다혈질=Temperament(숨김), 침착성=Composure(정신, 공개), 리더십=Leadership(정신, 공개). 성장(026)·이벤트(030)는 이 대응을 통해 읽는다.
- FR-41: 성격 요약 라벨(예: "모범 프로", "다혈질 야심가")을 숨김값 조합으로 만드는 규칙은 `[미정]` (이벤트·UI에서 필요).

### CA / PA
- FR-50: CA = Σ c_a·attr_a (능력치별 비용 c_a, 신체 속도 계열 고비용·Leadership 저비용) (research[3] 03 B4). c_a 값은 `[미정]` (튜닝 등록).
- FR-51: PA는 CA 상한이며 숨김값이다. 성장은 (PA − CA)에 비례한다 (계산은 026).
- FR-52: PA 공개 힌트: 관찰자(내 선수 본인, 스카우트, 감독)별 "알려진 범위"를 가진다. 범위 폭이 좁아지는 규칙(스카우트 리포트 수·스카우트 능력)은 `[미정]`. 실제 PA는 항상 알려진 범위 안에 있어야 한다.

### 경기 시 유효 능력치
- FR-60: 경기 폼 matchForm ~ N(0, σ_c), σ_c = lerp(0.08, 0.02, Consistency) (research[3] 03 B3). 경기마다 선수당 한 번, 컨디션 RNG 스트림(001 FR-30)에서 뽑는다.
- FR-61: 빅매치 보정: 경기 중요도 > 0.8이면 lerp(−0.06, +0.04, BigMatch)를 Composure·Decisions에만 적용 (research[3] 03 B3). 경기 중요도 값은 024·021이 제공.
- FR-62: 유효값 = 기본값 × (1 + matchForm) × fatigueCurve(E/E_max) (research[3] 03 B3). fatigueCurve는 005 FR-36이 제공. 유효값도 [0,100] 클램프.
- FR-63: 아픈 상태로 출전 시 능력치 −5~15% (기획서 4.6.1 가벼운 질병) 같은 외부 보정은 보정 목록으로 받아 순서와 무관하게 같은 결과가 나오게(곱셈, 정렬된 적용) 한다. 보정의 출처는 027.

### 경기 상태 · 직렬화
- FR-70: 경기·훈련 상태: 에너지, 경기 감각(Sharpness), 급성:만성 부하 비율(ACWR) (research[3] 03 B8 PlayerDev). 값의 의미·갱신은 005·026·027, 002는 보관과 범위 보장.
- FR-71: 선수 데이터 전체는 값으로 직렬화·역직렬화되고, 왕복 후 비트 단위로 같다 (형식은 022).

## 경계 · 예외 상황
- 능력치 0과 100, 표시값 경계(내부 0 → 1, 5.0 → 1, 5.01 → 2, 100 → 20), 음수·100 초과 입력(클램프), NaN 입력(거부)
- 약발 0·6 같은 범위 밖 값(거부), 주발과 약발 의미 충돌 없음 확인
- 부 포지션에 주 포지션과 같은 값, 부 포지션 0개, 3개
- GK가 필드 포지션 부 포지션을 가질 때, 필드 선수 GK 능력치(낮지만 존재) — 매핑은 항상 정의돼야 한다
- 경기 폼 극단(±4σ): 유효값 클램프로 0 미만·100 초과 방지
- 피로 0(E=0)일 때 fatigueCurve 값이 0이 되어 모든 능력치 0이 되는 사태 방지 (하한은 005 FR-36)
- 생년월일 2월 29일, 경기일이 생일인 경우의 나이 (001 FR-51)
- PA < CA (데이터 오류 또는 노화 후) — 허용 여부 `[제안]`: PA는 CA 이상으로 보정, 노화 감소는 CA만 줄인다
- 알려진 PA 범위가 실제 PA를 벗어나는 상태 (불변식 위반 → 테스트로 잡음)
- 수만 명 로드 시 id 충돌

## 비기능 요구사항
- 결정론: 유효 능력치·엔진 파라미터 계산은 입력이 같으면 비트 단위로 같다. 보정 적용 순서와 무관.
- 세이브 호환: 능력치 목록이 늘어나도 이전 세이브를 읽을 수 있어야 한다 (새 능력치 기본값 규칙, 022와 합의).
- 메모리: 수만 명 단위 DB를 메모리에 올릴 수 있어야 한다 (기획서 § 6).

## 수용 기준
- AC-01 [로직]: 능력치 목록이 FR-10의 49개(신체 8·기술 12·정신 12·GK 8·숨김 9)와 정확히 일치한다.
- AC-02 [로직]: 표시값 변환: 내부 0, 5.0, 5.01, 50.0, 50.01, 99.99, 100 → 1, 1, 2, 10, 11, 20, 20 (승인된 규칙 기준).
- AC-03 [로직]: −5, 120, NaN 입력은 각각 0, 100, 거부로 처리된다.
- AC-04 [로직]: 매핑 표 검사: 모든 공개·GK·숨김 능력치가 하나 이상의 엔진 파라미터에 연결돼 있고, 연결 없는 능력치를 하나 추가하면 검사가 실패한다.
