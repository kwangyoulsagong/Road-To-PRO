## 배경
경기 엔진은 2026-11-11부터 **혼합 구조**다(CLAUDE.md "경기 엔진" 행, 기획서 5.1.1). 22명 전원은 판단 AI가 매 틱 실행하고, 시나리오는 오픈플레이 공격 공 주변 2~6명과 세트피스 관여 선수 전원에게 "의도"만 준다. 시나리오는 엔진의 두뇌가 아니라 **선택 분포를 가진 연출 사전**이고, 개발 때 전부 만들어 검증·채택하며 빌드된 게임은 골라 쓰기만 한다.

이 스펙은 그 사전의 **원본인 기본 패턴 268개를 카탈로그에서 데이터 파일로 수록**하는 일을 맡는다. 수록은 득점 기여가 큰 순서(생산 우선순위)로 배치를 나눠 진행하고, 배치마다 엔진 결과를 현실 기준표와 구조 건강 지표로 잰다. 기본 패턴에서 약 4만 개 구체 시나리오를 만드는 조합 생성기·필터·태그·저장은 066, 생성 결과의 다양성 검증은 067로 나눴다(2026-11-11 Q7 정리).

2026-11-11 사용자 요구: 시나리오는 한 번 쓰고 끝나는 것이 아니라 **계속 찍어내야** 한다. 카탈로그뿐 아니라 **실제 축구에서 일어난 시나리오**와 **AI가 만들어낸 시나리오**도 라이브러리에 들어와야 하고, 같은 상황에서도 **선수에 따라 시나리오와 그 결과가 달라져야** 한다. 그래서 모든 패턴에 출처 경로를 남기고(FR-06), 배역 슬롯에 능력·성향 선호 조건을 둘 수 있게 하고(FR-26), 분기 확률이 능력치·버릇에 따라 달라지게 기록한다(FR-07). 실경기 추출은 068, LLM 초안은 069, 워크벤치는 053이 맡는다.

## 사용자 시나리오
1. 개발자가 생산 우선순위 1번 배치(코너 루틴)를 수록하고 배치 검증을 돌린다. 리포트에 수록 수, 로딩 오류 0, 1,000경기 시뮬에서 세트피스 득점 비중·코너 비중이 목표표 범위 안인지, 깨짐률·기회주의 종료 비율·시나리오 점유 시간이 시나리오 0개 기준선 대비 어떻게 바뀌었는지 나온다.
2. 개발자가 DEF 패턴 "터치라인 트랩"을 수록하면 런타임 후보 목록에는 들어가지 않고, 수비 형태 프리셋 원천 목록에 "압박 구역·트리거 가중" 항목으로 나타난다.
3. 엔진 판정 로직이 바뀌면 시나리오 회귀 테스트에서 성공률이 크게 변한 패턴 목록이 나온다.

## 요구사항

### 기본 패턴
- FR-01: 카탈로그 3문서(research[0]·[1]·[2])의 기본 패턴 268개를 모두 013 스키마 데이터 파일로 수록한다. 각 패턴: 카탈로그 ID, 한/영 이름, 분류, 트리거, 배역·단계(의도), 핵심 분기, 성공 지표(KPI), 선호 특성, 변주 축, 근거 수치와 출처 등급. 배역 수는 혼합 구조 기준(오픈플레이 공격 2~6명, 세트피스 양 팀 관여 전원)을 따른다(013 재확인).
- FR-02: FN 12개는 공용 분기 테이블, PP 11개는 수식자로 수록한다 (013 FR-05). 이 둘은 조합 생성 대상이 아니다.
- FR-03: 근거 수치(예: 하이 턴오버 경기당 11.5~16.7 [F], 코너 골 2.2~4.1% [S], 50m+ 솔로골 경기당 0.003~0.01 [E])는 패턴 파일에 출처 등급과 함께 남긴다. 등급이 [U]·[M]·[E]인 값은 "튜닝 출발값"으로 표시하고 017의 1,000경기 시뮬로 보정한다. (출처: scenarios.html 요약 "원문 미검증 수치 있음")
- FR-04: 특수 시나리오(부상·화려한 마무리·솔로골·징계 등)는 희소성 게이트 λ·상한을 반드시 가진다. 초기값은 research[2] § 6 빈도 튜닝 표 (예: 50m+ 솔로골 경기당 0.003~0.01 [E], 바이시클킥 골 0.003 [E], 집단 대치 0.05 [E]).
- FR-05: 실존 선수 이름·"누구 스타일" 표현을 패턴 이름·설명·데이터에 넣지 않는다. 역할 이름(메짤라, 트레콸르티스타 등)만 쓴다. 문헌 출처 문장에 나오는 실존 클럽 이름(통계 근거)은 출처 메모에만 남기고 게임 화면에 노출하지 않는다.
- FR-06: 모든 기본 패턴·후보 파일은 출처 경로(`카탈로그` / `실경기 추출` / `엔진 채굴` / `LLM 초안` / `수작성` 중 하나)와 근거(카탈로그 ID / 데이터셋 이름·라이선스 / 채굴 군집 id / 모델 이름·버전·프롬프트 해시)를 가진다. 출처 경로가 없거나 근거가 비어 있는 파일은 로딩 검증 오류다. 수록 리포트는 경로별 패턴 수를 보고한다.
- FR-07: 분기 확률은 고정 가중치 대신 `base + k·(능력치 − 50)`과 버릇 승수로 기록할 수 있다(능력치 내부 0~100). 예: 컷백 분기는 시야, "크로스 머신"은 크로스 분기에 고정 승수. base·k·승수 값은 [미정]이고 017로 보정한다. 결과 확률은 [0, 1]로 자른다. 런타임 해석은 013 재확인 "분기 확률" 항목이 맡는다.
- FR-08: **오픈플레이 수비 패턴(DEF 32)의 용도 재정의** (2026-11-11 혼합 구조, 보고서 권고): DEF 패턴은 오픈플레이 런타임 시나리오로 로드하지 않는다. 각 패턴 파일은 `용도` 필드를 하나 이상 가진다.
  - `형태 프리셋 원천`: 팀 단위 수비 행동(압박 트랩 D-PR, 라인 D-LN, 로우블록 D-BX-01 등). 블록 높이·라인 높이·압박 구역·압박 트리거 가중을 뽑아 009 수비 형태 프리셋 데이터의 근거로 쓴다(009 재확인).
  - `판단 AI 검증 픽스처`: 개인 수비 행동(1v1 D-DU, 러너 추적 D-TR 등). 010 판단 AI의 수비 행동(압박·커버·마크 넘기기·길목 차단)이 그 상황에서 기대 행동을 고르는지 확인하는 고정 상황으로 쓴다.
  - `세트피스 수비`: 정지 상황에서 쓸 수 있는 수비 배치(크로스 존·맨 마킹, 세컨볼 등). SP 시나리오의 수비 배역으로 연결해 양 팀 관여 전원 시나리오에 쓴다.
  - TRN 16 중 공 상실 측(역압박 등) 패턴도 오픈플레이 수비이므로 같은 용도 규칙을 따른다 [제안].
- FR-09: 패턴 스키마 대조: 013 스키마가 CMDragons·Setplay 계열 필드(적용 조건 OR-of-AND, 종료 4종 success·complete·abort·fail, 단계·전체 timeout/abort 시간, 좌우 반전 가능 플래그, 좌표 기준)를 표현하는지 수록 전에 대조하고, 빠진 필드는 013 재확인 항목으로 올린다. 수록 파일은 이 필드를 모두 채운다.

### 생산 우선순위와 배치
- FR-60: 수록은 득점 기여 순 생산 우선순위를 따른다 (출처: reports/축구 엔진 시나리오 방식.md § D, 기획서 5.1.1):

  | 순서 | 대상 | 이유(근거) |
  |---|---|---|
  | 0 | 시나리오 0개 기준선: 판단 AI(010) + 팀 형태(009)만으로 1,000경기 | 득점·슈팅·xG 분포를 먼저 본다 (013 AC-10 재사용) |
  | 1 | 코너 루틴(S-CK): 니어 플릭·파 포스트·숏·스폿 앞 컷백 × 존/대인 수비 | 세트피스 득점의 약 59%, 멈춘 상태라 양 팀 시나리오가 쉽다 |
  | 2 | 측면 크로스·컷백 | 크로스 약 2% vs 스폿 앞 5.8%, 결과 확률 차이가 큰 대표 패턴 |
  | 3 | 하이 턴오버 → 빠른 슈팅(PR) | 경기당 11.5회, 14.9% 슈팅 |
  | 4 | 역습(CT) 2v1·3v2·스루볼 | 득점 약 10~15%(추정), 스루볼 슈팅 전환 약 30% |
  | 5 | 기타 세트피스: 프리킥·롱스로·페널티·킥오프·골킥 | 롱스로 경기당 3.44회 |
  | 6 | 빌드업 → 하프스페이스 침투·3자 패스·오버래핑 | 오픈플레이 득점의 본체, 변주 축이 가장 많다 |
  | 7 | 롱테일(하이라이트 다양성용, 특수 73 포함) | 상위 패턴을 다듬은 뒤 |

  DEF 패턴(FR-08)과 FN·PP는 관련 배치(DEF 프리셋 원천은 0~1, 세트피스 수비는 1·5, FN은 2, PP는 6)와 함께 수록한다 [제안].
- FR-61: 배치마다 수록 목록(카탈로그 ID)을 미리 정하고, 배치 완료 조건은 그 목록 전부의 로딩 오류 0 · 회귀 기록 생성 · FR-70~72 보고다. 다음 배치는 앞 배치 완료 후에 시작한다.
- FR-62: 수록 리포트는 배치별·분류별 수록 수와 268 대비 진행률을 보고한다. 268 전체 수록은 마지막 배치 완료 시점의 조건이다.

### 회귀
- FR-40: 기본 패턴마다 고정 초기 배치 회귀 테스트: 성공률·평균 소요 시간을 기록하고, 이전 기록 대비 성공률 ±10%p 이상 또는 소요 시간 ±20% 이상 변하면 "변화"로 보고한다 [제안]. (출처: 기획서 5.1.1 테스트, GRF Academy 방식)
- FR-41: 회귀 기록 갱신은 승인 명령으로만 한다.

### 배역 선호 조건
- FR-26: 배역 슬롯은 선택 필드로 능력·성향 선호 조건(예: 침투 배역은 오프더볼 능력 상위, 크로스 배역은 크로스 성향)을 가질 수 있다. 런타임은 이 조건을 캐스팅 점수에 넣는다(013 재확인 FR-30a). 조건 필드가 없는 슬롯은 캐스팅 점수만으로 고른다. (2026-11-11 Q4 정리: 추천 B 채택)

## 경계 · 예외 상황
- 배치 목록에 있는 카탈로그 ID가 카탈로그에 없음 → 수록 리포트 오류, 배치 미완료.
- 같은 카탈로그 ID 파일 2개 → 로딩 오류.
- DEF 패턴에 `용도` 필드가 없음 → 로딩 오류. `용도`가 `형태 프리셋 원천`뿐인 패턴이 오픈플레이 런타임 후보로 들어가면 오류.
- 분기 확률식 결과가 0 미만·1 초과 → [0, 1]로 자르고 리포트에 경고(식 계수를 고치라는 신호).
- 시나리오 0개 기준선(배치 0)이 010 미구현으로 측정 불가 → 배치 0을 "보류"로 두고 배치 1 측정은 기준선 없이 보고하되 FR-71 비교 칸을 "기준선 없음"으로 표시한다.
- 출처 등급이 없는 수치 → 검증 오류.
- 좌우 반전이 비대칭 패턴(예: 왼발 전용 컷인)에 선언 → 규칙으로 금지(066 생성 단계에서도 거부).

## 비기능 요구사항
- 결정론: 수록 파일 로딩·검증 결과는 파일 순서와 무관하게 같다 (013 AC-15 규칙).
- 재현성: 배치 리포트에 수록 목록 해시·엔진 버전·시드·시뮬 경기 수를 남긴다.
- 데이터 크기: 기본 패턴 파일은 텍스트 기반으로 저장소에 커밋한다 (LFS 불필요).
