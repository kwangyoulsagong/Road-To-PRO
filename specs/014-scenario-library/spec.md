# 014 — 시나리오 라이브러리 · 조합 생성기

상태: 초안
브랜치: feat/014-scenario-library
기획 출처: docs/index.html § 기획서 5.1.1(시나리오 4만 개 규모로 키우는 방법, 출시 목표 라이브러리, 테스트) / docs/scenarios.html § 요약 카드, § 구조 1·4, research[0] § 1~3(공격 택소노미·카탈로그 113개·문헌 수치), research[1] § 0~5(수비·전환·세트피스·GK 82개, 공통 변형축, 선택 빈도), research[2] § 1~6(특수·하이라이트 73개, 빈도 튜닝 표)

## 배경
4만 개 시나리오를 손으로 쓰면 개당 10분만 잡아도 약 6,600시간이다. 그래서 사람은 기본 패턴만 쓰고, 변주 축을 곱해 구체 시나리오를 자동으로 만든다. 만든 조합은 헤드리스 시뮬로 수백 번씩 돌려 성공률이 비정상인 것을 버리고, 남은 것에 성공률·기대 xG·소요 시간 태그를 붙여 런타임(013)이 고를 때 쓴다. 이 스펙은 기본 패턴 작성 형식, 카탈로그 전체 수록, 변주 축, 생성기, 필터, 태그, 다양성 검증을 다룬다.

## 범위
- 포함:
  - 기본 패턴 카탈로그 수록: 공격 113 (BU 18 · PR 23 · FT 38 · FN 12 · CT 11 · PP 11), 수비·전환·세트피스·GK 82 (DEF 32 · TRN 16 · SP 26 · GKP 8), 특수·하이라이트 73 (부상 15 · 화려한 마무리 28 · 오프사이드 10 · 징계·드라마 20 · 솔로골). 카탈로그 ID 유지. (출처: scenarios.html 요약)
  - 기본 패턴 작성 규칙 (013 스키마 사용, 변주 축 선언, 출처 등급 [F]/[S]/[U]/[V]/[M]/[E]/[D] 표기 유지)
  - 변주 축 정의와 조합 생성기 (시작 구역, 상대 포메이션, 마무리 분기, 배역 변형, 좌우 반전 + 수비 문서의 능력 밴드·게임 상태·압박 강도·상대 대응 정책)
  - 헤드리스 필터: 조합마다 수백 회 시뮬 → 성공률 0% 또는 100% 제거
  - 태그: 성공률, 기대 xG, 평균 소요 시간, 시작 수, 표본 수
  - 다양성 검증: Decroos 등(KDD 2018) 공격 패턴 군집 방식을 시뮬 출력에 적용해 실제 리그 분포와 비교
  - 시나리오별 회귀 테스트 (초기 배치 고정, 성공률·평균 소요 시간)
  - 라이브러리 버전 관리 (생성 입력·시드·엔진 버전 → 같은 출력)
- 제외:
  - 스키마·로딩·선택·실행 런타임 (013)
  - 대량 시뮬 실행 인프라와 리그 통계 비교 (017이 제공, 여기서는 그 위에서 필터·태그만)
  - 부상 판정 공식 (027·008의 물리 훅), 징계 판정 (012)
  - 인게임 시나리오 에디터 (049)

## 사용자 시나리오
1. 개발자가 새 기본 패턴 "하프스페이스 언더랩 → 컷백" 하나를 데이터 파일로 추가하고 생성 명령을 돌린다. 몇 분 뒤 이 패턴에서 나온 구체 시나리오 수, 필터로 버려진 수와 이유, 남은 조합의 성공률·xG 분포가 리포트로 나온다.
2. 다양성 리포트에서 생성된 공격의 상위 10개 군집이 슈팅의 80%를 차지한다. 실제 리그(50~60%)보다 쏠림이 심하다는 경고가 뜨고, 개발자는 쏠린 패턴의 사전 가중치를 낮춘다.
3. 엔진 판정 로직이 바뀌면 시나리오 회귀 테스트에서 성공률이 크게 변한 패턴 목록이 나온다.

## 요구사항

### 기본 패턴
- FR-01: 카탈로그 3문서(research[0]·[1]·[2])의 기본 패턴 268개를 모두 013 스키마 데이터 파일로 수록한다. 각 패턴: 카탈로그 ID, 한/영 이름, 분류, 트리거, 배역(3~5명)·단계, 핵심 분기, 성공 지표(KPI), 선호 특성, 변주 축, 근거 수치와 출처 등급.
- FR-02: FN 12개는 공용 분기 테이블, PP 11개는 수식자로 수록한다 (013 FR-05). 이 둘은 조합 생성 대상이 아니다.
- FR-03: 근거 수치(예: 하이 턴오버 경기당 11.5~16.7 [F], 코너 골 2.2~4.1% [S], 50m+ 솔로골 경기당 0.003~0.01 [E])는 패턴 파일에 출처 등급과 함께 남긴다. 등급이 [U]·[M]·[E]인 값은 "튜닝 출발값"으로 표시하고 017의 1,000경기 시뮬로 보정한다. (출처: scenarios.html 요약 "원문 미검증 수치 있음")
- FR-04: 특수 시나리오(부상·화려한 마무리·솔로골·징계 등)는 희소성 게이트 λ·상한을 반드시 가진다. 초기값은 research[2] § 6 빈도 튜닝 표 (예: 50m+ 솔로골 경기당 0.003~0.01 [E], 바이시클킥 골 0.003 [E], 집단 대치 0.05 [E]).
- FR-05: 실존 선수 이름·"누구 스타일" 표현을 패턴 이름·설명·데이터에 넣지 않는다. 역할 이름(메짤라, 트레콸르티스타 등)만 쓴다. 문헌 출처 문장에 나오는 실존 클럽 이름(통계 근거)은 출처 메모에만 남기고 게임 화면에 노출하지 않는다.

### 변주 축과 생성
- FR-10: 변주 축 (기획서 5.1.1, scenarios.html § 구조 4, research[1] § 0):

  | 축 | 값 수 (평균) | 비고 |
  |---|---|---|
  | 시작 구역 | 3~4 | 패턴이 허용하는 구역 중 유효한 것 |
  | 상대 포메이션 | 4~5 | 4백 / 3백 / 5백 계열 (4-4-2, 4-3-3, 3-5-2, 5-4-1 등) |
  | 마무리 분기 | 4~5 | 컷백 / 크로스 / 슈팅 / 스루패스 → FN 테이블 |
  | 배역 변형 | 3 | 누가 침투하나 |
  | 좌우 반전 | 2 | 대칭 패턴만 |
  | 능력 밴드 · 게임 상태 · 압박 강도 · 상대 대응 정책 | 패턴별 선택 | 수비 문서 공통 변형축 |

- FR-11: 패턴마다 적용할 축과 허용 값을 선언한다. 생성기는 선언된 축의 곱집합에서 **무효 조합을 규칙으로 먼저 거른다** (예: 좌측 전용 패턴의 우측 구역, 3백 전용 트리거에 4백 상대). 규칙 위반 조합은 시뮬하지 않는다.
- FR-12: 구체 시나리오 id는 `기본 id + 축 값`으로 사람이 읽을 수 있고 안정적이다 (같은 입력 → 같은 id). 축 값 순서가 바뀌어도 id는 같다.
- FR-13: 후보 수십만 개 → 필터 → 최종 약 4만 개가 목표 (scenarios.html § 구조 4). 최종 수가 목표의 ±25%를 벗어나면 생성 리포트에 경고 [제안].

### 필터와 태그
- FR-20: 남은 후보 조합마다 초기 배치를 그 조합 조건에 맞게 고정하고, 시드를 바꿔 N회 헤드리스 시뮬한다 [제안: N = 200, 기획서 "수백 번"]. 실행은 017 대량 시뮬 인프라를 쓴다.
- FR-21: 성공률(조합의 KPI 달성 비율)이 0% 또는 100%인 조합은 버린다 (기획서 5.1.1). 표본 수가 부족해 신뢰구간이 넓은 조합은 "보류"로 두고 표본을 늘린다 [제안: 95% 신뢰구간 폭 > 0.2이면 추가 실행].
- FR-22: 남은 조합에 태그를 붙인다: 성공률, 기대 xG(시나리오 시작 후 슈팅까지 xG 합의 평균), 평균 소요 시간(초), 표본 수, 생성 시 엔진 버전·시드. 런타임(013)은 이 태그를 선택 점수에 쓴다.
- FR-23: 버린 조합은 이유(0%, 100%, 규칙 위반, 실행 오류·예외)와 함께 리포트에 남긴다. 실행 오류가 난 조합이 1개라도 있으면 생성 실패로 판정한다 (버그 은폐 금지).

### 다양성 검증
- FR-30: 생성 라이브러리로 돌린 리그 시뮬 출력에 Decroos 방식을 적용한다: 페이즈 분할(10초 이상 정지 또는 소유 전환 시 새 페이즈, 이벤트 3개 이상인 페이즈만), DTW 거리 + complete-linkage 계층 군집, 기본 100개 군집. (출처: research[0] § 3, PDF 직접 확인)
- FR-31: 비교 지표: 상위 10개 군집의 슈팅 집중도. 실제 기준 50.4%~59.2%, 최상위 1개 군집 9.4%~16.5% (research[0] § 3, EPL 2015/16 세 팀). 시뮬이 이 범위 밖이면 경고 [제안: 상위 10개 집중도 40~70% 허용].
- FR-32: 골 구성 지표도 함께 본다: 완료된 패스 포함 골 64.5%, 크로스 포함 골 약 25%, 박스 안 골 84%, 박스 안 골 중 컷백존 어시스트 29% (research[0] § 3). 허용 범위는 017과 같이 정한다.
- FR-33: 다양성 리포트는 군집별 대표 궤적 그림(2D 탑뷰 경로)을 포함한다.

### 회귀
- FR-40: 기본 패턴마다 고정 초기 배치 회귀 테스트: 성공률·평균 소요 시간을 기록하고, 이전 기록 대비 성공률 ±10%p 이상 또는 소요 시간 ±20% 이상 변하면 "변화"로 보고한다 [제안]. (출처: 기획서 5.1.1 테스트, GRF Academy 방식)
- FR-41: 회귀 기록 갱신은 승인 명령으로만 한다.

### 버전
- FR-50: 같은 기본 패턴 파일 + 같은 생성 시드 + 같은 엔진 버전 → 같은 최종 라이브러리(파일 내용 해시 동일).
- FR-51: 라이브러리에는 생성 입력 해시·엔진 버전이 기록된다. 엔진 판정 로직이 바뀌면 태그가 낡았음을 감지해 재생성을 요구한다.
- FR-52: 053 연동 (053 FR-20~25 요청): 053 워크벤치의 배치 검증은 이 스펙의 탈락 기준(FR-21)과 태그(FR-22)를 그대로 호출한다. 기준이 두 곳에 따로 있으면 안 된다. 태그에는 폴백률·폴백 종료 사유 분포·다음 시나리오 연결 비율·역습 허용률(013 집계)을 추가한다 `[제안]`.
- FR-53: 군집 재사용과 좌우 반전 정규화 (053 FR-43 요청): FR-30의 페이즈 분할·DTW 거리·complete-linkage 군집은 053 채굴이 같은 구현을 재사용한다. 군집 전에 궤적을 좌우 반전 정규화(공격 방향 고정 + 볼 쪽 측면을 한쪽으로 맞춤)해, 좌우 반전 쌍이 같은 군집에 들어가게 한다.

## 경계 · 예외 상황
- 변주 축이 0개인 패턴 → 구체 시나리오 1개(원본)로 생성.
- 축 곱이 상한을 넘는 패턴 [제안: 패턴당 2,000개] → 생성 전 경고, 축 값을 줄이라고 보고 (폭발 방지).
- 모든 조합이 필터에 걸린 패턴 → 그 패턴은 0개로 남고 리포트에 "전멸"로 표시. 원본 패턴이 엔진에서 깨진 신호이므로 경고.
- 성공률 정확히 0 또는 1이 아니지만 극단(예: 0.5%, 99.5%) → 버리지 않는다. 기준은 정확히 0%·100%(표본 기준).
- 생성 도중 중단 → 다시 실행하면 처음부터 같은 결과 (부분 결과가 섞이지 않게).
- 같은 구체 id가 두 경로로 생성 (축 표현 중복) → 오류.
- 좌우 반전이 비대칭 패턴(예: 왼발 전용 컷인)에 적용 → 규칙으로 금지.
- 출처 등급이 없는 수치 → 검증 오류.

## 비기능 요구사항
- 결정론: 생성·필터·태그는 시드 고정이고, 병렬로 돌려도 결과가 같다 (조합 단위 병렬, 조합 안은 단일 스레드, 결과 정렬 후 저장).
- 재현성: 생성 리포트에 입력 해시·시드·엔진 버전·실행 시간을 남긴다.
- 데이터 크기: 최종 라이브러리 파일은 저장소에 커밋 가능한 크기 [제안: ≤ 20 MB, 텍스트 기반이면 LFS 불필요].

## 수용 기준
- AC-01 [로직]: 기본 패턴 268개(공격 113 · 수비/전환/세트피스/GK 82 · 특수 73) 파일이 모두 013 로더로 오류 없이 로드되고, 분류별 개수가 카탈로그 표와 정확히 같다. (확정 (2026-11-02 사용자 결정))
