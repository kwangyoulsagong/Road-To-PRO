# 053 — 시나리오 워크벤치 · 채굴 파이프라인

## 배경
경기 엔진의 재미와 "축구처럼 읽히는 하이라이트"는 시나리오 라이브러리의 양과 질에 달려 있다. 기본 패턴 268개와 조합 생성(014)은 출발점일 뿐이고, 엔진을 튜닝할수록 시나리오도 계속 손봐야 하며, 반복이 보이면 새 패턴이 필요하다. 그래서 시나리오를 **한 번 쓰고 끝내는 것이 아니라 계속 생산하는 파이프라인**을 둔다. 쓰고 → 바로 검증하고 → 눈으로 보고 → 대량으로 돌려 태그를 붙이고 → 시뮬 로그에서 새 후보를 캐내고 → 사람이 채택하는 순환이다. 이 순환이 짧을수록 경기 엔진이 빨리 좋아진다.

## 범위
- 포함:
  - 시나리오 작성 즉시 검증 (013 스키마·로딩 검증 재사용 + 작성 단계 전용 정적 검사)
  - 고정 초기 배치 미리보기: 2D(040 디버그 오버레이)와 3D(041 하이라이트 플레이어 위에서 054 로코모션 적용) 재생, 단계별 캡처
  - 배치 검증: 한 시나리오(또는 그 변주 묶음)를 헤드리스로 수백 회 돌려 태그·탈락 판정·리그 통계 영향 확인
  - 채굴: 대량 시뮬 로그의 Utility 폴백 구간에서 반복적으로 좋은 결과를 낸 움직임 묶음을 군집으로 찾아 **시나리오 후보 초안**으로 만들기
  - 다양성·반복 감지 지표 (경기 안, 시즌 안, 하이라이트 안)
  - 생산 기록: 버전·변경 이력, 후보 채택/폐기 기록, 라이브러리 커버리지 대시보드(아티팩트 발행)
- 제외:
  - 시나리오 런타임(트리거·선택·배역·실행·폴백) → 013
  - 기본 패턴 268개 수록과 조합 생성기·0%/100% 필터·다양성 검증 알고리즘 본체 → 014 (053은 같은 기준을 호출한다)
  - 대량 시뮬 인프라와 리그 통계 목표 범위 → 017
  - 2D 뷰·디버그 오버레이 자체 → 040, 3D 재생 자체 → 041
  - 머신러닝 학습(신경망·강화학습·모방학습). 채굴은 군집·빈도 통계만 쓴다 (FR-45)
  - 사용자 모드로 받은 시나리오의 배포 검수 → 049 (053의 검증 단계를 재사용할 수는 있다)
  - 일반 플레이어용 인게임 에디터 UI → 049. 053은 개발용 도구다

## 사용자 시나리오
1. 개발자가 "하프스페이스 언더래핑 → 컷백" 패턴 파일을 쓰고 저장하면 1초 안에 검증 결과가 뜬다: 배역 4명 OK, 트리거 구역이 피치 밖이라 도달 불가 1건, 분기 `cb_steps_up`에 폴백 지점 없음 1건.
2. 고치고 나서 미리보기를 누르면 고정 배치에서 2D 탑뷰로 재생되고, 배역 선수가 강조되고 단계마다 캡처가 남는다. 같은 장면을 3D 하이라이트로도 본다.
3. 배치 검증을 돌리면 몇 분 뒤 성공률 31%, 기대 xG 0.09, 평균 9.2초, 폴백률 44% 태그가 붙고, 이 패턴을 넣은 리그 시뮬에서 평균 득점·크로스 비율이 017 범위 안이라 "채택 가능"이 된다.
4. 주말에 1만 경기 채굴을 돌려 두면, 월요일에 "시나리오가 없는데 자주 xT를 크게 올린 움직임 묶음" 상위 20개가 대표 궤적 그림과 함께 후보 초안으로 와 있다. 그중 3개를 채택해 이름을 붙이고, 2개는 기존 패턴의 변주로 합치고, 나머지는 사유를 적어 폐기한다.
5. 회사에서 휴대폰으로 커버리지 대시보드를 연다. 카테고리별 268 목표 대비 진행, 이번 주 채택·폐기 수, 반복 경고가 뜬 시나리오 목록이 보인다.

## 요구사항

### 작성과 즉시 검증
- FR-01: 시나리오 정의 형식은 013 스키마(FR-01~05) 그대로다. 053은 별도 형식을 만들지 않는다.
- FR-02: 저장할 때마다(또는 명령 한 번으로) 013 로딩 검증(FR-04)을 돌리고, 아래 **작성 단계 정적 검사**를 추가로 돈다. 결과는 파일·줄·필드와 함께 한 번에 모두 보인다.
  - 배역 수: 공격 3~5명, 수비 2~4명 (013 FR-30·34). 필수 배역 0명이면 오류.
  - 트리거 도달 가능성: 구역·국면·역할·공간 조건이 서로 모순되지 않는가(예: 상대 박스 안 + 빌드업 국면, 피치 밖 좌표, GK 역할 캐리어의 하프라인 너머 조건). 모순이면 오류.
  - 폴백 지점: 모든 단계에 실패 분기가 있거나 기본 폴백(Utility)으로 떨어지는가. 실패 시 갈 곳이 없는 단계가 있으면 오류.
  - 분기 그래프: 도달할 수 없는 단계(죽은 단계), 끝나지 않는 경로(종료·폴백·체이닝 없는 순환)가 있으면 오류.
  - 시간 상한: 단계·전체 시간 상한(013 FR-41)을 넘을 수밖에 없는 단계 구성이면 경고.
  - 이름·설명: 실존 인물 이름·"누구 스타일" 표현 금지(014 FR-05), 15세 등급 금칙어(051) 검사.
  - 카탈로그 연결: id가 카탈로그 ID 규칙을 따르는가, 신규 패턴이면 카탈로그 미등록 경고.
- FR-03: 정적 검사는 시뮬을 돌리지 않는다 (빠르게 반복하기 위해). 시뮬이 필요한 판정은 FR-20 배치 검증으로 넘긴다.

### 미리보기
- FR-10: 시나리오마다 **고정 초기 배치 픽스처**를 하나 이상 둔다: 22명 위치·속도, 공 상태, 국면, 양 팀 포메이션, 선수 능력치 세트(기본: 리그 평균 [제안]), 시드. 픽스처는 시나리오와 함께 버전 관리된다.
- FR-11: 미리보기는 픽스처에서 그 시나리오를 **강제 선택**해 실행한다 (트리거·게이트·선택 점수를 건너뛴다). 강제 실행 여부는 로그에 표시해 정상 실행과 섞이지 않게 한다.
- FR-12: 2D 미리보기: 040 탑뷰 + 디버그 오버레이(시나리오 id, 배역 강조, 단계 번호, 분기 결과, 피치 컨트롤·xT 레이어 선택).
- FR-13: 3D 미리보기: 같은 실행 기록을 041 하이라이트 플레이어로 재생하고, 선수 움직임은 054 로코모션·공 접촉 동기화를 그대로 쓴다 (2026-11-02 정리) (1x/1.5x, 리플레이 0.5x). 기록 주기는 30Hz(사용자 결정), 물리는 100Hz.
- FR-14: 단계마다 캡처를 남긴다 (2D·3D 각각). 캡처는 000 디바이스팜 형식으로 저장해 기준 이미지 비교가 가능하다.
- FR-15: 같은 픽스처·같은 시드면 미리보기 결과(이벤트 로그 해시와 캡처)가 매번 같다.
- FR-16: 시드를 바꿔 N회 미리보기 [제안: 기본 5회]해 결과가 갈리는 모습(성공 경로·실패 경로)을 나란히 볼 수 있다.

### 배치 검증
- FR-20: 한 시나리오(기본 패턴 1개 또는 지정한 변주 묶음)를 헤드리스로 돌린다. 기본 표본 [제안: 변주 조합당 500회], 시드는 결정론적으로 파생한다. 실행은 017 인프라를 쓴다.
- FR-21: 태그를 계산한다: 성공률(시나리오 KPI 달성 비율), 기대 xG, 평균·p90 소요 시간, **폴백률**(실패 분기 또는 깨짐으로 Utility에 넘어간 비율과 종료 사유 분포), 체이닝 비율, 상대 역습 허용률. 태그 정의는 014 FR-22와 같고 폴백률·사유 분포·역습 허용률을 더한다.
- FR-22: 탈락 판정은 014 FR-21 기준을 그대로 호출한다 (성공률 0%·100% 탈락, 신뢰구간 폭이 넓으면 보류 후 표본 추가). 053이 별도 기준을 두지 않는다.
- FR-23: **리그 영향 회귀**: 후보 시나리오를 라이브러리에 넣은 상태와 뺀 상태로 같은 시드의 리그 시뮬 [제안: 380경기(1시즌)]을 돌려 017 핵심 지표(평균 득점 2.5~3.0, 슈팅 수, 점유율 분포, 패스 성공률, 득점 원천 가중치 오픈플레이 0.60·세트피스 0.25·페널티 0.08·역습 0.07)를 비교한다. 지표가 017 범위를 벗어나게 만들면 "채택 불가", 범위 안이지만 변화가 [제안: 지표별 ±5%] 이상이면 "주의"로 표시한다.
- FR-24: 배치 검증 중 예외·무한 루프·시간 초과가 1건이라도 나면 그 시나리오 검증은 실패다 (014 FR-23과 같은 원칙, 버그 은폐 금지). 실패한 시드를 재현 정보로 남긴다.
- FR-25: 배치 검증 결과는 시나리오 파일 버전·엔진 버전과 함께 저장된다. 엔진 버전이 바뀌면 낡은 결과로 표시한다 (014 FR-51과 같은 규칙).

### 채굴 (후보 초안 뽑기)
- FR-40: 입력: 017 대량 시뮬의 SimEvent 로그 [제안: 기본 1만 경기]. 대상 구간: **시나리오 배역이 없는 공 소유 구간**(Utility 폴백 구간, 013 FR-43 종료 이후 포함).
- FR-41: 구간 분할: 014 FR-30과 같은 페이즈 규칙(10초 이상 정지 또는 소유 전환 시 새 페이즈, 이벤트 3개 이상 페이즈만)을 쓴다.
- FR-42: "좋은 결과" 기준: 페이즈 시작 대비 xT 증가량(007)이 상위 [제안: 10%] 이거나 슈팅·빅찬스(xG ≥ 0.15, 018 기준)로 끝난 페이즈. 기준은 데이터로 바꿀 수 있다.
- FR-43: 군집: 좋은 결과 페이즈를 공과 공 주변 선수(3~5명) 궤적으로 표현해 014 FR-30과 같은 거리·군집 방식(Decroos 2018: DTW 거리 + complete-linkage 계층 군집)으로 묶는다. 좌우 반전은 같은 군집으로 본다.
- FR-44: 후보 초안 생성: 군집마다 크기(빈도), 평균 xT 증가, 슈팅 전환율, 대표 궤적(2D 그림), 참여 역할 분포, 시작 구역·국면을 계산하고, 013 스키마의 **초안 파일**(트리거 추정 + 배역 역할 + 단계 동사 열 + 미정 분기)을 만든다. 초안은 `상태: 후보`로 표시되고 런타임 라이브러리에 자동으로 들어가지 않는다.
- FR-45: **ML 경계**: 채굴은 군집·빈도·평균 같은 기술 통계만 쓴다. 모델을 학습해 런타임에 쓰지 않고, 런타임 행동은 언제나 사람이 채택한 시나리오 데이터와 Utility 규칙으로만 결정된다 (CLAUDE.md "ML 아님"). 군집 결과는 사람이 읽고 고치는 초안일 뿐이다.
- FR-46: 기존 시나리오와 중복 판정: 후보 군집 대표 궤적과 기존 패턴(및 변주) 대표 궤적의 거리가 [제안: 임계값] 이하면 "기존 X의 변주 후보"로 표시하고 새 패턴으로 올리지 않는다.
- FR-47: 후보 목록은 점수 순으로 정렬한다: `빈도 × 평균 xT 증가 × 슈팅 전환율` [제안]. 상위 [제안: 20개]만 검토 큐에 올린다.
- FR-48: 채굴 입력은 **우리 엔진의 시뮬 로그만** 기본으로 한다. 공개 추적·이벤트 데이터를 입력으로 쓰는 것은 라이선스 확인 전까지 [미정]이며, 상용 게임의 데이터·리플레이·DB는 어떤 경우에도 쓰지 않는다 (01-legal).

### 검토와 채택
- FR-50: 검토 큐의 후보마다 사람이 결정한다: **채택**(새 기본 패턴으로, 이름·분류·KPI·분기 작성 후 FR-02~25 통과 필수), **변주로 합침**(기존 패턴의 변주 축 값으로), **폐기**(사유 필수: 비현실적, 기존과 중복, 엔진 버그 산물, 기타).
- FR-51: "엔진 버그 산물"로 폐기된 후보는 버그 리포트 항목(재현 시드·경기 시각)을 함께 남긴다. 채굴은 엔진 버그 발견 수단이기도 하다.
- FR-52: 채택된 시나리오는 FR-20~25 배치 검증과 리그 영향 회귀를 통과해야 라이브러리에 들어간다. 통과 전에는 실험 플래그로만 켤 수 있다.

### 다양성·반복 감지
- FR-60: 경기 안 반복: 한 경기에서 같은 기본 패턴(변주 무관) 시작 횟수 분포. 상한 [제안: 같은 팀 기준 경기당 4회]를 넘는 경기 비율이 [제안: 5%] 이상이면 경고. 013 FR-22 최근 사용 감쇠가 제대로 작동하는지 확인하는 지표다.
- FR-61: 시즌 안 집중도: 시나리오별 시작 비율의 지니계수·상위 10개 비율. 014 FR-31 군집 슈팅 집중도와 함께 보고한다.
- FR-62: 하이라이트 반복: 한 경기 하이라이트(018 선정 결과) 안에 같은 기본 패턴이 [제안: 3회] 이상 나오는 경기 비율, 연속 5경기 하이라이트에서 같은 패턴 비율. 플레이어가 "또 이 장면"이라고 느끼는 것을 잡기 위한 지표다.
- FR-63: 미사용·과사용: 1시즌 동안 한 번도 시작되지 않은 시나리오(트리거가 너무 좁음)와 시작 비율 상위 1% 시나리오(너무 넓음)를 목록으로 낸다.

### 생산 기록과 대시보드
- FR-70: 모든 시나리오 파일 변경은 버전과 변경 이력(무엇을·왜·배치 검증 결과 링크)을 가진다. 채택·변주 합침·폐기 결정도 같은 이력에 남는다.
- FR-71: 커버리지 대시보드: 카테고리별(공격 113 · 수비/전환/세트피스/GK 82 · 특수 73, 합계 268 — 사용자 결정 기준) 수록·검증 통과·태그 최신 여부, 최종 구체 시나리오 수(목표 약 4만, 014 FR-13), 이번 주기 채택/폐기/변주 수, 반복 경고 목록, 배치 검증 실패 목록, 엔진 버전 대비 낡은 태그 수.
- FR-72: 대시보드와 배치 검증·채굴 리포트는 000 리포트처럼 HTML로 만들어 아티팩트로 발행한다 (같은 리포트는 같은 링크로 갱신). 휴대폰 폭(400px)에서 읽힌다.
- FR-73: 한 명령으로 각 단계를 돌린다: 검증만 / 미리보기 / 배치 검증 / 채굴 / 대시보드 갱신. 각 단계는 독립적으로 다시 돌릴 수 있다.

## 경계 · 예외 상황
- 시나리오 파일이 문법 오류로 아예 읽히지 않음 → 정적 검사 단계에서 파일·줄 오류, 다른 파일 검사는 계속.
- 배역 조건을 만족하는 선수가 픽스처에 없음 → 미리보기 실패(사유: 배역 미충족), 픽스처를 고치라고 안내. 강제 실행으로 부분 배역 실행은 하지 않는다 (013 FR-31과 같음).
- 미리보기 중 시나리오가 첫 단계에서 바로 깨짐 → 정상 결과로 기록(깨짐 사유 표시). 시드 N회 중 100% 첫 단계 깨짐이면 경고.
- 배치 검증 표본 중 일부만 예외 → 전체 실패 (FR-24). 실패 시드 목록 보존.
- 성공률이 0%·100%에 매우 가깝지만 같지 않음(예: 0.2%) → 014 신뢰구간 규칙으로 보류·추가 표본.
- 리그 영향 회귀에서 지표 변화가 시드 잡음 수준 → 같은 시드 쌍 비교(넣은/뺀 상태 동일 시드)로 잡음을 줄이고, 변화가 신뢰구간 안이면 "영향 없음".
- 채굴 대상 구간 0개(모든 소유가 시나리오로 처리됨) → 오류가 아니라 "채굴 대상 없음" 리포트.
- 채굴 군집 수가 페이즈 수보다 많게 설정됨 → 군집 수를 페이즈 수로 낮추고 경고.
- 아주 큰 군집 하나가 대부분을 차지(의미 없는 "그냥 패스 돌리기") → 좋은 결과 기준(FR-42)을 통과한 페이즈만 군집하므로 줄어들지만, 그래도 생기면 "일반 구간" 표시로 검토 큐에서 내린다.
- 후보 초안이 기존 시나리오와 거의 같음 → FR-46 변주 후보로 처리, 새 패턴 생성 금지.
- 채굴 중 엔진 버전이 바뀜(로그가 서로 다른 버전 섞임) → 섞인 입력은 거부. 한 채굴은 한 엔진 버전 로그만 쓴다.
- 좌우 반전 쌍이 서로 다른 군집으로 갈라짐 → 반전 정규화 후 군집 (FR-43). 반전 쌍 분리 0건이 AC.
- 같은 시나리오 파일을 두 사람이(또는 두 작업이) 동시에 수정 → 저장 시 버전 충돌로 거부, 덮어쓰기 금지.
- 이름 필드에 실존 인물 이름·금칙어 → 정적 검사 오류, 채택 불가.
- 대시보드 이미지 합계가 아티팩트 한도를 넘음 → 000 FR-72 규칙(썸네일 압축)을 따른다.
- 엔진 판정 로직이 바뀌어 모든 태그가 낡음 → 전체 재검증 큐를 만들고, 그동안 대시보드에 "낡은 태그 N개" 경고.

## 비기능 요구사항
- 결정론: 같은 시나리오 파일·픽스처·시드·엔진 버전 → 미리보기 이벤트 로그 해시, 배치 검증 태그, 채굴 후보 목록(순서 포함)이 모두 같다. 병렬 작업자 수와 무관하다.
- 격리: 미리보기·배치 검증·채굴은 사용자 세이브와 출시 라이브러리를 건드리지 않는다. 채택(FR-50)만 라이브러리를 바꾼다.
- 추적성: 라이브러리에 들어간 모든 시나리오는 "누가 언제 무엇을 근거로 채택했는가"(배치 검증 결과, 리그 영향 회귀, 채굴 출처 군집)를 이력에서 찾을 수 있다.
- 반복 속도: 작성 → 정적 검사 → 2D 미리보기 한 바퀴가 1분 안에 끝나야 시나리오를 "계속 뽑아낼" 수 있다 (성능 예산 참고).

## 수용 기준
- AC-01 [로직]: 배역 6명인 공격 시나리오, 필수 배역 0명, 피치 밖 트리거 구역, 박스 안 + 빌드업 국면 모순, 실패 분기 없는 단계, 도달 불가 단계, 종료 없는 순환을 하나씩 넣은 파일 7개를 정적 검사하면 각각 파일·줄·필드가 포함된 오류가 나고, 정상 파일 1개는 오류 0이다.
- AC-02 [로직]: 정적 검사는 시뮬을 한 틱도 돌리지 않는다 (시뮬 호출 횟수 0). 시나리오 1개 검사가 1초 안에 끝난다.
- AC-03 [로직]: 이름 필드에 테스트용 금지 이름·금칙어를 넣으면 정적 검사 오류이고, 그 시나리오는 채택(FR-50) 명령이 거부된다.
- AC-04 [E2E]: 기본 패턴 1개(`wing_solo_run_cutback`, 기획서 5.1.1 예시)의 2D 미리보기를 smoke 프로필로 돌리면 단계별 캡처가 나오고, 캡처에 시나리오 id·배역 강조·단계 번호가 보인다 (요소 존재 단언). 같은 실행의 3D 미리보기 캡처도 단계 수만큼 나온다.
- AC-05 [결정론]: 같은 픽스처·시드로 미리보기 2회 → 이벤트 로그 해시가 같고 2D 캡처 차이가 0이다. 시드만 바꾸면 해시가 달라진다.
- AC-06 [로직]: 미리보기 강제 실행 로그에는 강제 표시가 있고, 이 로그는 배치 검증·채굴 입력에서 자동으로 제외된다 (입력 포함 0건).
- AC-07 [로직]: 배치 검증 결과에 성공률·기대 xG·평균·p90 소요 시간·폴백률·종료 사유 분포·체이닝 비율·역습 허용률 태그가 모두 있다 (빠진 태그 0).
- AC-08 [로직]: 항상 성공하도록 만든 인공 시나리오와 항상 실패하는 인공 시나리오는 014 기준으로 탈락하고, 탈락 이유가 리포트에 보인다. 053과 014가 같은 시나리오에 같은 판정을 낸다.
- AC-09 [로직]: 배치 검증 500회 중 1회에 예외를 주입하면 검증 전체가 실패이고, 그 시드로 단독 재실행하면 같은 예외가 재현된다.
- AC-10 [로직]: 득점을 크게 늘리도록 만든 인공 시나리오를 넣으면 리그 영향 회귀에서 평균 득점이 2.5~3.0 범위를 벗어나 "채택 불가"가 되고, 영향이 없는 인공 시나리오는 "영향 없음"이다.
- AC-11 [로직]: 인공 로그에 같은 움직임 묶음(언더래핑 → 컷백, 좋은 결과)을 좌우 반전 포함 200회 심어 두면 채굴이 그 묶음을 하나의 군집으로 찾아 후보 상위 3위 안에 올리고, 좌우 반전 쌍이 다른 군집으로 갈라지는 경우가 0건이다.
- AC-12 [로직]: 채굴 후보 초안 파일은 013 로더로 읽히고(문법 오류 0), `상태: 후보`이며, 런타임 라이브러리 로드 목록에 포함되지 않는다 (포함 0건).
- AC-13 [로직]: 기존 패턴과 같은 움직임을 심은 인공 로그에서 채굴 후보는 새 패턴이 아니라 "기존 패턴의 변주 후보"로 표시된다.
- AC-14 [로직]: 엔진 버전이 서로 다른 로그를 섞어 채굴을 시작하면 거부되고 이유가 보인다.
- AC-15 [로직]: 채굴 파이프라인 어디에도 학습된 모델 파라미터를 런타임 라이브러리로 내보내는 출력이 없다. 런타임이 로드하는 파일은 사람이 채택한 시나리오 파일과 014 태그뿐이다 (로드 파일 목록 검사).
- AC-16 [로직]: 폐기 결정은 사유 없이 저장되지 않는다. "엔진 버그 산물" 폐기에는 재현 시드·경기 시각이 함께 저장된다.
- AC-17 [로직]: 감쇠를 끈 설정으로 1시즌을 돌리면 경기 안 반복 경고(FR-60)가 뜨고, 감쇠를 켜면 경고 비율이 기준 아래로 내려간다.
- AC-18 [로직]: 트리거를 일부러 아주 좁게 만든 시나리오는 1시즌 미사용 목록에, 아주 넓게 만든 시나리오는 과사용 목록에 나온다.
- AC-19 [로직]: 하이라이트 반복 지표가 1시즌 결과에서 계산되고, 같은 패턴만 하이라이트에 나오게 만든 인공 설정에서 경고가 뜬다.
- AC-20 [E2E]: 커버리지 대시보드가 카테고리별 수록 수(공격 113 · 수비/전환/세트피스/GK 82 · 특수 73 = 268 목표 대비), 검증 통과 수, 낡은 태그 수, 이번 주기 채택/폐기 수를 보여 주고, 아티팩트로 발행되며 400px 폭에서 가로 스크롤 없이 읽힌다 (표·그림 제외).
- AC-21 [결정론]: 같은 1만 경기 로그(또는 축소 500경기 픽스처)로 채굴 2회 → 후보 목록과 순서가 같다. 병렬 작업자 수를 1과 8로 바꿔도 같다.
- AC-22 [성능]: 성능 예산 표의 정적 검사·미리보기 시작·배치 검증·채굴 항목이 기준 프로필에서 예산 안이다. 작성 → 정적 검사 → 2D 미리보기 한 바퀴가 1분 안이다.
