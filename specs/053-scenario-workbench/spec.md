## 배경
경기 엔진의 재미와 "축구처럼 읽히는 하이라이트"는 시나리오 라이브러리의 양과 질에 달려 있다. 기본 패턴 268개(014)와 조합 생성(066)은 출발점일 뿐이고, 엔진을 튜닝할수록 시나리오도 계속 손봐야 하며, 반복이 보이면 새 패턴이 필요하다. 그래서 시나리오를 **한 번 쓰고 끝내는 것이 아니라 계속 생산하는 파이프라인**을 둔다. 쓰고 → 바로 검증하고 → 눈으로 보고 → 대량으로 돌려 태그를 붙이고 → 시뮬 로그에서 새 후보를 캐내고 → 사람이 채택하는 순환이다. 이 순환이 짧을수록 경기 엔진이 빨리 좋아진다.

2026-11-11 사용자 요구: 시나리오를 **계속 찍어내야** 한다. **실제 축구에서 일어난 시나리오**와 **AI가 만들어낸 시나리오**를 만들어야 하고, 그래야 각 선수가 **자기 능력치·성격·플레이 스타일에 맞게 자율적으로** 다르게 행동하며 시나리오도 **선수에 따라** 달라진다. 그래서 후보의 입구를 넷으로 둔다: 카탈로그 수작성(014), 엔진 시뮬 로그 채굴(FR-40~, 017 이후 단계), 공개 실경기 데이터 추출(068), LLM 초안(069). 어느 입구로 들어와도 이 스펙의 같은 정적 검사·배치 검증·사람 채택을 거친다. 생산량은 268 진행과 커버리지 빈칸으로 관리한다(FR-74~77).

2026-11-11 혼합 구조 전환(CLAUDE.md "경기 엔진" 행): 시나리오는 판단 AI(010)에 의도만 주는 층이다. 오픈플레이 공격 배역은 공 주변 2~6명, 세트피스는 양 팀 관여 전원, 오픈플레이 수비 시나리오는 없다. 시나리오가 깨지면 "폴백"이 아니라 의도가 해제되고 판단 AI가 계속 실행한다(기회주의 종료 · 구조 붕괴, 013 재확인). 이 스펙의 검사·태그·채굴 대상도 이 기준을 따른다. 2026-11-11 Q7 정리(추천 B 채택)로 053은 **워크벤치 본체**(이전 053c)만 남기고, 실경기 추출은 068, LLM 초안은 069로 옮겼다. 엔진 채굴(이전 053d)은 017 이후 단계로 이 스펙 후속 절에 남긴다.

## 범위
- 포함:
  - 시나리오 작성 즉시 검증 (013 스키마·로딩 검증 재사용 + 작성 단계 전용 정적 검사)
  - 고정 초기 배치 미리보기: 3D(041 하이라이트 플레이어 위에서 054 로코모션 적용) 재생과 정적 2D 궤적 그림, 단계별 캡처. 2D 탑뷰(040 디버그 오버레이) 재생은 040 구현 후 (FR-12)
  - 배치 검증: 한 시나리오(또는 그 변주 묶음)를 헤드리스로 수백 회 돌려 태그·탈락 판정·리그 통계 영향 확인
  - [017 이후 단계] 엔진 채굴: 대량 시뮬 로그의 의도 없는 공 소유 구간(판단 AI만 실행한 구간)에서 반복적으로 좋은 결과를 낸 움직임 묶음을 군집으로 찾아 **시나리오 후보 초안**으로 만들기 (FR-40~48, 후속 절)
  - 다양성·반복 감지 지표 (경기 안, 시즌 안, 하이라이트 안)
  - 생산 기록: 버전·변경 이력, 후보 채택/폐기 기록, 라이브러리 커버리지 대시보드(아티팩트 발행)
  - 생산 진행(268 도달)·커버리지 행렬·경로별 지표 (FR-74~77)
  - 068·069가 만든 후보를 받는 공통 입구(정적 검사·배치 검증·검토 큐)
- 제외:
  - 시나리오 런타임(트리거·선택·캐스팅·의도·의도 해제) → 013, 판단 AI → 010
  - 기본 패턴 268개 수록 → 014, 조합 생성기·0%/100%·퇴화 필터·태그 → 066, 다양성 검증 알고리즘 본체 → 067 (053은 같은 기준을 호출한다)
  - 공개 실경기 데이터 추출 → 068, LLM 초안 생성 → 069
  - 대량 시뮬 인프라와 리그 통계 목표 범위 → 017
  - 2D 뷰·디버그 오버레이 자체 → 040 (미구현 동안 2D는 정적 궤적 그림으로 대신한다), 3D 재생 자체 → 041
  - 머신러닝 학습(신경망·강화학습·모방학습). 채굴은 군집·빈도 통계만 쓴다 (FR-45). LLM을 오프라인 초안 작성 도구로 쓰는 것은 학습이 아니며 069에서 다룬다
  - 사용자 모드로 받은 시나리오의 배포 검수 → 049 (053의 검증 단계를 재사용할 수는 있다)
  - 일반 플레이어용 인게임 에디터 UI → 049. 053은 개발용 도구다

## 사용자 시나리오
1. 개발자가 "하프스페이스 언더래핑 → 컷백" 패턴 파일을 쓰고 저장하면 1초 안에 검증 결과가 뜬다: 배역 4명 OK, 트리거 구역이 피치 밖이라 도달 불가 1건, 분기 `cb_steps_up`에 의도 해제 지점 없음 1건.
2. 고치고 나서 미리보기를 누르면 고정 배치에서 2D 탑뷰로 재생되고, 배역 선수가 강조되고 단계마다 캡처가 남는다. 같은 장면을 3D 하이라이트로도 본다.
3. 배치 검증을 돌리면 몇 분 뒤 성공률 31%, 기대 xG 0.09, 평균 9.2초, 깨짐률 44%(기회주의 종료 12% 포함) 태그가 붙고, 이 패턴을 넣은 리그 시뮬에서 평균 득점·크로스 비율이 017 범위 안이라 "채택 가능"이 된다.
4. (017 이후) 주말에 1만 경기 채굴을 돌려 두면, 월요일에 "시나리오가 없는데 자주 xT를 크게 올린 움직임 묶음" 상위 20개가 대표 궤적 그림과 함께 후보 초안으로 와 있다. 그중 3개를 채택해 이름을 붙이고, 2개는 기존 패턴의 변주로 합치고, 나머지는 사유를 적어 폐기한다.
5. 회사에서 휴대폰으로 커버리지 대시보드를 연다. 카테고리별 268 도달 진행, 이번 주 채택·폐기 수, 반복 경고가 뜬 시나리오 목록이 보인다.

## 요구사항

### 작성과 즉시 검증
- FR-01: 시나리오 정의 형식은 013 스키마(FR-01~05) 그대로다. 053은 별도 형식을 만들지 않는다.
- FR-02: 저장할 때마다(또는 명령 한 번으로) 013 로딩 검증(FR-04)을 돌리고, 아래 **작성 단계 정적 검사**를 추가로 돈다. 결과는 파일·줄·필드와 함께 한 번에 모두 보인다.
  - 배역 수 (혼합 구조, 013 재확인): 오픈플레이 공격 2~6명, 세트피스는 양 팀 관여 선수 전원. 오픈플레이 수비 배역(상대 배역 포함)이 있으면 오류. 필수 배역 0명이면 오류. DEF 패턴은 `용도` 필드(014 FR-08) 검사.
  - 트리거 도달 가능성: 구역·국면·역할·공간 조건이 서로 모순되지 않는가(예: 상대 박스 안 + 빌드업 국면, 피치 밖 좌표, GK 역할 캐리어의 하프라인 너머 조건). 모순이면 오류.
  - 의도 해제 지점: 모든 단계에 실패 분기가 있거나 의도 해제(판단 AI 기본 실행)로 끝나는가. 실패 시 갈 곳이 없는 단계가 있으면 오류.
  - 분기 그래프: 도달할 수 없는 단계(죽은 단계), 끝나지 않는 경로(종료·의도 해제·체이닝 없는 순환)가 있으면 오류. 분기 확률식(`base + k·(능력치 − 50)`, 014 FR-07)이 능력치 0~100 전 구간에서 [0, 1] 밖으로 나가면 경고.
  - 시간 상한: 단계·전체 시간 상한(013 FR-41)을 넘을 수밖에 없는 단계 구성이면 경고.
  - 이름·설명: 실존 인물 이름·"누구 스타일" 표현 금지(014 FR-05), 15세 등급 금칙어(051) 검사.
  - 카탈로그 연결: id가 카탈로그 ID 규칙을 따르는가, 신규 패턴이면 카탈로그 미등록 경고.
- FR-03: 정적 검사는 시뮬을 돌리지 않는다 (빠르게 반복하기 위해). 시뮬이 필요한 판정은 FR-20 배치 검증으로 넘긴다.

### 미리보기
- FR-10: 시나리오마다 **고정 초기 배치 픽스처**를 하나 이상 둔다: 22명 위치·속도, 공 상태, 국면, 양 팀 포메이션, 선수 능력치 세트(상·중·하 3밴드 [제안], 066 FR-24 밴드와 같은 경계), 시드. 픽스처는 시나리오와 함께 버전 관리된다.
- FR-11: 미리보기는 픽스처에서 그 시나리오를 **강제 선택**해 실행한다 (트리거·게이트·선택 점수를 건너뛴다). 강제 실행 여부는 로그에 표시해 정상 실행과 섞이지 않게 한다.
- FR-12: 2D 미리보기: 040 탑뷰 + 디버그 오버레이(시나리오 id, 배역 강조, 단계 번호, 분기 결과, 피치 컨트롤·xT 레이어 선택). 040이 구현되기 전에는 FR-13 3D 미리보기와 **정적 2D 궤적 그림**(실행 기록에서 그린 탑뷰 이미지: 시나리오 id, 배역별 궤적·강조, 단계 번호 표기)으로 대신하고, 040 연결 때 탑뷰 재생을 켜서 재확인한다.
- FR-13: 3D 미리보기: 같은 실행 기록을 041 하이라이트 플레이어로 재생하고, 선수 움직임은 054 로코모션·공 접촉 동기화를 그대로 쓴다 (2026-11-02 정리) (1x/1.5x, 리플레이 0.5x). 기록 주기는 30Hz(사용자 결정), 물리는 100Hz.
- FR-14: 단계마다 캡처를 남긴다 (2D·3D 각각). 캡처는 000 디바이스팜 형식으로 저장해 기준 이미지 비교가 가능하다.
- FR-15: 같은 픽스처·같은 시드면 미리보기 결과(이벤트 로그 해시와 캡처)가 매번 같다.
- FR-16: 시드를 바꿔 N회 미리보기 [제안: 기본 5회]해 결과가 갈리는 모습(성공 경로·실패 경로)을 나란히 볼 수 있다.

### 배치 검증
- FR-20: 한 시나리오(기본 패턴 1개 또는 지정한 변주 묶음)를 헤드리스로 돌린다. 기본 표본은 066 FR-20을 따른다(053이 따로 정하지 않는다). 시드는 결정론적으로 파생한다. 실행은 017 인프라를 쓴다.
- FR-21: 태그를 계산한다: 성공률(시나리오 KPI 달성 비율), 기대 xG, 평균·p90 소요 시간, **결과 4종**(success·complete·abort·fail) 비율과 **깨짐률**(abort·fail 비율, 종료 사유 분포: 인터셉트·태클·트리거 소멸·타임아웃·기회주의), 기회주의 종료 비율, 체이닝 비율, 상대 역습 허용률, 상대 블록·능력 밴드별 조건부 값. 태그 정의는 066 FR-30·24·31·52와 같다.
- FR-22: 탈락 판정은 066 FR-21·22 기준을 그대로 호출한다 (성공률 0%·100% 탈락, 퇴화 5종 탈락, 신뢰구간 폭이 넓으면 보류 후 표본 추가). 053이 별도 기준을 두지 않는다.
- FR-23: **리그 영향 회귀**: 후보 시나리오를 라이브러리에 넣은 상태와 뺀 상태로 같은 시드의 리그 시뮬 [제안: 380경기(1시즌)]을 돌려 017 핵심 지표(평균 득점 2.5~3.0, 슈팅 수, 점유율 분포, 패스 성공률, 득점 원천 가중치 오픈플레이 0.60·세트피스 0.25·페널티 0.08·역습 0.07)를 비교한다. 지표가 017 범위를 벗어나게 만들면 "채택 불가", 범위 안이지만 변화가 [제안: 지표별 ±5%] 이상이면 "주의"로 표시한다.
- FR-24: 배치 검증 중 예외·무한 루프·시간 초과가 1건이라도 나면 그 시나리오 검증은 실패다 (066 FR-23과 같은 원칙, 버그 은폐 금지). 실패한 시드를 재현 정보로 남긴다.
- FR-25: 배치 검증 결과는 시나리오 파일 버전·엔진 버전과 함께 저장된다. 엔진 버전이 바뀌면 낡은 결과로 표시한다 (066 FR-51과 같은 규칙).

### 엔진 채굴 — 후속 단계 (017 이후)
> 2026-11-11 Q7 정리: 엔진 채굴(이전 053d)은 별도 번호 없이 이 스펙의 후속 단계로 둔다. 017 대량 시뮬과 010 판단 AI가 구현된 뒤 구현하며, 그전에는 이 소절과 관련 AC(AC-11~15, AC-21)를 "보류"로 표시한다.
- FR-40: 입력: 017 대량 시뮬의 SimEvent 로그 [제안: 기본 1만 경기]. 대상 구간: **시나리오 의도가 걸리지 않은 공 소유 구간**(판단 AI만 실행한 구간, 의도 해제 이후 포함).
- FR-41: 구간 분할: 067 FR-30과 같은 페이즈 규칙(10초 이상 정지 또는 소유 전환 시 새 페이즈, 이벤트 3개 이상 페이즈만)을 쓴다.
- FR-42: "좋은 결과" 기준: 페이즈 시작 대비 xT 증가량(007)이 상위 [제안: 10%] 이거나 슈팅·빅찬스(xG ≥ 0.15, 018 기준)로 끝난 페이즈. 기준은 데이터로 바꿀 수 있다.
- FR-43: 군집: 좋은 결과 페이즈를 공과 공 주변 선수(2~6명) 궤적으로 표현해 067 FR-30·34와 같은 거리·군집 방식(Decroos 2018: DTW 거리 + complete-linkage 계층 군집)으로 묶는다. 좌우 반전은 같은 군집으로 본다.
- FR-44: 후보 초안 생성: 군집마다 크기(빈도), 평균 xT 증가, 슈팅 전환율, 대표 궤적(2D 그림), 참여 역할 분포, 시작 구역·국면을 계산하고, 013 스키마의 **초안 파일**(트리거 추정 + 배역 역할 + 단계 동사 열 + 미정 분기)을 만든다. 초안은 `상태: 후보`로 표시되고 런타임 라이브러리에 자동으로 들어가지 않는다.
- FR-45: **ML 경계**: 채굴은 군집·빈도·평균 같은 기술 통계만 쓴다. 모델을 학습해 런타임에 쓰지 않고, 런타임 행동은 언제나 사람이 채택한 시나리오 데이터와 판단 AI(Utility) 규칙으로만 결정된다 (CLAUDE.md "ML 아님", 런타임 LLM 없음). 군집 결과는 사람이 읽고 고치는 초안일 뿐이다. 생성 모델(LLM)을 오프라인 초안 작성 도구로 쓰는 것(069, 2026-11-11 Q2 정리)도 이 경계 안에 둔다: 런타임·빌드는 LLM을 호출하지 않고, LLM 출력은 사람이 채택한 시나리오 파일로만 런타임에 닿는다.
- FR-46: 기존 시나리오와 중복 판정: 후보 군집 대표 궤적과 기존 패턴(및 변주) 대표 궤적의 거리가 [제안: 임계값] 이하면 "기존 X의 변주 후보"로 표시하고 새 패턴으로 올리지 않는다.
- FR-47: 후보 목록은 점수 순으로 정렬한다: `빈도 × 평균 xT 증가 × 슈팅 전환율` [제안]. 상위 [제안: 20개]만 검토 큐에 올린다.
- FR-48: 채굴(FR-40~47) 입력은 **우리 엔진의 시뮬 로그만**이다. 공개 실경기 데이터는 별도 경로(068)로만 들어온다. 상용 게임의 데이터·리플레이·DB는 어떤 경우에도 쓰지 않는다 (01-legal).

### 검토와 채택
- FR-50: 검토 큐의 후보마다 사람이 결정한다: **채택**(새 기본 패턴으로, 이름·분류·KPI·분기 작성 후 FR-02~25 통과 필수), **변주로 합침**(기존 패턴의 변주 축 값으로), **폐기**(사유 필수: 비현실적, 기존과 중복, 엔진 버그 산물, 기타).
- FR-51: "엔진 버그 산물"로 폐기된 후보는 버그 리포트 항목(재현 시드·경기 시각)을 함께 남긴다. 채굴은 엔진 버그 발견 수단이기도 하다.
- FR-52: 채택된 시나리오는 FR-20~25 배치 검증과 리그 영향 회귀를 통과해야 라이브러리에 들어간다. 통과 전에는 실험 플래그로만 켤 수 있다.

### 다양성·반복 감지
- FR-60: 경기 안 반복: 한 경기에서 같은 기본 패턴(변주 무관) 시작 횟수 분포. 상한 [제안: 같은 팀 기준 경기당 4회]를 넘는 경기 비율이 [제안: 5%] 이상이면 경고. 013 FR-22 최근 사용 감쇠가 제대로 작동하는지 확인하는 지표다.
- FR-61: 시즌 안 집중도: 시나리오별 시작 비율의 지니계수·상위 10개 비율. 067 FR-31 군집 슈팅 집중도와 함께 보고한다.
- FR-62: 하이라이트 반복: 한 경기 하이라이트(018 선정 결과) 안에 같은 기본 패턴이 [제안: 3회] 이상 나오는 경기 비율, 연속 5경기 하이라이트에서 같은 패턴 비율. 플레이어가 "또 이 장면"이라고 느끼는 것을 잡기 위한 지표다.
- FR-63: 미사용·과사용: 1시즌 동안 한 번도 시작되지 않은 시나리오(트리거가 너무 좁음)와 시작 비율 상위 1% 시나리오(너무 넓음)를 목록으로 낸다.

### 생산 목표와 지표
- FR-74: 생산 목표: 주당 채택 [미정]개, 스펙(배치)당 채택 [미정]개 (기획서에 근거 없음, 2026-11-11 Q6 정리: 수치는 [미정] 유지). 대시보드는 목표 대신 **268 도달 진행**(카테고리별·014 생산 우선순위 배치별 수록·검증 통과 수, 최근 주기 채택 속도, 그 속도로 계산한 268 도달 예상일)을 보여 준다. 목표 수치가 정해지면 목표 대비 실적을 더한다. 이 스펙 완료 시점에는 실제 기본 패턴 [제안: 10개]를 작성 → 검증 → 미리보기 → 배치 검증 → 채택까지 처음부터 끝까지 통과시킨 기록이 있어야 한다.
- FR-75: 커버리지 행렬: 역할 27개 × 국면(009 FSM) × 구역(18존) 칸마다 시나리오 수를 세고, 0인 칸을 "빈 곳" 목록으로 낸다. 빈 곳 목록은 다음 생산 대상(수작성·069 LLM 초안 요청)을 정하는 입력이다. 오픈플레이 수비 국면 칸은 시나리오 대상이 아니므로 빈 곳 집계에서 뺀다.
- FR-76: 출처 경로별(카탈로그 · 실경기 추출 · 엔진 채굴 · LLM 초안 · 수작성, 014 FR-06) 후보·채택·폐기·변주 합침 수와 폐기 사유 분포를 낸다.
- FR-77: 반복 감지(FR-60~63) 경고가 뜬 패턴은 "변주 보강 대상"으로 생산 큐에 자동으로 올라간다.

### 068·069 후보 입구
- FR-78: 068(실경기 추출)과 069(LLM 초안)가 만든 `상태: 후보` 파일은 이 스펙의 정적 검사(FR-02) → 배치 검증(FR-20~25) → 리그 영향 회귀(FR-23) → 검토 큐(FR-50)를 엔진 채굴 후보와 똑같이 거친다. 출처 경로(014 FR-06)별 통과율을 대시보드(FR-76)에 낸다. 자동 채택은 없다.

## 경계 · 예외 상황
- 시나리오 파일이 문법 오류로 아예 읽히지 않음 → 정적 검사 단계에서 파일·줄 오류, 다른 파일 검사는 계속.
- 배역 조건을 만족하는 선수가 픽스처에 없음 → 미리보기 실패(사유: 배역 미충족), 픽스처를 고치라고 안내. 강제 실행으로 부분 배역 실행은 하지 않는다 (013 FR-31과 같음).
- 미리보기 중 시나리오가 첫 단계에서 바로 깨짐(구조 붕괴 또는 기회주의 종료) → 정상 결과로 기록(종료 사유 표시). 시드 N회 중 100% 첫 단계 깨짐이면 경고.
- 배치 검증 표본 중 일부만 예외 → 전체 실패 (FR-24). 실패 시드 목록 보존.
- 성공률이 0%·100%에 매우 가깝지만 같지 않음(예: 0.2%) → 066 신뢰구간 규칙으로 보류·추가 표본.
- 리그 영향 회귀에서 지표 변화가 시드 잡음 수준 → 같은 시드 쌍 비교(넣은/뺀 상태 동일 시드)로 잡음을 줄이고, 변화가 신뢰구간 안이면 "영향 없음".
- 채굴 대상 구간 0개(모든 소유에 의도가 걸림) → 오류가 아니라 "채굴 대상 없음" 리포트.
- 채굴 군집 수가 페이즈 수보다 많게 설정됨 → 군집 수를 페이즈 수로 낮추고 경고.
- 아주 큰 군집 하나가 대부분을 차지(의미 없는 "그냥 패스 돌리기") → 좋은 결과 기준(FR-42)을 통과한 페이즈만 군집하므로 줄어들지만, 그래도 생기면 "일반 구간" 표시로 검토 큐에서 내린다.
- 후보 초안이 기존 시나리오와 거의 같음 → FR-46 변주 후보로 처리, 새 패턴 생성 금지.
- 채굴 중 엔진 버전이 바뀜(로그가 서로 다른 버전 섞임) → 섞인 입력은 거부. 한 채굴은 한 엔진 버전 로그만 쓴다.
- 좌우 반전 쌍이 서로 다른 군집으로 갈라짐 → 반전 정규화 후 군집 (FR-43). 반전 쌍 분리 0건이 AC.
- 같은 시나리오 파일을 두 사람이(또는 두 작업이) 동시에 수정 → 저장 시 버전 충돌로 거부, 덮어쓰기 금지.
- 이름 필드에 실존 인물 이름·금칙어 → 정적 검사 오류, 채택 불가.
- 대시보드 이미지 합계가 아티팩트 한도를 넘음 → 000 FR-72 규칙(썸네일 압축)을 따른다.
- 엔진 판정 로직이 바뀌어 모든 태그가 낡음 → 전체 재검증 큐를 만들고, 그동안 대시보드에 "낡은 태그 N개" 경고.

## 비기능 요구사항
- 결정론: 같은 시나리오 파일·픽스처·시드·엔진 버전 → 미리보기 이벤트 로그 해시, 배치 검증 태그, 채굴 후보 목록(순서 포함)이 모두 같다. 병렬 작업자 수와 무관하다.
- 격리: 미리보기·배치 검증·채굴은 사용자 세이브와 출시 라이브러리를 건드리지 않는다. 채택(FR-50)만 라이브러리를 바꾼다.
- 추적성: 라이브러리에 들어간 모든 시나리오는 "누가 언제 무엇을 근거로 채택했는가"(배치 검증 결과, 리그 영향 회귀, 채굴 출처 군집)를 이력에서 찾을 수 있다.
- 반복 속도: 작성 → 정적 검사 → 2D 미리보기 한 바퀴가 1분 안에 끝나야 시나리오를 "계속 뽑아낼" 수 있다 (성능 예산 참고).

## 수용 기준
- AC-01 [로직]: 배역 7명인 오픈플레이 공격 시나리오, 필수 배역 0명, 피치 밖 트리거 구역, 박스 안 + 빌드업 국면 모순, 실패 분기 없는 단계, 도달 불가 단계, 종료 없는 순환, 오픈플레이 수비 배역을 하나씩 넣은 파일 8개를 정적 검사하면 각각 파일·줄·필드가 포함된 오류가 나고, 정상 파일 1개는 오류 0이다.
- AC-02 [로직]: 정적 검사는 시뮬을 한 틱도 돌리지 않는다 (시뮬 호출 횟수 0). 시나리오 1개 검사가 1초 안에 끝난다.
