## 배경
2026-11-11 사용자 요구: 라이브러리에는 **실제 축구에서 일어난 시나리오**도 들어와야 한다. 실제 축구는 소수 패턴이 다수 상황을 차지하는 롱테일이라, 실경기 데이터는 "어떤 패턴이 얼마나 자주, 얼마나 효과적인가"를 알려 준다. 다만 입구는 라이선스가 정한다. 이 스펙은 **라이선스가 명확한 공개 데이터만** 받아, 로드 즉시 익명화하고, 여러 경기의 군집 대표에서만 시나리오 후보 초안을 만든다. 원본 궤적을 복제하지 않고 최종 템플릿은 우리가 저작한다. 이것이 실명 A안과 01-legal("살짝 바꾼 이름 금지")을 지키는 가장 단순한 선이다.

2026-11-11 사용자 결정(053 Q1 → 추천 B 채택): Wyscout 공개 데이터셋(CC BY 4.0)과 SkillCorner Open Data(LICENSE 파일 직접 확인 후)만 쓴다. StatsBomb Open Data는 제외, Metrica는 보류. 이 스펙은 053에서 Q7 분할로 나온 이전 "053a" 범위이며 개발용 오프라인 도구다. 만든 후보는 053 워크벤치의 같은 검증·채택 경로를 거친다.

## 범위
- 포함:
  - 허용 데이터셋 목록과 라이선스 기록, 기록 없는 데이터셋 거부
  - 로드 즉시 익명화(실명·원천 id 제거, 역할·슬롯 라벨로 치환)
  - 점유 단위 분할, 방향 통일·좌우 반전·105×68 표준화 정규화
  - 원형 액션 기호화와 군집(067 군집 구현 재사용), 코너는 루틴(역할별 런 조합) 방식
  - 여러 경기 군집 대표에서만 후보 초안 생성(단일 장면 복제 금지)
  - 실경기 패턴 빈도 순위 산출 — 067 패턴 빈도 분포 비교와 014 검증 목표표의 기준
  - 출처 표기(크레딧) 자동 수집
- 제외:
  - 정적 검사·배치 검증·리그 영향 회귀·검토 큐·대시보드 (053)
  - 군집 알고리즘 본체 (067), 엔진 시뮬 로그 채굴 (053 후속 단계)
  - 상용 게임 데이터·리플레이·DB, 유료 계약 데이터 (영구 금지)
  - 머신러닝 학습. 군집·빈도·평균 같은 기술 통계만 쓴다

## 사용자 시나리오
1. 개발자가 Wyscout 공개 이벤트 데이터를 지정해 추출을 돌린다. 라이선스 기록(이름 · URL · CC BY 4.0 · 확인일 · 표기 문구)이 있으니 진행되고, 로드 직후 선수·팀·경기 식별자가 사라진다. 결과로 "측면 크로스 → 스폿 앞 컷백" 군집이 23경기에서 모여 후보 초안 1개가 되고, 053 검토 큐에 들어간다.
2. 개발자가 실수로 StatsBomb Open Data 경로를 지정하면 추출 명령이 이유와 함께 거부된다.
3. 개발자가 실경기 빈도 순위 표를 열어 엔진 빈도 순위(067)와 나란히 본다.

## 요구사항
- FR-01: 입력은 부록 A 표에서 "허용"으로 판정된 공개 데이터셋만이다 (2026-11-11 사용자 결정: Wyscout 공개 데이터셋 — 이벤트 CC BY 4.0, 메타데이터 CC0 / SkillCorner Open Data — 저장소 LICENSE 파일을 직접 확인해 기록한 뒤에만). 데이터셋마다 라이선스 기록(이름 · URL · 라이선스 · 확인일 · 출처 표기 문구)이 있어야 하고, 기록이 없으면 추출 명령이 거부한다.
- FR-02: **StatsBomb Open Data는 이용약관이 상업적 이용과 파생 분석의 상업적 이용을 금지하므로 사용하지 않는다.** Metrica 샘플은 서면 허가 전까지 보류한다. 입력으로 지정하면 거부한다 (부록 A).
- FR-03: 익명화: 원천의 선수명 · 선수 id · 팀명 · 팀 id · 대회 · 경기 id · 날짜 · 등번호는 로드 단계에서 버린다. 남기는 값은 역할(27개 역할 체계로 매핑) · 슬롯 라벨(P1..P22) · 상대 좌표 · 시간 · 이벤트 종류뿐이다. 원천 경기 식별자는 출시물에 들어가지 않는 별도 추적 기록에만 해시로 남긴다 (01-legal 실명 금지).
- FR-04: 정규화: 점유 단위로 분할하고(067 FR-30 페이즈 규칙), 공격 방향 통일 · 좌우 반전 정규화(067 FR-34) · 105×68 m 표준 좌표로 바꾼다. 이벤트 데이터는 공 경로와 관여 선수의 위치·역할만, 트래킹 데이터는 공 주변 2~6명의 오프더볼 궤적까지 쓴다.
- FR-05: 기호화와 군집: 액션 시작 위치·방향 분포로 원형 액션(SoccerMix 방식)을 만들어 단계 어휘로 쓰고, 궤적은 DTW 거리 또는 편집 거리로 군집한다(067 구현 재사용). 코너는 공격수 런 조합을 역할별로 특징화한 루틴 방식(Shaw & Gopaladesikan)으로 묶는다. (출처: reports/축구 엔진 시나리오 방식.md § 실경기 데이터…)
- FR-06: **재현 금지**: 실경기 한 장면이 그대로 시나리오가 되지 않는다. 후보는 서로 다른 경기 [제안: 5경기 이상]의 페이즈가 모인 군집 대표에서만 만든다 (특정 실존 골·선수를 알아볼 수 있는 단일 장면 복제 방지). 후보 초안의 궤적은 군집 대표(평균·중앙값)이고 원본 좌표 열을 담지 않는다.
- FR-07: 후보 초안은 013 스키마의 `상태: 후보` 파일(트리거 추정 + 배역 역할 + 단계 의도 열 + 미정 분기)이고, 출처 경로는 `실경기 추출`, 근거는 데이터셋 이름·라이선스·군집 id다(014 FR-06). 런타임 라이브러리에 자동으로 들어가지 않고 053 FR-78 경로를 거친다. 오픈플레이 수비 군집은 시나리오 후보가 아니라 009 수비 형태 프리셋 참고 자료로만 낸다.
- FR-08: **실경기 빈도 순위**: 군집을 사람이 카탈로그 ID에 대응시킨 표를 유지하고, 탐지기로 전체 데이터를 재검색해 카탈로그 패턴별 빈도·슈팅 전환율·득점 비중을 계산한다. 이 표가 067 FR-35(패턴 빈도 분포 비교)와 014 FR-70 "패턴 빈도 분포" 행의 기준이다. 군집 분포는 067 FR-31 "실제 기준"(문헌 EPL 3팀 값)을 보강하는 비교 자료로도 쓴다.
- FR-09: 상용 게임 데이터·리플레이·DB와 유료 계약 데이터는 어떤 경우에도 입력으로 쓰지 않는다.
- FR-10: 출처 표기가 필요한 데이터셋(CC BY 등)은 크레딧 목록에 자동으로 들어간다.
- FR-11: 실행은 개발 머신의 오프라인 도구다. 출시 빌드는 이 스펙의 코드·원천 데이터·추적 기록을 포함하지 않는다.

## 경계 · 예외 상황
- 라이선스 기록의 확인일이 [제안: 12개월] 이상 지남 → 경고, 재확인 전까지 추출은 진행하되 리포트에 표시.
- SkillCorner LICENSE 파일이 데이터에 적용되지 않는 것으로 확인됨 → 부록 A 판정을 "보류"로 바꾸고 해당 입력 거부.
- 원천 데이터에 역할 매핑이 불가능한 포지션 표기 → 해당 선수는 `역할 미상`으로 두고, 군집 대표의 역할 분포에서 비율로만 보고.
- 한 경기에서만 나온 페이즈로 이루어진 군집 → 후보가 되지 않는다(FR-06).
- 실명·팀명이 이벤트 설명 문자열 안에 섞여 있음 → 문자열 필드는 통째로 버린다.
- 추출 결과에 원천 경기 해시가 남음 → 출시물 경로면 오류.

## 비기능 요구사항
- 결정론: 같은 입력 데이터·설정 → 같은 후보 목록과 순서. 병렬 작업자 수와 무관하다.
- 격리: 원천 데이터와 추적 기록은 레포 밖 또는 gitignore 경로에 두고 커밋하지 않는다 [제안]. 후보 초안 파일만 레포에 들어간다.
- 추적성: 채택된 실경기 후보는 데이터셋·라이선스·군집 id·참여 경기 수를 이력에 남긴다.

## 수용 기준
- AC-01 [로직]: FR-01·02: 라이선스 기록이 없는 데이터셋으로 추출하면 거부되고 이유가 보인다. StatsBomb Open Data와 Metrica 샘플을 입력으로 지정해도 거부된다.
- AC-02 [로직]: FR-03: 추출 결과의 모든 필드를 테스트용 실명·팀명 사전과 원천 id 목록에 대조하면 일치 0건이다. 문자열 설명 필드가 결과에 0개다.
- AC-03 [로직]: FR-06: 한 경기에서만 나온 페이즈로 이루어진 군집은 후보가 되지 않는다 (후보 0건). 후보 파일에 원본 좌표 열이 없다.
- AC-04 [결정론]: FR-04·05: 같은 입력 데이터·설정으로 추출 2회 → 후보 목록과 순서가 같다. 병렬 작업자 수를 1과 8로 바꿔도 같다.
- AC-05 [로직]: FR-07: 후보 초안은 013 로더로 읽히고 `상태: 후보`·출처 경로 `실경기 추출`·근거(데이터셋·라이선스·군집 id)를 가지며, 런타임 라이브러리 로드 목록에 포함되지 않는다.
- AC-06 [로직]: FR-08: 카탈로그 ID 대응표가 있는 인공 데이터(패턴 A 100회, B 30회, C 5회)를 재검색하면 빈도 순위가 A > B > C로 나오고 빈도 값이 정확하다.
- AC-07 [로직]: FR-10: CC BY 데이터셋을 쓴 추출 뒤 크레딧 목록에 해당 표기 문구가 정확히 1번 들어간다.
- AC-08 [로직]: FR-04: 좌우 반전 쌍 페이즈 100쌍이 정규화 후 같은 군집으로 들어간다(분리 0건, 067 AC-02와 같은 구현).
- AC-09 [성능]: 성능 예산 표 항목이 기준 프로필에서 예산 안이다.
