# 007 — 피치 컨트롤 · xT

상태: 초안
브랜치: feat/007-pitch-control-xt
기획 출처: docs/index.html § 기획서 5.2(xT 테이블, 결정 주기), § 기획서 5.4(피치 컨트롤), § 아키텍처 3("피치 컨트롤과 xT를 공용 모듈로"), § 리서치 01 B-6, § 리서치 02 §0·§5.4

## 배경
AI가 "어디가 비어 있나", "이 패스를 보내면 얼마나 위협적인가"를 판단하려면 공간의 가치가 숫자로 있어야 한다. 피치 컨트롤은 "어느 팀이 그 지점에 먼저 도착해 공을 통제할 확률"이고, xT는 "그 구역에서 공을 가지면 결국 득점할 확률"이다. 두 값은 패스 성공 확률(008), 침투 공간 탐색과 압박 판단(010), 키 모먼트 선택지(019), 시나리오 트리거의 공간 조건(013)이 함께 쓰는 공용 평가 모듈이다.

## 범위
- 포함:
  - Spearman 방식 피치 컨트롤: 선수별 도달 확률, 시간 적분으로 팀 컨트롤 확률 계산
  - 지점 질의(후보 지점 몇 개)와 그리드 질의(저해상도 전체 맵) 두 가지 방식, 그리드 캐시
  - 공 궤적 위 컨트롤 적분: 패스·루즈볼의 "누가 먼저 잡나" 확률 (008이 성공 확률로 사용)
  - xT 테이블 16×12: 데이터 형식, 조회, 액션 가치(ΔxT), 수비 리스크 항
  - xT 학습: 대량 시뮬 로그(017)에서 이동·슈팅 확률을 집계해 value iteration으로 재계산
- 제외:
  - 패스·슈팅을 실제로 실행하고 결과를 판정 (008)
  - 압박 강도(Pressing Intensity) 공식 (008이 소유. 이 스펙의 도달 확률 함수를 재사용)
  - 행동 선택 (010)
  - 선수 TTI 함수 자체 (005가 제공, 이 스펙은 피치 컨트롤용 파라미터로 호출)

## 사용자 시나리오
1. 키 모먼트에서 "수비 뒷공간이 열렸다"는 선택지가 뜰 때, 실제로 뒷공간의 우리 팀 컨트롤 확률이 높은 상황이다.
2. 경기 후 분석 화면에서 내 선수의 패스가 xT를 얼마나 올렸는지 보인다 (015·038이 표시).
3. 디버그 뷰에서 피치 컨트롤 히트맵을 켜면, 수비 라인 뒤 공간이 공격 팀 색으로 물드는 게 보인다.

## 요구사항

### 피치 컨트롤 모델 (리서치 01 B-6 [V], 리서치 02 §0)
- FR-01: 선수별 도착 시간 `τ = t_r + ‖r_target − (r + v·t_r)‖ / v_max` (기본: 반응 0.7 s, v_max 5 m/s). 선택 모드로 005의 선수 고유 TTI를 쓸 수 있다 (이 경우 반응 ~0.3 s, 리서치 01 B-6·PitchControlParams 메모).
- FR-02: 도달 확률 `P(T) = 1 / (1 + exp(−π/√3 · (T − τ)/σ))`, σ = 0.45 s.
- FR-03: 컨트롤 누적 `dPC_j/dT = (1 − ΣPC)·P_j(T)·λ_j`. λ_att = λ_def = 4.3 s⁻¹, 수비 계수 κ_def 1.0~1.72 (기본 1.0, 코드 기본값 기준), λ_gk = 3 × λ_def.
- FR-04: 적분 간격 0.04 s, 최대 적분 시간 10 s, 수렴 허용치 0.01 (ΣPC ≥ 0.99면 종료). 지점 질의는 수렴 즉시 끝내고, 도달 시각이 가장 이른 선수부터 합산 대상에 넣어 먼 선수(τ가 현재 적분 시각 + 3σ보다 큰 선수)는 건너뛴다 `[제안]` (평균 비용을 낮추되 결과 차이 ≤ 1e-3).
- FR-05: 공 도착 시간은 평균 공 속도 15 m/s 직선으로 근사(그리드 모드), 또는 004 궤적 예측의 실제 도착 시각(궤적 모드).
- FR-06: 능력치 연결 [설계값, 리서치 02 §0]: 반응시간 ← 예측력·위치선정(0.85~0.5 s), λ_att ← 퍼스트터치, λ_def ← 태클(3.0~5.5), λ_gk ← GK 핸들링. 능력치 연결은 켜고 끌 수 있다(끄면 원 논문 값).
- FR-07: 뜬공 구간: 공 높이 > 2.5 m인 궤적 구간은 필드 선수 도달 확률을 0으로 둔다 (리서치 02 §1.1). GK는 손 사용 높이 [제안: 3.0 m]까지 허용.
- FR-08: 결과는 팀별·선수별 컨트롤 확률 (공격 + 수비 + 미통제 = 1).

### 질의 방식
- FR-10: 지점 질의: 후보 지점 N개(패스 대상·리드 지점 등)에 대해 컨트롤 확률을 계산한다. 매 결정 틱에 쓰는 기본 경로 (리서치 02 §0 성능 메모).
- FR-11: 그리드 질의: 32×20 그리드(기획서 5.4) 전체 맵. **시뮬 기본 경로(매 결정 틱)에서는 쓰지 않는다** `[제안]` — 그리드 1회 ≤ 4 ms라 0.5 s마다 돌려도 경기당 40 s 이상이 되어 006 FR-80 예산(경기 2 s)을 넘는다. 쓰임: 디버그 히트맵(040), 키 모먼트 선택지 생성(019), 경기 후 분석. 쓸 때는 캐시 시각·유효성 정보를 함께 준다. 결정에 필요한 공간 값은 FR-10 지점 질의로만 얻는다.
- FR-12: 궤적 질의: 004가 예측한 공 궤적을 따라 0.04 s 간격으로 적분해 "의도한 수신자 / 다른 동료 / 상대 / 아무도 못 잡음(아웃)" 확률을 준다 (리서치 02 §1.1 절차 2~3).
- FR-13: 질의는 상태를 바꾸지 않는다 (부작용 없음). 같은 입력 → 같은 출력.

### xT (기획서 5.2, 리서치 02 §5.4 [V])
- FR-20: 피치를 16×12 구역으로 나눈 테이블. 공격 방향 기준 좌표계로 정의하고, 팀별로 좌우 반전해 조회한다.
- FR-21: 정의 `xT(x,y) = s(x,y)·g(x,y) + m(x,y)·Σ T((x,y)→(z,w))·xT(z,w)` (s: 슈팅 확률, g: 슈팅 시 득점 확률, m: 이동 확률, T: 이동 전이 행렬).
- FR-22: 액션 가치 `ΔxT = xT(도착) − xT(출발)`. 구역 경계 사이 연속 좌표는 [제안: 쌍선형 보간] 또는 구역 값 그대로 — 모드 선택 가능.
- FR-23: 수비 리스크 항: 공을 잃을 경우 그 지점에서 상대의 xT(좌우 반전 조회)를 리스크 값으로 제공한다 (기획서 5.2 "한계" 대응, 리서치 02 §6 `LossRisk × xT_opponent_at(lossPoint)`).
- FR-24: 초기 테이블은 공개 자료로 만든 상수 테이블 [미정: 출처 맵 선택]. 테이블은 데이터 파일로 교체 가능.
- FR-25: xT 학습: 017 대량 시뮬 이벤트 로그에서 구역별 s, g, m, T를 집계하고, 0에서 시작해 수렴할 때까지 value iteration (리서치: 4~5회로 수렴). 수렴 기준 [제안: 셀 최대 변화 < 1e-4] 또는 최대 반복 [제안: 50].
- FR-26: 학습 결과는 버전 번호와 함께 저장하고, 기존 테이블과의 셀별 차이 리포트를 낸다. 적용은 승인 후에만.
- FR-27: 디버그 진단 출력 (040 FR-30 레이어 '피치 컨트롤 · xT'에 공급): 질의한 지점의 팀별 컨트롤 확률·도달 시간, 진단 모드에서만 32×20 전체 그리드, xT 격자 값과 액션별 ΔxT. 진단 출력은 시뮬 결과와 RNG 소비를 바꾸지 않고, 꺼져 있으면 추가 비용·할당이 0이다. (UI 검수 정리, 2026-11-02)

## 경계 · 예외 상황
- 선수가 0명인 팀(테스트 입력) → 그 팀 컨트롤 0, 예외 없음.
- 모든 선수가 목표 지점에서 아주 멀어 10 s 안에 수렴하지 않음 → 미통제 확률을 그대로 반환하고, ΣPC ≤ 1을 지킨다.
- 선수가 목표 지점 위에 정확히 있음(거리 0) → τ = t_r, 정상 계산.
- 피치 밖 지점 질의 → 정의된 동작: 피치 밖은 "아웃" 영역으로 컨트롤 0 [제안] 또는 가장 가까운 경계 셀 — 하나로 정한다.
- 적분 중 ΣPC가 1을 넘는 수치 오차 → 매 스텝 정규화로 1을 넘지 않는다.
- xT 조회 좌표가 피치 경계(x = 105, y = 68) 정확히 위 → 마지막 셀로 귀속 (인덱스 범위 초과 없음).
- 학습 데이터에서 슈팅·이동이 0회인 구역 → 0으로 나누기 금지, 이웃 평활 또는 초기값 유지 [제안].
- 그리드 캐시가 오래된 상태(선수 교체·퇴장 직후) → 이벤트 발생 시 캐시 무효화.

## 비기능 요구사항
- 결정론: 같은 입력 → 비트 단위 동일. 난수 없음. 선수 합산 순서는 id 순 고정.
- 할당: 지점·궤적·그리드 질의 경로 힙 할당 0 (버퍼 재사용).
- 병렬화(작업 분할·SIMD, 기획서 5.4)는 "경기 하나 안에서 결과 순서가 바뀌지 않는" 경우에만 허용 [미정].

## 수용 기준
- AC-01 [로직]: 공개 구현 기본 파라미터(반응 0.7, 5 m/s, σ 0.45, λ 4.3, κ 1.0, λ_gk ×3, dt 0.04, 최대 10 s, 허용치 0.01)로 계산한 고정 시나리오 5개(정적 배치)의 지점별 컨트롤 확률이 참조 계산값(같은 수식을 독립 구현한 검증용 스크립트)과 ±0.01 이내다.
- AC-02 [로직]: 대칭 배치(양 팀 선수가 지점에서 같은 거리·같은 파라미터)에서 공격·수비 컨트롤이 같다 (λ·κ 동일 시).
- AC-03 [로직]: 어떤 질의에서도 공격 + 수비 + 미통제 = 1 ± 1e-5, 각 값 0~1.
- AC-04 [로직]: 한 선수만 지점으로 1 m 다가가면 그 팀 컨트롤 확률이 줄지 않는다 (단조성, 무작위 고정 시드 1,000 케이스).
- AC-05 [로직]: 궤적 질의: 수신자 앞을 상대가 가로막은 땅볼 패스는 상대 확률이 0.5 초과, 아무도 없는 공간으로 간 패스는 수신자 확률이 0.9 초과다. 높이 > 2.5 m 구간에서는 필드 선수 컨트롤 증가가 0이다.
- AC-06 [로직]: xT 테이블 조회가 좌우 반전으로 양 팀에서 대칭이다 (팀 A의 (x,y) = 팀 B의 (105−x, 68−y)).
- AC-07 [로직]: 알려진 작은 전이 행렬(4×3 장난감 피치, 손으로 계산한 해)에 value iteration을 돌리면 해석해와 1e-6 이내로 수렴하고, 반복 n회 값이 "n 액션 이내 득점 확률"과 같다.
- AC-08 [로직]: 017 로그(고정 시드 1,000경기)로 학습한 xT가 수렴 기준 안에서 끝나고, 골문 앞 중앙 구역 값이 하프라인 구역 값보다 크며, 모든 셀이 0~1이다.
- AC-09 [로직]: 경계 · 예외 상황 목록 입력(0명 팀, 비수렴, 거리 0, 피치 밖, 경계 좌표, 빈 구역 학습, 퇴장 직후 캐시) 각각에서 NaN 0건, 인덱스 초과 0건, 규칙대로 처리된다.
- AC-10 [결정론]: 고정 시드 경기 상태 1,000개에 대한 지점·궤적·그리드 질의 결과 해시가 2회 실행에서 같고, 선수 입력 순서를 섞어도 같다.
- AC-11 [성능]: 성능 예산 표 항목이 기준 프로필에서 예산 안, 할당 0 B. 조기 종료·먼 선수 건너뛰기 결과가 전체 적분 결과와 고정 상태 1,000개에서 ≤ 1e-3 차이다. 풀 경기 1개 동안 그리드 질의 호출 수가 0이다 (디버그 끈 상태).
- AC-12 [E2E]: 디버그 히트맵(040 2D 뷰 오버레이)에서 고정 배치 3종(역습 3v2, 높은 라인 뒷공간, 박스 혼전)의 피치 컨트롤 그리드 캡처와 xT 테이블 캡처가 기준 이미지와 일치한다. 프로필: smoke. 뷰가 없으면 040 완료 후 검증.
- AC-13 [결정론]: FR-27 진단 출력을 켠 실행과 끈 실행(같은 시드)의 이벤트 로그 해시와 체크포인트 해시가 모두 같다. 끈 실행에서 진단용 할당은 0 B다.

## 미정 / 질문
- [미정] 초기 xT 상수 테이블의 출처 맵 (공개 맵 중 라이선스상 수치 사용 가능한 것). 학습 테이블로 처음부터 대체할지.
- [미정] κ_def 기본값: 논문 1.72 vs 공개 코드 1.0.
- 확정 (2026-11-02): 그리드 해상도 32×20(기획서 5.4), 데이터로 바꿀 수 있다. 리서치 02 §0의 32×24는 쓰지 않는다.
- [미정] 병렬화(작업 분할·SIMD) 도입 여부와 결정론 보장 방법.
- [제안] 그리드 질의를 시뮬 기본 경로에서 빼기(FR-11), 조기 종료·먼 선수 건너뛰기(FR-04). 피치 밖 지점은 컨트롤 0, 빈 구역은 초기값 유지, value iteration 수렴 기준 1e-4·최대 50회는 승인 필요.
