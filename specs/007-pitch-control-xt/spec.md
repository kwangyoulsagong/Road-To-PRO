## 배경
AI가 "이 패스를 보내면 누가 먼저 공에 닿나"를 알아야 패스를 고른다. 지금 엔진은 007 대신 임시 근사(받는 지점에서 내 도달 시간 vs 상대 최단 도달 시간, 레인 위 상대의 횡거리)를 쓴다. 그 결과 087 뒤 100경기에서 **판단이 본 패스 성공 확률 평균은 0.94인데 실제 성공은 54 %**이고, 실패의 대부분은 공이 날아가는 동안 상대가 먼저 경로에 닿는 인터셉트(19 %)와 루즈볼(11 %)이다(087 evidence/measure-after.json). 084에서 008·010 계수 개정 3방향을 모두 시도했지만 성공률 54~55 %에 머물렀다(084 AC-02 보류). 원인은 계수가 아니라 판단 입력에 "비행 중 경로 위 컨트롤"이 없다는 것이다.

이 스펙은 피치 컨트롤 모델(지점·궤적·그리드 질의)을 만들고, 그것을 008 패스 평가와 072 온볼 패스 선택에 연결해 **판단 확률이 실제와 맞게** 만든다. 판단이 위험한 패스를 위험하다고 알면 더 안전한 패스·보유·드리블을 고르고, 패스 수와 성공률이 081 1차 범위(≥ 550, ≥ 60 %)로 올라가는 것이 목표다.

## 범위
- 포함:
  - Spearman 방식 피치 컨트롤: 선수별 도달 확률, 시간 적분으로 팀·선수별 컨트롤 확률 계산
  - 지점 질의(후보 지점 몇 개), 궤적 질의(공 궤적 위 "누가 먼저 잡나"), 그리드 질의(32×20 전체 맵, 시뮬 루프 밖)
  - **연결**: 008 패스 평가의 수신 지점 컨트롤 입력을 지점 질의로 교체, 072 온볼 패스 선택(그리고 같은 패스 평가를 쓰는 대체 경로)이 상위 패스 후보의 성공 확률에 궤적 질의 결과를 반영
  - D19 재측정: 100경기 패스 수·성공률, 판단 확률 보정도, 다른 1차 범위 지표의 회귀 감시
  - 진단 출력(질의한 지점·궤적의 컨트롤 값)
- 제외:
  - **xT 테이블 · xT 학습 (원 FR-20~26)** — 별도 스펙으로 분리 [제안]. 학습은 017 대량 시뮬 로그가 필요한데 017이 아직 구현 전이다. 그동안 008·072는 지금의 대체 위협도(상대 골까지 거리 기반)를 그대로 쓴다.
  - 010 오프볼 공간 평가(대체 `Control`)와 009 형태의 피치 컨트롤 이득 방향 교체 — 후속 [제안]. 오프볼 움직임이 바뀌면 이미 맞춘 081~087 지표가 다시 흔들리므로 D19 해결과 섞지 않는다. 010 AC-37·008 AC-24 중 패스 경로 부분만 이 스펙에서 재확인한다.
  - 디버그 히트맵 화면 (040, 아직 초안). 이 스펙은 그리드 값과 진단 출력만 제공한다.
  - 패스·슈팅 실행과 결과 판정 (008·071), 압박 강도 공식 (008), 선수 TTI 함수 자체 (005)
  - 병렬화(작업 분할·SIMD) — 단일 스레드로 예산 안이면 도입하지 않는다

## 사용자 시나리오
1. 하이라이트에서 내 팀 미드필더가 상대 수비가 길목에 서 있는 패스 대신 열린 동료에게 패스하거나 공을 지킨다 — 전보다 패스가 끊기는 장면이 줄어든다.
2. 경기 결과 통계에서 패스 수·패스 성공률이 축구다운 쪽으로 올라간다 (1차 목표 ≥ 550개·≥ 60 %).
3. (개발자) 디버그 진단을 켜면 패스 후보마다 "수신자 / 다른 동료 / 상대 / 아웃" 확률과 받는 지점의 컨트롤 값이 보인다.

## 요구사항

### 피치 컨트롤 모델 (리서치 01 B-6 [V], 리서치 02 §0)
- FR-01: 선수별 도착 시간 `τ = t_r + ‖r_target − (r + v·t_r)‖ / v_max` (원 논문 모드: 반응 0.7 s, v_max 5 m/s). 엔진 모드는 005의 선수 고유 TTI를 쓴다 (이 경우 반응 ~0.3 s, 리서치 01 B-6·PitchControlParams 메모). **연결 경로는 엔진 모드**다 — 실행(008 인터셉트·수신)이 005 TTI로 움직이므로 판단도 같은 도달 시간을 써야 판단과 실행이 어긋나지 않는다 [제안].
- FR-02: 도달 확률 `P(T) = 1 / (1 + exp(−π/√3 · (T − τ)/σ))`, σ = 0.45 s.
- FR-03: 컨트롤 누적 `dPC_j/dT = (1 − ΣPC)·P_j(T)·λ_j`. λ_att = λ_def = 4.3 s⁻¹, 수비 계수 κ_def 기본 1.0 (공개 코드 기본값. 논문 1.72는 선택값) [제안], λ_gk = 3 × λ_def.
- FR-04: 적분 간격 0.04 s, 최대 적분 시간 10 s, 수렴 허용치 0.01 (ΣPC ≥ 0.99면 종료). 지점 질의는 수렴 즉시 끝내고, 도달 시각이 이른 선수부터 합산하며 τ가 현재 적분 시각 + 5σ보다 큰 선수는 건너뛴다 [제안] (결과 차이 ≤ 1e-3). 마지막 스텝은 ΣPC가 정확히 1 − 허용치에 닿도록 그 스텝 증가분을 비례로 줄인다. (구현 중 개정 2026-11-18 T06: 3σ는 전체 적분 대비 차이 ≈ 1e-2로 같은 FR의 ≤ 1e-3을 못 지켜 5σ(≈ 4e-4)로. 마지막 스텝 비례 축소는 조기 종료 때문에 선수가 다가가도 팀 컨트롤이 최대 0.004 줄던 불연속을 없앤다)
- FR-05: 공 도착 시간은 그리드 모드에서 평균 공 속도 15 m/s 직선 근사, 궤적 모드에서 004 공 물리의 실제 도착 시각.
- FR-06: 능력치 연결 [설계값, 리서치 02 §0]: 반응시간 ← 예측력·위치선정(0.85~0.5 s), λ_att ← 퍼스트터치, λ_def ← 태클(3.0~5.5), λ_gk ← GK 핸들링. 켜고 끌 수 있다(끄면 원 논문 값). 002 능력치가 아직 대체 입력이면 지금 엔진의 대체 능력치를 쓴다.
- FR-07: 뜬공 구간: 공 높이 > 2.5 m인 궤적 구간은 필드 선수 도달 확률을 0으로 둔다 (리서치 02 §1.1, 008 컨트롤 높이 상한과 같은 값). GK는 손 사용 높이 [제안: 3.0 m]까지 허용.
- FR-08: 결과는 팀별·선수별 컨트롤 확률 (공격 + 수비 + 미통제 = 1).

### 질의 방식
- FR-10: 지점 질의: 후보 지점 N개에 대해 컨트롤 확률을 계산한다. 매 결정 틱 경로에서 쓸 수 있다.
- FR-11: 그리드 질의: 32×20 그리드(기획서 5.4) 전체 맵. **시뮬 루프(결정 틱) 경로에서는 쓰지 않는다** [제안] — 쓰임은 디버그(040)·키 모먼트 선택지(019)·경기 후 분석. 결과에 계산 시각을 함께 준다.
- FR-12: 궤적 질의: 공 궤적을 따라 0.04 s 간격으로 적분해 "의도한 수신자 / 다른 동료 / 상대 / 아무도 못 잡음(아웃)" 확률을 준다 (리서치 02 §1.1 절차 2~3). 008 FR-10 물리 xPass가 이 질의다 — 지금 있는 물리 xPass(첫 도달 순간 수신 확률로 질량을 가져가는 근사)는 이 질의로 바꾸거나 이 질의의 결과와 맞춘다.
- FR-13: 질의는 상태를 바꾸지 않는다. 같은 입력 → 같은 출력. RNG를 쓰지 않는다.

### 패스 판단 연결 (D19)
- FR-20: 008 패스 평가의 수신 지점 컨트롤 입력(`receiverPC`)은 FR-10 지점 질의의 수신자 팀 컨트롤 확률이다. 지금의 대체 근사(로지스틱 도달 시간 차)는 비교용 모드로만 남긴다.
- FR-21: 072 온볼 판단(그리고 같은 008 평가를 쓰는 대체 패스 선택 경로)이 패스 후보를 고를 때, 로지스틱 평가 상위 K개 후보 [제안: K = 3]는 FR-12 궤적 질의를 돌려 그 결과로 성공 확률을 다시 정한다. 판단에 쓰는 성공 확률 = 궤적 질의의 수신자 확률 + 다른 동료 확률 × 동료 수신 가치 [제안: 0.5]. 나머지 후보는 로지스틱 값을 그대로 쓴다.
- FR-22: 궤적 질의에 넣는 궤적은 의도한 조준점·초속·발사각의 명목 궤적(실행 오차 없음)이다. 실행 오차는 지금처럼 접촉 순간 008이 정한다.
- FR-23: 크로스(071)·슈팅·스루볼 조준점 풀이·키 모먼트는 이 스펙에서 바꾸지 않는다. 단, 스루볼 후보가 상위 K개에 들면 같은 궤적 질의를 거친다.
- FR-24: 보정 목표 (081 FR-10 1차 범위 그대로): 100경기(고정 시드, 081~087과 같은 측정 도구) 패스 수 ≥ 550, 패스 성공률 ≥ 60 %. 판단 확률 보정: 실제 실행된 패스의 판단 성공 확률 평균과 실제 성공률의 차이 ≤ 0.10 [제안] (지금 0.94 vs 0.54).
- FR-25: 회귀 감시: 같은 100경기에서 087 뒤 범위 안이던 1차 지표(드리블 터치당 탈취율 ≤ 12 %, GK 선방률 60~80 %, 슈팅 전환율 ≤ 18 %, 슈팅당 xG 0.07~0.14, 테이크온 성공률 30~45 %)가 범위 안에 남는다. 범위를 벗어나면 이 스펙 범위의 [대체] 계수(K, 동료 수신 가치, 008 [대체] 계수)로만 되돌리고, [설계] 개정이 필요하면 멈추고 제안한다 (081 FR-11 방식).
- FR-26: FR-24를 [대체] 계수로 못 맞추면 측정값·사유를 남기고 해당 AC를 보류로 표시한다 (084 Q3 방식). FR-20~23 연결 자체와 결정론·성능 AC는 보류 대상이 아니다.

### 진단
- FR-27: 진단 출력: 패스 후보별 로지스틱 xPass·궤적 질의 4종 확률·수신 지점 컨트롤, 진단 모드에서만 32×20 그리드. 진단 출력은 시뮬 결과와 RNG 소비를 바꾸지 않고, 꺼져 있으면 추가 비용·할당이 0이다.

## 경계 · 예외 상황
- 선수가 0명인 팀(테스트 입력) → 그 팀 컨트롤 0, 예외 없음.
- 10 s 안에 수렴하지 않음 → 미통제 확률을 그대로 반환하고 ΣPC ≤ 1을 지킨다.
- 선수가 목표 지점 위에 정확히 있음(거리 0) → τ = t_r, 정상 계산.
- 피치 밖 지점 질의 → 컨트롤 0(전부 미통제) [제안].
- 적분 중 ΣPC가 1을 넘는 수치 오차 → 매 스텝 정규화로 1을 넘지 않는다.
- 궤적이 라인 밖으로 나감 → 남은 확률은 아웃. 궤적이 멈추거나 상한 시간에 도달 → 남은 확률은 그 지점의 지점 질의 결과로 나눈다 [제안].
- 패서 자신은 궤적 질의의 수신 대상에서 뺀다.
- 퇴장·교체 직후 → 다음 질의부터 바뀐 선수 구성을 쓴다 (캐시가 있다면 무효화).

## 비기능 요구사항
- 결정론: 같은 입력 → 비트 단위 동일. 난수 없음. 선수 합산 순서는 슬롯 순 고정, 입력 순서를 섞어도 같은 결과.
- 할당: 지점·궤적·그리드 질의 경로 힙 할당 0 (버퍼 재사용).
- 세이브 호환: 질의는 상태를 갖지 않으므로 체크포인트 형식은 바뀌지 않는다. 경기 결과(시드별 이벤트 로그)는 판단이 바뀌므로 달라진다 — 결정론 해시 기준값을 갱신한다.
