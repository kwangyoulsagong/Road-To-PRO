## 배경
이 게임은 숫자와 선택이 많다. 화면이 수십 개로 늘어나도 같은 모양·같은 간격·같은 동작이어야 읽기 쉽고 버그가 적다. 그래서 모든 화면이 공통으로 쓰는 **디자인 토큰**(색·간격·라운드·글꼴·모션)과 **기본 컴포넌트**, 테마, 현지화, 접근성, 키보드 조작 기반을 먼저 만든다. 개별 화면(038, 039)은 이것만 조립한다.

**방향 변경 이력**
- 2026-11-02 (기획서 4.9, 초판): "깔끔한 모바일 금융 앱" 톤 — 밝은 회색 바탕 + 흰 카드(모서리 16~20px, 그림자 거의 없음), 포인트 컬러는 블루 하나, 큰 숫자, 선택지는 화면 아래에서 올라오는 바텀시트, 라이트/다크 동시 지원, 성공 시 햅틱(모바일).
- 2026-11-10: PC 전용 확정. 모바일·태블릿 프로필과 터치·햅틱 전제가 빠진다.
- **2026-11-11 (사용자 결정)**: "UI는 토스(모바일 금융 앱)라고 했는데 FIFA나 FM이 맞는 것 같아, 다크하면서". → **축구 게임 스타일 다크 UI**로 바꾼다. 어두운 바탕 계층 위에 정보 밀도 높은 표·목록·능력치 그리드·비교 뷰를 놓고, 선수 카드·능력치·전술판이 화면의 중심이 된다. 마우스·키보드 우선.
- 이 개정에서 바뀐 것: 회색 바탕 + 흰 카드 → 어두운 바탕 계층 + 패널 / 블루 포인트 1개 → 강조색 1개(청록·시안, 2026-11-11) + 능력치 구간 색 / 바텀시트 → 선택 패널(키 모먼트 포함) / 확인 시트 → 확인 모달 / 하단 탭바 → 사이드 내비 / 넉넉한 여백·한 화면 한 숫자 → 정보 밀도 / 터치 영역·햅틱·세로 화면 → 마우스 대상 크기·키보드 단축키·PC 해상도와 UI 배율 / E2E는 mac-m1-1600p 1프로필 스크린샷 + 사용자 육안 승인(2026-11-11 매트릭스 폐지).
- 2026-11-11 (사용자 결정 '베스트 케이스'): 다크 단독(라이트 없음), 강조색 청록·시안, 상승/하락 기본 초록/빨강(설정에서 빨강/파랑), 능력치 4구간, 038 FR-01 "한 화면 한 가지 일"을 FR-08 정보 밀도 원칙으로 완화.

**상용 게임 참고 원칙** (01-legal): FIFA(EA FC)·Football Manager·eFootball의 화면 배치·아이콘·색 조합·카드 모양을 그대로 베끼지 않는다. 참고는 **장르 관례 수준**까지다 — 공개 스크린샷을 보고 "축구 게임 UI에 무엇이 관례인지"(예: 능력치를 1~20 숫자와 색 구간으로 보인다, 포지션은 약어 배지로 보인다, 폼은 화살표로 보인다, 선수 목록은 정렬 가능한 표다)만 정리하고, 실제 배치·색·아이콘·모양은 이 프로젝트가 직접 정한다. 게임 파일·에셋은 열지 않는다.

## 사용자 시나리오
1. 플레이어가 어떤 화면을 열어도 어두운 바탕 위에 패널이 층으로 놓이고, 왼쪽 사이드 내비에서 지금 위치가 강조색으로 보인다.
2. 내 선수 프로필에서 능력치 그리드가 한눈에 보이고, 각 능력치는 1~20 숫자와 구간 색으로 표시된다. 숫자에 마우스를 올리면 툴팁에 지난달 대비 변화가 보인다.
3. 동료 선수 목록 표에서 "포지션" 열 머리글을 누르면 정렬되고, 필터 칩으로 "MF만"을 고른다. 행을 우클릭하면 "선수 비교" 메뉴가 나오고, 비교 뷰에서 두 선수의 능력치 차이가 나란히 보인다.
4. 연봉이 오르면 숫자가 이전 값에서 새 값으로 올라가는 카운트업이 보이고, 오른 폭이 상승 색 + ▲로 표시된다.
5. 인터뷰 답변을 고를 때 어두운 선택 패널이 뜨고, 숫자 키 1~3이나 마우스로 고른다.
6. 언어를 English로 바꾸면 긴 문장도 잘리거나 겹치지 않고 줄바꿈되거나 말줄임 처리된다.

## 요구사항

### 디자인 토큰
- FR-01: 모든 색·간격·라운드·글꼴 크기·글꼴 굵기·그림자·모션 시간·이징은 토큰으로만 정의한다. 컴포넌트·화면 스타일에서 토큰이 아닌 직접 값(색 코드, px 간격)은 금지한다. 정적 검사로 위반을 0으로 유지한다 (기획서 4.9의 토큰 원칙 유지).
- FR-02: 색 토큰 (의미 이름으로, 테마별 값):
  - **바탕 계층**: 가장 어두운 앱 바탕 → 패널 → 패널 안 패널(중첩) → 떠 있는 요소(모달·메뉴·툴팁)의 [제안] 4단계. 층은 명도 차로 구분하고 단계마다 바탕보다 밝아진다. 순수 검정(#000)은 바탕에 쓰지 않는다 [제안] (긴 시간 읽기 피로).
  - 구분선·테두리, 본문 텍스트, 보조 텍스트, 비활성 텍스트, 표의 줄무늬 행·호버 행·선택 행
  - **강조색 1개**: 기본 버튼·선택 상태·현재 위치·링크·포커스 링. 색상(hue)은 **청록·시안 계열** (2026-11-11 사용자 결정 '베스트 케이스'). 정확한 값은 대비(FR-60)·색각(FR-15) 검사를 통과하도록 [제안] 값으로 정하고, 능력치 구간 색·상승/하락 색과 색상이 겹치지 않게 한다(AC-03 색차 기준). 강조색 외의 장식용 색은 추가하지 않는다. 의미색·능력치 구간 색·포지션 줄 색은 정보용이라 장식색으로 쓰지 않는다.
  - 의미색: 상승, 하락, 경고, 위험(파괴적 동작). 상승/하락 색 쌍 기본값은 **초록=상승 / 빨강=하락** (2026-11-11 사용자 결정 '베스트 케이스'). 설정에서 빨강=상승 / 파랑=하락으로 바꿀 수 있다(기획서 4.9: "빨강/파랑 또는 초록/빨강"). 어느 쌍이든 ▲▼ 부호를 함께 보인다(FR-63).
  - 오버레이(모달·선택 패널 뒤 딤)
- FR-03: 라운드 토큰: 정보 밀도에 맞춰 작게 [제안] 패널 6px, 버튼·칩·배지 4px. (옛 기획서 4.9의 16~20px는 폐기)
- FR-04: 깊이는 바탕 계층 명도 차로 표현한다. 그림자는 떠 있는 요소(모달·메뉴·툴팁)에만 [제안] 1단계.
- FR-05: 간격 토큰은 4px 배수 단계 [제안] (2, 4, 8, 12, 16, 24, 32). 기본 밀도는 촘촘하게: 표 행 높이 [제안] 28px(배율 1.0), 패널 안 여백 [제안] 12px. 화면 좌우 여백, 패널 안 여백, 패널 사이 간격, 표 행 높이는 각각 토큰.
- FR-06: 글꼴: 가독성 좋은 산세리프, OFL 라이선스 (Pretendard 또는 Noto Sans KR, 기획서 4.9). 어느 쪽인지는 [미정]. 숫자는 고정폭 숫자(tabular figures)로 표시해 표의 숫자 열이 세로로 정렬되고 카운트업 중 폭이 흔들리지 않는다. 숫자용 별도 글꼴을 쓸지는 [미정]. 글꼴 파일은 `Art/LICENSES.csv`에 기록한다.
- FR-07: 글자 크기 단계: 핵심 수치 > 제목 > 소제목 > 본문 > 표 > 캡션. 기본 본문 [제안] 14px, 표 [제안] 13px, 최소 글자 [제안] 12px (배율 1.0, 1920×1080 기준). 한글은 같은 크기에서 영문보다 획이 많으므로 12px 미만을 쓰지 않는다. 능력치 숫자·평점·연봉·시장가치는 굵게 표시한다.
- FR-08: 정보 밀도 원칙: 매니지먼트 화면은 한 화면에 표·목록·그리드·비교를 함께 놓을 수 있다. 다만 **결정**(선택 패널로 묻는 것)은 한 번에 하나만 요구한다. 화면마다 가장 중요한 수치 1~4개는 핵심 수치 단계로 키운다.

### 테마
- FR-10: **다크 테마 단독**이다 (2026-11-11 사용자 결정 '베스트 케이스'). 라이트 테마와 테마 선택 설정은 만들지 않는다. 그래도 모든 색은 테마 토큰으로만 정의해 나중에 테마를 추가할 수 있게 한다.
- FR-11: UI 배율·상승/하락 색 쌍 전환은 화면을 다시 만들지 않고 즉시 반영되며, 스크롤 위치·열린 패널·입력 중 텍스트·표 정렬 상태를 유지한다.
- FR-12: 강조색은 정확히 하나(청록·시안)이고, 의미색(상승/하락 두 쌍 모두)·능력치 구간 색은 다크 바탕 대비 기준(FR-60)을 만족한다. 테마를 나중에 추가하면 테마별 값을 가진다.

### 능력치 · 색 구간
- FR-13: 능력치는 표시값 1~20 정수로 보인다 (CLAUDE.md 확정: 내부 0~100, 표시 1~20). 숫자는 항상 함께 표시하고 색은 보조다.
- FR-14: 능력치 색 구간: 1~20을 **4구간**(1~6 낮음, 7~12 보통, 13~16 좋음, 17~20 뛰어남)으로 나누고 구간마다 색 토큰을 둔다 (2026-11-11 사용자 결정 '베스트 케이스'). 경계는 [제안] 채택 (2026-11-11, 측정 후 조정), 구간 색 값은 대비·색각 검사(AC-02·AC-03)를 통과하는 값으로 정한다. 특정 상용 게임의 구간 경계·색 조합을 그대로 쓰지 않는다.
- FR-15: 색각 이상 대응: 능력치 구간 색, 상승/하락 색, 포지션 줄 색은 적색약·녹색약·청색약 시뮬레이션 후에도 인접 구간끼리 구분된다 (명도 차를 함께 둔다). 별도 "색각 보정 팔레트" 설정을 둘지는 [미정]. 어느 경우에도 색만으로 정보를 전달하지 않는다 (숫자·화살표·부호·모양 병기, research 07 § 5.3).
- FR-16: 능력치 막대: 1~20을 길이로 보이는 막대 + 숫자. 막대 채움 색은 구간 색. 변화(지난 기간 대비)는 막대 끝 표시 + 증감 숫자로 [제안].

### 컴포넌트 — 기본
- FR-20: 패널(카드): 제목(선택), 본문 슬롯, 하단 동작(선택). 누를 수 있는 패널은 호버·포커스 상태를 보이고, 아닌 패널과 구분된다.
- FR-21: 핵심 수치: 값, 단위(통화·%·점), 증감(이전 값 대비 차이와 방향 색·부호). 값이 바뀌면 카운트업 애니메이션 (기획서 4.9). 지속 시간 [제안] 0.6초, 변화폭이 작으면 짧게. 화면에 처음 들어올 때는 카운트업하지 않는다 [제안] (변화가 있을 때만).
- FR-22: 버튼: 기본(강조색 채움), 보조(외곽선 또는 옅은 바탕), 텍스트, 위험. 호버·눌림·포커스·비활성·로딩 상태. 눌림 시 스케일 [제안] 0.97 (기획서 4.9 값 유지). 연속 클릭으로 동작이 두 번 실행되지 않는다.
- FR-23: **선택 패널** (옛 바텀시트를 대체): 어두운 떠 있는 패널에 제목(대화체 한 줄), 선택지 목록(각 항목: 번호, 제목, 부연 한 줄, 선택 시 예상 결과 표시 슬롯)을 보인다. 선택지는 마우스 클릭, 숫자 키 1~9, 방향키 + Enter로 고른다. 닫기 가능 여부 설정(키 모먼트·필수 선택은 닫기 불가). 선택지가 패널 높이를 넘으면 패널 안에서 스크롤한다. 뒤 화면은 딤 처리되고 입력을 막는다. 위치: 메뉴 화면에서는 화면 중앙 [제안], 경기 중 키 모먼트에서는 하이라이트 화면 아래쪽 가운데 [제안] (공 주변을 가리지 않게, 039 FR-40).
- FR-24: 목록: 수천 행에서도 끊기지 않도록 보이는 행만 그린다 (research 07 § 5.2: 선수 목록·스카우팅 리포트 수백~수천 행). 빈 상태, 로딩 상태. 데이터 테이블(FR-35)의 바탕이 된다.
- FR-25: 토스트: 짧은 알림 한 줄, 자동 사라짐 [제안] 2.5초, 동시에 여러 개면 순서대로. 위치는 화면 오른쪽 아래 [제안].
- FR-26: 빈 상태·오류 상태: 대화체 한 줄 + 선택 동작. 데이터가 없을 때 빈 패널이나 0 대신 이 상태를 보인다.
- FR-27: 별점 표시(★1~5, 반 개 단위 여부 [미정]), 진행 막대(0~100), 칩, 증감 화살표.
- FR-28: 탐색: 왼쪽 **사이드 내비**(섹션 목록, 현재 위치 강조) + 상단바(현재 화면 제목·경로, 게임 날짜, 잔고, 진행 버튼 자리). 창 폭이 [제안] 1366px 이하면 사이드 내비는 아이콘 + 툴팁 폭으로 접힌다. 섹션 수는 [미정] (038에서 화면 목록 확정 후). 뒤로 가기(Esc·마우스 뒤로 버튼·Backspace [제안])는 이전 화면으로.
- FR-29: 확인 모달: 되돌릴 수 없는 동작(서명·삭제·은퇴)은 화면 중앙 모달로 묻는다. 모달이 열리면 포커스가 모달 안에 갇히고, 닫으면 연 요소로 돌아간다. 닫기 가능한 모달은 Esc로 닫힌다. 동시에 모달·선택 패널은 하나만 열린다 (대기열).

### 컴포넌트 — 축구 게임 관례
- FR-30: 선수 카드: 이름, 나이, 포지션 배지, 국적(텍스트 약어 [제안], 국기 표시 여부 [미정]), 역할, 대표 수치(전체 등급 표시 방식은 [미정] — 038 FR-03과 같은 질문), 폼 화살표, 컨디션·부상 표시. 크기 [제안] 3단계(목록 행 / 작은 카드 / 큰 카드). 카드 외곽 모양(방패형 등 특정 상용 게임의 카드 모양)은 쓰지 않고 이 프로젝트 패널 모양을 쓴다.
- FR-31: 능력치 그리드: 분류별(분류 목록은 능력치 도메인 스펙이 제공) 열로 능력치 이름 + 1~20 숫자(구간 색)를 나열한다. 드러나지 않은 능력치는 "?" 또는 범위로 표시 [미정] (스카우팅 정보 공개 규칙은 도메인 스펙).
- FR-32: 포지션 배지: 포지션 약어(GK, CB, DM, AM, ST 등 — 목록은 도메인 스펙) + 줄(GK / 수비 / 미드필드 / 공격) 색. 약어 텍스트가 항상 있어 색 없이도 읽힌다. 주 포지션과 가능 포지션을 구분 표시한다 (채움 vs 외곽선 [제안]).
- FR-33: 폼 화살표: 최근 폼을 [제안] 5단계(크게 상승 / 상승 / 유지 / 하락 / 크게 하락) 방향 화살표로 보인다. 단계는 화살표 각도·개수로 구분되고 색은 보조다. 폼 값 계산은 도메인 스펙(015·025 등)이 제공.
- FR-34: 선수 비교 뷰: 두 선수(또는 선수 vs 이전 시즌의 자기 자신)를 나란히 놓고 능력치별로 차이를 보인다. 더 높은 쪽 표시는 색 + 부호/화살표. 레이더 차트(research 07 § 5.2)는 비교 뷰의 선택 표시 [제안].
- FR-35: 데이터 테이블: 열 머리글 클릭으로 오름/내림 정렬(정렬 방향 표시), 같은 값은 이전 순서 유지(안정 정렬), 필터(칩·검색어), 열 표시/숨김, 스크롤 중 머리글 고정, 행 호버·선택, 행 더블클릭 또는 Enter로 상세 열기, 방향키 행 이동. 정렬은 **표시값** 기준이다 (내부값으로 정렬해 숨은 정보를 드러내지 않는다).
- FR-36: 전술판: 피치 도식 위에 포메이션 슬롯 11개를 토큰(포지션 약어 또는 등번호 [미정])으로 놓는다. 내 선수 토큰은 강조색으로 구분하고, 토큰에 호버하면 툴팁(이름·역할), 클릭하면 선수 카드. 표시·조회 전용 [제안]. 포메이션·슬롯 좌표는 팀 형태 데이터(009 등)가 제공.
- FR-37: 탭: 한 화면 안의 하위 보기 전환 (예: 프로필 — 능력치 / 기록 / 계약). Ctrl+Tab [제안] 또는 탭 단축키로 전환. 선택한 탭은 화면을 다시 열어도 유지 [제안].
- FR-38: 툴팁: 마우스 호버 [제안] 0.4초 후, 또는 키보드 포커스 시 표시. 화면 가장자리에서는 안쪽으로 뒤집혀 잘리지 않는다. 능력치·약어·아이콘에는 툴팁 설명을 단다.
- FR-39: 컨텍스트 메뉴: 표 행·선수 카드·전술판 토큰에서 우클릭, 또는 키보드(Shift+F10·메뉴 키)로 연다. 항목은 해당 대상에 할 수 있는 동작(비교, 상세, 메시지 보내기 등 — 항목은 화면 스펙이 정함). 화면 가장자리에서 잘리지 않고, Esc·바깥 클릭으로 닫힌다.

### 마이크로 인터랙션 · 모션 · 문구
- FR-40: 패널 등장·화면 전환·버튼 눌림·호버·카운트업·토스트의 시간·이징은 모션 토큰. 모션은 짧게 [제안] 120~250ms (정보 화면은 기다리게 하지 않는다).
- FR-41: "모션 줄이기" 설정을 켜면 카운트업은 즉시 최종 값, 등장 애니메이션은 페이드 또는 즉시 전환으로 바뀐다 (research 07 § 5.3).
- FR-42: 성공 동작(계약 서명 등)의 **성공 피드백 지점**을 정의한다. 그 지점과 컴포넌트 이벤트(눌림·선택 패널·카운트업)에 붙는 소리는 052가 정한다. PC에는 햅틱이 없다 (휴대 PC 게임패드 진동 여부는 [미정]).
- FR-43: 안내 문장은 짧은 대화체 한 줄 (기획서 4.9: "이번 주 훈련을 골라주세요", "에이전트가 새 제안을 가져왔어요"). 문구 작성 규칙을 문서로 남기고, 화면 제목·버튼·빈 상태에 적용한다. 표 머리글·능력치 이름은 짧은 명사형.

- FR-50: 화면에 보이는 모든 문자열은 키로 참조한다. 하드코딩 문자열은 정적 검사로 0.

- FR-55: 언어 전환은 재시작 없이 반영된다.

### 접근성
- FR-60: 텍스트 대비: 본문 4.5:1 이상, 큰 텍스트·아이콘·능력치 구간 색 위 숫자 3:1 이상 [제안] (WCAG AA 기준). 다크 테마 기준.
- FR-61: 클릭할 수 있는 요소의 최소 크기 [제안] 24×24px (UI 배율 1.0 기준, 마우스 기준. 옛 터치 기준 44pt는 폐기). 표 행 전체를 클릭 영역으로 한다.
- FR-62: 텍스트 크기 배율 3단계 [제안] (100%, 115%, 130%). 130%에서도 겹침·잘림 0. UI 배율(FR-81)과 별개.
- FR-63: 상승/하락, 능력치 구간, 폼, 포지션 줄, 카드(경고·퇴장)는 색만으로 구분하지 않는다. 숫자·화살표·부호·모양을 같이 쓴다 (research 07 § 5.3).
- FR-64: 마우스 없이 키보드만으로 모든 동작에 도달할 수 있다. 포커스 순서는 화면별로 명시하고, 포커스 링(강조색)이 보인다 (research 07 § 5.2). 게임패드(휴대 PC)는 같은 포커스 이동을 따른다 [제안].
- FR-65: 버튼·선택지·핵심 수치·표 셀에 스크린리더 라벨을 단다 (research 07 § 5.3). 지원 범위는 [미정] (macOS VoiceOver, Windows Narrator).

### 키보드 · 단축키
- FR-66: 전역 단축키 [제안]: Esc = 닫기/뒤로, Space 또는 Enter = 진행 버튼(상단바, 예: "다음 주로"), Tab / Shift+Tab = 포커스 이동, 방향키 = 표·그리드·목록 안 이동, 1~9 = 선택 패널 선택지, Ctrl+F = 현재 표 검색, F1 = 단축키 목록 보기. 사이드 내비 섹션 단축키는 [미정]. 키 목록은 채택 (2026-11-11, 측정 후 조정).
- FR-67: 단축키는 화면 맥락별로 정의하고, 같은 맥락 안에서 한 키가 두 동작에 묶이지 않는다. 텍스트 입력에 포커스가 있으면 한 글자 단축키는 꺼진다. 단축키 바꾸기(리바인딩) 지원 여부는 [미정].
- FR-68: 단축키가 있는 버튼은 툴팁에 단축키를 표시한다.

### 렌더 빈도 · 배터리
- FR-70: 메뉴·매니지먼트 화면의 목표 프레임은 30fps (기획서 5.5.1). 메뉴에서는 3D 씬을 언로드한다 (CLAUDE.md "그래픽", 048). 앱 상태별 렌더 정책과 유휴 수치(2초 후 ≤ 10프레임/초, 입력 후 다음 프레임 복귀)의 원본은 048 FR-10~11이다. 이 스펙은 UI가 그 정책에 '애니메이션 중' 신호를 정확히 주는 것을 책임진다.
- FR-71: 입력과 애니메이션이 없으면 048 정책대로 렌더 간격이 늘어난다. 입력(마우스 이동·호버 포함)이 들어오거나 UI 애니메이션(카운트업·패널 등장·토스트·화면 전환)이 시작되면 그 프레임에 '애니메이션 중' 신호를 올려 다음 프레임부터 정상 빈도로 돌아오게 한다 (입력 지연 체감 없음).
- FR-72: 애니메이션(카운트업, 패널 등장)이 도는 동안은 렌더 빈도를 낮추지 않는다.

### 해상도 · UI 배율
- FR-80: 레이아웃은 000의 PC 프로필 해상도 범위(1280×800 ~ 3840×2160, 16:10 ~ 21:9)에서 겹침·잘림·화면 밖 요소가 0이다. 최소 지원 창 크기 [제안] 1280×720.

### 컴포넌트 갤러리

## 경계 · 예외 상황
- 핵심 수치: 0, 음수(빚·하락), 매우 큰 값(10억 이상 → FR-52 축약), 소수(평점 6.85 → 표시 자릿수 [제안] 1자리), 값이 같으면 카운트업 없음, 카운트업 도중 값이 또 바뀌면 현재 표시값에서 새 값으로 이어간다(처음부터 다시 하지 않음).
- 증감: 이전 값이 없으면(첫 표시) 증감 숨김. 0 변화는 중립 표시.
- 능력치: 표시값 범위 밖(0, 21 이상, 정수 아님) 입력은 경고 로그 + 가장 가까운 유효값으로 표시. 드러나지 않은 능력치는 정렬 시 맨 뒤.
- 데이터 테이블: 0행(빈 상태), 5,000행, 필터 결과 0행(필터 해제 동작 제공), 모든 열 숨김 시도(최소 1열은 남김), 정렬 중 데이터 갱신(정렬 유지), 표시값이 같고 내부값이 다른 행(표시값 기준 동률로 취급, 이전 순서 유지).
- 선택 패널·모달: 선택지 0개(오류 → 닫기만 가능한 오류 패널), 1개, 20개 이상(스크롤), 열린 상태에서 다른 패널·모달 요청(대기열, 동시에 둘 열리지 않음), 등장 애니메이션 도중 닫기 요청, 닫기 불가 패널에서 Esc·뒤로 가기·바깥 클릭 무시, 선택지 10개 이상일 때 숫자 키는 1~9까지만(나머지는 방향키).
- 툴팁·컨텍스트 메뉴: 화면 네 모서리에서 열기(안쪽으로 뒤집힘), 메뉴가 열린 채 창 크기 변경(닫힘 [제안]), 툴팁 대상이 스크롤로 사라짐(툴팁 닫힘).
- 전술판: 포메이션 슬롯이 11개가 아님(경고 + 있는 슬롯만 표시), 퇴장으로 10명 이하, 토큰 위치가 겹치는 포메이션(최소 간격으로 밀어냄 [제안]).
- 버튼: 연타(두 번 실행 금지), 눌린 채 밖으로 드래그(취소), 로딩 중 클릭(무시).
- 상승/하락 색 쌍·언어·텍스트 배율·UI 배율을 패널·애니메이션 도중 바꿔도 깨지지 않는다.
- 긴 문자열: 공백 없는 긴 단어(en 합성어, URL 형태) 말줄임, 한 줄 제목 2줄 넘침, 숫자+단위 줄바꿈 금지(값과 단위가 갈라지지 않음), 표 셀 말줄임 + 툴팁.
- 빈 목록·로딩 실패·문자열 키 누락·글꼴 글리프 누락(□ 표시 0).
- 창 크기를 실행 중에 바꿔도 레이아웃이 다시 계산된다 (사이드 내비 접힘 경계 포함).

## 수용 기준
E2E는 `mac-m1-1600p` 1프로필 스크린샷 + 사용자 육안 승인이다 (2026-11-11, 기준 이미지 비교 없음). 해상도 차이는 같은 기기에서 창 크기·UI 배율을 바꿔 확인한다.

- AC-01 [로직]: 정적 검사가 컴포넌트·화면 스타일 전체에서 토큰 아닌 색·간격·라운드 값 0개, 하드코딩된 화면 문자열 0개를 보고한다. 일부러 넣은 색 코드 1개는 위반으로 잡힌다.
- AC-02 [로직]: 다크 테마의 모든 텍스트/바탕 토큰 쌍 대비가 본문 4.5:1, 큰 텍스트 3:1 이상이고, 능력치 구간 색 위 숫자가 3:1 이상이다. 강조색 토큰은 정확히 1개이고 색상(hue)이 청록·시안 범위([제안] 170°~200°)다. 상승/하락 두 쌍(초록/빨강 기본, 빨강/파랑 대체) 모두 대비 기준을 넘는다. 바탕 계층 4단계는 단계마다 명도가 증가한다.
- AC-03 [로직]: 능력치 구간 색의 인접 구간 쌍, 상승/하락 색 쌍이 적색약·녹색약·청색약 시뮬레이션 변환 후에도 색차 [제안] ΔE2000 ≥ 10이다.
- AC-04 [로직]: 표시값 1~20이 각각 4구간 중 정확히 한 구간에 매핑되고 경계값(6/7, 12/13, 16/17 — [제안] 경계 기준)이 맞다. 0·21·소수 입력은 경고 로그 1건 + 가장 가까운 유효값 구간으로 표시된다.
- AC-05 [E2E]: `e2e/037-gallery`를 `mac-m1-1600p`에서 다크 × (ko / en)로 실행하면 모든 캡처에서 `겹침 없음`·`잘림 없음` 단언이 통과하고, 스크린샷을 사용자가 육안 승인한다.
- AC-06 [E2E]: `e2e/037-resize`: `mac-m1-1600p`에서 창 크기를 1280×800 → 1366×768 → 1920×1080 → 2560×1080으로, UI 배율을 80% / 100% / 150%로 바꾸면 각 상태에서 레이아웃이 다시 계산되고 겹침·잘림 0이다. 1366 이하에서 사이드 내비가 접히고, 2560×1080에서 늘어난 폭이 표 열·보조 패널에 쓰이며 본문 문단은 최대 폭을 넘지 않는다.
- AC-07 [로직]: 핵심 수치 카운트업: 1,000 → 1,500 변화 시 중간 값이 단조 증가하고 최종 값이 정확히 1,500이다. 도중에 2,000으로 바뀌면 현재 표시값에서 2,000으로 이어간다. 같은 값이면 애니메이션이 시작되지 않는다. 모션 줄이기 켜면 즉시 최종 값.
- AC-08 [E2E]: `e2e/037-countup`: 카운트업 진행 중·종료 캡처에서 숫자 폭이 변하지 않는다(고정폭 숫자). 증가는 상승 색 + ▲ 부호, 감소는 하락 색 + ▼ 부호다(기본 초록/빨강). 설정에서 빨강/파랑으로 바꾸면 재시작 없이 다음 카운트업부터 새 색 쌍이 보인다.
- AC-09 [E2E]: `e2e/037-choice-panel`: 선택지 3개 선택 패널이 뜨고, 뒤 화면이 딤 처리되며 뒤 화면 버튼을 클릭해도 반응하지 않는다. 숫자 키 2를 누르면 두 번째 선택지가 선택된다. 선택지 25개 패널은 패널 안에서 스크롤되고 방향키로 마지막 항목까지 도달한다. 닫기 불가 패널은 Esc·뒤로 가기·바깥 클릭에 닫히지 않는다.
- AC-10 [로직]: 선택 패널이 열린 상태에서 패널·모달 2개를 더 요청하면 하나씩 순서대로 열리고 동시에 둘이 열리지 않는다. 선택지 0개 요청은 오류 패널로 바뀐다. 선택지 12개 패널에서 숫자 키는 1~9만 반응한다.
- AC-11 [로직]: 버튼을 50ms 간격으로 3회 연타해도 동작은 1회만 실행된다. 로딩 중 클릭은 무시된다.
- AC-12 [E2E]: 버튼 호버 캡처에서 호버 상태가 기본 상태와 구분되고, 눌림 순간 캡처에서 버튼 크기가 원래의 0.97배(±0.005)다.
- AC-13 [로직]: 데이터 테이블: 열 정렬이 표시값 기준 안정 정렬이다(같은 표시값은 이전 순서 유지, 내부값이 달라도 순서가 바뀌지 않는다). 오름→내림→오름 전환이 맞다. 필터 2개 조합 결과가 각 필터 결과의 교집합이다. 모든 열 숨김 시도 시 1열이 남는다. 정렬 중 데이터가 갱신되어도 정렬이 유지된다.
- AC-14 [E2E]: `e2e/037-data-table`: 5,000행 표에서 열 머리글 클릭 시 정렬 방향 표시가 바뀌고, 필터 칩 적용·해제, 열 숨김, 스크롤 중 머리글 고정, 방향키 행 이동, 행 우클릭 컨텍스트 메뉴가 각각 캡처에 보인다. 필터 결과 0행이면 빈 상태 + 필터 해제 동작이 보인다.
- AC-15 [E2E]: `e2e/037-player-components`: 선수 카드 3크기, 능력치 그리드(1~20 전 구간), 능력치 막대, 포지션 배지 전 종류(주/가능 구분), 폼 화살표 5단계, 선수 비교 뷰가 캡처된다. 같은 장면을 흑백 변환한 캡처에서도 능력치·폼·포지션·증감이 숫자·화살표·약어로 읽힌다 (사용자 육안 승인).
- AC-16 [로직]: 전술판: 포메이션 슬롯 11개가 모두 피치 안 좌표로 변환되고 토큰끼리 최소 간격 [제안] 이상 떨어진다. 슬롯 10개(퇴장) 입력은 10개만 그리고, 11개가 아닌 입력은 경고 로그를 남긴다.

- AC-18 [E2E]: `e2e/037-overlays`: 툴팁이 호버 [제안] 0.4초 후와 키보드 포커스 시 뜨고, 화면 네 모서리 대상에서 안쪽으로 뒤집혀 잘리지 않는다. 컨텍스트 메뉴가 우클릭과 Shift+F10으로 열리고 모서리에서 잘리지 않으며 Esc로 닫힌다. 확인 모달이 열리면 Tab 포커스가 모달 밖으로 나가지 않고, 닫으면 연 요소로 포커스가 돌아온다.

- AC-22 [E2E]: `e2e/037-text-scale`: 텍스트 배율 130%로 갤러리·데이터 테이블을 캡처하면 겹침·잘림 0이고 값과 단위가 갈라지지 않는다.
- AC-23 [로직]: 갤러리의 클릭할 수 있는 모든 요소가 UI 배율 1.0 기준 24×24px 이상이다. 모든 버튼·선택지에 스크린리더 라벨이 비어 있지 않다.
- AC-24 [E2E]: `e2e/037-keyboard-focus`: 마우스 없이 키보드만으로 갤러리의 모든 버튼·선택지·표 행·탭·사이드 내비 항목에 포커스가 도달하고, 포커스 링이 캡처에 보인다. 포커스 순서가 명시된 순서와 같다. F1로 단축키 목록이 뜬다.
- AC-25 [로직]: 단축키 표에서 같은 맥락 안에 중복 키가 0개다. 텍스트 입력에 포커스가 있으면 한 글자 단축키(1~9 등)가 동작하지 않는다. 단축키가 있는 버튼의 툴팁에 단축키가 표시된다.
- AC-26 [성능]: 갤러리 애니메이션 구간 p95 프레임 시간 ≤ 33.3 ms(mac-m1-1600p 기록), 메인 스레드 p95 ≤ 8 ms(IL2CPP 벤치 판정).
- AC-27 [성능]: 입력 없이 2초가 지나면 렌더 프레임이 초당 10회 이하로 떨어지고, 키 입력·마우스 이동 후 다음 프레임에 정상 빈도로 돌아온다. 카운트업·패널 애니메이션 중에는 낮아지지 않는다. 메뉴 화면에서 3D 씬이 로드되어 있지 않다.
- AC-28 [성능]: 5,000행 데이터 테이블을 끝까지 스크롤하는 구간에서 p95 ≤ 33.3 ms, 스크롤 중 프레임당 GC 0 B. 5,000행 정렬·필터 적용 ≤ 50 ms(IL2CPP 벤치).
- AC-29 [성능]: UI 배율 전환 ≤ 100 ms, 언어 전환 ≤ 200 ms (mac-m1-1600p).
