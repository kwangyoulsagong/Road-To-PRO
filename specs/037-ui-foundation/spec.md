# 037 — UI 기반: 디자인 토큰 · 컴포넌트 · 다크 모드 · 현지화

상태: 초안
브랜치: feat/037-ui-foundation
기획 출처: docs/index.html § 기획서 4.9(UI 디자인 방향, 확정), § 4.10(라이프 탭 쇼핑 카드·메신저형), § 5.5.1(배터리 정책: 메뉴 30fps·OnDemandRendering), § 2.2(현지화) / research 07 § 5.2(매니지먼트 화면 구현 관례), § 5.3(접근성)

## 배경
이 게임은 숫자와 선택이 많다. 화면이 수십 개로 늘어나도 같은 모양·같은 간격·같은 동작이어야 읽기 쉽고 버그가 적다. 그래서 모든 화면이 공통으로 쓰는 **디자인 토큰**(색·간격·라운드·글꼴·모션)과 **기본 컴포넌트**(카드, 큰 숫자, 버튼, 바텀시트, 목록, 토스트, 탭바), 라이트/다크 테마, 현지화, 접근성 기반을 먼저 만든다. 개별 화면(038, 039)은 이것만 조립한다.

## 범위
- 포함:
  - 디자인 토큰 세트와 라이트/다크 두 테마 값
  - 기본 컴포넌트: 카드, 큰 숫자(카운트업 포함), 증감 표시, 기본/보조/위험 버튼, 바텀시트(선택지 목록), 목록(가상화), 탭바·상단바, 토스트, 빈 상태, 로딩 상태, 확인 시트, 진행 막대, 별점(★1~5) 표시, 칩(태그)
  - 화면 전환·시트 슬라이드·버튼 눌림 마이크로 인터랙션
  - 현지화 기반: 문자열 키, 언어 전환, 숫자·통화·날짜 형식, 긴 문자열 대응 규칙
  - 접근성 기반: 대비, 최소 터치 영역, 텍스트 크기 배율, 모션 줄이기, 키보드·게임패드 포커스 이동, 스크린리더 라벨
  - UI 화면 렌더 빈도 정책(메뉴 30fps, 입력 없을 때 렌더 간격 늘리기)
  - 컴포넌트 갤러리 화면(개발용, E2E 기준 이미지 대상)
- 제외:
  - 개별 매니지먼트 화면(038), 경기 HUD(039), 2D 매치뷰(040), 에디터(049)
  - 3D 씬 로드·언로드 정책 자체(048이 제공. 이 스펙은 UI 쪽 렌더 빈도만)
  - 번역문 작성(키와 형식만. en 문자열은 E2E 검증용 최소 세트)
  - 모바일 햅틱 구현(모바일 포팅 시점. 이 스펙은 "성공 시 햅틱 호출 지점"만 정의)

## 사용자 시나리오
1. 플레이어가 어떤 화면을 열어도 밝은 회색 바탕 위 흰 카드, 가장 중요한 숫자가 가장 크게 보인다.
2. 연봉이 오르면 숫자가 이전 값에서 새 값으로 올라가는 카운트업이 보이고, 오른 폭이 상승 색으로 표시된다.
3. 인터뷰 답변을 고를 때 화면 아래에서 시트가 올라오고, 선택지를 누르면 살짝 눌렸다가 시트가 내려간다.
4. 설정에서 다크 모드를 켜면 모든 화면이 즉시 어두운 테마로 바뀌고, 다시 켜도 같은 화면에서 같은 위치를 유지한다.
5. 언어를 English로 바꾸면 긴 문장도 잘리거나 겹치지 않고 줄바꿈되거나 말줄임 처리된다.

## 요구사항

### 디자인 토큰
- FR-01: 모든 색·간격·라운드·글꼴 크기·글꼴 굵기·그림자·모션 시간·이징은 토큰으로만 정의한다. 컴포넌트·화면 스타일에서 토큰이 아닌 직접 값(색 코드, px 간격)은 금지한다. 정적 검사로 위반을 0으로 유지한다.
- FR-02: 색 토큰 (의미 이름으로, 테마별 값):
  - 바탕(밝은 회색), 카드(흰색), 카드 위 구분선, 본문 텍스트, 보조 텍스트, 비활성 텍스트
  - **포인트 컬러는 블루 하나** (버튼·강조·선택 상태·링크). 다른 강조색을 추가하지 않는다 (기획서 4.9)
  - 의미색: 상승, 하락, 경고, 위험(파괴적 동작). 상승/하락 색 쌍은 [미정] (기획서 4.9: "빨강/파랑 또는 초록/빨강"). 테마 설정에서 전환 가능해야 하며, 기본값은 [미정]
  - 오버레이(시트 뒤 딤), 포커스 링
- FR-03: 라운드 토큰: 카드 16~20px 범위 안의 값 (기획서 4.9). 기본 카드 [제안] 18px, 시트 상단 [제안] 20px, 버튼·칩은 별도 토큰.
- FR-04: 그림자는 "거의 없음" (기획서 4.9). 카드 구분은 바탕과의 명도 차로 하고, 그림자 토큰은 최대 1단계 [제안].
- FR-05: 간격 토큰은 4px 배수 단계 [제안] (4, 8, 12, 16, 20, 24, 32, 40). 화면 좌우 여백, 카드 안 여백, 카드 사이 간격은 각각 토큰.
- FR-06: 글꼴: 가독성 좋은 산세리프, OFL 라이선스 (Pretendard 또는 Noto Sans KR, 기획서 4.9). 어느 쪽인지는 [미정]. 숫자는 고정폭 숫자(tabular figures)로 표시해 카운트업 중 폭이 흔들리지 않는다. 글꼴 파일은 `Art/LICENSES.csv`에 기록한다.
- FR-07: 글자 크기 단계: 큰 숫자(화면 최상위 수치) > 제목 > 소제목 > 본문 > 보조 > 캡션. "연봉, 시장가치, 평점, 신뢰도"는 화면에서 가장 큰 단계를 쓴다 (기획서 4.9).

### 테마
- FR-10: 라이트/다크 두 테마. 시스템 설정 따르기 / 라이트 / 다크 중 선택. 선택은 설정에 저장된다.
- FR-11: 테마 전환은 화면을 다시 만들지 않고 즉시 반영되며, 스크롤 위치·열린 시트·입력 중 텍스트를 유지한다.
- FR-12: 다크 테마에서도 포인트 블루는 하나이고, 의미색은 다크 바탕 대비 기준을 만족하도록 테마별 값을 가진다.

### 컴포넌트
- FR-20: 카드: 제목(선택), 본문 슬롯, 하단 동작(선택). 누를 수 있는 카드와 아닌 카드를 구분 표시한다.
- FR-21: 큰 숫자: 값, 단위(통화·%·점), 증감(이전 값 대비 차이와 방향 색). 값이 바뀌면 카운트업 애니메이션 (기획서 4.9). 지속 시간 [제안] 0.6초, 변화폭이 작으면 짧게. 화면에 처음 들어올 때는 카운트업하지 않는다 [제안] (변화가 있을 때만).
- FR-22: 버튼: 기본(블루 채움), 보조(외곽선 또는 옅은 바탕), 텍스트, 위험. 눌림 시 스케일 0.97 (기획서 4.9). 비활성·로딩 상태. 연속 탭으로 동작이 두 번 실행되지 않는다.
- FR-23: 바텀시트: 화면 아래에서 슬라이드로 올라온다 (기획서 4.9). 제목(대화체 한 줄), 선택지 목록(각 항목: 제목, 부연 한 줄, 선택 시 예상 결과 표시 슬롯), 닫기 가능 여부 설정(키 모먼트·필수 선택은 닫기 불가). 선택지가 화면 높이를 넘으면 시트 안에서 스크롤한다. 뒤 화면은 딤 처리되고 입력을 막는다.
- FR-24: 목록: 수천 행에서도 끊기지 않도록 보이는 행만 그린다 (research 07 § 5.2: 선수 목록·스카우팅 리포트 수백~수천 행). 정렬 머리글, 빈 상태, 로딩 상태.
- FR-25: 토스트: 짧은 알림 한 줄, 자동 사라짐 [제안] 2.5초, 동시에 여러 개면 순서대로.
- FR-26: 빈 상태·오류 상태: 대화체 한 줄 + 선택 동작. 데이터가 없을 때 빈 카드나 0 대신 이 상태를 보인다.
- FR-27: 별점 표시(★1~5, 반 개 단위 여부 [미정]), 진행 막대(0~100), 칩, 증감 화살표.
- FR-28: 탭바·상단바: 현재 위치 표시, 뒤로 가기. 탭 수는 [미정] (038에서 화면 목록 확정 후).

### 문장 · 문구
- FR-30: 안내 문장은 짧은 대화체 한 줄 (기획서 4.9: "이번 주 훈련을 골라주세요", "에이전트가 새 제안을 가져왔어요"). 문구 작성 규칙을 문서로 남기고, 화면 제목·버튼·빈 상태에 적용한다.

### 마이크로 인터랙션 · 모션
- FR-40: 시트 슬라이드, 화면 전환, 버튼 눌림, 카운트업, 토스트 등장의 시간·이징은 모션 토큰.
- FR-41: "모션 줄이기" 설정을 켜면 카운트업은 즉시 최종 값, 슬라이드는 페이드 또는 즉시 전환으로 바뀐다 (research 07 § 5.3).
- FR-42: 성공 동작(계약 서명 등)에 햅틱을 요청하는 지점을 정의한다. 데스크톱에서는 아무 일도 하지 않는다. 같은 지점과 컴포넌트 이벤트(눌림·시트·카운트업)에 붙는 소리는 052가 정한다.

### 현지화
- FR-50: 화면에 보이는 모든 문자열은 키로 참조한다. 하드코딩 문자열은 정적 검사로 0.
- FR-51: 기본 언어 ko, 검증 언어 en. 이후 언어 목록은 [미정] (기획서 2.2: 영어 → 스페인어, 이탈리아어, 포르투갈어, 한국어 검토).
- FR-52: 숫자(천 단위 구분), 통화, 날짜(게임 날짜), 서수, 복수형은 언어별 형식 규칙을 따른다. **표시 포맷은 이 스펙이 단일 소유**: 큰 수 축약 ko `만·억`(예: 1.2억), en `K·M·B`(예: 12.4M) [제안 소수 1자리], 축약 기준 [제안] ≥ 1만(ko)·≥ 10,000(en). 통화 값·반올림 규칙은 032 FR-14 소유, 통화 이름·기호는 [미정].
- FR-53: 문자열 키가 없으면 기본 언어로 대체 표시하고 경고 로그를 남긴다 (검증 실행에서는 경고 = 실패, 000 FR-60).
- FR-54: 텍스트가 들어가는 모든 컴포넌트는 en 기준 ko 대비 [제안] 1.6배 길이에서도 겹치지 않는다 (줄바꿈 또는 말줄임 + 전체 문구 보기).
- FR-55: 언어 전환은 재시작 없이 반영된다.

### 접근성
- FR-60: 텍스트 대비: 본문 4.5:1 이상, 큰 텍스트·아이콘 3:1 이상 [제안] (WCAG AA 기준). 두 테마 모두.
- FR-61: 누를 수 있는 요소의 최소 영역 [제안] 44×44 pt (기준 배율 1.0에서 44px, 배율에 비례).
- FR-62: 텍스트 크기 배율 3단계 [제안] (100%, 115%, 130%). 130%에서도 겹침·잘림 0.
- FR-63: 상승/하락은 색만으로 구분하지 않는다. 화살표·부호를 같이 쓴다 (research 07 § 5.3: 색만이 아닌 텍스트 병기).
- FR-64: 키보드·게임패드로 모든 동작에 도달할 수 있다. 포커스 순서는 화면별로 명시하고, 포커스 링이 보인다 (research 07 § 5.2).
- FR-65: 버튼·선택지·숫자 카드에 스크린리더 라벨을 단다 (research 07 § 5.3: Unity 6 접근성 모듈). 지원 범위는 [미정] (macOS VoiceOver, Windows Narrator).

### 렌더 빈도 · 배터리
- FR-70: 메뉴·매니지먼트 화면의 목표 프레임은 30fps (기획서 5.5.1). 앱 상태별 렌더 정책과 유휴 수치(2초 후 ≤ 10프레임/초, 입력 후 다음 프레임 복귀)의 원본은 048 FR-10~11이다. 이 스펙은 UI가 그 정책에 '애니메이션 중' 신호를 정확히 주는 것을 책임진다.
- FR-71: 입력과 애니메이션이 없으면 048 정책대로 렌더 간격이 늘어난다. 입력이 들어오거나 UI 애니메이션(카운트업·시트·토스트·화면 전환)이 시작되면 그 프레임에 '애니메이션 중' 신호를 올려 다음 프레임부터 정상 빈도로 돌아오게 한다 (입력 지연 체감 없음).
- FR-72: 애니메이션(카운트업, 시트)이 도는 동안은 렌더 빈도를 낮추지 않는다.

### 해상도 · 배율
- FR-80: 레이아웃은 000의 모든 기기 프로필(1280×800 ~ 3840×2160, 4:3 ~ 21:9, 세로 화면)에서 겹침·잘림·화면 밖 요소가 0이다.
- FR-81: 넓은 화면(21:9, 4K)에서는 콘텐츠 최대 폭 [제안] 1200px(배율 1.0 기준)으로 가운데 정렬하고 양쪽은 바탕색이다.
- FR-82: 세로 화면(phone-portrait)에서는 카드가 한 열로 쌓인다.
- FR-83: DPI 배율(1.0 / 2.0 / 3.0)에서 글자와 아이콘이 흐리지 않다.

### 컴포넌트 갤러리
- FR-90: 개발용 갤러리 화면에 모든 컴포넌트의 모든 상태(기본·눌림·비활성·로딩·오류·빈 상태, 짧은/긴 문자열, 큰 숫자 증가/감소)를 배치한다. E2E 기준 이미지의 기준점이 된다. 출시 빌드에는 포함하지 않는다.

## 경계 · 예외 상황
- 큰 숫자: 0, 음수(빚·하락), 매우 큰 값(10억 이상 → 단위 축약 규칙 [미정]), 소수(평점 6.85 → 표시 자릿수 [제안] 1자리), 값이 같으면 카운트업 없음, 카운트업 도중 값이 또 바뀌면 현재 표시값에서 새 값으로 이어간다(처음부터 다시 하지 않음).
- 증감: 이전 값이 없으면(첫 표시) 증감 숨김. 0 변화는 중립 표시.
- 바텀시트: 선택지 0개(오류 → 닫기만 가능한 오류 시트), 1개, 20개 이상(스크롤), 시트가 열린 상태에서 또 다른 시트 요청(대기열, 동시에 둘 열리지 않음), 시트 애니메이션 도중 닫기 요청, 닫기 불가 시트에서 뒤로 가기·Esc 입력 무시.
- 버튼: 연타(두 번 실행 금지), 눌린 채 밖으로 드래그(취소), 로딩 중 탭(무시).
- 테마·언어·텍스트 배율을 시트·애니메이션 도중 바꿔도 깨지지 않는다.
- 긴 문자열: 공백 없는 긴 단어(en 합성어, URL 형태) 말줄임, 한 줄 제목 2줄 넘침, 숫자+단위 줄바꿈 금지(값과 단위가 갈라지지 않음).
- 빈 목록·로딩 실패·문자열 키 누락·글꼴 글리프 누락(□ 표시 0).
- 창 크기를 실행 중에 바꿔도 레이아웃이 다시 계산된다.

## 비기능 요구사항
- 결정론: UI는 시뮬 결과에 영향을 주지 않는다. 같은 픽스처·같은 입력이면 같은 화면(000 FR-21). 애니메이션은 캡처 시점에 끝난 상태로 고정 가능해야 한다(000 FR-23).
- 세이브 호환: 테마·언어·텍스트 배율·모션 줄이기 설정은 세이브가 아니라 사용자 설정에 저장한다.

## 수용 기준
- AC-01 [로직]: 정적 검사가 컴포넌트·화면 스타일 전체에서 토큰 아닌 색·간격·라운드 값 0개, 하드코딩된 화면 문자열 0개를 보고한다. 일부러 넣은 색 코드 1개는 위반으로 잡힌다.
- AC-02 [로직]: 라이트·다크 두 테마의 모든 텍스트/바탕 토큰 쌍 대비가 본문 4.5:1, 큰 텍스트 3:1 이상이다. 포인트 컬러 토큰은 테마마다 정확히 1개다.
- AC-03 [E2E]: 갤러리 시나리오 `e2e/037-gallery`를 전체 프로필 × (ko/en × light/dark)로 실행하면 모든 캡처에서 `겹침 없음`·`잘림 없음` 단언이 통과하고, 기준 이미지 차이가 임계값 이하다.
- AC-04 [E2E]: compact-1366, phone-portrait, uhd-4k-200 프로필에서 갤러리의 en 긴 문자열 항목이 줄바꿈 또는 말줄임으로 표시되고 부모 밖으로 넘치지 않는다. 값과 단위가 다른 줄로 갈라지지 않는다.
- AC-05 [E2E]: ultrawide-1080 프로필에서 콘텐츠 폭이 최대 폭 이하이고 가운데 정렬된다. phone-portrait에서는 카드가 한 열이다.
- AC-06 [로직]: 큰 숫자 카운트업: 1,000 → 1,500 변화 시 중간 값이 단조 증가하고 최종 값이 정확히 1,500이다. 도중에 2,000으로 바뀌면 현재 표시값에서 2,000으로 이어간다. 같은 값이면 애니메이션이 시작되지 않는다. 모션 줄이기 켜면 즉시 최종 값.
- AC-07 [E2E]: `e2e/037-countup`: 카운트업 진행 중·종료 캡처에서 숫자 폭이 변하지 않는다(고정폭 숫자). 증가는 상승 색 + ▲ 부호, 감소는 하락 색 + ▼ 부호다.
- AC-08 [E2E]: `e2e/037-bottomsheet`: 선택지 3개 시트가 아래에서 올라오고, 뒤 화면이 딤 처리되며 뒤 화면 버튼을 눌러도 반응하지 않는다. 선택지 25개 시트는 시트 안에서 스크롤되고 마지막 항목까지 도달한다. 닫기 불가 시트는 Esc·뒤로 가기에 닫히지 않는다.
- AC-09 [로직]: 시트가 열린 상태에서 시트 2개를 더 요청하면 하나씩 순서대로 열리고 동시에 둘이 열리지 않는다. 선택지 0개 시트 요청은 오류 시트로 바뀐다.
- AC-10 [로직]: 버튼을 50ms 간격으로 3회 연타해도 동작은 1회만 실행된다. 로딩 중 탭은 무시된다.
- AC-11 [E2E]: 버튼 눌림 순간 캡처에서 버튼 크기가 원래의 0.97배(±0.005)다.
- AC-12 [E2E]: 시트가 열리고 목록이 중간까지 스크롤된 상태에서 테마를 바꾸면, 스크롤 위치·시트 상태가 유지되고 모든 색이 다크 토큰 값으로 바뀐다 (`e2e/037-theme-switch`).
- AC-13 [E2E]: 언어를 ko → en으로 바꾸면 재시작 없이 모든 보이는 문자열이 바뀌고, 숫자 형식(천 단위 구분)이 언어 규칙을 따른다.
- AC-14 [로직]: 없는 문자열 키를 요청하면 ko로 대체 표시되고 경고 로그 1건이 남는다. 검증 실행에서 이 경고는 실패로 집계된다.
- AC-15 [E2E]: 텍스트 배율 130%로 갤러리 전체 프로필 실행 시 겹침·잘림 0 (smoke 프로필 + phone-portrait).
- AC-16 [로직]: 갤러리의 누를 수 있는 모든 요소가 배율 1.0 기준 44×44px 이상이다. 모든 버튼·선택지에 스크린리더 라벨이 비어 있지 않다.
- AC-17 [E2E]: 키보드만으로 갤러리의 모든 버튼·시트 선택지에 포커스가 도달하고, 포커스 링이 캡처에 보인다. 포커스 순서가 명시된 순서와 같다.
- AC-18 [성능]: low-igpu-1080p에서 갤러리 애니메이션 구간 p95 프레임 시간 ≤ 33.3 ms, 메인 스레드 p95 ≤ 8 ms.
- AC-19 [성능]: 입력 없이 2초가 지나면 렌더 프레임이 초당 10회 이하로 떨어지고, 키 입력 후 다음 프레임에 정상 빈도로 돌아온다. 카운트업·시트 애니메이션 중에는 낮아지지 않는다.
- AC-20 [성능]: 5,000행 목록을 끝까지 스크롤하는 구간에서 p95 ≤ 33.3 ms, 스크롤 중 프레임당 GC 0 B.
- AC-21 [성능]: 테마 전환 ≤ 100 ms, 언어 전환 ≤ 200 ms (mac-m1-1600p).
- AC-22 [E2E]: 실행 중 창 크기를 1920×1080 → 1366×768 → 2560×1080으로 바꾸면 각 크기에서 레이아웃이 다시 계산되고 겹침·잘림 0이다.
- AC-23 [E2E]: 모든 언어 문자열 렌더 캡처에서 누락 글리프(□)가 0이다 (ko 전체 문자열 세트 + en).
