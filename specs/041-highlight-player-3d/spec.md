## 배경
경기는 90분 전체를 백그라운드에서 시뮬레이션하고, 플레이어는 하이라이트 장면만 3D로 본다(확정). 경기 1회 시청은 1.5배속 기준 약 2~3분이어야 한다(기획서 4.4). 이 스펙은 "선정된 장면 목록을 받아 3D로 재생하는 플레이어"를 정의한다. 재생은 시뮬 결과를 **읽기만** 하고 절대 바꾸지 않는다. 장면이 바뀔 때 끊기거나 멈칫하면 몰입이 깨지므로 프레임 스파이크 없는 전환이 핵심이다.

## 범위
- 포함:
  - 하이라이트 장면 목록(018이 제공)을 순서대로 3D 재생
  - 재생 속도 1x / 1.5x(기본) / 2x / 3x 전환, 리플레이 0.5x 슬로모
  - 재생 제어: 일시정지·재개, 다음 장면 건너뛰기, 남은 장면 모두 건너뛰기(결과 화면으로)
  - 장면 사이: 텍스트 타임라인·미니맵 구간으로 빠르게 넘기기(039가 화면 제공, 이 스펙은 전환 타이밍만)
  - 키 모먼트 지점에서 재생 일시정지 → 선택 화면 호출 → 결과에 따라 이어서 재생(선택·재시뮬 자체는 019)
  - 3D 씬 로드·언로드 수명 주기: 하이라이트 진입 시 로드, 매니지먼트로 복귀 시 언로드
  - 장면 전환 프리로드·셰이더 워밍업으로 스파이크 제거
  - 독립 재생 시계(슬로모·배속이 시뮬·UI 시간에 영향 없음)
- 제외:
  - 하이라이트 선정 알고리즘·장면 점수 (018)
  - 카메라 컷·앵글 연출, 리플레이 앵글 배치 (042)
  - 선수 모델·애니메이션 선택·보간 (043)
  - 경기장·관중·사운드 (044, 045, 046)
  - 품질 프리셋·배터리 모드 정의 (048이 제공, 이 스펙은 따르기만)
  - 풀경기 시청 (확정 결정상 만들지 않음)
- 대체 입력 (2026-11-09 사용자 결정): 018·019·039·042·045·046·048이 아직 없으므로 고정 장면 목록, 고정 키 모먼트 응답, 검증용 HUD, 고정 방송 시점, 고정 프레임 정책으로 대체해 이 스펙의 FR 전체를 구현한다. 대체물로 판정할 수 없는 AC만 보류하고, 해당 스펙을 연결할 때 재확인한다.

## 사용자 시나리오
1. 경기 시작을 누르면 짧은 로딩 후 첫 하이라이트 장면이 1.5배속으로 재생된다. 화면 구석에 현재 속도 `1.5x`가 보인다.
2. 골 장면이 끝나면 같은 골이 0.5x 슬로모로 다른 각도에서 2~3번 다시 나온다.
3. 장면과 장면 사이에는 "34' 코너킥 … 41' 슈팅 빗나감" 같은 타임라인이 빠르게 지나가고 다음 장면으로 끊김 없이 넘어간다.
4. 67분에 내 선수 앞에 뒷공간이 열리면 화면이 멈추고 바텀시트 선택지가 뜬다. 고르면 그 결과로 이어진 장면이 재생된다.
5. 2배속으로 바꾸고 남은 장면을 다 보면 결과 화면으로 넘어가고, 3D 씬이 내려가 메뉴가 가벼워진다.

## 요구사항

### 재생
- FR-01: 장면 목록(장면 id, 시작·끝 시뮬 시각, 리플레이 여부, 키 모먼트 여부, 우선순위)을 받아 순서대로 재생한다. 장면 구간 기본값은 이벤트 −8초 ~ +3초(아키텍처 4, research 07 § 2.4)이며 **구간은 018이 소유**한다(장면 최대 20 s, 골 세리머니 +6 s). 이 스펙은 받은 구간을 그대로 쓴다.
- FR-02: 재생 데이터는 006이 제공하는 SimEvent 스트림과 재구성 클립(006 FR-52~53: 체크포인트에서 임의 구간을 다시 계산한 엔티티 상태 스냅샷)만 읽는다. 장면별 클립은 하이라이트 진입 로딩 단계에서 미리 만들고 재생 중에는 재구성하지 않는다. 키 모먼트 재시뮬(019)로 장면 목록이 바뀌면 바뀐 장면의 클립을 같은 방식으로 다시 만든다. 재생 중 시뮬 상태·RNG·이벤트 로그를 변경하지 않는다.
- FR-03: 엔티티(선수 22명, 공, 심판 3명) 위치·회전은 리플레이 버퍼 샘플 사이를 보간해 렌더 프레임마다 부드럽게 보인다. 기록 주기는 30Hz (확정 (2026-11-02 사용자 결정)). 클립의 프레임 형식은 006이 소유한다. 006의 60초 링 버퍼는 90분 경기의 지난 장면을 담지 못하므로 재생 입력으로 쓰지 않는다.
- FR-04: 공은 보간 시 지면 아래로 내려가지 않고, 골망·골대를 통과해 보이지 않는다(접촉 순간 위치는 시뮬 값 그대로).

### 재생 속도
- FR-10: 재생 속도는 1x / 1.5x / 2x / 3x. 기본 1.5x(확정). **재생 속도 규칙의 원본은 이 스펙**이다. 값은 사용자 설정 하나에 저장되며, 경기 중 039 HUD에서 바꾼 값과 038 설정 화면의 '기본 재생 속도'는 같은 값이다(경기 중에 바꾸면 다음 경기에도 유지).
- FR-11: 리플레이 구간은 사용자 속도 설정과 무관하게 0.5x(확정). 슬로모 단계는 **0.5x 하나만** (확정 (2026-11-02 사용자 결정)) — research 07 § 2.3의 0.35x·0.25x는 쓰지 않는다.
- FR-12: 속도 변경은 재생 중 즉시 반영되며, 변경 순간에 위치가 튀지 않는다(재생 시계 연속). 포즈 튐 측정 기준은 054 FR-53.
- FR-13: 재생 시계는 시뮬 시계·UI 애니메이션 시계와 분리한다. 일시정지·배속이 UI 트랜지션 속도를 바꾸지 않는다.
- FR-14: 배속 시 애니메이션 재생 속도도 같이 오른다. 1.5x에서 자연스러운 모션은 043이 책임지고, 이 스펙은 애니메이션 시계에 같은 배속을 전달한다.
- FR-15: 오디오는 배속 시 피치가 변하지 않는다(타임스트레치 또는 이벤트 단위 재생은 046). 이 스펙은 재생 속도·일시정지 상태를 오디오에 전달한다.

### 제어
- FR-20: 일시정지·재개, 다음 장면, 모두 건너뛰기, 속도 변경. 키보드·마우스·터치 모두 지원(입력 매핑은 037 공통 규칙).
- FR-21: "모두 건너뛰기"를 제공한다 (확정 (2026-11-02 사용자 결정), 이 스펙이 동작의 원본). 남은 하이라이트의 3D 재생을 건너뛰고 3D 씬을 언로드한다. **키 모먼트는 건너뛰지 않는다**: 남은 키 모먼트마다 039 텍스트 타임라인 + 미니맵으로 상황을 보이고 바텀시트 선택을 받는다 (019 재시뮬 규칙 그대로). 장면 하나 건너뛰기는 키 모먼트 시점을 넘지 않는다(039 FR-23).
- FR-22: 키 모먼트 장면은 지정 시각에 정확히 멈추고(±1 렌더 프레임) 선택 화면을 띄운다. 선택이 결과를 바꾸면 019가 재계산한 이후 장면 목록으로 교체하고 이어서 재생한다.

### 전환과 로딩
- FR-30: 하이라이트 진입 시 3D 씬(경기장·선수·공·관중·사운드 뱅크)을 로드하고, 첫 장면 재생 전 셰이더 워밍업을 끝낸다. 로딩 화면은 진행률을 보여준다.
- FR-31: 다음 장면에 필요한 에셋(세리머니 애니메이션, 리플레이 카메라, 이펙트)은 현재 장면 재생 중에 미리 로드한다. 장면 전환 순간 메인 스레드에서 동기 로드·셰이더 컴파일이 일어나지 않는다.
- FR-32: 장면 사이 텍스트 타임라인 구간 동안 3D는 정지 화면 또는 렌더 중지(배터리). 정확한 방식은 048 정책을 따른다.
- FR-33: 결과 화면·매니지먼트로 돌아가면 3D 씬을 언로드하고 관련 메모리를 해제한다(확정: 메뉴는 3D 언로드). 언로드 후 목표 프레임레이트는 메뉴 값(048)으로 바뀐다.
- FR-34: 하이라이트 목표 fps는 모든 프리셋 60fps, 배터리 절약 모드에서만 30fps(아키텍처 8). 값 적용은 048이 제공.

### 표시
- FR-40: 화면 위에 현재 속도, 경기 시각(시뮬 분), 스코어는 039 HUD가 그린다. 이 스펙은 HUD에 재생 상태(장면 n/전체, 리플레이 여부, 속도)를 제공한다.
- FR-41: 리플레이 구간 여부·리버스 앵글 여부(042가 플래그 제공)를 HUD에 넘긴다. 와이프·'REPLAY'·'리버스 앵글' 표시를 그리는 것은 039 FR-05, 모양은 037 토큰.

### 경계 · 예외 상황
- FR-50: 장면 0개(무득점·무찬스 경기): 3D를 로드하지 않고 바로 결과 화면으로 간다. 로딩 화면이 보였다 사라지는 깜빡임이 없어야 한다.
- FR-51: 장면 구간이 경기 시작(0분) 이전이나 종료 이후로 넘어가면 경계에서 자른다. 하프타임을 걸치는 구간은 하프 경계에서 자른다.
- FR-52: 두 장면 구간이 겹치거나 이어지면 018이 병합한다. 그래도 겹쳐 들어오면 앞 장면의 끝을 뒤 장면 시작으로 당긴다(같은 순간을 두 번 재생하지 않음, 리플레이는 예외).
- FR-53: 해당 구간의 재구성 클립을 만들 수 없으면(체크포인트 범위 밖) 그 장면을 건너뛰고 경고 로그 대신 진단 이벤트를 남긴다. 006이 경기 전 구간의 재구성을 보장하므로 검증에서는 실패로 처리한다.
- FR-54: 재생 중 앱이 백그라운드로 가면 자동 일시정지. 복귀 시 일시정지 상태 유지.
- FR-55: 3x에서 렌더 프레임당 진행 시간이 커도 이벤트 큐(골망 흔들림, 휘슬, 관중 반응)는 빠짐없이 순서대로 발화한다. 같은 프레임에 여러 큐가 겹쳐도 순서는 시뮬 시각 순.
- FR-56: 일시정지 중 속도 변경 → 재개 시 새 속도로 재생. 리플레이 중 속도 변경 → 리플레이는 0.5x 유지, 리플레이 끝나면 새 속도.
- FR-57: 키 모먼트 선택 화면에서 앱 종료 → 다음 실행 시 019 규칙대로 복구(이 스펙은 재생 위치를 019에 넘긴다).
- FR-58: 로딩 중 취소(뒤로 가기) → 로드 중이던 에셋을 모두 해제하고 메뉴로. 메모리 누수 없음. 로딩 중 취소 외 입력은 무시한다(048 경계 규칙).
- FR-70: 진단 출력 켜기·끄기 (개발·검증 빌드): 재생 중 엔티티 루트 위치·접촉 프레임·포즈 샘플을 054 측정용으로 기록한다. 끄면 기록 비용 0 (GC 0 B). 출시 빌드에는 진입점 없음.
- FR-59: 배속 변경이 장면 전환 순간(앞 장면 마지막 프레임 ~ 다음 장면 첫 프레임)과 겹치면 새 속도는 다음 장면 첫 프레임부터 적용되고, 전환 구간 길이·큐 발화 순서는 바뀌지 않는다. 같은 프레임에 배속 변경과 건너뛰기가 함께 오면 건너뛰기를 먼저 처리한다.
- FR-5A: 장면 전환·리플레이 진입 중 일시정지 입력은 전환이 끝난 첫 프레임에 적용된다(전환 도중 반쯤 그려진 화면에서 멈추지 않음).

## 비기능 요구사항
- 결정론: 같은 경기 데이터·같은 장면 목록이면 재생 결과(각 렌더 시각의 엔티티 위치)가 동일. 재생이 시뮬 해시를 바꾸지 않는다.
- 해상도 독립: 프로필 해상도·품질 프리셋이 재생 타이밍·장면 순서에 영향을 주지 않는다.
- 세이브 호환: 재생 상태는 세이브에 넣지 않는다(키 모먼트 복구 위치만 019 경유).

## 수용 기준
- AC-01 [로직]: 장면 3개 목록을 넣으면 재생 순서가 목록 순서와 같고, 각 장면의 첫·마지막 재생 시뮬 시각이 지정 구간과 ±1 스냅샷 이내로 일치한다.
- AC-02 [결정론]: 같은 경기를 하이라이트 재생 전·후로 시뮬 해시를 비교하면 같다. 재생을 2회 반복해도 같다.
- AC-03 [로직]: 1.5x로 실제 시간 10초 재생하면 재생 시계가 15초 진행한다(±1 프레임). 1x/2x/3x도 같은 비율.
- AC-04 [로직]: 리플레이 구간은 사용자 속도가 3x여도 0.5x로 재생되고, 리플레이 종료 후 3x로 돌아간다.
- AC-05 [로직]: 재생 중 1.5x→3x로 바꾼 순간 앞뒤 렌더 프레임의 엔티티 위치 차이가 해당 속도의 1프레임 이동량을 넘지 않는다(튐 없음).
- AC-06 [로직]: 3x 재생에서 한 렌더 프레임에 이벤트 큐 5개가 겹치는 구간을 재생하면 5개 모두 시뮬 시각 순으로 1번씩 발화한다.
- AC-07 [로직]: 장면 0개 경기는 3D 씬 로드 요청이 0회이고 바로 결과 화면 상태로 간다.
- AC-08 [로직]: 경기 시작 −8초가 되는 1분 득점 장면은 0분에서 잘리고, 하프타임 걸침 구간은 하프 경계에서 잘린다.
- AC-09 [로직]: 키 모먼트 장면은 지정 시각 ±1 렌더 프레임 안에 멈추고 선택 요청을 1번만 보낸다. 선택 결과로 장면 목록이 바뀌면 바뀐 목록의 다음 장면부터 재생한다.
- AC-10 [E2E]: `e2e/041-highlight-playback` — 고정 시드 경기에서 첫 장면 시작, 골 순간, 리플레이 0.5x 중간, 장면 전환 직후를 캡처. 전체 프로필에서 공과 필드 선수 10명 이상의 화면 투영 위치가 뷰포트 안(가장자리 여백 ≥ 2%)이고, 빈·단색·검은 화면 판정(000 FR-34)이 없으며, HUD 속도 표시가 캡처 시점 재생 속도와 같다.
- AC-11 [E2E]: `e2e/041-speed-switch` — 1x, 1.5x, 2x, 3x 각각 같은 시뮬 시각에서 캡처한 화면이 서로 같다(재생 속도가 화면 내용에 영향 없음, 속도 라벨 영역은 마스크). 프로필: smoke.
- AC-12 [E2E]: `e2e/041-keymoment-pause` — 키 모먼트 정지 후 1초 간격 캡처 2장에서 3D 영역(시트·HUD 마스크 제외) 픽셀 차이가 0이다(재생이 정확히 멈춤). 시트의 레이아웃·잘림 검증은 039 AC-08이 맡는다. 프로필: smoke.
- AC-13 [E2E]: `e2e/041-unload` — 하이라이트 → 결과 → 매니지먼트 복귀 후 캡처. 3D 잔상 없음, 메뉴 목표 fps로 전환됨이 로그로 확인된다. 프로필: smoke.
- AC-14 [성능]: `low-igpu-1080p`에서 하이라이트 재생 구간 프레임 p95가 빈 화면 대비 ≤ 1 ms 증가하고(절대값은 기록), GPU 평균 ≤ 10 ms, 메인 스레드 p95 ≤ 8 ms (CPU는 IL2CPP 벤치로 판정, 006 D17).
- AC-15 [성능]: (보류: 048·042 연결 때 릴리스 빌드 재생으로 판정, 2026-11-09 사용자 결정) 장면 전환 ±1초 구간 최대 프레임 ≤ 25 ms를 모든 전환(최소 8회)에서 만족하고, 전환 순간 동기 로드·셰이더 컴파일 이벤트가 0건이다.
- AC-16 [성능]: 재생 성능 구간의 모든 프레임에서 GC 할당 0 B (프리로드는 로딩 단계에서만).
- AC-21 [로직]: 장면 전환 프레임에 배속 변경을 넣으면 새 속도가 다음 장면 첫 프레임부터 적용되고 이벤트 큐 순서·개수가 변경 없는 실행과 같다. 같은 프레임 배속 변경 + 건너뛰기는 건너뛰기가 먼저 처리된다. 로딩 중 취소 외 입력은 상태를 바꾸지 않는다.
- AC-17 [성능]: 하이라이트 진입·언로드를 10회 반복해도 메모리가 진입 전 대비 +20 MB 이내로 돌아온다(누수 없음).
- AC-18 [성능]: 배터리 절약 모드에서 하이라이트 fps가 30으로 고정되고 프레임 p95가 빈 화면 대비 ≤ 1 ms 증가한다(절대값은 기록).
- AC-19 [결정론]: 해상도가 다른 두 프로필에서 같은 장면을 재생해 기록한 엔티티 위치 시퀀스가 같다.
- AC-20 [로직]: 로딩 중 취소를 하면 로드된 에셋 핸들이 모두 해제되고(남은 핸들 0) 메뉴 상태로 간다.
