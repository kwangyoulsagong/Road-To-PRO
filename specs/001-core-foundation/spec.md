## 배경
경기 결과, 하이라이트 재생, 키 모먼트 재시뮬, 세이브 재현, 1,000경기 밸런스 검증이 모두 **같은 시드 → 같은 결과**에 기대고 있다. 이 스펙은 그 약속을 지키는 바닥이다. 모듈 경계(Unity 비참조), 결정론적 수학, 시드 난수, 정수 기반 시뮬 시계, 안정 해시, 주입형 로거, 튜닝 상수 등록을 한 번에 정해 이후 모든 스펙이 같은 도구를 쓰게 한다. 플레이어가 직접 보는 것은 없지만, 여기서 생긴 버그는 "같은 경기를 다시 봤는데 결과가 다르다"로 나타난다.

## 범위
- 포함:
  - 모듈(어셈블리) 구성과 참조 방향, Unity 비참조 보장
  - 결정론 수학: 2D/3D 벡터, 각도, 보간, 클램프, 선분-원(swept) 판정, 초월함수 래퍼
  - 피치 좌표계 정의 (정규화 좌표 ↔ 미터)
  - 시드 RNG: 서브시스템별 스트림 분리, 분포 함수, 상태 저장·복원
  - 시뮬 시계: 정수 틱, 결정 10Hz / 물리 100Hz 서브스텝, 경기 시각 표기
  - 게임 날짜 값 타입 (커리어용, 시스템 시계 비의존)
  - 안정 해시: 이벤트 로그·상태 스냅샷 해시, 체크포인트 해시
  - 주입형 로거 (레벨, 비활성 시 비용 0)
  - 튜닝 상수 등록 (id, 기본값, 범위, 출처 태그)
  - 정렬·순회 순서를 고정하는 공용 규칙
- 제외:
  - 크로스플랫폼 비트 일치 (고정소수점 여부는 결정 대기 — "같은 빌드·같은 플랫폼 재현"이 이 스펙의 기준)
  - 공·선수 물리 자체 (004, 005)
  - 이벤트 스키마 (006), 세이브 형식 (022), 캘린더 규칙 (021)
  - Unity 좌표 변환 (프레젠테이션 041이 001의 좌표 정의를 따라 변환)

## 사용자 시나리오
1. 플레이어가 경기를 끝내고 세이브 → 로드 후 "경기 다시보기"를 누르면, 처음 본 것과 똑같은 하이라이트가 나온다.
2. 키 모먼트에서 다른 선택을 고르면, 그 시점 이전은 그대로이고 이후만 바뀐다 (019가 이 스펙의 RNG 상태 복원에 기댄다).
3. 개발자가 밸런스 수치 하나를 바꾸고 1,000경기를 돌리면, 바꾼 수치 외에는 아무것도 달라지지 않았다는 걸 해시로 확인한다.

## 요구사항

### 모듈 구성
- FR-01: 모듈은 Core, MatchEngine, Career, WorldGen, Data, Presentation, UI, Tests(EditMode)로 나눈다. 참조 방향은 `.claude/rules/10-csharp.md`를 따른다 (확정 (2026-11-02 사용자 결정): Data는 도메인 전부를 참조하고, 도메인 모듈은 Data를 모른다. 저장·로딩은 인터페이스로 주입): MatchEngine→Core, Career→Core·MatchEngine, WorldGen→Core·Career, Data→Core·MatchEngine·Career·WorldGen, Presentation·UI·Verification→위 전부, Tests→전부. 역방향 참조는 컴파일이 실패해야 한다.
- FR-02: Core와 MatchEngine은 Unity 엔진 어셈블리를 참조하지 않는다 (아키텍처 § 2 "noEngineReferences"). Career·WorldGen도 같게 한다 (확정 2026-11-02 사용자 결정, `.claude/rules/10-csharp.md`).
- FR-03: Core·MatchEngine은 Unity 없이 일반 .NET 테스트 러너에서도 돌 수 있는 코드만 포함한다 (CI 헤드리스 대량 시뮬, 아키텍처 § 2 하단).
- FR-04: 모듈 참조 그래프를 검사하는 자동 테스트가 있다. 금지 참조·금지 API(엔진 수학, 시스템 시계, 비시드 난수, 스레드 풀)가 코어 모듈에 들어오면 실패한다 (하네스 훅과 별개로 테스트로도 보장).

### 결정론 수학
- FR-10: 2D·3D 벡터 값 타입 (덧셈·뺄셈·스칼라곱·내적·외적(3D)·길이·제곱길이·정규화·거리·투영·회전(2D)). 길이 0 벡터 정규화는 0 벡터를 돌려준다 (NaN 금지).
- FR-11: 초월함수(제곱근, sin, cos, atan2, exp, log, pow)는 한 곳의 래퍼를 통해서만 쓴다 (research[1] 01 A-8 "System.Math 래퍼를 고정"). 나중에 고정소수점·결정론 구현으로 바꿀 때 이 래퍼만 바꾸면 되게 한다.
- FR-12: 각도 정규화(−π, π], 각도 차이, 각도 보간(최단 경로), lerp·inverse lerp·clamp·smoothstep·시그모이드.
- FR-13: 선분-원 교차(swept) 판정: 한 서브스텝 동안 이동한 공(선분)이 선수 컨트롤 반경(원)과 처음 닿는 시점 t∈[0,1]을 돌려준다 (research[1] 01 A-8: 30 m/s × 0.01 s = 0.3 m 이동, 접촉은 swept 판정).
- FR-14: 모든 수학 연산은 단정밀도(float)를 일관되게 쓴다 (research[1] 01 A-8). 단정밀도↔배정밀도 혼용은 래퍼 내부에서만.
- FR-15: NaN·무한대가 생기면 디버그 빌드에서 즉시 실패(어서션)하고, 릴리스에서는 안전값으로 바꾸고 경고 로그를 남긴다.

### 피치 좌표계
- FR-20: 정규화 좌표 x∈[0,1](자기 골라인 → 상대 골라인), y∈[0,1](폭), 높이 z(미터)를 기본 좌표로 쓴다 (research[3] 03 A1). 미터 변환은 105×68 m 기준.
- FR-21: 팀 관점 변환(홈/원정, 전후반 진영 교체)은 한 함수로만 한다. 같은 지점을 두 팀 관점으로 바꿨다가 되돌리면 원래 값과 같아야 한다 (float 반올림 1 ulp 이내, AC-05).
- FR-22: 피치 크기는 경기 설정 값으로 받을 수 있게 한다 (기본 105×68). 정규화↔미터 변환은 그 값을 따른다.

### 시드 RNG
- FR-30: 경기 시드(64비트) 하나에서 서브시스템별 독립 스트림을 만든다. 스트림 id 예: 물리 노이즈, 선수 결정, 심판 판정, 부상, 시나리오 선택, 하이라이트, 컨디션(경기 폼). 한 스트림의 호출 횟수가 바뀌어도 다른 스트림 출력은 바뀌지 않는다.
- FR-31: 필요하면 스트림을 다시 하위 스트림으로 나눈다 (예: 선수 결정 스트림 → 선수별). 하위 스트림 id는 안정적인 값(선수 고유 id, 슬롯 번호)으로 만들고, 언어 런타임의 해시코드는 쓰지 않는다.
- FR-32: 분포: 균등 실수 [0,1), 균등 정수 [a,b] (편향 없음), 정규, 로그정규, 베르누이, 가중 선택, softmax(온도 τ) 선택, 셔플.
- FR-33: RNG 상태는 저장·복원할 수 있다. 복원 후 출력은 저장 시점 이후 출력과 같다.
- FR-34: RNG는 전역·정적 상태로 두지 않고 인자로 주입한다 (`.claude/rules/20-match-engine.md`).
- FR-35: 커리어(주간 루프·이벤트·월드 생성)도 같은 방식의 시드 스트림을 쓴다. 커리어 시드는 세이브에 들어간다 (형식은 022).

### 시뮬 시계
- FR-40: 시뮬 시간의 기준은 정수 틱 번호다. 결정 틱 10Hz(0.1 s), 물리 서브스텝 100Hz(0.01 s, 틱당 10회) (아키텍처 § 3, research[1] 01 A-8 `FixedDt 0.01`). 실수 시간을 누적하지 않고 틱 번호에서 계산한다.
- FR-41: 경기 시각 표기: 전반 0:00~45:00, 후반 45:00~90:00, 추가시간은 `45+N`, `90+N` 형식, 연장 `105+N`, `120+N`. 표기용 값과 내부 틱은 일대일로 오간다.
- FR-42: 틱 수 상한: 연장·승부차기 포함 최장 경기 `[제안]` 150분(90,000 결정 틱)을 넘어도 오버플로가 없다 (64비트 카운터 또는 증명된 32비트 범위).

### 게임 날짜
- FR-50: 게임 날짜 값 타입: 연·월·일, 요일, 주차, 날짜 더하기·빼기, 날짜 차이(일). 윤년 계산 포함. 시스템 시계를 읽지 않는다.
- FR-51: 나이 계산 규칙: 생일 당일에 나이가 오른다. 2월 29일생은 평년에 `[제안]` 3월 1일에 나이가 오른다.

### 안정 해시
- FR-60: 바이트열 기준 안정 해시(프로세스·실행·런타임 버전과 무관하게 같은 값). 이벤트 로그, 상태 스냅샷, 튜닝 값 묶음을 해시한다.
- FR-61: 체크포인트 해시: 경기 시각 10초마다 그때까지의 이벤트 로그 누적 해시와 상태 스냅샷 해시를 기록할 수 있다 (research[7] 07 §2.3 10초 체크포인트). 두 실행의 체크포인트 목록을 비교해 **처음 갈라진 체크포인트**를 찾는 함수를 제공한다 (000 FR-50).
- FR-62: 실수는 비트 패턴으로 해시한다 (+0/−0, NaN은 정규화한 뒤).

### 로거
- FR-70: 로거는 인터페이스로 주입한다. 레벨: 추적·디버그·정보·경고·에러. 코어는 엔진 로그 함수를 직접 부르지 않는다.
- FR-71: 비활성 레벨 호출은 문자열을 만들지 않는다 (틱 경로 할당 0).
- FR-72: 경고·에러는 000 하네스가 수집할 수 있는 형식으로 나간다 (000 FR-60).

### 튜닝 상수
- FR-80: 밸런스·설계 수치는 코드에 박지 않고 튜닝 레지스트리에 등록한다: id, 기본값, 허용 범위, 단위, 출처 태그(`[설계값]` `[V]` `[U]` `[M]` `[E]` `[제안]` 등 기획서 표시 그대로), 원문 위치.
- FR-81: 튜닝 값 묶음은 데이터 파일에서 읽고, 묶음 전체 해시를 경기 결과에 기록한다 (어떤 튜닝으로 나온 결과인지 추적).
- FR-82: 범위를 벗어난 값을 읽으면 로드 실패(어느 id가 왜 틀렸는지 메시지).

### 순회 순서
- FR-90: 결과에 영향을 주는 순회는 정의된 순서(선수 id 오름차순, 슬롯 번호 등)로만 한다. 해시 기반 컬렉션의 순회 순서에 기대는 코드는 테스트로 잡는다 (예: 같은 입력을 다른 삽입 순서로 넣어도 결과 해시가 같아야 함).
- FR-91: 정렬은 안정 정렬, 동점 처리 규칙을 명시한다 (동점이면 id 오름차순).

## 경계 · 예외 상황
- 0 벡터 정규화, 아주 작은 길이(1e−7) 벡터, 길이 계산 오버플로(아주 큰 값)
- atan2(0,0), 각도 정확히 π / −π, 각도 보간 시 정반대 방향(180°)
- swept 판정: 선분 길이 0(정지한 공), 시작점이 이미 원 안, 접선으로 스치는 경우, 원 반지름 0
- RNG: 균등 정수 범위 a=b, a>b(오류), 범위 전체(최소~최대 정수), softmax에 τ→0(최댓값 선택), 모든 가중치 0(오류 또는 균등 선택 규칙 명시), 가중치에 음수·NaN(오류)
- 정규분포 꼬리: 극단값(±6σ 이상) 발생 시 클램프 여부는 호출자 몫 — RNG는 값을 바꾸지 않는다
- 시계: 틱 0, 전반 마지막 틱, 하프타임 경계, 추가시간 0분, 연장 없는 경기에서 연장 표기 요청(오류)
- 날짜: 2월 29일, 연말(12/31→1/1), 주차 계산의 해 경계, 아주 먼 미래(커리어 40년 이상)
- 해시: 빈 로그, +0/−0, NaN 비트 패턴 차이
- 튜닝: 파일 없음, id 중복, 알 수 없는 id, 단위 불일치

## 비기능 요구사항
- 결정론: 같은 빌드·같은 플랫폼·같은 시드·같은 입력이면 비트 단위로 같은 결과. 크로스플랫폼은 결정 대기.
- 세이브 호환: RNG 상태·게임 날짜·튜닝 해시의 직렬화 형식은 버전을 가진다 (형식 자체는 022).
- 테스트 가능성: 모든 기능이 Unity 없이 단위 테스트된다.

## 수용 기준
- AC-01 [로직]: Core에서 Presentation을, MatchEngine에서 Career를 참조하도록 바꾸면 컴파일이 실패한다. 참조 그래프 검사 테스트가 아키텍처 § 2 방향과 다른 참조를 찾으면 실패한다.
- AC-02 [로직]: Core·MatchEngine 어셈블리의 참조 목록에 Unity 엔진 어셈블리가 없다 (테스트가 어셈블리 메타데이터를 검사).
- AC-03 [로직]: 0 벡터 정규화 결과가 0 벡터이고 NaN이 아니다. 각도 정규화가 −π를 π로 바꾼다. 179°와 −179°의 최단 보간 중간값이 180°(또는 −180°)다.
- AC-04 [로직]: swept 판정: 반지름 0.5 m 원 중심을 지나는 0.3 m 선분은 정확한 첫 접촉 t를 돌려주고, 원에서 0.6 m 떨어져 지나는 선분은 "접촉 없음", 시작점이 원 안이면 t=0.
- AC-05 [로직]: 정규화 좌표 (0.5, 0.5)는 미터 (52.5, 34)다. 홈 관점 좌표를 원정 관점으로 바꿨다 되돌리면 원래 값과의 차이가 축마다 1.2e−7(1.0의 float 1 ulp) 이하이고, 같은 입력의 변환 결과는 항상 비트 단위로 같다 (2026-11-02 사용자 승인: [0,1] float의 1−x 반전은 비트 왕복이 불가능).
- AC-06 [결정론]: 같은 시드로 만든 두 RNG의 출력 100만 개가 모두 같다.
- AC-07 [결정론]: 스트림 A에서 추가로 1,000번 뽑아도 스트림 B의 다음 1,000개 출력은 바뀌지 않는다.
- AC-08 [결정론]: RNG 상태를 저장하고 복원하면, 복원 후 1만 개 출력이 저장하지 않고 계속 뽑은 1만 개와 같다.
- AC-09 [로직]: 균등 정수 [1,6] 600만 회의 카이제곱 검정이 유의수준 0.001에서 통과한다. 정규분포 100만 개의 평균·표준편차가 ±0.005 안에 든다. softmax(τ=0.01)는 최댓값 후보를 99% 이상 고른다.
- AC-10 [로직]: 모든 가중치 0, 음수 가중치, a>b 범위 요청은 명확한 오류로 실패한다.
- AC-11 [로직]: 틱 27,000은 `45:00`, 전반 추가시간 2분 30초 지점은 `45+2`(초 포함 표기 `45+2:30`), 후반 시작 틱은 `45:00`으로 표기된다. 경기 시각 → 틱 → 경기 시각 변환이 모든 틱에서 일치한다 (전 범위 검사).
- AC-12 [로직]: 90,000 틱(150분)과 그 10배까지 카운터 오버플로 없이 표기·변환이 맞다.
- AC-13 [로직]: 2028-02-29 + 1년 = 2029-03-01 규칙(또는 승인된 규칙), 2000-02-29생의 2001-02-28 나이 0, 2001-03-01 나이 1. 12/31 + 1일 = 다음 해 1/1.
- AC-14 [결정론]: 같은 이벤트 로그의 해시가 다른 프로세스 실행 두 번에서 같다. 이벤트 하나의 실수 필드가 1 ulp 바뀌면 해시가 다르다. +0과 −0 처리 규칙이 문서대로 동작한다.
- AC-15 [결정론]: 두 체크포인트 목록에서 7번째부터 다를 때, 처음 갈라진 체크포인트로 7번째(경기 시각 60~70초 구간)를 돌려준다.
- AC-16 [로직]: 범위를 벗어난 튜닝 값, 중복 id, 알 수 없는 id가 있는 파일은 로드에 실패하고 메시지에 id가 나온다. 정상 파일은 묶음 해시를 돌려주고, 값 하나를 바꾸면 해시가 바뀐다.
- AC-17 [로직]: 같은 원소를 다른 삽입 순서로 넣은 해시 기반 컬렉션 두 개를 공용 정렬 순회 규칙으로 처리한 결과 해시가 같다.
- AC-18 [성능]: 성능 예산 표의 항목이 mac-m1-1600p에서 모두 예산 안이고, 수학·RNG·시계·비활성 로그 호출 할당이 0 B다.
- AC-19 [로직]: 디버그 빌드에서 NaN을 만드는 연산(0/0 정규화 경로 외)이 어서션으로 실패하고, 릴리스 설정에서는 안전값 + 경고 로그 1건으로 처리된다.
