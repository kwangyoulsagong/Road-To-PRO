## 배경
2026-11-11 사용자 요구: 라이브러리에는 **AI가 만들어낸 시나리오**도 들어와야 한다. 268개 기본 패턴과 커버리지 빈 곳을 사람이 하나씩 쓰면 생산 속도가 느리다. LLM은 카탈로그 행과 스키마를 받아 초안을 대량으로 써 줄 수 있다. 그러나 런타임 LLM은 성능(10Hz × 22명 = 초당 220회 결정, 응답 지연이 한 틱보다 김)·결정론·내장 GPU 목표 때문에 바로 탈락한다. 그래서 LLM은 **개발 파이프라인의 초안·설명·검증 케이스 작성까지만** 쓰고, 산출물은 사람이 검토·채택한 데이터로 고정한다.

2026-11-11 사용자 결정(053 Q2 → 추천 A 채택): LLM 초안 허용, 사람 채택 필수, 런타임과 무관. 이 스펙은 053에서 Q7 분할로 나온 이전 "053b" 범위다. 초안은 053 워크벤치의 같은 정적 검사·배치 검증·채택 경로를 거친다.

## 범위
- 포함:
  - LLM 입력 묶음(카탈로그 행 · 013 스키마 · 커버리지 빈 곳 · 금칙 규칙) 구성
  - 초안 파일 생성과 출처 기록(모델 이름·버전·프롬프트 해시)
  - 초안의 근거 수치 규칙, 실명·금칙어 검사
  - 변주 설명·검증 케이스(고정 상황 픽스처 설명) 초안 보조
  - 생성 배치별 통과율 기록
- 제외:
  - 정적 검사·배치 검증·리그 영향 회귀·검토 큐·대시보드 (053)
  - 런타임·빌드의 LLM 호출 (금지 — CLAUDE.md)
  - LLM이 낸 파라미터·가중치를 엔진에 직접 넣는 일 (금지)
  - 특정 LLM 서비스·모델 선정 (플랜에서 정한다)

## 사용자 시나리오
1. 개발자가 커버리지 빈 곳 목록(053 FR-75)에서 "하프스페이스 × FinalThird × 메짤라" 칸을 골라 초안 생성을 돌린다. 초안 10개가 `상태: 후보`로 생기고, 053 정적 검사에서 3개가 걸러지고, 배치 검증에서 4개가 탈락하고, 사람이 2개를 채택한다. 대시보드에 이 배치의 통과율이 남는다.
2. 초안 하나가 설명에 실존 선수 이름을 썼다. 정적 검사에서 거부되고 채택 명령도 거부된다.

## 요구사항
- FR-01: 개발자가 LLM에게 카탈로그 행(ID · 이름 · 트리거 · 배역 · 분기 · KPI), 013 스키마, 혼합 구조 규칙(오픈플레이 공격 배역 2~6명, 세트피스 양 팀 관여 전원, 오픈플레이 수비 시나리오 없음, 의도 표기), 커버리지 빈 곳(053 FR-75)을 주고 시나리오 초안 파일을 받는다. 초안은 `상태: 후보`, 출처 경로 `LLM 초안`, 근거는 모델 이름·버전·프롬프트 해시다(014 FR-06).
- FR-02: 초안은 053 FR-02 정적 검사 → FR-20~25 배치 검증 → FR-23 리그 영향 회귀 → 사람 채택(FR-50)을 모두 통과해야 라이브러리에 들어간다(053 FR-78). 자동 채택은 없다.
- FR-03: LLM은 오프라인 작성 도구일 뿐이다. 런타임·빌드는 LLM을 호출하지 않고, 채택된 시나리오 파일 외의 LLM 출력(파라미터·가중치)을 받지 않는다. 결정론은 채택된 파일 기준이다.
- FR-04: 초안의 근거 수치는 원 카탈로그의 출처 등급 또는 `[D]`(설계값) [제안]만 쓴다. LLM이 새로 낸 통계 수치는 `[미정]`으로 표시하고 근거로 쓰지 않는다.
- FR-05: 실명 · "누구 스타일" · 15세 등급 금칙어 검사(053 FR-02)를 LLM 초안에 똑같이 적용한다. 입력 묶음에도 실명을 넣지 않는다.
- FR-06: 생성 배치마다 통과율(정적 검사 / 배치 검증 / 채택)과 폐기 사유 분포를 기록하고 053 대시보드(FR-76)에 낸다.
- FR-07: 보조 산출물: 변주 축 값 설명, 고정 상황 픽스처 설명(검증 케이스 초안)도 같은 출처 기록과 사람 채택을 거친다. 채택 전 산출물은 런타임·테스트 기준선에 쓰지 않는다.
- FR-08: 같은 입력 묶음·같은 프롬프트 해시로 다시 생성해도 결과가 같을 필요는 없다(LLM 출력은 비결정). 대신 채택된 파일이 고정되고, 프롬프트·입력 묶음·원 출력은 추적 기록으로 보관한다 [제안].

## 경계 · 예외 상황
- 초안이 013 스키마로 읽히지 않음 → 정적 검사 오류, 같은 배치의 다른 초안은 계속 검사.
- 초안이 기존 패턴과 거의 같음 → 053 FR-46 변주 후보로 처리, 새 패턴 생성 금지.
- 초안이 오픈플레이 수비 배역을 씀 → 정적 검사 오류(053 FR-02).
- 초안에 근거 없는 통계 수치 → `[미정]`으로 바꾸고 경고, 등급 없는 수치는 014 규칙대로 검증 오류.
- 모델 이름·버전·프롬프트 해시가 빈 초안 → 로딩 검증 오류(014 FR-06).
- 네트워크·서비스 장애로 생성 실패 → 부분 결과는 버리고 배치 실패로 기록(개발 도구 문제, 런타임 영향 없음).

## 비기능 요구사항
- 결정론: 런타임 결정론은 채택된 시나리오 파일로만 정해진다. LLM 출력의 비결정성은 채택 단계에서 차단된다.
- 격리: 출시 빌드에 LLM 관련 코드·키·설정이 없다.
- 추적성: 채택된 LLM 초안은 모델·프롬프트 해시·입력 묶음 해시·채택자·배치 검증 결과를 이력에서 찾을 수 있다.
- 비밀 관리: API 키 등은 개인 설정(gitignore)에만 두고 커밋하지 않는다.

- AC-04 [로직]: FR-01: 모델 이름·버전·프롬프트 해시 중 하나라도 빈 초안은 로딩 검증 오류다.

- AC-06 [로직]: FR-06: 생성 배치 리포트에 정적 검사·배치 검증·채택 단계별 통과 수와 폐기 사유 분포가 나오고, 합계가 배치 초안 수와 같다.
