# 006 — 경기 루프 · 틱 파이프라인 · SimEvent

## 배경
90분 경기 전체는 화면 없이 백그라운드에서 계산되고, 화면은 그 결과(SimEvent)를 재생만 한다 (아키텍처 1). 이 스펙은 그 계산의 뼈대다: 매 틱 어떤 순서로 무엇을 평가하는지, 경기가 어떻게 시작·진행·종료되는지, 무슨 일이 일어났는지를 어떤 형식으로 남기는지, 지난 장면을 어떻게 다시 꺼내는지. 각 단계의 내용(물리, AI, 심판)은 다른 스펙이 채우고, 006은 순서·시간·기록·재현을 책임진다. M0 완료 기준 "11 vs 11 시뮬, 스코어와 이벤트 로그 출력"(기획서 § 7)의 중심이다.

## 범위
- 포함:
  - 틱 파이프라인 단계 순서와 단계 간 데이터 전달 규칙
  - 결정 10Hz / 물리 100Hz 서브스텝 스케줄, 선수 결정 LOD 스케줄
  - 경기 진행 상태: 준비, 킥오프, 인플레이/데드볼, 전후반, 하프타임, 추가시간, 연장, 승부차기, 종료, 몰수·중단
  - 교체 슬롯·교체 창 관리, 퇴장으로 인한 인원 감소
  - 추가시간 누적과 발표
  - SimEvent 공통 스키마, 순서 규칙, 버전, 이벤트 종류 목록(소유 스펙 표시)
  - 경기 입력(경기 설정)과 출력(경기 결과) 형식의 공통 계약
  - ReplayBuffer: 최근 구간 스냅샷, 체크포인트, 임의 구간 재구성, 클립 추출
  - 상태 스냅샷·복원, 외부 입력 주입(키 모먼트 선택) 후 재시뮬
  - 실행 제어: 한 틱 진행, 지정 시각까지, 조건 이벤트까지, 일시정지
  - 결정론 체크포인트 해시 기록 (001 FR-61)
- 제외:
  - 단계 내용: 전술·국면(009), 역할·성향(003), 시나리오(013), Utility AI(010), Steering(005), 공 물리(004), 액션 판정(008), 심판·재시작 판정(012), 하이라이트 점수(018), 스탯·평점(015), 키 모먼트 UX(019)
  - 저정밀 통계 모드의 계산 (016) — 006은 같은 결과 형식만 정의
  - 대회 규칙(연장·승부차기 유무) 정의 (021이 경기 설정으로 넘김)
  - 화면 (039, 040, 041)

## 사용자 시나리오
1. 플레이어가 "경기 시작"을 누르면 2초 안에(기준 기기, FR-80 예산) 90분이 계산되고, 하이라이트 8~15장면이 준비된다 (기획서 4.4, 아키텍처 4).
2. 하이라이트 중 키 모먼트에서 "침투 요구"를 고르면, 그 순간부터 경기가 다시 계산되어 이후 장면이 바뀐다. 그 이전 장면과 스코어는 그대로다 (아키텍처 4).
3. 경기 종료 후 텍스트 타임라인에 "67' 교체", "90+3' 골"처럼 시각이 정확하게 찍힌다.
4. 세이브 후 "경기 다시보기"에서 원하는 장면을 다시 보면 처음과 같은 움직임이 나온다.

## 요구사항

### 틱 파이프라인
- FR-01: 결정 틱(0.1 s)마다 아래 순서로 단계를 실행한다 (아키텍처 3):
  1. 팀 전술 (포메이션·지시) — 009
  2. 국면 FSM — 009
  3. ShapeSolver (슬롯 목표좌표) — 009
  4. 역할 보정 (오프셋·가중치) — 003·009
  5. 성향·버릇 — 003
  6. 시나리오 선택 — 013 (맞는 시나리오 → 시나리오 실행, 없음·깨짐 → Utility 폴백 — 010)
  7. Steering 목표 갱신 — 005
  8. 물리 서브스텝 100Hz × 10 (선수·공) — 004·005
  9. 심판 판정 (파울·카드·오프사이드) — 012
  10. SimEvent 발행 → ReplayBuffer 기록, 하이라이트 후보(018), 스탯·평점(015)
- FR-02: 각 단계는 앞 단계의 결과만 읽고, 같은 틱 안에서 뒤 단계가 쓴 값을 읽지 않는다. 단계 간 데이터는 틱 단위 상태로 넘긴다 (읽기 순서 의존 버그 방지).
- FR-03: 물리 서브스텝 중 일어난 접촉·라인 통과(공 아웃, 골라인)는 서브스텝 시각을 붙여 그 틱의 심판 단계로 넘긴다. 한 틱 안에서 여러 사건이 생기면 서브스텝 시각 → 단계 → 선수 id 순으로 정렬한다.
- FR-04: 단계가 아직 구현되지 않은 스펙은 대체 단계(고정 위치 유지, 단순 패스·슈팅)로 바꿔 끼울 수 있다. M0에서 "22명 위치 + 공 + 틱 루프 + 단순 패스/슈팅 판정"(기획서 § 9)으로 경기가 끝까지 돈다.
- FR-05: 선수 결정 LOD의 규칙(반경·주기·즉시 재결정 트리거·동시 결정 상한)은 010 FR-40~41이 소유한다. 006은 010이 정한 "이번 틱 결정 대상" 목록을 선수 id 오름차순으로 실행하고, 결정하지 않는 선수는 직전 목표를 유지하는 실행 순서만 보장한다.
- FR-06: 데드볼 상태(재시작 대기)에서는 결정·이동 단계가 재시작 배치 규칙(012)에 따라 돌고, 경기 시계 정지 여부는 규칙대로 처리한다 (축구는 시계가 멈추지 않고 추가시간으로 보정 — FR-21).

### 경기 진행
- FR-10: 경기 설정 입력: 경기 시드, 홈/원정 팀, 선발 11명·벤치·주장, 포메이션·지시, 세트피스 키커, 심판(성향, 012), 피치 상태(건조/젖음/인조, 004 반발계수와 연결), 피치 크기, 대회 규칙(연장 유무, 승부차기 유무, 교체 수·창 수, 벤치 인원), 경기 중요도(002 FR-61), 튜닝 묶음 해시(001 FR-81), 내 선수 id.
- FR-11: 진행 상태: 준비 → 킥오프(동전 던지기 결과) → 전반 → 하프타임 → 후반(반대 팀 킥오프, 진영 교체) → (연장 전반 → 연장 후반) → (승부차기) → 종료. 골 후에는 실점 팀 킥오프.
- FR-12: 교체 규칙은 006이 소유한다 (016·017·025는 이 값을 참조). 대회 규칙의 교체 수·창 수를 지킨다. 교체 수·창 수·벤치 인원 값은 리그·대회 규칙 데이터(020 FR-15)에서 받는다. 데이터가 없을 때의 기본값 `[제안]` 5명 / 경기 중 3창(하프타임 제외), 연장 시 +1명·+1창. 뇌진탕 영구 교체 1회는 기존 한도와 별개 (scenarios research 뇌진탕 규정 [V]). 교체로 나간 선수는 복귀 불가.
- FR-13: 교체 결정은 팀 AI(감독 로직, 025와 연결)가 하고, 006은 한도·창·시점(데드볼에서만 실행) 규칙만 강제한다. 한도 초과 요청은 거부되고 이벤트로 남는다.
- FR-14: 퇴장·부상으로 인원이 줄면 남은 인원으로 계속한다. 7명 미만 판정은 012 FR-91이 내고, 006은 그 이벤트를 받으면 같은 틱에 경기를 중단 결과로 끝낸다 `[제안]`.
- FR-15: 승부차기: 5명씩 교대 후 서든데스. 키커 순서는 팀 AI가 정한다. 각 킥의 판정은 008·011.

### 추가시간
- FR-20: 추가시간 집계와 산정 공식은 006이 소유한다. 정지 요인별 시간: 골 세리머니·교체·부상 처치는 006 이벤트에서, VAR 체크·카드 지연·판정 항의는 012가 이벤트 데이터로 준 실제 정지 시간(012 FR-90)에서 하프별로 누적한다. 요인별 가산값·반올림 규칙 `[미정]` (부상 퇴장 +1~3분: scenarios research INJ-15).
- FR-21: 전반 45:00·후반 90:00(연장 105:00·120:00)에 추가시간(분 단위, 올림)을 발표하는 이벤트를 낸다. 실제 진행한 추가시간은 발표값 이상이어야 하고, 발표 이후 정지 요인이 생기면 늘어날 수 있다.
- FR-22: 종료 규칙 `[제안]`: 추가시간이 끝나는 시점에 종료 휘슬. 단, 페널티킥 선언 후에는 그 킥이 끝날 때까지 종료하지 않는다. 시간 끝 시점에 공이 골라인을 넘는 서브스텝 판정은 FR-03 정렬 규칙으로 정한다 (시각이 종료 시각 이하이면 골 인정).

### SimEvent
- FR-30: 공통 필드: 일련번호(경기 내 단조 증가), 틱, 서브스텝 인덱스, 경기 시각(표기용, 001 FR-41), 이벤트 종류, 팀, 주 선수 id, 보조 선수 id, 위치(정규화 x·y, 높이 z), 공 상태, 관련 이벤트 일련번호(예: 슈팅 → 골), 시나리오 id(있으면), 종류별 데이터.
- FR-31: 이벤트 종류와 소유 스펙 (006은 공통 스키마·순서·버전만 소유):

  | 종류 | 소유 |
  |---|---|
  | 경기 진행: 킥오프, 전후반 시작·종료, 추가시간 발표, 종료, 중단, 승부차기 킥 | 006 |
  | 교체, 교체 거부 | 006 |
  | 점유 변경, 국면 변경 | 009 |
  | 패스·패스 받음·크로스·드리블(돌파)·캐리·슈팅·블록·태클·인터셉트·클리어·경합 | 008 |
  | 선방·캐치·펀칭·돌진 | 011 |
  | 골, 골대 맞음 | 008·012 |
  | 파울·카드·오프사이드·재시작(스로인·골킥·코너·프리킥·페널티)·VAR 검토·VAR 번복 | 012 |
  | 부상 발생 | 027 (경기 중 부상 위험 모델: 008 FR-43 접촉 이벤트 + 005 피로 입력 → 발생·종류·기간). 006은 이벤트 발행과 교체·드롭볼 흐름만 |
  | 시나리오 시작·단계·깨짐·종료 | 013 |
  | 지시 위반 | 003 |
  | 키 모먼트 발생·선택 적용 | 019 |

  `xG`, `ΔxT`, 제친 수비 수 같은 종류별 데이터는 각 소유 스펙이 정의한다 (research[7] 07 §2.4 하이라이트 점수가 이 값을 씀).
- FR-32: 순서: 이벤트는 (틱, 서브스텝, 단계 순서, 단계 내 발생 순) 오름차순으로 한 줄로 나온다. 같은 입력이면 같은 순서다.
- FR-33: 스키마 버전을 가진다. 필드 추가는 하위 호환, 의미 변경은 버전 증가. 세이브 속 이벤트 로그는 버전과 함께 저장된다 (022).
- FR-34: 이벤트 로그는 경기 결과에 포함되고, 001 안정 해시로 해시된다. 체크포인트(경기 시각 10초마다)에서 누적 해시를 기록한다 (001 FR-61, 000 FR-50).
- FR-35: 구독: 프레젠테이션·스탯·하이라이트 등은 이벤트 스트림을 읽기만 한다. 구독자가 시뮬 상태를 바꿀 수 없다 (아키텍처 1 "프레젠테이션은 SimEvent만 구독").

### 경기 결과
- FR-40: 경기 결과 형식: 최종 스코어(정규·연장·승부차기 구분), 득점자·도움·시각, 카드, 교체, 부상, 선수별 출전 시간, 스탯 입력(015), 평점(015), 이벤트 로그(전체 정밀 모드만), 체크포인트 해시 목록, 시드, 튜닝 해시, 엔진 버전.
- FR-41: 저정밀 모드(016)도 같은 결과 형식을 채운다 (이벤트 로그·체크포인트는 선택). 커리어(024)는 두 모드의 결과를 구분 없이 소비한다.

### ReplayBuffer · 재구성
- FR-50: 최근 구간 링 버퍼: 최근 60초를 30Hz 스냅샷으로 보관 (확정 (2026-11-02 사용자 결정): 기록 30Hz, 화면은 보간) (research[7] 07 §2.3). 스냅샷 대상: 선수 22명(+벤치에서 들어온 선수), 공, 심판 3명 — 위치·높이·이동 방향과 별도의 **몸 방향(yaw)**(054 FR-05)·이동 상태(애니 힌트: 걷기/달리기/스프린트/킥/태클/넘어짐 등 종류 코드)·공 상태.
- FR-51: 전체 경기는 시드 + 외부 입력 로그 + 10초 간격 상태 체크포인트로 재구성한다 (research[7] 07 §2.3 하이브리드).
- FR-52: 임의 구간 재구성: 경기의 아무 구간 [t1, t2]를 가장 가까운 이전 체크포인트에서 다시 돌려 30Hz 스냅샷으로 만든다. 재구성 결과는 원래 실행의 상태와 비트 단위로 같다.
- FR-53: 클립 추출: 018이 정한 구간 [t1, t2]를 FR-52 재구성으로 꺼낸다 (구간 규칙은 018 FR-10~16 소유: 기본 −8초 ~ +3초, 8~20초, 골 세리머니 연장). 하이라이트 선정(018)이 고른 장면마다 클립을 만든다. 클립에는 구간 안 SimEvent도 함께 들어간다.
- FR-54: 스냅샷 값은 재생 용도로 압축해도 되지만(반정밀도 등), 시뮬 상태 체크포인트는 무손실이다.
- FR-55: 체크포인트 보관 모드: 전체(관전 경기 기본) / 키 모먼트 지점만 / 없음(017 대량 시뮬 기본). 어느 모드든 체크포인트 **해시**는 10초마다 기록한다 (결정론 비교용).

### 스냅샷 · 복원 · 입력 주입
- FR-60: 전체 시뮬 상태(모든 엔티티, 공, 단계별 내부 상태, RNG 스트림 상태, 이벤트 일련번호, 추가시간 누적, 교체 현황)를 스냅샷으로 저장하고 복원할 수 있다.
- FR-61: 복원 후 계속 실행한 결과는 중단 없이 실행한 결과와 비트 단위로 같다.
- FR-62: 외부 입력(키 모먼트 선택 등)은 (틱, 대상 선수, 입력 내용)으로 입력 로그에 기록되고 해당 틱의 결정 단계에서 적용된다. 입력 이전 구간의 결과는 바뀌지 않는다 (아키텍처 4).
- FR-63: 키 모먼트 재시뮬: 선택 시점 스냅샷에서 복원 → 입력 주입 → 경기 끝까지 다시 계산. 선택 이전 이벤트 로그는 그대로 두고 이후만 교체한다 (UX는 019).

### 실행 제어
- FR-70: 실행 단위: 한 틱, N틱, 지정 경기 시각까지, 조건(이벤트 종류·선수·구역) 만족까지, 끝까지. 일시정지 상태에서 상태 조회 가능.
- FR-71: 경기 하나는 단일 스레드에서 돈다. 여러 경기는 별도 스레드에서 동시에 돌 수 있고, 동시 실행 여부가 결과에 영향을 주지 않는다 (`.claude/rules/20-match-engine.md`).
- FR-72: 경기 진행 중 에러(단계 예외, NaN)는 그 경기를 실패 결과로 끝내고 원인 이벤트·틱을 남긴다. 다른 경기 실행에는 영향이 없다.

### 시뮬 성능 예산 분배 (006 소유)
- FR-80: 풀 정밀 경기 1개(90분, 54,000 결정 틱)의 예산은 기준 기기 단일 스레드 ≤ 2 s `[제안]`이다. 결정 틱 1회 평균 ≤ 37 µs를 단계별로 나눈다. 각 소유 스펙의 성능 예산은 이 몫과 일치해야 한다:

  | 단계 | 결정 틱당 평균 몫 | 소유 |
  |---|---|---|
  | 물리 서브스텝 10회 (공 + 22명 조향·적분) | 12 µs | 004, 005 |
  | 팀 형태·국면·라인·압박 지정 | 3 µs | 009 |
  | 의사결정 (후보 생성·008 평가·007 지점 질의 포함) | 12 µs | 010, 008, 007 |
  | 시나리오 트리거·선택·실행 | 3 µs | 013 |
  | 골키퍼 | 1.5 µs | 011 |
  | 심판 판정·위치 | 1.5 µs | 012 |
  | 이벤트 발행·체크포인트 해시·스탯 갱신 | 2 µs | 006, 015 |
  | 여유 | 2 µs | — |

  피치 컨트롤 32×20 전체 그리드는 이 예산 밖이다 (시뮬 기본 경로에서 쓰지 않음, 007 FR-11).
- FR-81: 실측이 몫을 넘으면 그 단계 소유 스펙의 성능 AC가 실패한다. 몫 조정은 이 표를 고쳐서만 한다 (합계 37 µs 유지).
- FR-82: 접촉 이벤트 상세 (054 FR-30·32 요청): 공 접촉 SimEvent(패스·슈팅·크로스·트래핑·드리블 터치·헤딩·태클·GK 캐치/펀칭)는 사용 부위(왼발/오른발/머리/가슴/허벅지/손)와 서브스텝 단위 정확 시각(틱 + 서브스텝 번호)을 담는다. 3D는 이 시각에 접촉 프레임을 맞춘다.
- FR-83: 100Hz 원본 진단 출력 (054 FR-52 요청): 검증 모드에서만 지정 구간의 선수·공 100Hz 원본 궤적을 내보낸다. 30Hz 기록 보간 오차 측정용이며, 켜고 꺼도 시뮬 결과는 같다. 기본 꺼짐.

## 비기능 요구사항
- 결정론: 같은 경기 설정·같은 입력 로그 → 같은 이벤트 로그·같은 체크포인트 해시·같은 결과. 해상도·프레임레이트·동시 실행 수·실행 제어 단위(한 틱씩 vs 끝까지)와 무관.
- 격리: 시뮬은 렌더링·오디오·UI 상태를 읽지 않는다.
- 세이브 호환: 스냅샷·이벤트 로그 형식 버전 관리 (022). **경기 중 저장은 없다** (확정 (2026-11-02 사용자 결정)): 저장은 경기 전·후에만 하고, 경기 도중 앱이 꺼지면 경기 시작 직전 상태에서 다시 시작한다. FR-60 스냅샷은 메모리 안 재구성·재시뮬용이며 세이브 파일에 들어가지 않는다.

## 수용 기준
- AC-01 [로직]: 대체 단계만으로 11 vs 11 경기가 킥오프부터 종료까지 돌고, 결과에 스코어와 이벤트 로그가 들어 있다 (M0 기준).
- AC-02 [로직]: 단계 실행 순서를 기록하는 테스트 단계를 끼우면 매 틱 FR-01 순서와 정확히 같다. 물리 서브스텝은 틱당 정확히 10회.
- AC-03 [로직]: 단계 B가 같은 틱의 단계 C 결과를 읽으려 하면(테스트용 잘못된 단계) 검출되어 실패한다.
- AC-04 [로직]: 010이 넘긴 결정 대상 목록대로만 결정이 실행된다: 3틱 주기로 지정된 선수는 90분 동안 결정 횟수가 전체 틱 수 / 3(±1)이고, 주기가 매 틱으로 바뀌는 순간 결정 누락·중복이 0이며, 같은 틱 안 실행 순서는 선수 id 오름차순이다.
- AC-05 [로직]: 골 후 실점 팀이 킥오프한다. 후반은 전반 킥오프 반대 팀이 하고 진영이 바뀐다.
- AC-06 [로직]: 교체 한도 5명·3창 규칙에서 6번째 교체·4번째 창 요청은 거부되고 "교체 거부" 이벤트가 남는다. 하프타임 교체는 창 수에 들어가지 않는다. 뇌진탕 교체는 한도와 별개로 1회 허용된다. 나간 선수는 다시 들어올 수 없다.
- AC-07 [로직]: 012의 7명 미만 이벤트를 받은 틱에 경기가 중단 결과로 끝나고 결과에 사유가 들어간다.
- AC-08 [로직]: 추가시간 발표값(분, 올림)은 그때까지 누적 정지 시간 이상이고, 실제 진행 추가시간은 발표값 이상이다. 페널티 선언 후 시간이 끝나도 킥이 끝날 때까지 종료되지 않는다.
- AC-09 [로직]: 종료 시각 이하 서브스텝에 골라인을 넘은 공은 골, 그 다음 서브스텝이면 무효로 판정된다 (고정 배치 테스트).
- AC-10 [로직]: 연장·승부차기 설정 경기가 동점이면 연장 → 승부차기로 가고, 승부차기 5-5 이후 서든데스가 승자가 날 때까지 계속된다. 연장 없는 대회는 동점으로 끝난다.
- AC-11 [로직]: 모든 이벤트의 일련번호가 1씩 증가하고, (틱, 서브스텝, 단계, 순서) 정렬과 실제 출력 순서가 같다. 경기 시각 표기가 001 규칙과 일치한다 (예: 후반 추가 3분 12초 = `90+3`).
- AC-12 [결정론]: 같은 경기 설정으로 2회 실행한 이벤트 로그 해시와 모든 체크포인트 해시가 같다.
- AC-13 [결정론]: 같은 경기를 "한 틱씩" 실행한 결과와 "끝까지" 실행한 결과가 같다. 8개 경기를 동시에 돌린 결과와 하나씩 돌린 결과가 같다.
- AC-14 [결정론]: 60분 시점 스냅샷에서 복원해 끝까지 돌린 결과가 중단 없는 실행과 비트 단위로 같다 (틱 0, 체크포인트 경계, 마지막 틱에서도).
- AC-15 [결정론]: 60분에 키 모먼트 입력을 주입해 재시뮬하면 60분 이전 이벤트 로그·체크포인트 해시는 원래와 같고, 이후는 달라질 수 있다. 같은 입력으로 재시뮬을 2회 하면 두 결과가 같다.
- AC-16 [결정론]: 임의 구간 [t1, t2] 재구성 스냅샷이 원래 실행 중 기록한 스냅샷과 비트 단위로 같다 (무작위 구간 100개).
- AC-17 [로직]: 골 이벤트 기준 클립이 −8초 ~ +3초 구간 스냅샷(30Hz, 330프레임 ±1)과 그 구간 이벤트를 담는다. 경기 시작 3초 후 골이면 클립은 0초부터 시작한다(구간 잘림 규칙).
- AC-18 [로직]: 구독자가 예외를 던져도 시뮬은 끝까지 돌고 결과 해시가 같다. 구독자는 시뮬 상태를 바꿀 수 없다 (읽기 전용 확인 테스트).
- AC-19 [로직]: 단계에서 NaN이 생긴 경기는 실패 결과로 끝나고 원인 틱·단계가 기록되며, 같은 배치의 다른 경기 결과는 정상이다.
- AC-20 [로직]: 저정밀 모드(016) 결과와 전체 정밀 결과가 같은 결과 형식 검사를 통과한다 (016 구현 후).
- AC-21 [성능]: 성능 예산 표 항목이 mac-m1-1600p에서 예산 안, 워밍업 후 틱당 할당 0 B. FR-80 분배표의 단계별 실측 평균이 표의 몫 이하이고 합계 ≤ 37 µs다 (단계별 프로파일 표를 증거에 첨부).
- AC-22 [로직]: 체크포인트 보관 모드 "없음"으로 돌린 경기와 "전체"로 돌린 경기의 이벤트 로그 해시·체크포인트 해시 목록이 같다.
- AC-23 [로직]: FR-82: 접촉 이벤트 1만 건 표본에서 사용 부위·서브스텝 시각 누락 0건, 같은 경기 재실행 시 값이 비트 단위로 같다.
- AC-24 [결정론]: FR-83: 100Hz 원본 출력을 켠 실행과 끈 실행의 이벤트 로그 해시가 같고, 출력된 100Hz 궤적을 30Hz로 뽑은 값이 FR-50 스냅샷과 같다(압축 허용 오차 안).
