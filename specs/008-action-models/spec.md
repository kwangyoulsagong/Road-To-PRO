## 배경
판단 AI(010·072)와 시나리오 의도(013)는 "무엇을 하려는지"만 정한다. 패스가 동료에게 가는지, 첫 터치가 붙는지는 액션 모델이 능력치·압박·물리로 판정한다. 그래서 같은 의도라도 선수 실력에 따라 결과가 달라진다. 액션 모델은 (1) 실행 전 평가(성공 확률·기대 가치, 072가 점수에 씀)와 (2) 실제 실행(오차를 넣은 킥·터치·경합 결과) 두 가지를 같은 모델로 제공한다.

2026-11-11 사용자 결정("베스트 케이스로 다 진행")으로 원래 008을 셋으로 나눴다. 이 스펙(원래 Q6의 008a 범위)은 **공통 규칙**(능력치 정규화·압박 강도·평가/실행 분리·출력·접촉 시각·운동 연속성·실행 결과 종류·접촉 상세 기록 저장)과 **패스·수신·첫 터치·인터셉션**을 맡는다. 드리블·테이크온·태클·몸싸움·접촉 이벤트는 `specs/070-dribble-tackle-duel`, 크로스·공중볼·헤더·슈팅·xG는 `specs/071-cross-header-shot`이 맡고, 둘 다 이 스펙의 공통 인터페이스(FR-01~04, FR-60~72)를 쓴다.

2026-11-11 사용자 피드백: 현재 빌드(008·010 대체 단계) 하이라이트에서 "선수 움직임이 부자연스럽다", "주변에 아무도 없는데 태클 동작이 나온다". 그래서 이 스펙은 실행 결과가 005 운동 한계 안에서 연속적이고(FR-64), 공 접촉 순간·부위를 서브스텝 단위로 내며(FR-65·66), 실행 결과 종류(패스·태클·인터셉트·블록·클리어 등)를 구분해 낸다(FR-70). 3D 동작 선택은 058 FR-50~52, 속도 점프 경고의 원인 분류는 058 FR-11·12가 맡는다. 또한 "선수가 자기 능력치·성격·플레이 스타일에 맞게 행동해야 한다"는 요구에 따라 실행 품질을 능력치와 003 성향·버릇에 연결한다(FR-71). 책임 분리: 기술 능력치는 실행 정확도만 바꾸고 무엇을 고를지는 바꾸지 않는다(선택은 010·072).

의존: 001, 004, 005 구현 완료. 002(능력치·주발·약발)와 007(PPCF·ΔxT)은 아직 구현되지 않았다. **정리됨 (2026-11-11 사용자 결정 '베스트 케이스'): 대체 입력으로 먼저 구현**(013 방식) — 002 자리에 임시 능력치 입력, 007 자리에 005 도달 시간(TTI) 기반 컨트롤 근사와 고정 xT 표를 쓰고(구체 형태는 plan), 002·007 연결 때 AC-24로 다시 검증한다.

## 요구사항

### 공통 (리서치 02 §0)
- FR-01: 능력치 정규화는 002 FR-14 (a = 내부/100, 표시 N의 대표값 a = (N−1)/19). 확률 보정은 logit 공간에서 더한다: `logit += k·(a − 0.5)` (포화 방지).
- FR-02: 압박 강도 (Bekkers, 리서치 02 §4.1 [V]):
  - `T_ij = τ_r + ‖d_j − d_i‖/v_max + τ_β`, `d_j = r_j + v_j`(상대 1초 뒤), `d_i = r_i + v_i·τ_r`, `τ_β = ‖v_i‖·β/π`, β = 수비수 진행 방향과 목표 방향 사이 각(rad)
  - `p_ij = 1/(1 + exp(−(π/(√3σ))·(T − T_ij)))`, σ = 0.45, T = 1.5 s
  - 팀 압박 `P_j = 1 − Π_i(1 − p_ij)`. 볼 소유자는 선수·공 중 큰 값.
  - 속도 2 m/s 미만 수비수는 능동 압박 아님(0). 터치라인 3 m 안이면 +0.1~0.2 보정 [설계값] (기본 0.15 [제안]).
- FR-03: 이 압박 값을 패스·드리블·슈팅의 `pressure`(0..1) 입력으로 공통 사용한다 (070·071도 이 값을 쓴다).
- FR-04: 모든 계수는 튜닝 데이터에 둔다. 아래 [설계값]은 초기값이고 017 대량 시뮬로 c0·b0만 이동해 목표 범위에 맞춘다 (리서치 02 §6 보정 루프).

### 패스 (리서치 02 §1)
- FR-10: 물리 기반 xPass: 004 궤적 예측 + 007 궤적 질의로 "의도한 수신자 / 다른 동료 / 상대 / 아웃" 확률을 낸다. 땅볼은 004 구름 모델을 쓴다 (리서치 02 §1.1의 단순 마찰 `v0 − μgt`는 004 모델로 대체 — 같은 공 물리 유지).
- FR-11: 로지스틱 근사 xPass [설계값]: `logit P = b0 − b1·dist/10 − b2·pressureOnPasser − b3·lanePressure + b4·receiverPC + b5·forwardness + b6·(Passing − 0.5) + b7·(Vision − 0.5)`, forwardness ∈ [−1, 1]은 공격 방향 성분(리서치 02 §1.2). 초기 b0 3.2, b1 0.45, b2 1.0, b3 2.0, b4 1.5, b5 0.6, b6 1.2, b7 0.5. 계수는 FR-10 물리 모델 결과로 오프라인 피팅한다. 틱 기본 경로의 평가는 로지스틱 근사를 쓰고, 물리 xPass는 키 모먼트(019)·계수 피팅·디버그용이다 (정리됨 (2026-11-11 사용자 결정 '베스트 케이스'): 성능 예산 기준 로지스틱 기본, 설정으로 바꿀 수 있음).
- FR-12: 속도 후보 땅볼 {10, 14, 18, 22 m/s} + 뜬공 2~3종을 평가하고 `argmax P_success × ΔxT` (ΔxT는 007). 빠른 패스는 수신 난이도 증가: `λ_recv ×= lerp(1.0, 0.6, (v − 12)/12)`, 퍼스트터치가 높을수록 감쇠 감소 [설계값].
- FR-13: 실행 오차 [설계값]: 방향 `σ_angle = lerp(7°, 1.5°, a_Passing) × (1 + 0.8·pressure) × (1 + 0.5·(1 − a_Composure))`, 속도 `σ_speed = lerp(15%, 4%, a_Passing)`. 오차는 주입된 시드 RNG로 샘플링 (001).
- FR-14: 스루볼 조준: `|r + v_r·τ + lead − s| = u·τ`의 가장 작은 양의 해. lead 후보 {0, 2, 4, 6 m}를 xPass × xT로 평가. 시야(Vision)에 따른 후보 집합·보이는 러너 범위는 072 FR-02가 정한다 (008은 받은 후보만 평가). 해가 없으면 그 후보는 제외.
- FR-15: 오프사이드 판정에 필요한 "패스 순간 러너 위치·라인" 스냅샷을 패스 이벤트에 붙인다 (판정은 012). 저장은 FR-72 접촉 상세 기록을 쓴다.
- FR-45: 인터셉션은 별도 확률 굴림 없이 FR-10 궤적 적분에서 수비 컨트롤이 이기면 발생한다 (리서치 02 §4.4). 실제 시뮬에서는 공이 수비수 컨트롤 반경을 지나는 물리 서브스텝(006 단계 7)에 컨트롤 판정(λ_def 반영)을 시드 RNG로 굴리고, 그 서브스텝 시각으로 이벤트를 낸다.

### 출력 · 공통 실행 인터페이스 (070·071 공용)
- FR-60: 모든 실행은 004용 킥 입력(초속 벡터·스핀·상태) 또는 결과 상태(컨트롤 이전·다운·분리)와, SimEvent 후보(종류, 참여 선수, 위치, 평가값 xPass/xG/ΔxT, 결과, **터치 종류**: 의도적 플레이 / 굴절 / 블록)를 낸다. 터치 종류는 012 오프사이드 리셋 판정(012 FR-05)이 쓴다 (GK 세이브는 011 FR-13). SimEvent 스키마와 기록은 006. 공 접촉 SimEvent는 006 FR-82에 따라 사용 부위와 틱+서브스텝 정확 시각을 담는다.
- FR-61: 평가 함수와 실행 함수는 같은 계수를 쓴다. 평가는 RNG를 쓰지 않고, 실행만 시드 RNG를 쓴다. 액션 하나의 RNG 소비 개수는 분기와 무관하게 고정한다 [제안] (재시뮬 019에서 갈라지지 않게). 070·071의 모든 평가·실행도 이 규칙을 따른다.
- FR-63: 디버그 진단 출력 (040 FR-30 레이어 '액션 평가'에 공급): 액션 후보별 평가값(xPass·xG·ΔxT·성공 확률·위험), 선택된 액션, 접촉 이벤트(070 FR-13) 요약. 070·071의 평가값도 같은 레이어로 낸다. 진단 출력은 시뮬 결과와 RNG 소비를 바꾸지 않고, 꺼져 있으면 추가 비용·할당이 0이다. (UI 검수 정리, 2026-11-02)
- FR-64: **운동 연속성**: 008·070·071의 실행 결과(테이크온 성공 분리·수비수 회복 지연, 태클 다운, 접촉 속도 손실, 킥·터치 직후 감속)는 선수 위치·속도를 직접 바꾸지 않고 005 이동 명령과 한계(가속·감속·횡가속, 접촉 시 허용 배율 005 FR-04)로만 나타낸다. 회복 지연과 다운은 정해진 시간 동안 이동 명령을 받지 않는 것으로 표현한다 (다운 상태 소유는 070 FR-11).
- FR-65: **접촉 시각·부위**: 공 접촉이 있는 실행(패스·크로스·슈팅·클리어·드리블 터치·첫 터치·헤더·태클·블록)은 접촉 부위가 공에 닿는 실제 물리 서브스텝에 006 FR-82 형식으로 이벤트를 낸다. 결정 틱 시작에 고정하지 않는다. 킥은 공이 사용 발 도달 거리 [미정] 안에 있을 때만 실행하고, 밖이면 먼저 005 이동으로 접근한다.
- FR-66: **킥 기술·접근**: 킥 계열은 사용 발(주발·약발, 002), 킥 기술(인사이드·인스텝·아웃사이드·칩 [미정: 목록]), 접촉 순간 몸 방향과 킥 방향의 차이를 정해 이벤트에 담는다 (리서치 06 §3.2 "t초 후 위치 P에서 오른발 인사이드로 패스"). 차이가 [미정]°를 넘으면 FR-13과 071 FR-02·14의 σ를 [미정]배로 키운다. 킥 기술 선택은 FR-71을 따른다.
- FR-67: **첫 터치 실행**: 수신 시 첫 터치 이격 거리·방향을 FR-12의 λ_recv, 퍼스트터치 능력치, 공 속도, 압박으로 시드 RNG 샘플링한다. 계수 [미정] (대안: 리서치 03 B2 "FirstTouch 이격 σ 1.8 − 1.4s m"). 이격 > 1.5 m면 070 FR-14의 "불안한 터치" 플래그를 낸다.
- FR-70: **실행 결과 종류 구분**: 실행 결과는 종류를 구분해 낸다 — 패스·크로스·슈팅·헤더·드리블 터치·첫 터치·태클(스탠딩/슬라이딩, 공 먼저 여부)·인터셉트·블록·클리어·경합·공 회수. 태클은 상대 볼 캐리어(또는 직전 소유자)에게 070 FR-10·11 도달 거리 안에서 시도한 경우에만 태클로 기록하고, 근처에 상대가 없는 공 획득은 인터셉트(FR-45) 또는 공 회수로 기록한다. 3D 동작 선택은 058 FR-50~52가 이 종류를 읽는다.
- FR-71: **능력치·성향·버릇 연결**: 실행 품질은 선수 고유값으로 달라진다. ① 능력치: FR-13·67과 070 FR-02, 071 FR-02·14의 오차·터치 거리·이격 계수 (002 FR-14 정규화). ② 버릇: 003 FR-21 "부가 효과"(예: 원터치 마스터 정확도 +5%, 컷인 장인 감아차기 정확도 +10%, 슬라이딩 장인 파울 확률 ×1.4는 012가 읽음)를 실행에 적용하고, "정확도 +x%"는 해당 σ에 ×(1 − x)로 매핑한다 (정리됨 (2026-11-11 사용자 결정 '베스트 케이스'): [제안] 채택). ③ 성향(003 FR-10): 행동 선택은 010·072 소유이고, 실행 안의 세부 선택(태클 스타일 → 스탠딩/슬라이딩 비율은 070 FR-31, 킥 기술 선택은 이 FR과 071 FR-20)은 성향 가중치(003 FR-12)를 쓴다 — 매핑 [미정]. 같은 상황·같은 RNG 시드에서 능력치·버릇만 다른 두 선수는 실행 결과 분포가 다르다.
- FR-72: **접촉 상세 기록 저장** (정리됨 (2026-11-11 사용자 결정 '베스트 케이스'): 원 Q1 추천 ②): 006 SimEvent의 종류별 데이터(정수 2개·실수 2개)에 다 담지 못하는 상세(패스 순간 오프사이드 스냅샷 FR-15, 070 접촉 이벤트·핸드볼 입력, 071 공중볼 동작 정보)는 SimEvent 1건 + 관련 이벤트 일련번호로 연결한 상세 기록으로 저장한다. 상세 기록은 체크포인트·해시에 포함하고, 006 스키마·세이브 버전은 바꾸지 않는다. 소비자(012·027·054)는 필요한 상세만 읽는다.

## 경계 · 예외 상황
- 수신자가 패서 자신, 또는 수신 후보 0명 → 패스 후보 없음으로 반환 (예외 없음).
- 패스 거리 0~1 m 초근접 → 정상 평가, 속도 후보 중 최저 속도로.
- 스루볼 2차방정식 판별식 < 0, 해가 음수뿐 → 후보 제외.
- softmax·logit 값이 매우 큼(오버플로) → 최댓값을 빼고 계산.
- 능력치 극단값(1 또는 20) 조합 → 모든 확률이 (0,1) 열린 구간, 0.001~0.999로 자른다 (정리됨 (2026-11-11 사용자 결정 '베스트 케이스'): [제안] 채택, 070·071 공통).
- 압박 값 계산 대상 수비수 0명 → 압박 0.
- 같은 서브스텝에 두 수비수가 인터셉트 컨트롤 반경 안 → 선수 id 순으로 판정, 첫 성공 이후 두 번째는 무효.

## 비기능 요구사항
- 결정론: 평가 함수는 순수 함수(입력 같으면 출력 같음). 실행 함수는 주입된 시드 RNG만 사용, 호출 순서 고정, 액션당 RNG 고정 소비 (FR-61).
- 할당: 평가·실행 경로 힙 할당 0.
- 튜닝 가능성: 모든 [설계값] 계수가 데이터에서 바뀐다.
