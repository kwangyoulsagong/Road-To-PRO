상태: 완료 (2026-11-05)

## 접근
새 모듈은 없다. 043 클립 생성기(`Art/Blender/scripts/player/clips/*`)를 고치고, Unity 쪽은 043 로코모션 블렌드·액션 선택에 "스타일"(원형) 입력을 더한다.

1. **잴 수 있게 먼저**: 생성 클립의 형태 지표(FR-70)를 FK만으로 계산하는 모듈을 만들고(Blender 없이 mathutils만), 기준 범위는 데이터 파일 한 곳(`Data/anim/055-gait-standards.json`)에 둔다. 테스트는 이 파일을 읽어 범위를 판정한다. T02에서 현재(043·056) 클립을 재 기준선을 남긴다.
2. **보법 재작성** (`gait.py`): 스펙 배경의 다섯 원인을 하나씩 고친다.
   - 시간 구조: 주기 프레임을 걸음 빈도 표(FR-01)로 다시 정한다 — walk 32 f(1.88 Hz)·jog 22 f(2.73 Hz)·run 19 f(3.16 Hz)·sprint 15 f(4.00 Hz). 30 fps 정수 프레임이라 빈도가 양자화되므로 "프레임 → 빈도 → 보폭 = 속도/빈도"로 계산하고 표 범위 안인지 생성기가 단언한다. 접지 비율은 표 중앙값.
   - 골반 상하: 고정 cos 대신 **스프링-질량 곡선** — 접지 구간 안 반사인(최저점 = 접지 50%), 공중 구간은 포물선(최고점 = 공중 중간). 진폭은 표 중앙값. 접지 발 도달 제한(`max_y`)은 유지하되 최저점 위상을 깨면 무릎 굴곡으로 흡수(FR-11 범위 안).
   - 다리: 착지 거리 = `STANCE_BACK`을 보법별로(FR-10 착지 거리 상한), 스윙 궤적은 "뒤꿈치 접기 → 무릎 앞으로 → 정강이 펴기" 순서가 되게 스윙 발 경로를 엉덩이 기준 극좌표(허벅지 각·무릎 각 시간 곡선)로 정의하고 FK로 발 위치를 얻는다. 접지 구간은 지금처럼 IK(미끄러짐 0 구성 유지).
   - 몸통·머리: 몸통 경사는 보법별 표 중앙값(FR-20)으로 낮춘다(sprint 17° → 8°). 머리는 **몸통과 한 줄**(목 신전 ≤ 10°) — `head = −lean × 0.8` 보상을 없애고 시선 보정은 목 신전 상한 안에서만. 골반 요·흉곽 반대 회전·골반 기울기(FR-22·23) 추가.
   - 팔: 어깨 스윙 범위를 FR-32 표로, 팔꿈치를 **위상 함수**로 — 앞쪽 끝 최소(60~80°)·뒤쪽 끝 최대(100~120°), walk는 10~30°. 외전 5~15°, 앞으로 갈 때 손이 몸 가운데로(중앙선 안 넘음). 위상은 반대쪽 다리 엉덩이 굴곡 피크에 맞춘다(FR-30).
3. **축구 특화 클립** (FR-40~42): `start_f`(정지 → 최고속 4~6걸음, 비루프, 걸음별 속도 곡선 태그), `stop_f`(감속 2~4걸음, 비루프), `dribble_run_{30,50,65}`(루프, 공 없는 보법 대비 보폭 −15%·골반 −4.5 cm·무릎 들기 낮춤·터치 쪽 팔 외전 +). **런타임 연결(언제 재생하나)은 054** — 055는 클립·태그·지표만 만든다(스펙 경계: 054 FR-20·21·37이 이 클립을 쓴다).
4. **달리기 원형** (FR-50~52): 원형 = 기본 보법 파라미터에 대한 오프셋 표(`Data/anim/055-run-styles.json`). 클립 수를 억제하려고 **정면 run·sprint만 원형별로** 만들고, 옆·뒤 방향과 walk·jog는 공유한다(원형 차이가 가장 잘 보이는 곳이 정면 질주). 원형 sprint는 표의 최고속도 중앙값·보폭 × 빈도로 만들고, run은 같은 보폭/빈도 비율을 5.4 m/s에 적용(빈도 = √(v/r), r = 보폭/빈도). 선수별 ±5% 흔들기(FR-51)는 **sprint 극단 클립 2개**(원형 파라미터 −5%·+5%)를 선수 id 시드 가중치로 섞어 연속값을 얻는다.
5. **킥 원형** (FR-60·61): 공통 기준(디딤발·백스윙·근육 타이밍·접촉 무릎)을 `kick()`에 반영하고, K1~K8은 기존 클립을 다시 빚거나 새로 만든다(아래 표). 원형 선택은 액션 선택 점수에 "선수 킥 원형과 클립 원형 불일치" 항을 더하는 방식 — 후보 목록(AnimationMap)은 그대로 두고 같은 상황 안에서 원형 클립을 고른다.
6. **증거**: 지표 표(FR-70)는 생성 때 JSON으로 내고 리포트에 표로 싣는다. 필름스트립(FR-71)은 Unity E2E 화면이 클립을 8위상에 고정해 측면·정면 직교 촬영하고, 옆에 **연구 기준 스틱 피겨**를 그린다. 스틱 피겨 관절각 곡선은 생성기가 기준 파일 중앙값과 표준 파형(Novacheck 위상 구분)으로 만들어 `player.gait-reference.json`으로 낸다 — 우리 생성기 포즈를 그대로 쓰지 않는다(자기 비교 방지).

대안: (a) 원형마다 8방향 × 4보법 전체 → 클립 +288개로 FR-52 상한(+50%) 초과. (b) 런타임 뼈 오프셋 레이어로 원형 표현 → 보폭·빈도는 클립 형상이라 미끄러짐 없이 못 바꾼다. (c) 원형 흔들기를 원형당 클립 1개 + 기본 클립 혼합으로 → 기본 쪽으로만 흔들려 ±가 안 된다. → 정면 run·sprint 원형 클립 + sprint 극단 2개.

## 결정론 · 성능
- 생성기: 파라미터 표 순서 고정, 노이즈 없음(원형은 표 값), 출력 6자리 → 2회 바이트 동일(AC-14).

## 버그 방지
- 주기 프레임을 줄이면(sprint 19 → 15) 접지 프레임이 3~4개뿐 → 접지 비율 양자화로 범위를 벗어날 수 있다. 위상은 연속 함수로 계산하고 지표는 서브프레임(클립을 120 Hz로 재샘플)으로 잰다. Unity 재생도 클립 보간이라 같은 곡선.
- 스윙 경로를 극좌표로 바꾸면 스윙 시작·끝에서 접지 IK 포즈와 불연속이 난다 → 경계(접지 끝·시작) ± 0.1 위상에서 IK 발 위치와 FK 발 위치를 smoother로 섞고, 발 속도 연속을 테스트(`test_gait.py::test_swing_continuity`).
- 골반 최저점을 접지 중간으로 옮기면 접지 시작 순간 다리가 다 펴져 도달 불가가 될 수 있다 → 착지 무릎 굴곡 10~25°를 먼저 정하고 그에 맞춰 골반 높이 상한을 계산(현재 `max_y` 방식), 그래도 모자라면 진폭을 줄이고 테스트가 잡게 둔다.
- 팔 스윙 범위를 sprint 100~120°로 키우면 손이 반바지·허벅지를 뚫는다(056 팔 내림 상한 27°) → 외전 하한 5°·뒤쪽 끝 팔꿈치 펴짐을 관통 검사(`test_player.py::test_no_penetration_extremes`)에 새 클립 포함.
- 원형 sprint 블렌드: lo·hi 프레임 수가 달라도 정규 위상 공유라 가능하지만, 접지 구간 위상이 다르면 블렌드에서 발이 끌린다 → 두 극단의 접지 시작 위상을 같게(왼발 0, 오른발 0.5) 고정하고 접지 비율만 다르게.
- run 대체(정면 외 방향): run 가중치를 jog·sprint로 나눌 때 보폭 계산(`Stride`)도 같은 규칙을 써야 위상 속도가 맞는다 → `Evaluate`·`Stride`가 공통 함수로 단계 가중치를 얻게 한다. 테스트: 45°·90°에서 run 속도 근처 위상 속도 연속.
- 킥 디딤발을 옆 30 → 5~28 cm로 좁히면 접촉 맞춤(`fit_leg`)이 실패하거나 다리가 교차 → 원형별 디딤발 표 + 맞춤 실패 시 예외(생성 중단)로 바로 드러나게.
- 이름: 원형 표·클립 id·태그·테스트에 실존 선수 이름 금지 — `spec-lint.py` 실명 검사를 `Data/anim/*.json`에도 돌린다.
