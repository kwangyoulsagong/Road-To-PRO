# 049 — 인게임 에디터 · 모드 가져오기

상태: 초안
브랜치: feat/049-editor-mod-import
기획 출처: docs/index.html § 기획서 4.7(세계 생성: 실존 이름 미사용, 커뮤니티 에디터(모드) 지원), § 5.1.1(시나리오 라이브러리를 데이터로 작성, 모드로 유저 시나리오도 받음) / § 아키텍처 1(UI3 에디터 · 모드 가져오기 → 공개 JSON 포맷), § 7(데이터 · 로스터 업데이트 · 모드: 커뮤니티 데이터 파일 → 사용자가 직접 가져오기 → 인게임 에디터·임포터 → 기본 DB) / research 00 § 2(게임은 깨끗하게, 데이터는 열어둔다), § 5(결정할 것: A/B/C)

## 배경
기본 배포 데이터는 가상 선수·감독과 변형 이름 클럽으로 깨끗하게 둔다. 대신 이름·능력치·유니폼 색·엠블럼 이미지를 편집하고, 커뮤니티가 만든 데이터 파일을 **사용자가 직접** 가져올 수 있게 한다 (research 00 § 2). 우리는 그 파일을 만들거나 호스팅하지 않는다. 이 스펙은 인게임 에디터, 공개 포맷 파일 가져오기·내보내기, 검증과 오류 표시, 모드 적용 범위를 정한다. 실명 데이터 정책(A/B/C)은 **결정 대기**이므로, 이 스펙은 정책과 무관하게 필요한 "편집·가져오기 기능"만 다루고 어떤 데이터를 기본 탑재할지는 정하지 않는다.

## 범위
- 포함:
  - 인게임 에디터: 선수(이름, 국적, 생년, 포지션, 능력치, 역할 성향·버릇, 외형 파라미터), 감독(이름, 성향), 클럽(이름, 약칭 3글자, 팀 색, 엠블럼 이미지, 경기장 이름), 리그·대회 이름
  - 공개 포맷 파일 가져오기·내보내기 (스키마는 022가 제공)
  - 시나리오 정의 파일 가져오기 (스키마는 013·014가 제공)
  - 가져오기 전 검증: 스키마, 값 범위, 참조 무결성, 중복 id, 이미지 형식·크기
  - 오류·경고 표시 (파일·줄·필드 단위), 부분 가져오기 여부 선택
  - 모드 목록·켜기/끄기·적용 순서·충돌 표시
  - 모드 적용 범위: 새 커리어 시작 시 적용 / 진행 중 커리어에 적용 가능 여부 규칙
  - 기본 데이터 복원
- 제외:
  - 실명 데이터 정책 결정 — A안 확정 (2026-11-02 사용자 결정): 클럽·경기장 변형 이름, 선수·감독 가상, 실명 로스터는 사용자가 이 스펙으로 직접 가져온다
  - 데이터 파일 공유·검색·다운로드 기능, 호스팅 (만들지 않는다)
  - 로스터 업데이트 서버 배포 (022 또는 별도 스펙)
  - 시나리오 그래프 편집기(시각적 단계 편집). 이 스펙은 시나리오 파일 가져오기·검증까지 [미정: 편집기는 이후]
  - 3D 얼굴·유니폼 텍스처 편집 (팀 색·엠블럼 이미지만)

## 사용자 시나리오
1. 플레이어가 설정 → 데이터 → 가져오기에서 내려받은 데이터 파일을 고른다. 검증 결과 "선수 2,140명, 클럽 40개, 경고 3건"이 보이고, 경고를 확인한 뒤 가져온다.
2. 새 커리어를 시작할 때 켜진 모드 목록이 보이고, 그 데이터로 세계가 만들어진다.
3. 에디터에서 클럽 이름과 팀 색을 바꾸면 미리보기 카드에 바로 반영되고, 저장하면 그 클럽이 나오는 모든 화면에 반영된다.
4. 오류가 있는 파일을 가져오면 "players.json 412번째 항목: 능력치 'passing'이 21이에요 (1~20)"처럼 위치와 이유가 보이고, 가져오기는 진행되지 않는다.
5. 두 모드가 같은 클럽을 바꾸면 충돌 표시와 함께 어느 모드가 이기는지(적용 순서) 보인다.

## 요구사항

### 에디터
- FR-01: 편집 대상: 선수, 감독, 클럽, 경기장 이름, 리그·대회 이름. 필드 목록과 값 범위는 002·003·020·022의 정의를 그대로 쓴다 (에디터가 별도 규칙을 만들지 않는다).
- FR-02: 능력치는 표시 스케일 1~20 정수로 편집한다 (기획서 4.2). 내부 스케일과 변환 규칙은 002가 정한다(내부 0~100 / 표시 1~20 — 확정 (2026-11-02 사용자 결정), 002 FR-14). 공개 포맷 파일의 능력치 스케일은 022 스키마를 따른다. 숨김값(부상 경향 등)과 잠재력도 편집 가능하되, 에디터 화면에서만 보이고 일반 게임 화면 노출 규칙(038 FR-65·AC-10)은 그대로다.
- FR-03: 편집 즉시 미리보기(선수 카드, 클럽 카드: 037 컴포넌트). 저장 전까지 게임 데이터에 반영되지 않는다. 저장하지 않고 나가면 확인 시트.
- FR-04: 되돌리기/다시하기 [제안] 최근 50단계.
- FR-05: 검색·필터·정렬 (이름, 클럽, 포지션, 능력치). 수만 명 목록에서도 끊기지 않는다 (037 FR-24).
- FR-06: 엠블럼 이미지: 형식(PNG [제안]), 최대 크기 [제안] 512×512, 최대 파일 크기 [제안] 1MB. 넘으면 거부하고 이유 표시.
- FR-07: 팀 색: 주색·보조색. 두 팀 색 대비가 너무 낮으면 경고 (2D·3D·HUD 구분 문제, research 07 § 5.3).
- FR-08: 클럽 약칭 3글자 (039 FR-01). 같은 리그 안 중복이면 경고.
- FR-09: 진행 중 커리어에서 에디터 편집 허용 범위 [미정] (편집 시 "업적 비활성" 같은 표시를 둘지 포함).

### 가져오기 · 내보내기
- FR-20: 공개 포맷 파일(022가 정의하는 JSON 스키마, 아키텍처 7: 공개 JSON 포맷)을 사용자가 고른 로컬 파일 또는 폴더에서 가져온다. 네트워크에서 직접 받지 않는다.
- FR-21: 가져오기 전 검증 단계 (모두 끝난 뒤 결과 요약):
  - 스키마 버전 확인 (지원 버전 목록은 022가 제공, 낮은 버전은 변환, 높은 버전은 거부)
  - 필드 타입·필수 필드·값 범위
  - 참조 무결성 (선수의 클럽 id가 존재, 대회 참가 클럽 수 등)
  - id 중복 (파일 안, 기존 데이터와)
  - 문자열 길이·금지 문자 (제어 문자 등)
  - 이미지 형식·크기
  - 수량 상한 [제안] (선수 20만 명, 클럽 5,000개, 파일 총 500MB)
- FR-22: 결과는 오류(가져오기 불가)와 경고(가져오기 가능)로 나눈다. 각 항목에 파일, 위치(항목 번호·줄), 필드, 이유, 고칠 값 힌트.
- FR-23: 오류가 1개라도 있으면 기본은 가져오기 불가. "오류 항목만 건너뛰고 가져오기"를 선택할 수 있다 [제안]. 건너뛴 항목 수와 그 때문에 깨지는 참조(건너뛴 클럽 소속 선수 등)를 미리 보인다.
- FR-24: 가져오기는 원자적이다: 중간에 실패하거나 앱이 종료되면 이전 상태로 남는다 (부분 적용 상태 없음). 무결성 보장 방식은 022.
- FR-25: 내보내기: 현재 편집된 데이터(또는 모드 하나)를 같은 공개 포맷으로 내보낸다. 내보낸 파일을 다시 가져오면 같은 데이터가 된다 (왕복 동일).
- FR-26: 시나리오 정의 파일도 같은 흐름으로 가져온다 (스키마는 013·014). 시나리오는 추가 검증: 트리거·배역·분기 참조가 유효한지, 실행 시 무한 분기 루프가 없는지.
- FR-27: 가져온 파일의 내용은 데이터로만 다룬다. 실행 가능한 코드·스크립트는 받지 않는다 (보안). 경로가 들어가는 필드(이미지 등)는 모드 폴더 밖을 가리킬 수 없다.
- FR-28: 이름 덮어쓰기 팩: 개체 id → 표시 이름(클럽·약칭·리그·대회·경기장·선수·감독)만 바꾸는 가벼운 모드 형식을 지원한다(스키마는 022). 능력치 등 다른 값은 건드리지 않고, 일반 모드와 같은 적용 순서·충돌 규칙을 따른다. 정책 중립 기능이며, 실명 정책 A를 고르면 커뮤니티 실명 로스터가 이 형식을 쓸 수 있다 (020이 넘긴 요구).

### 모드 관리
- FR-30: 모드 목록: 이름, 출처 메모(사용자 입력), 포함 내용 요약(선수·클럽·시나리오 수), 켜기/끄기, 적용 순서.
- FR-31: 같은 개체를 여러 모드가 바꾸면 충돌로 표시하고, 적용 순서상 뒤의 모드가 이긴다. 충돌 개체 목록을 볼 수 있다.
- FR-32: 기본 데이터 복원: 모든 모드를 끄고 배포 기본 데이터로 돌아간다. 사용자 모드 파일은 지우지 않는다.
- FR-33: 모드 적용 시점: 새 커리어 시작 시 켜진 모드로 세계를 만든다 (020). 진행 중 커리어에 모드를 바꿔 적용하는 것은 [미정] (세이브 일관성 위험, 022와 함께).
- FR-34: 세이브는 어떤 모드(이름, 내용 해시)로 시작했는지 기록한다. 그 모드가 없거나 바뀌었으면 불러오기 시 경고한다 (022).

### 기본 데이터 정책 (실명 정책 A안 — 확정 (2026-11-02 사용자 결정))
- FR-40: 이 스펙의 구현과 테스트에 쓰는 모든 샘플·픽스처 데이터는 명백한 가상 이름만 쓴다 (`.claude/rules/01-legal.md`). 실존 선수·감독 이름, "살짝 바꾼" 이름 금지.
- FR-41: 에디터와 가져오기는 이름 필드에 대해 실명 여부를 판정하거나 막지 않는다 [제안] (판정 불가능하고, 사용자 데이터는 사용자 책임 — research 00 § 2). A안 확정 (2026-11-02 사용자 결정)과 일치: 실명 로스터는 사용자가 가져오는 커뮤니티 데이터이고, 우리는 만들거나 호스팅하지 않는다.
- FR-42: 에디터 첫 진입 시 안내 문구 [미정] (사용자가 가져온 데이터의 권리 관련 안내, 법률 검토 전까지 문구 확정 금지).

### 화면
- FR-50: 에디터·가져오기·모드 관리 화면은 037 토큰·컴포넌트만 쓰고, 038의 설정 화면에서 진입한다.
- FR-51: 검증 결과 화면: 오류 수·경고 수가 최상위 수치. 목록은 파일·필드별로 묶어 보고, 항목이 수만 개여도 끊기지 않는다.
- FR-52: 가져오기 진행 중 진행률(검증 단계·적용 단계)과 취소. 취소하면 아무것도 바뀌지 않는다.

## 경계 · 예외 상황
- 빈 파일, 빈 배열, 0바이트 파일, JSON 문법 오류(줄·열 표시), 잘못된 문자 인코딩(UTF-8 아님), BOM 있음.
- 매우 큰 파일(상한 근처, 상한 초과 → 거부), 매우 긴 문자열, 이모지·결합 문자·RTL 문자가 들어간 이름 표시.
- 능력치 0, 21, 소수, 음수, 문자열 숫자("15").
- 순환 참조(클럽 A의 모회사가 B, B가 A — 해당 필드가 있으면), 존재하지 않는 국적·리그 id.
- 같은 파일을 두 번 가져오기, 가져오는 중 같은 파일 수정.
- 스키마 버전: 이전 버전(변환), 현재, 미래 버전(거부), 버전 필드 없음.
- 이미지: PNG가 아닌 파일에 .png 확장자, 손상 이미지, 투명도 없음, 1×1, 상한 초과.
- 경로 필드에 `../`, 절대경로, 심볼릭 링크 → 거부.
- 모드 20개 이상 켬, 모든 모드가 같은 클럽 수정, 켜진 모드 파일이 디스크에서 지워짐.
- 가져오기 도중 앱 종료 → 재시작 시 이전 상태, 깨진 임시 파일 정리.
- 가져오기·내보내기·에디터 저장 중 디스크 공간 부족: 원자적으로 실패해 이전 상태 유지, "저장 공간이 부족해요 (필요 N MB)" 이유 표시. 내보내기는 부분 파일을 남기지 않는다.
- 에디터에서 리그에 클럽이 하나도 없게 만들거나, 대회 참가 수가 일정 생성(021) 조건을 만족하지 않게 만드는 편집 → 저장 시 오류.

## 비기능 요구사항
- 결정론: 같은 기본 데이터 + 같은 모드 목록(순서 포함) + 같은 시드 → 같은 세계 (020). 모드 적용 결과는 파일 읽는 순서·파일 시스템 순서와 무관해야 한다.
- 세이브 호환: 모드 정보(이름, 내용 해시)를 세이브에 기록 (022).
- 보안: 가져온 데이터로 코드가 실행되지 않는다. 경로 탈출 0.
