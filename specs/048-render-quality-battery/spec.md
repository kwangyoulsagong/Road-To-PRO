## 배경
그래픽 목표는 확정됐다: FM 경기 화면 수준, **내장 GPU 노트북에서도 60fps**, 배터리 고려. 3D는 하이라이트에만 쓰고 매니지먼트 화면에서는 3D를 아예 내린다. 이 스펙은 품질 프리셋(Low/Medium/High)이 정확히 무엇을 켜고 끄는지, 앱 상태별 프레임레이트·렌더 정책, 그리고 **전체 프레임 예산**을 정한다. 다른 프레젠테이션 스펙(041~047)은 여기서 정한 예산의 자기 몫을 지킨다. 성능 판정은 000 디바이스팜 프로필별 측정값으로만 한다.

## 이번 스펙 범위 (P1, 2026-11-10 사용자 결정)
이 스펙 문서는 렌더 품질 전체 설계를 담고, **이번 구현은 P1만** 한다. 각 FR·AC 끝의 `(후속)`은 뒤 스펙으로 넘긴 항목이다.
- **P1 구현**: Low 프리셋(렌더 스케일 0.67 · STP 업스케일 · 블롭 섀도 · 톤맵+약한 블룸 · 텍스처 1K), 하이라이트 60fps · 배터리 절약 모드 30fps, 타임라인 구간 3D 렌더 정지, 셰이더 워밍업 · 장면 전환 스파이크 방지, 전체 프레임 예산과 하위 시스템 몫 측정.
- **후속**: Medium/High 프리셋 정의 구현, 기기 감지 자동 추천, 설정 화면·설정 파일, 메뉴 유휴 렌더 정책·백그라운드, 재생 중 프리셋 변경, 하이라이트↔메뉴 반복 메모리, 화면비 검증.
- **URP 에셋**: 기존 Mobile/PC 에셋은 그대로 두고 **새 Low 에셋 + 품질 레벨을 추가**한다. Medium(현재 Mobile)·High(현재 PC)는 후속 스펙까지 기존 에셋을 대역으로 쓴다. 품질 설정과 디바이스팜 프로필 매핑이 바뀌므로 Low 프로필들의 기준 이미지는 재승인이 필요하다.
- **041 AC-15 · 042 AC-17 판정**: 장면 전환·리플레이 진입 전환 프레임 ≤ 25 ms를 이 스펙에서 **릴리스 빌드 E2E**로 판정한다 (AC-18). 디바이스팜에 릴리스 빌드 재생 측정을 추가한다.
- **[제안] 채택**: 최대 프레임 33 ms, 타임라인 구간 3D 렌더 정지, Low 후처리 톤맵+약한 블룸, Low 텍스처 1K, FR-21·22 하위 시스템 몫 원문 그대로. P1 범위 AC의 [제안] 수치(프리셋 차이 2% 등)도 원문대로 채택. 후속 항목의 [제안]은 후속 스펙에서 다시 정한다.

## 범위
- 포함:
  - 품질 프리셋 Low / Medium / High 정의 (P1은 Low만 구현, Medium/High는 후속)와 자동 추천(첫 실행 시 기기 감지) (후속)
  - 앱 상태별 렌더 정책: 매니지먼트·메뉴(UI만, 3D 언로드, 30fps, 입력 없을 때 렌더 간격 확대) (후속), 하이라이트(3D 로드, 60fps), 배터리 절약 모드(하이라이트 30fps), 타임라인 구간 3D 렌더 정지
  - 렌더 스케일과 업스케일 (0.67~0.75), 출력 해상도
  - 렌더링 구성: 실시간 GI 없음, 라이트맵 베이크, 방향광 1개, 블롭 섀도, 무거운 후처리 기본 꺼짐
  - 전체 프레임 예산(GPU·CPU 메인 스레드·드로우콜·삼각형·텍스처 메모리)과 하위 시스템 몫 배분
  - 셰이더 워밍업·장면 전환 프리로드로 프레임 스파이크 방지
  - 설정 화면 항목(프리셋, 렌더 스케일, 프레임 제한, 배터리 절약 모드)과 즉시 적용 (후속)
  - 프로필별 성능 회귀 검증 (000 FR-40~44)
  - 041 AC-15 · 042 AC-17 전환 프레임의 릴리스 빌드 판정
- 제외:
  - 각 에셋의 제작 (선수 모델 043, 경기장 044, 관중 045)
  - 카메라 연출 (042)
  - UI 화면 디자인 (037). 이 스펙은 UI 화면의 **렌더 빈도 정책**만 정한다
  - Ultra 프리셋, 레이트레이싱, 실시간 GI(Surface Cache GI), SSR, DLSS/FSR — 출시 이후 검토 (research 06 § 7 3단계)
  - 모바일 빌드 (프로필로 화면비만 흉내 — 000)

## 사용자 시나리오
1. 내장 GPU 노트북에서 처음 실행하면 Low가 자동 선택되고, 하이라이트가 60fps로 부드럽게 재생된다.
2. 매니지먼트 화면에서 아무것도 안 하고 있으면 노트북 팬이 조용하고 배터리가 거의 줄지 않는다.
3. 전원을 뽑고 배터리 절약 모드를 켜면 하이라이트가 30fps로 바뀐다. 끄면 60fps로 돌아온다.
4. 데스크톱에서 High를 고르면 잔디가 입체적이고 관중이 개별로 움직이며 나이트 경기 조명탑 그림자가 생긴다.
5. 하이라이트 장면이 바뀔 때 화면이 멈칫하지 않는다.

## 요구사항

### 품질 프리셋
- FR-01: 프리셋 정의 (기획서 5.5.1, 아키텍처 8):

  | 항목 | Low | Medium | High |
  |---|---|---|---|
  | 조명 | 라이트맵 베이크, 방향광 1개 | Low와 같음 | Low와 같음 + 플러드라이트 실그림자 4개 |
  | 선수 그림자 | 발밑 블롭 섀도 (나이트 경기 4장) | 방향광 그림자 1개 + 블롭 섀도 | 실시간 그림자 (방향광 + 플러드라이트) |
  | 잔디 | 단일 셰이더 (줄무늬 + SDF 라인) | Low와 같음 | 셸 텍스처 잔디 |
  | 관중 | 빌보드 | 빌보드 + 관중 LOD (045) | 정점 애니메이션 관중 (045) |
  | 선수 LOD | LOD1 위주 (약 2~3k tris), 클로즈업만 LOD0 | LOD0 클로즈업, LOD1 기본 | LOD0 (약 6~10k tris) 확대 범위 |
  | SSAO · 볼류메트릭 · SSR | 끔 | 끔 | 끔 [제안: 6.7 LTS 이후 High 옵션 검토] |
  | 후처리 | 톤맵 + 약한 블룸 [제안] | 톤맵 + 블룸 + 비네트 | Medium + 리플레이 DoF [제안] |
  | 렌더 스케일 기본 | 0.67 | 0.75 | 1.0 [제안] |
  | 텍스처 최대 해상도 | 1K [제안] | 2K | 2K |

  [제안] 표시 칸 외에는 기획서 원문 값. Low 열의 [제안](톤맵+약한 블룸, 텍스처 1K)은 채택 (2026-11-10). P1은 Low 열만 구현하고 Medium/High 열은 후속 스펙에서 구현한다 (그때까지 기존 Mobile/PC 에셋이 대역). 클로스 시뮬레이션은 모든 프리셋에서 끔 (기획서 5.5.1).
- FR-02: 첫 실행 시 기기를 감지해 프리셋을 추천한다: 내장 GPU → Low, 보급형 외장(GTX 1050급) → Medium, 그 이상 → High [제안: 감지 기준은 미정]. 사용자가 바꾸면 그 값을 유지한다. (후속)
- FR-03: 프리셋·렌더 스케일 변경은 재시작 없이 다음 프레임부터 적용된다. 하이라이트 재생 중 변경도 허용 (재생이 끊기지 않는다). (후속 — P1은 배터리 절약 모드 토글만 재생 중 즉시 적용)
- FR-04: 실시간 GI 없음 (기획서 5.5.1). 라이트맵은 경기장별로 베이크된 것을 쓴다 (044 제공).

### 앱 상태별 렌더 정책
- FR-10: 매니지먼트·메뉴 화면: 3D 씬 언로드, UI만 렌더, 목표 30fps, 입력이 없으면 렌더 빈도를 더 낮춘다 (기획서 5.5.1 `OnDemandRendering.renderFrameInterval` 언급). 입력·애니메이션(카운트업, 시트 슬라이드)이 시작되면 즉시 정상 빈도로 돌아온다. (후속)
- FR-11: 입력 없는 상태의 렌더 간격과 복귀 지연 (이 스펙이 값의 원본, 037 FR-70~72가 UI 쪽 규칙을 따른다): 입력·애니메이션 없이 2초 [제안] 후 렌더 ≤ 10프레임/초 [제안], 입력이 들어오면 다음 프레임부터 정상 빈도, 입력 후 첫 반응 프레임까지 ≤ 50 ms [제안]. (후속)
- FR-12: 하이라이트: 3D 씬 로드, 모든 프리셋 목표 60fps (아키텍처 8).
- FR-13: 배터리 절약 모드: 사용자가 켤 때만 하이라이트 30fps (기획서 5.5.1). 자동으로 켜지 않는다. 전원 연결 상태 표시는 할 수 있다 [제안] (후속). P1은 켜고 끄는 진입점(코드·E2E용)만 두고 설정 화면은 후속.
- FR-14: 수직 동기·프레임 제한: 목표 fps를 넘어 렌더하지 않는다 (불필요한 전력 소비 방지). 고주사율 모니터에서도 메뉴 30 / 하이라이트 60 (사용자 설정으로 하이라이트 상한 변경 가능 [제안]). P1은 하이라이트 60/30 상한, 메뉴 30과 사용자 상한 변경은 후속.
- FR-15: 하이라이트 → 메뉴 전환 시 3D 씬·텍스처·메시·관중·경기 오디오 리소스가 해제된다. 메뉴 → 하이라이트 전환 시 필요한 리소스를 미리 로드한다. (후속 — 해제는 041 FR 현행 유지, 50회 반복 검증은 후속)
- FR-16: 앱이 백그라운드·최소화되면 렌더를 멈추거나 최저 빈도로 낮춘다. (후속)
- FR-17: 하이라이트 장면 사이 텍스트 타임라인 구간(041 FR-32, 039 FR-30)에서는 3D 렌더를 멈추고 마지막 프레임을 타임라인 UI 뒤에 고정한다 (채택 2026-11-10). 다음 장면 시작 1프레임 전에 렌더를 재개해 첫 프레임이 늦지 않는다. 이 구간 렌더 빈도는 메뉴 정책(FR-10~11)을 따른다 — P1에서는 메뉴 정책이 없으므로 구간 동안 3D 렌더 0프레임, UI만 그린다.

### 프레임 예산 (전체)
- FR-20: 하이라이트 60fps 기준 전체 예산 (기획서 5.5.1):
  - 프레임 16.6 ms 중 **GPU ≤ 10 ms**, **CPU 메인 스레드 ≤ 8 ms**
  - **드로우콜 ≤ 300** (Low), **화면 내 삼각형 ≤ 50만**, **텍스처 메모리 ≤ 1 GB**
  - 경기장 전체(피치 포함, 관중 제외) ≤ 10만 tris (기획서 5A.3). 선수 폴리곤은 043이 정한 LOD 예산(기획서 5.5.1: LOD0 6~10k / LOD1 2~3k)을 따른다 — 5A.3의 '1명 3~5k'와의 차이는 미정 참고
- FR-21: 하위 시스템 몫 (채택 2026-11-10) — 각 스펙이 자기 몫을 AC로 검증한다:

  | 시스템 | GPU (Low) | 드로우콜 (Low) | 삼각형 | 담당 스펙 |
  |---|---|---|---|---|
  | 피치·잔디 | 1.0 ms | 10 | 0.5만 | 044 |
  | 경기장 구조 | 1.5 ms | 50 | 9.5만 | 044 |
  | 선수 22명 + 심판 3명 | 2.0 ms | 75 | 15만 (클로즈업 LOD0 포함) | 043 |
  | 관중 | 1.5 ms | 20 | 10만 | 045 |
  | 공·골망·소품·VFX | 0.5 ms | 30 | 1만 | 041/044 |
  | 후처리·업스케일 | 1.0 ms | 5 | — | 048 |
  | HUD (UI) | 0.5 ms | 30 | — | 039 |
  | 여유 | 2.0 ms | 80 | 14만 | — |
  | **합계** | **10 ms** | **300** | **50만** | |

  이 표가 하위 몫의 **원본**이다. 044(경기장 합계 드로우콜 60·삼각형 10만·피치 GPU 1.0 ms·구조 GPU 1.5 ms), 043(GPU 2 ms·드로우콜 75·삼각형 15만), 045(GPU 1.5 ms·드로우콜 20·삼각형 10만), 039(드로우콜 30)는 이 값을 인용한다. 값을 바꾸면 여기서 먼저 바꾸고 해당 스펙을 맞춘다.

- FR-22: CPU 메인 스레드 8 ms 몫 (채택 2026-11-10): 재생·애니메이션 3 ms (이 안에 043 선수 애니메이션 2 ms, 그 안에 054 궤적 맞춤 0.8 ms), 카메라·연출 1 ms, UI 1 ms, 오디오 0.3 ms, 관중 0.3 ms, 여유 2.4 ms. 하이라이트 재생은 이미 계산된 시뮬 결과를 읽으므로 시뮬 계산 몫은 0 (90분 시뮬은 재생 전에 끝남 — 006/017).
- FR-23: 하이라이트 재생 중 GC 할당 0 B/프레임 (모든 프레젠테이션 시스템 공통 규칙).

### 업스케일과 해상도
- FR-30: 출력 해상도는 창·화면 해상도, 내부 렌더 해상도 = 출력 × 렌더 스케일. 1080p + Low + 0.67~0.75 업스케일로 60fps (기획서 5.5.1).
- FR-31: 업스케일러는 URP 기본 업스케일(STP) 사용 (research 06 § 1.2). STP는 동적 해상도와 같이 쓸 수 없으므로 렌더 스케일 고정값만 쓴다.
- FR-32: 빠른 공·가려졌다 드러나는 영역의 업스케일 잔상(고스팅)은 E2E 캡처로 검증한다 (research 06 § 1.2).
- FR-33: UI는 렌더 스케일과 무관하게 출력 해상도로 선명하게 그려진다.

### 스파이크 방지
- FR-40: 하이라이트 첫 장면 전에 셰이더 워밍업을 끝낸다 (기획서 5.5.1). 장면 전환 시 다음 장면 에셋을 미리 로드한다.
- FR-41: 하이라이트 재생 중 어떤 프레임도 33 ms를 넘지 않는다 (채택 2026-11-10) (60fps 기준 2프레임 드롭 이상 금지). 장면 전환·리플레이 진입 ±1초 구간은 더 엄격한 ≤ 25 ms (041 FR-31·042 성능 예산). 이 ≤ 25 ms는 릴리스 빌드에서 판정한다 (AC-18).
- FR-42: 하이라이트 진입 로딩 시간은 041이 원본: 첫 진입 ≤ 4 s [제안], 같은 세션 재진입 ≤ 2 s [제안] (메뉴 → 첫 장면 프레임).

### 설정 (후속 — FR-50~52 전부)
- FR-50: 설정 항목: 품질 프리셋, 렌더 스케일(0.5~1.0, 0.05 단위 [제안]), 하이라이트 프레임 상한, 배터리 절약 모드, 창 모드·해상도. 프리셋을 고른 뒤 개별 항목을 바꾸면 "사용자 지정"으로 표시.
- FR-51: 설정은 사용자 설정 파일에 저장되고 세이브와 독립이다.
- FR-52: 잘못된 설정 파일(손상, 범위 밖 값)은 기본값(자동 추천)으로 복구하고 경고 1회 표시 — 크래시 없음.

### 경계 · 예외 상황
P1 범위: 배터리 절약 모드 재생 중 토글, GPU가 목표를 못 맞출 때 재생 시각·오디오 동기, 타임라인 구간 정지 중 창 크기 변경. 나머지는 후속.
- 하이라이트 재생 중 프리셋 변경 Low → High → Low: 리소스 누수 없음, 재생 계속, 변경 직후 1초 안에 목표 fps 회복.
- 배터리 절약 모드 켬/끔을 재생 중 반복: 프레임 상한이 즉시 바뀌고 재생 속도(1.5x 등) 시간 진행은 fps와 무관하게 정확하다 (30fps에서도 장면 길이가 같다).
- 창 크기 변경·전체 화면 전환·외부 모니터 연결/해제: 렌더 타깃이 다시 만들어지고 UI 레이아웃이 깨지지 않는다.
- 고DPI(배율 2.0, 3.0) + 렌더 스케일 0.5: UI는 선명, 3D만 낮은 해상도.
- 21:9·4:3·세로 화면비: 3D 카메라 시야·HUD가 잘리지 않는다 (042/039와 함께).
- 메뉴에 오래(30분 이상) 머문 뒤 하이라이트 진입: 리소스가 정상 로드된다.
- 하이라이트 ↔ 메뉴 50회 반복: 메모리 누적 증가 없음.
- GPU가 목표를 못 맞추는 기기: 프레임이 떨어져도 재생 시각·오디오 동기가 어긋나지 않는다. 설정 화면에 "낮은 프리셋 권장" 안내 [제안].
- 앱 백그라운드 → 복귀: 하이라이트가 멈춘 지점부터 이어진다.
- 메뉴 → 3D 전환(로딩) 중 입력: 취소(뒤로 가기)만 받고 나머지 입력(탭 전환·설정 변경)은 무시한다. 3D → 메뉴 전환 중에는 입력을 막고, 전환이 끝난 다음 프레임부터 받는다 (중간 상태에서 메뉴 버튼이 눌려 3D가 반만 해제되는 일 없음).
- 텍스트 타임라인 구간에서 렌더를 멈춘 상태로 프리셋·창 크기를 바꾸면 다음 장면 재개 첫 프레임에 새 설정이 적용된다.

## 비기능 요구사항
- 결정론: 프리셋·렌더 스케일·fps·해상도가 시뮬 결과와 재생 시각 진행을 바꾸지 않는다 (000 FR-51과 같은 원칙). 같은 장면·같은 시점 캡처는 같은 프리셋이면 같은 이미지다.
- 전력: 메뉴 대기 상태의 GPU 사용이 하이라이트 대비 크게 낮아야 한다 (측정 기준은 [미정] — 맥에서는 전력 지표 측정 방법을 플랜에서 정한다).
- 진짜 성능 판정: 000 FR-44에 따라, 흉내 낸 프로필(`low-igpu-1080p`를 맥에서 실행)은 상대 비교용이다. **실제 내장 GPU 기기 측정이 생기기 전에는 최소 사양 60fps를 '완료'로 판정할 수 없다** (research 06 § 8.1: Windows 기기 필요).

## 수용 기준
P1 판정 대상: AC-01, 04, 05, 06, 08, 09, 11, 12, 15, 16, 17(렌더 부분), 18. `(후속)` AC는 뒤 스펙으로 옮긴다. 흉내 낸 프로필 측정이므로 최소 사양 60fps 관련 AC는 통과해도 "잠정"으로 표시한다 (000 FR-44).
- AC-01 [로직]: Low 프리셋 정의 데이터가 FR-01 표 Low 열과 항목별로 일치한다 (렌더 스케일 0.67, STP 업스케일, 블롭 섀도, 실시간 그림자·셸 잔디·SSAO·볼류메트릭·SSR 꺼짐, 후처리 톤맵+약한 블룸, 텍스처 최대 1K). Medium/High 열 검증은 후속.
- AC-02 [로직]: 기기 정보 입력(내장 GPU / 보급형 외장 / 상위 외장)마다 추천 프리셋이 Low / Medium / High다. 사용자가 바꾼 값은 재시작 후에도 유지된다. (후속)
- AC-03 [로직]: 손상된 설정 파일·범위 밖 렌더 스케일(0.1, 3.0)을 넣으면 기본값으로 복구되고 크래시·예외가 없다. (후속)
- AC-04 [결정론]: 같은 하이라이트를 Low/Medium/High(Medium·High는 대역 에셋), 30/60fps로 재생한 시뮬 해시와 장면별 재생 길이(시뮬 시각)가 모두 같다.
- AC-05 [E2E]: `e2e/048-presets` — 고정 장면 고정 시점을 Low/Medium/High(Medium·High는 기존 Mobile/PC 대역)로 캡처하면 프리셋 쌍 사이 픽셀 차이 비율이 각각 ≥ 2% [제안] (프리셋이 실제로 다르게 그린다: 블롭 섀도 vs 실시간 그림자, 셸 잔디 유무, 관중 표현)이고, 각 캡처는 자기 기준 이미지와 차이 임계값 이하. 프로필: low-igpu-1080p(Low), mac-m1-1600p(Medium), desktop-1440p(High).
- AC-06 [E2E]: `e2e/048-upscale` — 빠른 슈팅 장면을 렌더 스케일 1.0 / 0.75 / 0.67로 캡처해 공 주변 잔상을 비교하고, UI 텍스트는 세 스케일에서 같은 선명도다 (UI 영역 차이 0). 프로필: low-igpu-1080p, uhd-4k-200.
- AC-07 [E2E]: `e2e/048-aspect` — 하이라이트 고정 시점을 16:9·16:10·21:9·4:3·세로 화면비에서 캡처해 검은 화면·잘린 HUD·늘어난 화면이 없다. 프로필: 전체. (후속)
- AC-08 [성능]: `e2e/048-perf-highlight` — 대표 하이라이트 3장면(골·코너킥·역습, 나이트 경기 포함) 성능 구간에서 프로필별(Low 프로필은 새 Low 에셋, Medium/High 프로필은 대역 에셋 — 기준선 기록용) p95 프레임·GPU·CPU·드로우콜·삼각형·텍스처 메모리가 예산 안이다. 프로필: 성능 예산 표의 프로필 전체.
- AC-09 [성능]: 하이라이트 재생 중 최대 프레임 시간 ≤ max(33 ms, 같은 실행에서 3D 없이 같은 목표 fps로 잰 빈 화면 구간의 최대), 장면 전환 프레임 포함 — 재생이 유발한 스파이크만 판정하고 맥 프레임 페이싱 소음은 빼낸다 (2026-11-10 사용자 결정, 041·054 '빈 화면 대비' 선례). GC 0 B/프레임. 프로필: low-igpu-1080p.
- AC-10 [성능]: `e2e/048-menu-idle` — 매니지먼트 화면에서 입력 없이 2초가 지나면 렌더가 ≤ 10프레임/초로 떨어지고(10초 관찰), 입력 후 다음 프레임에 정상 빈도로 돌아오며 첫 반응 프레임까지 ≤ 50 ms. 카운트업·시트 애니메이션 중에는 낮아지지 않는다. 메뉴 상태의 3D 리소스 메모리 0. 프로필: smoke. (후속)
- AC-11 [성능]: 배터리 절약 모드에서 하이라이트가 30 ± 1 fps, 끄면 1초 안에 60fps로 돌아온다. 프로필: low-igpu-1080p.
- AC-12 [성능]: 하이라이트 진입 로딩 첫 진입 ≤ 4 s·재진입 ≤ 2 s (041 AC와 같은 측정), 첫 장면에서 셰이더 컴파일로 인한 스파이크 없음 (첫 장면 최대 프레임 ≤ 33 ms). 프로필: low-igpu-1080p.
- AC-17 [E2E]: `e2e/048-timeline-gap` — 장면 사이 텍스트 타임라인 구간에서 3D 렌더 프레임 수가 0(또는 메뉴 정책 빈도)이고, 다음 장면 첫 프레임이 지연 없이(재개 ≤ 1프레임 전) 그려진다. 로딩 중 탭 전환 입력이 무시되고 취소만 동작한다(이 입력 부분은 후속 — 메뉴 화면이 생긴 뒤). 프로필: smoke.
- AC-13 [성능]: 하이라이트 ↔ 메뉴 50회 반복 후 메모리가 첫 회 대비 증가하지 않는다 (허용 오차 ≤ 2% [제안]). (후속)
- AC-14 [E2E]: 재생 중 프리셋 Low → High → Low, 창 크기 변경, 배터리 절약 모드 토글을 순서대로 해도 재생이 이어지고 에러·경고 로그 0. 1초 안에 목표 fps 회복. 프로필: mac-m1-1600p. (후속 — 재생 중 프리셋 변경이 후속이므로)
- AC-15 [성능]: 성능 회귀: 이전 통과 측정 대비 p95 프레임 시간·GPU 시간이 +10% 이상 나빠지면 실패 (000 FR-43). 이 스펙의 성능 시나리오는 이후 모든 프레젠테이션 스펙의 회귀 기준선이 된다.
- AC-16 [성능]: 하위 시스템 몫(FR-21)을 프레임 통계 마커로 나눠 기록하고, 몫을 넘긴 시스템이 리포트에 표시된다.
- AC-18 [성능]: `e2e/048-transition-release`·`e2e/048-replay-release` — 릴리스 빌드(개발 빌드 아님)로 하이라이트를 재생해 모든 장면 전환(최소 8회)과 리플레이 진입 ±1초 구간 최대 프레임이 ≤ max(25 ms, 같은 구간의 전환 밖 프레임 최대)이고 (전환이 유발한 스파이크만 판정, 2026-11-10 사용자 결정 — 릴리스 측정에서 25 ms 초과 비율이 전환 안팎에서 같았다), 전환 순간 동기 로드·셰이더 컴파일 이벤트가 0건이다. 이 결과로 041 AC-15·042 AC-17을 판정한다. 프로필: low-igpu-1080p (mac-m1-1600p 참고 기록).
