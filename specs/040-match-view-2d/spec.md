# 040 — 2D 탑뷰 매치뷰

상태: 초안
브랜치: feat/040-match-view-2d
기획 출처: docs/index.html § 기획서 7(로드맵 M1 2D 매치뷰: "탑뷰 2D로 시뮬 시각화, 선수 이동과 패스가 눈으로 자연스러움"), § 8(리스크: 3D 비용 → 2D 뷰로 먼저 출시 가능하게 설계), § 4.4(하이라이트만 재생, 풀경기 시청 없음), § 5.2(xT 16×12), § 5.4(피치 컨트롤 32×20), § 5.1.1(시나리오 배역 3~5명, 형태 레이어) / § 아키텍처 3(결정 10Hz, 물리 100Hz) / research 01 § B-1(Vmax ≈ 8.95 m/s, a0 ≈ 8.5 m/s²), § A-6(공 구름), research 07 § 2.3(상태 스냅샷 30Hz 녹화·보간)

## 배경
3D(M5)보다 먼저, 시뮬이 "축구처럼" 움직이는지 눈으로 확인할 화면이 필요하다 (M1). 2D 탑뷰는 두 가지 역할을 한다. ① **개발 도구**: 시뮬 코어를 디버깅하고 밸런스를 보는 창. 피치 컨트롤·xT·시나리오 배역 같은 내부 상태를 겹쳐 본다. ② **대체 재생기**: 3D가 준비되기 전, 또는 3D를 끈 저사양 환경에서 하이라이트를 2D로 재생한다 (기획서 8: 2D로 먼저 출시 가능하게). "자연스러움"은 주관이라, 이 스펙은 그것을 측정 가능한 기준(순간이동 없음, 속도·가속 한계 안, 공 궤적 연속, 프레임 안정)으로 바꾼다.

## 범위
- 포함:
  - 피치(105×68m, 라인·박스·센터서클·골대) 탑뷰 렌더
  - 선수 22명 표시 (팀 색, 등번호, 내 선수 강조, 진행 방향), 심판 표시
  - 공 표시 (높이를 크기·그림자 오프셋으로 표현), 공 궤적 꼬리
  - 녹화된 시뮬 상태(주기는 006이 정함, research 07 § 2.3 권장 30Hz — README D2) 사이를 보간해 매끄럽게 재생
  - 재생 시계: 배속 1x/1.5x/2x/3x, 리플레이 0.5x, 일시정지, 시점 이동(seek)
  - 하이라이트 재생 모드(제품용) / 전체 경기 재생 모드(개발용 전용)
  - 개발용 디버그 오버레이: 004~013 스펙의 E2E 증거를 찍는 공용 창 (FR-30 표의 레이어 전부)
  - 039 HUD를 위에 올릴 수 있는 영역
- 제외:
  - 시뮬 계산 자체(004~013), 스냅샷 녹화 형식(006이 제공하는 SimEvent·상태 스트림을 소비만)
  - 3D 재생(041), 중계 카메라(042)
  - HUD(039)
  - 출시 빌드에서 전체 경기 시청 기능 (확정: 풀경기 시청 없음. 전체 경기 모드는 개발 빌드 전용)

## 사용자 시나리오
1. (개발자) 시드 42 경기를 전체 경기 모드로 열고 3x로 돌리며, 피치 컨트롤 오버레이를 켜서 빌드업 때 공간이 어떻게 열리는지 본다.
2. (개발자) 이상한 패스가 나온 시각으로 이동해 0.5x로 보고, 패스 후보 점수 오버레이에서 왜 그 패스가 선택됐는지 확인한다.
3. (플레이어, 3D 꺼짐) 하이라이트가 2D 탑뷰로 재생된다. 선수 점들이 끊김 없이 달리고, 크로스는 공이 커졌다 작아지며 박스로 날아간다.
4. (개발자) 시나리오 배역 오버레이를 켜면 공 주변 4명에게 "carrier / st / am_or_cm / fb_same" 라벨과 현재 단계가 보이고, 배역이 끝난 선수는 형태 슬롯으로 돌아가는 화살표가 보인다.

## 요구사항

### 피치 · 개체 표시
- FR-01: 피치 규격 105×68m, 골대 폭 7.32m (기획서 5A.1). 축척은 화면 크기에 맞춰 피치 전체가 보이게 하고, 화면비가 달라도 피치 비율을 유지한다 (남는 공간은 바탕).
- FR-02: 선수: 팀 색 원 + 등번호 + 진행 방향 표시. 내 선수는 테두리 강조. 팀 색이 비슷하면 한 팀에 모양 구분을 더한다 (research 07 § 5.3 색각 보정).
- FR-03: 공: 위치 + 높이 표현(높을수록 크게, 그림자는 지면 위치). 공 상태(Controlled, Air, Bounce, Rolling, Rest — 아키텍처 5)를 디버그 오버레이에서 표시.
- FR-04: 공 궤적 꼬리 [제안] 최근 1초.
- FR-05: 심판 표시 (주심, 부심 위치).

### 재생
- FR-10: 시뮬이 기록한 상태 스냅샷(주기는 006이 정함, 기본 가정 30Hz) 사이를 보간해 화면 프레임마다 위치를 계산한다. 렌더 프레임률은 시뮬 기록 주기와 독립이다.
- FR-11: 재생 시계는 게임 프레임 시간과 분리된 별도 시계다 (research 07 § 2.3: 슬로모는 리플레이 시계를 따로). 배속은 이 시계에만 곱한다.
- FR-12: 배속 1x / 1.5x / 2x / 3x, 리플레이 0.5x (확정). 일시정지, 시점 이동(임의 시각으로).
- FR-13: 시점 이동 후 첫 프레임부터 정확한 위치를 보인다 (이전 위치에서 미끄러지듯 이동하지 않음).
- FR-14: 하이라이트 모드: 018이 준 장면 구간([이벤트 −8초, +3초], research 07 § 2.4)만 재생하고, 사이는 039 타임라인으로 넘긴다.
- FR-15: 전체 경기 모드(개발 빌드 전용): 90분 + 추가시간 전체를 재생·이동. 출시 빌드에는 진입 경로가 없다.
- FR-16: 재생은 시뮬 결과를 바꾸지 않는다. 같은 녹화를 어떤 배속·이동 조합으로 봐도 같은 시각에는 같은 위치다.

### "자연스러움"의 측정 기준
- FR-20: **순간이동 없음**: 화면에 그려지는 선수 위치의 프레임 간 이동량이 (선수 최고속도 × 재생 시간 경과 × 여유 계수) 이하. 최고속도 기준은 research 01 § B-1의 Vmax ≈ 8.95 m/s를 상한 참고값으로 쓰고, 실제 상한은 005가 선수별로 제공. 여유 계수 [제안] 1.2. 시점 이동 직후 1프레임과 교체 투입·퇴장은 예외.
- FR-21: **가속 한계**: 보간된 표시 위치에서 계산한 가속이 005의 선수별 최대 가속·감속 한계(참고: a0 ≈ 8.5 m/s², 감속 −5~−7 m/s² [U], research 01 § B-1·B-2)의 [제안] 1.5배를 넘지 않는다. 보간이 만든 덜컹임(속도 꺾임)을 잡기 위한 기준.
- FR-22: **공 궤적 연속**: 공 표시 위치는 공이 소유자에게 붙어 있는 구간(Controlled)을 제외하면 끊기지 않는다. 패스·슈팅 시작 시 공이 차는 선수 위치에서 출발한다 (출발 지점 오차 [제안] ≤ 0.5m).
- FR-23: **겹침**: 같은 팀 선수 두 명이 [제안] 0.3m 이내로 0.5초 이상 겹쳐 보이면 경고로 기록한다 (시뮬 충돌 회피 문제를 드러내는 디버그 지표. 검증 실패는 아니고 리포트에 집계).
- FR-24: **프레임 안정**: 재생 중 렌더 프레임이 목표(60fps, 048) 이하로 떨어지는 프레임 비율 [제안] ≤ 1%.
- FR-25: 위 지표를 재생 중 자동 집계하는 "자연스러움 리포트"를 만든다 (경기 단위: 순간이동 횟수, 가속 초과 횟수, 공 불연속 횟수, 겹침 경고 수, 프레임 드롭 비율). 이 리포트는 017 대량 시뮬에서도 헤드리스로 계산 가능해야 한다 (렌더 없이 보간 위치만으로).

### 디버그 오버레이 (개발 빌드 전용)
- FR-30: 오버레이 레이어 목록. 각 레이어는 값을 제공하는 스펙이 정한 디버그 데이터를 **그리기만** 한다. 이 표가 004~013 스펙 E2E AC의 증거 화면이다.

  | 레이어 | 그리는 것 | 값 제공 | 쓰는 E2E |
  |---|---|---|---|
  | 공 궤적 | 공 3D 궤적의 탑뷰 투영 + 높이 눈금, 공 상태(Controlled/Air/Bounce/Rolling/Rest), 바운스 지점 | 004 | `e2e/004-*` (004 AC-15) |
  | 이동 | 선수별 속도·가속 벡터, 목표점, 최고속도 대비 비율 | 005 | `e2e/005-*` (005 AC-14) |
  | 피치 컨트롤 | 32×20 격자(기획서 5.4), 우세 팀 색 + 확률 농도 | 007 | `e2e/007-*` (007 AC-12) |
  | xT | 16×12 격자(기획서 5.2), 농도 + 숫자 토글 | 007 | `e2e/007-*` |
  | 액션 평가 | 패스·슈팅·압박 후보의 xPass·xG·압박 값 숫자 | 008 | `e2e/008-*` (008 AC-15) |
  | 형태 | 슬롯 목표점, 라인 높이, 블록 폭, **국면 라벨**(빌드업·전환·블록 등) | 009 | `e2e/009-shape-snapshots` |
  | 의사결정 | 공 소유자의 행동 후보와 점수 상위 [제안] 5개(막대), 시야 부채꼴, 선택된 행동, 결정 LOD(매 틱 / 2~4틱) | 010 | `e2e/010-decision-overlay` |
  | 골키퍼 | GK 위치, 슈팅 각 이등분선, 위험도 후보 점, 돌진 판단 | 011 | `e2e/011-gk-positioning` |
  | 심판 | 오프사이드 라인(판정 순간 스냅샷), 어드밴티지 보류 표시와 남은 시간, 주심·부심 위치와 대각선 | 012 | `e2e/012-referee-overlay` |
  | 시나리오 | **실행 중 시나리오 id**, 배역 선수 강조 테두리 + 배역 이름·현재 단계·분기 결과 라벨, 배역 종료 시 형태 슬롯 복귀 화살표, 폴백(Utility) 전환 표시 | 013 | `e2e/040-debug-overlays` (013 E2E 대체) |

- FR-31: 레이어 추가는 표에 행을 더하는 것으로 끝나야 한다(다른 레이어 수정 없음). 값 제공 스펙이 디버그 데이터를 내보내지 않으면 해당 레이어는 "데이터 없음" 라벨을 보이고 오류 없이 빈 레이어로 그린다.
- FR-32: 오버레이 숫자 표시는 값 제공 스펙의 로직 결과와 같은 값(표시 반올림 자릿수만 다름)이어야 한다 — E2E와 로직 검증이 같은 원천을 보게 한다.
- FR-33: 오버레이 캡처는 결정론적이다: 같은 녹화·같은 재생 시각·같은 레이어 조합 → 같은 이미지.
- FR-34: 오버레이를 특정 시각·레이어 조합으로 여는 것을 E2E 시나리오 단계로 지정할 수 있다(000 FR-20 캡처 단계에서 쓰기 위해).
- FR-35: 오버레이는 각각 켜고 끌 수 있고, 여러 개를 동시에 켤 수 있다. 켜고 꺼도 재생 결과(위치)는 같다.
- FR-36: 선수를 누르면 그 선수의 현재 능력치 요약·역할·성향·버릇·체력·현재 결정을 패널로 본다.
- FR-37: 출시 빌드에는 디버그 오버레이 코드 경로와 진입점이 포함되지 않는다.
- FR-38: 시나리오 워크벤치(053) 지원 (개발 빌드): ① 고정 픽스처(초기 배치·능력치 세트) 로드 진입점 ② 시나리오 강제 실행 진입점(013 강제 선택 모드 호출) ③ 시나리오 레이어에 "강제 실행" 표시, 현재 단계 번호/전체 단계 수, 직전 분기 결과(성공·실패·폴백) 표시. 053 E2E `e2e/053-preview-2d3d`가 이 화면을 캡처한다.

### 레이아웃 · 해상도
- FR-40: 000의 모든 프로필에서 피치 전체가 보이고 비율이 유지된다. phone-portrait에서는 피치를 세로로 회전해 표시 [제안].
- FR-41: 039 HUD 영역과 피치가 겹치지 않도록 여백을 둔다 (가장자리 HUD 안전 영역, 039 FR-51).
- FR-42: 고DPI(uhd-4k-200)에서 선·번호·라벨이 흐리지 않다.
- FR-43: 2D 매치뷰 색은 039 HUD처럼 테마와 무관한 고정 팔레트다 [제안] (다크/라이트 전환이 기준 이미지를 바꾸지 않게). 오버레이 라벨은 037 토큰의 고정 팔레트 값을 쓴다.

## 경계 · 예외 상황
- 공이 피치 밖(터치라인·골라인 밖, 골망 안)에 있을 때 표시 영역 밖으로 잘리지 않는다 (피치 둘레 여백 [제안] 5m).
- 공 높이 0(구름), 매우 높은 공(골킥 최고점), 골대 위로 넘어가는 공.
- 교체: 나가는 선수 사라짐·들어오는 선수 나타남이 순간이동으로 집계되지 않는다. 퇴장 선수, 10명·9명 팀.
- 부상으로 경기 중단 중(선수 정지), 하프타임·추가시간 경계, 연장전.
- 시점 이동: 0초, 경기 마지막 프레임, 녹화 범위 밖 요청(가장 가까운 유효 시각으로 고정 + 경고), 하이라이트 구간 경계.
- 배속 3x에서 보간 간격이 렌더 프레임보다 길 때·짧을 때 모두 FR-20~22 충족.
- 0.5x 리플레이에서 30Hz 스냅샷 보간이 덜컹이지 않는다 (FR-21).
- 같은 위치에 선수 여러 명(세트피스 벽, 코너킥 박스 혼전)에서 등번호가 읽히지 않을 때 겹침 처리 규칙 [미정].
- 녹화 데이터가 비어 있거나 중간이 빠진 경우 오류 상태로 표시하고 크래시하지 않는다.

## 비기능 요구사항
- 결정론: 재생은 시뮬을 다시 돌리지 않는다. 같은 녹화 + 같은 재생 시각 → 같은 표시 위치 (배속·이동 경로와 무관). 프로필(해상도)이 표시 위치의 피치 좌표에 영향을 주지 않는다.
- 세이브 호환: 녹화 형식은 006이 제공. 이 스펙은 형식 변경에 따른 재생 호환을 006의 버전 규칙에 맡긴다.

## 수용 기준
- AC-01 [E2E]: `e2e/040-highlight-2d`: 픽스처 경기 녹화의 하이라이트 3개(골, 크로스, 슈팅 선방)를 2D로 재생하며 장면별 고정 시각 캡처. 전체 프로필에서 피치 전체가 보이고 비율이 105:68(±1%)이며 기준 이미지 차이 임계값 이하.
- AC-02 [로직]: 자연스러움 리포트(FR-25)를 픽스처 경기 10개(시드 고정)에 대해 1x, 1.5x, 3x, 0.5x로 계산하면 순간이동 0, 가속 초과 0, 공 불연속 0이다 (교체·시점 이동 예외 제외).
- AC-03 [로직]: 일부러 스냅샷 하나를 5m 옮긴 녹화로 리포트를 계산하면 순간이동 1건이 그 시각과 선수 id로 보고된다. 공 위치를 1프레임 빼면 공 불연속이 보고된다.
- AC-04 [결정론]: 같은 녹화를 (1x 끝까지), (3x + 임의 시점 이동 20회), (0.5x 구간 반복)으로 재생해 같은 재생 시각 100개 지점의 표시 위치를 비교하면 모두 같다 (부동소수 허용 오차 [제안] 1e-4 m).
- AC-05 [결정론]: low-igpu-1080p와 uhd-4k-200에서 같은 재생 시각의 피치 좌표 표시 위치가 같다.
- AC-06 [로직]: 패스 SimEvent마다 공 출발 위치와 차는 선수 표시 위치의 거리가 0.5m 이하다.
- AC-07 [E2E]: 시점 이동 직후 첫 프레임 캡처가 그 시각의 정답 위치(녹화 보간값) 캡처와 같다.
- AC-08 [E2E]: `e2e/040-debug-overlays` (개발 빌드): FR-30 표의 레이어 10종을 각각 켠 캡처와 모두 켠 캡처. 오버레이를 켜고 끄기 전후의 선수 위치가 같다. 시나리오 레이어에 시나리오 id 1개와 배역 강조 선수 3~5명이 보이고, 그 수와 id가 013 실행 로그의 같은 시각 값과 같다 (시나리오 실행 중인 픽스처 시각).
- AC-17 [로직]: 오버레이에 표시된 숫자(xT, 피치 컨트롤 확률, xPass, 후보 점수)가 같은 시각 값 제공 스펙의 로직 결과와 표시 자릿수 안에서 같다. 디버그 데이터가 없는 레이어를 켜면 '데이터 없음' 라벨만 보이고 예외 0.
- AC-09 [로직]: 출시 빌드 구성에서 전체 경기 모드와 디버그 오버레이 진입점이 0개다 (빌드 산출물 검사).
- AC-10 [E2E]: 공이 터치라인 밖 3m, 골망 안에 있는 픽스처 시각에서 공이 화면 안에 보인다. 골킥 최고점에서 공 크기가 가장 크다.
- AC-11 [E2E]: 교체·퇴장 픽스처에서 선수 수가 정확하고(10명), 교체가 순간이동으로 집계되지 않는다.
- AC-12 [E2E]: phone-portrait에서 피치가 세로로 표시되고 HUD 영역과 겹치지 않는다. ultrawide-1080에서 피치 비율이 유지되고 양옆이 바탕이다.
- AC-13 [성능]: low-igpu-1080p에서 2D 하이라이트 재생 p95 ≤ 16.6 ms, 메인 스레드 p95 ≤ 4 ms, GC 0 B/프레임, 드로우콜 ≤ 50, 목표 이하 프레임 비율 ≤ 1%.
- AC-14 [성능]: 전체 경기 임의 시각 이동 ≤ 100 ms. 오버레이 전부 켠 개발 빌드 p95 ≤ 16.6 ms (mac-m1-1600p).
- AC-15 [성능]: 자연스러움 리포트 헤드리스 계산 경기 1개 ≤ 200 ms.
- AC-16 [E2E]: 빈 녹화·중간이 빠진 녹화를 열면 오류 상태가 보이고 크래시·예외가 없다. 콘솔 에러는 의도된 1건(오류 보고)만.
- AC-18 [E2E]: `e2e/040-forced-scenario` (개발 빌드): 고정 픽스처를 로드하고 시나리오 1개를 강제 실행하면 시나리오 레이어에 "강제 실행" 표시, 단계 번호 "n/N", 분기 결과 라벨이 보이고, 값이 013 실행 로그와 같다. 프로필: smoke.

## 검증 · 증거
- 로직: 자연스러움 리포트·출발 위치·빌드 산출물 검사 테스트 리포트 스크린샷.
- E2E: `e2e/040-highlight-2d`(전체), `e2e/040-debug-overlays`(smoke, 개발 빌드), `e2e/040-seek`, `e2e/040-edge-ball`, `e2e/040-substitution`, `e2e/040-bad-recording`(smoke + phone-portrait + ultrawide-1080).
- 성능: 프로필별 측정 표.
- 결정론: 재생 경로 3종 위치 비교 결과, 프로필 간 위치 비교 결과.
- 자연스러움 리포트(경기 10개 × 배속 4종) 표를 증거 리포트에 포함.

## 미정 / 질문
- [미정] 밀집 상황(벽, 박스 혼전)에서 등번호 겹침 표시 규칙.
- [미정] phone-portrait에서 피치 세로 회전 여부.
- [미정] 2D 하이라이트를 출시 기능(3D 끄기 옵션)으로 둘지, 3D 준비 전 임시 기능으로만 둘지 (기획서 8은 "2D로 먼저 출시 가능하게 설계"까지만 언급).

- [제안] 순간이동 여유 계수 1.2, 가속 여유 1.5배, 공 출발 오차 0.5m, 겹침 0.3m/0.5초, 프레임 드롭 1%, 궤적 꼬리 1초, 피치 둘레 여백 5m, 결정 후보 5개는 승인 필요.
