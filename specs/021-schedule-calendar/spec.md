# 021 — 일정 · 캘린더

상태: 승인됨
브랜치: feat/021-schedule-calendar
기획 출처: docs/index.html § 기획서 4.7(일정 확정: 첫 시즌 실제 일정, 2시즌부터 자동 생성), § 3(시즌 루프), § 아키텍처 7(season_YYYY.json → 시즌 캘린더, 라운드로빈 자동 생성), research[5] 05 § 6.4(서클 메소드·Berger 테이블, 시즌 캘린더, 컵 대회)

## 배경
커리어는 날짜 위에서 흘러간다. 주말 리그, 주중 컵, A매치 기간, 이적시장 창구가 정해진 캘린더가 있어야 주간 루프(024)가 돈다. 확정 사항: 새 커리어의 **첫 시즌은 실제 시즌 일정**(라운드 날짜·대진, 컵·A매치 기간, 이적시장 기간)을 쓰고, **두 번째 시즌부터는 자동 생성**한다. 실제 일정이 맞지 않으면(시즌 중간에 시작, 데이터 없음) 자동 생성으로 대체한다. 일정이 틀리면(같은 날 두 경기, 홈 연속 과다, 빠진 라운드) 커리어 전체가 깨지므로 불변식 검증이 중요하다.

## 범위
- 포함:
  - 실제 시즌 일정 파일(`season_YYYY.json`) 형식과 읽기·검증·가상 세계 매핑
  - 리그 일정 자동 생성 (서클 메소드 라운드로빈, 홈/원정 교대, break 최소화, 2차 리그 미러링)
  - 시즌 캘린더 템플릿 (주말 리그, 주중 컵·대륙 대회, A매치 기간, 이적 창구, 프리시즌, 시즌 종료·시상식)
  - 컵 대회 대진·일정 (단판 토너먼트, 시드, 예선 라운드)
  - 일정 충돌 해결 (컵을 리그보다 먼저 잠금, 연기 경기 재배치)
  - 실제 일정 → 자동 생성 대체 규칙
  - 일정 불변식 검증
- 제외:
  - 리그·클럽 구성 (020)
  - 일정 파일 배포 (로스터 업데이트 서버 — 운영 범위, 이 스펙은 파일 형식과 읽기만)
  - 주간 진행·경기일 처리 (024), 이적시장 동작 (029), 국가대표 소집 (035)
  - 저장 (022)

## 사용자 시나리오
1. 첫 시즌을 시작하면 캘린더에 실제 그 시즌의 라운드 날짜, 컵 라운드 주, A매치 주, 이적시장 마감일이 보인다.
2. 시즌을 끝내고 두 번째 시즌으로 넘어가면 새 일정이 자동으로 만들어진다. 승격한 팀이 들어가 있고, 홈·원정이 고르게 섞여 있다.
3. 컵에서 이기고 올라가면 주중 경기가 생기고, 주말 리그와 겹치지 않는다.
4. 시즌 도중(예: 1월)에 커리어를 시작하면, 남은 라운드는 일정 데이터가 없어도 자연스럽게 채워진다.

## 요구사항

### 실제 시즌 일정 파일
- FR-01: `season_YYYY.json`: 시즌 식별(YYYY), 대회 목록(대회 id, 종류: 리그/컵/대륙/국가대표 기간), 라운드별 날짜, 경기(날짜, 홈 슬롯, 원정 슬롯, 대회 id, 라운드), 이적 창구 시작·마감일, A매치 기간 (기획서 4.7). 파일에 형식 버전 필드.
- FR-02: 일정 파일에는 실제 팀 이름을 넣지 않는다. 경기는 **팀 슬롯 번호**(리그 내 0..N−1)로 기록하고, 파일에 슬롯 → 기본 세계 템플릿 클럽 id(020 FR-72) 매핑 표를 둔다 (실명 정책 A안 확정 (2026-11-02 사용자 결정)). 템플릿 기반 세계면 이 표대로 배정하고, 완전 가상 세계(020 FR-74)나 매핑에 없는 클럽이면 시드 기반 섞기로 배정한다 (같은 시드 → 같은 배정).
- FR-03: 읽기 시 검증: 날짜 형식, 같은 팀 같은 날 2경기 없음, 라운드 수 = 2·(N−1), 각 팀 홈·원정 각 N−1회, 모든 팀 쌍이 홈·원정 1회씩. 하나라도 어기면 그 대회는 자동 생성으로 대체하고 경고를 남긴다.
- FR-04: 대회 매핑: 실제 일정 파일의 리그 팀 수와 가상 리그 팀 수가 같을 때만 그 리그에 실제 일정을 쓴다. 다르면 날짜 틀(라운드 날짜)만 쓰고 대진은 자동 생성 [제안].
- FR-05: 실제 일정 파일에 날짜 미정 경기(연기·TBD)가 있으면 [제안] 해당 라운드 기본 날짜로 채우고 표시한다.
- FR-06: 실제 일정의 대회명·로고는 쓰지 않는다. 대회 id를 가상 대회에 매핑한다 (기획서 4.7: 대회명은 상표).

### 리그 자동 생성
- FR-10: 서클 메소드(Berger 테이블): N이 홀수면 더미(휴식) 추가, 팀 0 고정, 나머지 회전으로 N−1라운드 (05 § 6.4).
- FR-11: 홈·원정은 라운드마다 교대. 짝수 N에서 생기는 연속 홈/원정(break)을 최소화한다. 목표: 1차 리그 break 수 = 이론 최솟값 N−2 [제안: Berger 테이블 이론값, 검증 필요].
- FR-12: 2차 리그는 1차를 미러링하고 홈·원정 반전. 같은 대진이 연속 라운드에 반복되지 않게 2차 리그 라운드 순서를 섞는다 (05 § 6.4). 1차 마지막 라운드와 2차 첫 라운드가 같은 대진이 되면 안 된다.
- FR-13: 템플릿 매핑이 없을 때의 팀 슬롯 배정은 시드 기반 섞기 (FR-02). 더비(같은 도시 클럽)는 같은 라운드에 둘 다 홈이 되지 않게 [제안] 보완 쌍 배정.
- FR-14: 한 시즌에 각 팀 쌍이 정확히 홈 1회·원정 1회. 3라운드 이상 리그(일부 소규모 리그 33라운드 등)는 [미정].

### 시즌 캘린더
- FR-20: 캘린더 템플릿 (05 § 6.4 [U]): 주말 리그, 주중 컵·대륙 대회, A매치 기간 4~5회, 하계 이적 창구 약 9주, 동계 약 4주. 시즌 시작·종료 주, 프리시즌, 시상식 주를 포함한다.
- FR-21: 템플릿은 국가(또는 반구·리그 형식)별 데이터. 기본 템플릿 [제안]: 8월 시작 5월 종료 유럽형 1개. 다른 형식(봄–가을 시즌)은 [미정].
- FR-22: 경기일 배치 순서: ① A매치 기간 잠금 → ② 컵·대륙 대회 날짜 잠금 (05 § 6.4: 컵을 리그보다 먼저) → ③ 리그 라운드를 남은 주말에 배치 → ④ 남는 주중을 예비일로.
- FR-23: 한 팀의 최소 경기 간격 [제안] 2일 (같은 팀이 연속 날 경기 금지), 주당 최대 2경기.
- FR-24: A매치 기간에는 리그 경기 없음 (1·2부 기준; 하위 리그 예외 [미정]). A매치 기간 횟수·길이의 소유는 이 스펙 (리서치 05 §6 "4~5회" [U]). 035는 이 값을 읽기만 한다.
- FR-25: 리그 라운드 수가 남은 주말보다 많으면 주중 라운드를 넣는다. 그래도 부족하면 템플릿 오류로 실패 (조용히 라운드를 빼지 않는다).
- FR-26: **경기 시간대 칸** (064 FR-08, 064 Q4 (a)): 모든 경기 레코드는 시간대 칸(낮·나이트 2종 — 044 FR-40 조명 프리셋과 같은 구분)을 가진다. 시각(시:분)이 아니라 범주라 아래 '날짜만' 원칙을 바꾸지 않는다. 배정 규칙은 이 스펙 소유: 실제 일정 파일에 시간대가 있으면 그 값, 없으면 결정론 규칙으로 정한다 — 주중 경기는 나이트, 주말 경기는 낮·나이트 혼합 [제안], 혼합 비율 `[미정]`. 같은 입력 → 같은 시간대(FR-51). 064 날씨 생성·044 조명·041 재생이 이 칸을 읽는다.

### 컵 대회
- FR-30: 단판 토너먼트. 하위 디비전은 초기 라운드, 상위 디비전은 시드를 받아 늦게 진입 (05 § 6.4).
- FR-31: 참가 팀 수가 2의 거듭제곱이 아니면 예선 라운드로 맞춘다. 예선 라운드 경기 수 = 참가 수 − 직전 2의 거듭제곱.
- FR-32: 대진 추첨은 시드 RNG로 결정론적. 다음 라운드 대진은 이전 라운드 결과가 나온 뒤 추첨 (결과 의존 — 024가 라운드 종료 시 호출).
- FR-33: 무승부 처리(연장·승부차기)는 경기 규칙(012)이 처리하고, 일정은 승자만 받는다. 재경기 방식은 [미정] (기본 없음).
- FR-34: 결승은 중립 경기장 [제안].

### 대체 규칙
- FR-40: 커리어 시작 시점이 시즌 중간이면: 실제 일정 파일의 남은 라운드를 그대로 쓰되, 이미 지난 라운드 결과는 저정밀 시뮬(016)로 채운다 [제안]. 남은 일정이 FR-03 검증에 실패하면 남은 기간 전체를 자동 생성으로 대체.
- FR-41: 해당 시즌 일정 파일이 없으면 첫 시즌도 자동 생성 (기획서 4.7).
- FR-42: 대체가 일어났는지, 왜인지를 캘린더 메타에 남겨 UI가 표시할 수 있게 한다 [제안].

### 일정 변경
- FR-50: 경기 연기 — 사유 목록: 국가대표 차출 충돌, 컵 진출로 인한 충돌, **날씨**(064 FR-30·31 킥오프 전 피치 점검 결과). 같은 팀의 다음 예비일로 재배치하고 연기 사유를 레코드에 남긴다. 재배치 후에도 FR-23을 지킨다. 날씨로 연기된 경기의 새 날짜 날씨는 064가 다시 생성한다.
- FR-51: 일정 변경은 결정론적 (같은 상황 → 같은 재배치).

### 불변식 (항상 검증)
- FR-60: 같은 팀 같은 날 2경기 없음 · 리그 각 팀 쌍 홈·원정 1회씩 · 라운드 수 = 2·(N−1) · 각 팀 라운드당 최대 1경기(휴식 제외) · A매치 기간 리그 경기 없음(FR-24 범위) · 최소 경기 간격 · 시즌 시작 ≤ 모든 경기 ≤ 시즌 종료 · 이적 창구는 시즌 안에서 겹치지 않음.

## 경계 · 예외 상황
- N = 2 (최소), N = 3 (홀수, 더미 포함), N = 20, N = 24.
- 홀수 N에서 휴식 라운드: 각 팀 정확히 2회(1차·2차 각 1회) 휴식.
- 윤년 2월 29일, 연도가 바뀌는 시즌(8월~5월)의 날짜 계산, 주 번호 경계(ISO 주 1과 52/53).
- 시간대: 게임 날짜는 날짜만(시각 없음) [제안] — 시간대 문제를 원천 차단. 경기의 낮·나이트 구분은 시각이 아니라 FR-26 범주 칸이다.
- 실제 일정 파일이 빈 파일·손상된 JSON·알 수 없는 형식 버전: 자동 생성으로 대체 + 경고. 예외로 커리어 시작이 막히면 안 된다.
- 실제 일정 파일에 리그 팀 수보다 많은 슬롯 번호: 검증 실패 처리.
- 컵 참가 팀 1팀 또는 0팀: 대회 생략.
- 컵 참가 팀 수가 정확히 2의 거듭제곱: 예선 없음.
- 시즌 마지막 주에 연기 경기를 넣을 예비일이 없음: [제안] 시즌 종료를 1주 연장, 그래도 없으면 에러로 보고 (조용히 경기 삭제 금지).
- 승강 후 다음 시즌 팀 수 변화(리그 재편): 새 N으로 재생성.
- 2시즌 생성이 1시즌 마지막 날 이후 시작하는지 (시즌 경계 겹침 없음).
- 이적 창구 마감일이 시즌 경계일 또는 경기일과 같음 → 날짜는 그대로 두고, 같은 날 처리 순서는 024가 정한다 (경기 → 마감 → 시즌 경계).
- 메이저 대회 본선(035)이 프리시즌과 겹치는 여름 → 본선 기간은 캘린더 템플릿의 "국가대표 대회" 구간으로 잠그고, 리그 시작일은 옮기지 않는다 [제안] (출전 선수의 프리시즌 지연은 035→024).

## 비기능 요구사항
- 결정론: (세계 시드, 시즌 번호, 리그 구성, 실제 일정 파일 해시) → 같은 일정. 컵 추첨은 (시드, 라운드, 이전 결과) → 같은 대진.
- 순수 C# (WorldGen 또는 Career, UnityEngine 비참조).
- 일정 파일 형식은 공개 포맷 원칙 (아키텍처 원칙 3) — 022의 모드 스키마와 같은 규칙(LF, 2칸 들여쓰기, camelCase)을 쓴다.

## 수용 기준
- AC-01 [로직]: N = 2~24 모든 값에 대해 자동 생성 리그가 FR-60 불변식을 전부 만족한다.
- AC-02 [로직]: 짝수 N(4~24)에서 1차 리그 break 수가 이론 최솟값(N−2)과 같다 (이론값 확인 후 확정 — [제안]).
- AC-03 [로직]: 홀수 N에서 각 팀 휴식이 정확히 2회이고, 휴식 라운드가 연속되지 않는다.
- AC-04 [로직]: 1차 마지막 라운드와 2차 첫 라운드에 같은 대진이 없고, 같은 대진이 연속 라운드에 나오는 경우가 0건이다 (N = 4~24, 시드 100개).
- AC-05 [로직]: 유효한 실제 일정 픽스처 파일을 읽으면 날짜·대진이 파일과 같고 불변식을 만족한다.
- AC-06 [로직]: 손상된 JSON, 같은 팀 같은 날 2경기, 슬롯 범위 초과, 라운드 누락 픽스처를 읽으면 각각 자동 생성으로 대체되고 경고 1개가 남으며 예외로 중단되지 않는다.
- AC-07 [로직]: 리그 팀 수가 다른 실제 일정 픽스처에서는 라운드 날짜만 쓰고 대진은 자동 생성된다.
- AC-08 [로직]: 1월 시작 픽스처에서 지난 라운드는 결과가 채워지고, 남은 라운드만 진행 대상이며 불변식을 만족한다.
- AC-09 [로직]: 컵 참가 팀 수 1, 2, 7, 16, 33, 64 픽스처에서 예선 경기 수가 FR-31 공식과 같고, 상위 디비전이 늦게 진입한다.
- AC-10 [로직]: 기본 캘린더 템플릿에서 A매치 기간 4~5회, 하계 창구 약 9주, 동계 약 4주가 만들어지고, A매치 기간에 1·2부 리그 경기가 0건이다.
- AC-11 [로직]: 컵 진출로 충돌이 난 리그 경기가 다음 예비일로 옮겨지고 최소 간격(2일)을 지킨다. 예비일이 없는 픽스처에서는 시즌 1주 연장 또는 명시적 에러가 나며 경기가 사라지지 않는다.
- AC-12 [로직]: 윤년 2월, 연도 넘김(12→1월), ISO 53주 연도 픽스처에서 날짜·주 계산이 맞다.
- AC-13 [결정론]: 같은 입력으로 일정을 2회 생성하면 해시가 같고, 컵 추첨도 같은 이전 결과에서 같은 대진이 나온다.
- AC-14 [로직]: 1시즌 → 2시즌 전환 시 2시즌 첫 경기가 1시즌 마지막 경기 이후이고, 승격·강등이 반영된 팀 구성으로 생성된다.
- AC-15 [성능]: 일정 생성·읽기 시간이 성능 예산 표 안에 든다.
- AC-16 [E2E]: `e2e/021-calendar` — 고정 세이브의 캘린더 화면(월간 보기: 리그·컵·A매치·이적 창구 표시, 다음 경기 카드)이 기준 이미지와 일치한다. 1시즌(실제 일정 픽스처)과 2시즌(자동 생성) 두 단계 캡처. 프로필: 전체.
- AC-17 [로직]: 슬롯→클럽 id 매핑 표가 있는 일정 픽스처 + 같은 id의 테스트 템플릿 세계에서 1라운드 대진의 클럽 id가 표와 정확히 같다. 매핑 표에 없는 클럽 id가 있으면 그 리그만 시드 섞기로 대체되고 경고 1개가 남는다.
- AC-18 [로직]: FR-26·50: 자동 생성 시즌의 모든 경기 레코드에 시간대(낮·나이트)가 있고 주중 경기는 모두 나이트이며, 같은 입력 2회 생성 시 시간대가 같다. 실제 일정 파일에 시간대가 있으면 그 값을 쓴다. 064 날씨 연기 요청을 주입하면 그 경기가 다음 예비일로 옮겨지고 연기 사유 "날씨"가 레코드에 남으며 FR-23을 지킨다.
