# 031 — 이벤트 카탈로그 (12 카테고리 300+)

## 배경
스토리렛 엔진(030)은 그릇이고, 플레이어가 실제로 겪는 것은 이벤트 콘텐츠다. 출시 목표는 12개 카테고리 300개 이상. 1인 개발로 이 양을 쓰면서도 품질(등급·실명·톤·버그 없는 데이터)을 지키려면 **작성 형식, 카테고리별 수량 목표, 자동 린트, 도달 가능성 검사**가 필요하다. 이 스펙은 콘텐츠 자체와 그 검수 기준을 정한다.

## 범위
- 포함:
  - 카테고리 12개와 카테고리별 목표 수 (기획서 4.6.2)
  - 이벤트 한 개를 쓰는 작성 형식 (030 스토리렛 형식 위의 작성 규칙: 톤, 길이, 선택지 원칙, 결과 크기 가이드)
  - 콘텐츠 린트: 금지어·실명·등급·텍스트 길이·현지화 키 누락·결과 크기 범위
  - 도달 가능성 검사: 헤드리스 커리어 시뮬로 각 이벤트가 실제로 뜰 수 있는지
  - 카테고리별 커버리지 리포트 (작성 수 / 목표 수 / 도달 확인 수)
  - 마일스톤별 최소 세트 (M4 수직 슬라이스용 이벤트 묶음)
- 제외:
  - 스토리렛 형식·디렉터 규칙 → 030
  - 이벤트 결과가 바꾸는 수치의 모델 → 각 시스템 스펙(025, 027, 028, 029, 032, 033, 034, 035, 036)
  - 화면 연출 → 038, 047
  - 번역 실작업 (ko 기본 작성, en 키는 037 현지화 체계)

## 사용자 시나리오
1. 개발자가 새 "회식" 이벤트를 쓰고 린트를 돌리면, 본문이 길이 상한을 넘었고 en 키가 없다는 경고 2개가 나온다.
2. 커버리지 리포트를 열면 "연애 · 가족 22/40, 도달 확인 18" 처럼 카테고리별 진척이 보인다.
3. 헤드리스 커리어 100회 시뮬 후, 한 번도 뜨지 않은 이벤트 목록이 나온다. 전제조건이 모순(나이 < 18 ∧ 결혼함)인 이벤트를 찾는다.

## 요구사항

### 카테고리 · 수량
- FR-01: 카테고리와 출시 목표 수 (기획서 4.6.2, 합계 330):

  | 카테고리 id | 이름 | 예시 (기획서) | 목표 |
  |---|---|---|---|
  | `match_career` | 경기 · 커리어 | 데뷔전, 데뷔골, 주전 경쟁, 벤치 강등, 주장 임명, 100경기, 해트트릭, 자책골, PK 실축, 결승전 | 50 |
  | `manager_club` | 감독 · 구단 | 감독 면담, 감독 경질·신임 감독, 포지션 변경 제안, 훈련 태도 지적, 구단 재정 위기, 강등·승격 | 35 |
  | `transfer_contract` | 이적 · 계약 | 빅클럽 관심, 복수 오퍼, 재계약 협상, 임대 제안, 에이전트 교체, 바이아웃 발동, 이적 요청 거절 | 35 |
  | `teammates` | 동료 · 라커룸 | 절친 동료, 라이벌과 다툼, 베테랑 멘토, 신입 적응 도움, 회식, 동료 이적 | 30 |
  | `media_fans` | 미디어 · 팬 | 인터뷰 발언 후폭풍, SNS 논란, 파파라치, 팬 응원가, 팬과의 사진, 악성 루머 | 30 |
  | `romance_family` | 연애 · 가족 | 첫 만남, 데이트, 공개 연애, 이별, 프러포즈, 결혼식, 출산, 가족 병환, 고향 방문 | 40 |
  | `spending_assets` | 소비 · 자산 | 집·차 구매, 투자 성공·실패, 사기 피해, 세금 문제, 재정 위기 | 20 |
  | `nightlife_social` | 유흥 · 사교 | 파티 초대, 클럽, 카지노, 휴가지 사건, 경기 전날 외출 적발 | 20 |
  | `health` | 건강 · 부상 · 질병 | 감기, 독감, 팀 내 전염, 부상 재발, 조기 복귀 선택, 수술 결정, 심장 이상, 번아웃 | 30 |
  | `national_team` | 국가대표 | 첫 발탁, 대표팀 탈락, 메이저 대회, 국가대표 은퇴 | 15 |
  | `retirement_legacy` | 은퇴 · 레거시 | 은퇴 고민, 은퇴 경기, 지도자·해설·에이전트 제안, 명예의 전당 | 10 |
  | `random_life` | 랜덤 · 생활 | 교통사고(경미), 자선 행사 요청, 광고 촬영, 반려동물, 이웃 사건 | 15 |

- FR-02: 목표 수는 "서로 다른 이벤트 id" 기준이다. 같은 이벤트의 텍스트 변형(문장 바꿈)은 1개로 센다. 선택지 결과만 다른 복제는 1개로 센다.
- FR-03: 마일스톤별 최소 세트 [제안]: M2(커리어 MVP) 각 카테고리 0~5개 중 `match_career` 10·`manager_club` 5·`health` 5, M4 각 카테고리 목표의 50%, M6(데모) 목표의 80%, 출시 100%.
- FR-04: 포지션 공평성: `match_career`의 이벤트는 GK·수비수·미드필더·공격수 모두에게 뜰 수 있는 이벤트가 각 포지션군 [제안] 최소 8개 (리서치 05 §8 시사점 1).

- FR-05: **성인 콘텐츠 연령 하한 `adultContentMinAge`** — 연애·유흥(파티·클럽·카지노)·결혼 관련 스토리렛과 활동이 열리는 최소 만 나이. 데이터 상수 **하나**로 이 스펙이 소유하고, 030·032·033은 이 값만 읽는다. 값 **18** (확정 (2026-11-02 사용자 결정)). 선수 최소 나이 15와 별개. 국가별 법정 연령과 무관한 게임 규칙.

### 작성 형식
- FR-10: 이벤트마다: 030 스토리렛 필드 + 작성 메타(작성일, 카테고리, 마일스톤, 등급, 연출 힌트, 관련 시스템 목록) + **연출 형식** 필드: `3d_cutscene` / `card_2d` / `messenger` / `text` 중 하나 (047이 해석, 메신저는 038 관계 화면). 없으면 린트 오류.
- FR-11: 텍스트 원칙 (기획서 4.9): 짧고 친근한 대화체. 제목 [제안] ≤ 24자, 본문 ≤ 140자(ko), 선택지 ≤ 20자. 숫자·이름은 치환 변수로.
- FR-12: 선택지 원칙: 정답 하나가 뻔한 선택지 금지 — 각 선택지는 얻는 것과 잃는 것이 있어야 한다 (예외: "확인" 단일 선택지 이벤트는 카테고리별 [제안] 20% 이하). 결과는 즉시 1개 이상, 또는 지연 결과로 나타나야 한다.
- FR-13: 결과 크기 가이드 [제안]: 일반 이벤트 한 번의 수치 변화는 신뢰 ±1~8, 사기 ±1~10, 평판 ±1~10. 그 이상은 `높음`·`강제` 우선순위 이벤트만. 린트가 범위를 검사.
- FR-14: 지연·콜백 사용 비율 [제안]: 전체 이벤트의 30% 이상이 지연 결과 또는 인용 시드 콜백을 가진다 (리서치 05 §8 시사점 4 "결과가 지연되어 나타나는 결정").

### 콘텐츠 린트
- FR-20: 린트 항목 (하나라도 오류면 콘텐츠 빌드 실패):
  1. 실존 인물 이름 목록·실존 클럽·리그 이름 목록과 일치하는 문자열 (목록은 데이터 파일로 관리, 01-legal)
  2. 금지어 목록 (노골적 성적 표현, 혐오 표현, 실제 도박 결제 유도 표현) — 데이터는 051 FR-43 금칙어 목록을 공유한다 (따로 두지 않음)
  3. 등급 규칙: 연애·유흥은 암시적 표현만, 도박은 가상 화폐로만, 질병은 실명 질병 묘사 가볍게·커리어 위협은 진지한 톤 (기획서 4.6.1, 4.10) — 금지 패턴과 필수 태그로 검사
  4. 텍스트 길이 상한 (FR-11)
  5. ko 텍스트 키 누락 (오류), en 키 누락 (경고)
  6. 치환 변수 이름이 정의된 변수 목록에 있는지
  7. 결과 크기 범위 (FR-13)
  8. 선택지 원칙 (FR-12): 모든 선택지 결과가 같은 방향(전부 이득)이면 경고
  9. 030 로딩 검증 통과
- FR-21: 린트 결과는 파일·이벤트 id·줄·항목·메시지로 출력. 경고는 빌드를 막지 않지만 리포트에 남는다.
- FR-22: 경고 무시는 이벤트 데이터에 사유와 함께 명시 (사유 없는 무시 금지).

### 도달 가능성 · 커버리지
- FR-30: 헤드리스 커리어 시뮬(024 FR-55 헤드리스 모드, 024 FR-56 축소 월드, 내 경기도 016 저정밀) [제안] 다양한 시작 조건(포지션·국적·성격·선택 정책) 200회 × 15시즌을 돌려 이벤트별 발생 횟수를 센다.
- FR-31: 한 번도 발생하지 않은 이벤트는 "도달 불가 의심"으로 보고하고, 전제조건을 정적 분석해 모순(항상 거짓)인지 표시한다.
- FR-32: 너무 자주 뜨는 이벤트 [제안] 시즌당 평균 2회 초과(반복 가능 제외)도 보고.
- FR-33: 커버리지 리포트: 카테고리별 작성 수 / 목표 / 린트 통과 / 도달 확인, 포지션군별 `match_career` 수, 지연·콜백 비율, 마일스톤 최소 세트 충족 여부.

## 경계 · 예외 상황
- 같은 이벤트가 두 카테고리에 속해 보임 → 카테고리는 하나만. 태그로 보조 분류.
- 나이 경계: 15세 유스 시작 선수에게 유흥·연애 성인 이벤트가 뜨면 안 된다 → `nightlife_social` 전체와 `romance_family`의 연애·결혼 이벤트는 `나이 ≥ adultContentMinAge`(FR-05) 전제조건이 필수 (린트가 검사). 상수 값을 숫자로 직접 쓰면 린트 오류 (상수 참조만 허용).
- 결혼·자녀 상태와 모순되는 이벤트 (미혼인데 배우자 이벤트) → 정적 분석으로 경고.
- 은퇴 후 시점에 커리어 이벤트가 남아 있음 → `retirement_legacy` 외 카테고리는 은퇴 후 후보 아님 (030 정리 규칙과 연결).
- 텍스트 길이 계산은 표시 글자 수 기준 (한글·영문·이모지 혼합 시 바이트 수 아님).
- 실명 목록 일치 검사에서 흔한 단어와 겹치는 이름(예: 일반 명사)은 단어 경계·대소문자 규칙으로 오탐을 줄이고, 오탐 무시는 사유 명시.

## 비기능 요구사항
- 결정론: 도달 가능성 시뮬은 시드 고정. 같은 콘텐츠·같은 시드 → 같은 커버리지 수치.
- 콘텐츠 변경이 코드 변경을 요구하지 않는다 (데이터만).
- 세이브 호환: 이벤트 삭제·id 변경은 이전 세이브의 기록을 깨뜨리지 않는다 (030 FR 세이브 호환).

## 수용 기준
- AC-01 [로직]: 린트 항목 9개 각각에 대해 일부러 위반한 샘플 이벤트가 해당 오류(또는 경고)로 보고되고, 정상 샘플은 통과한다.
- AC-02 [로직]: 실존 이름 목록에 있는 문자열이 본문·선택지·치환 기본값 어디에 있어도 오류로 잡힌다.
- AC-03 [로직]: `adultContentMinAge` 전제조건이 없는 `nightlife_social`·연애 이벤트, 그리고 연령을 숫자(예: `age >= 18`)로 직접 쓴 이벤트는 린트 오류다. 상수를 17·19로 바꾼 픽스처에서 도달 가능성 시뮬의 첫 발생 나이가 따라 바뀐다.
- AC-04 [로직]: 커버리지 리포트의 카테고리별 작성 수 합계가 실제 이벤트 id 수와 같고, 목표 표(합계 330)와 비교한 진척률이 맞다.
- AC-05 [로직]: 전제조건이 항상 거짓인 샘플 이벤트(나이 < 18 ∧ 기혼)는 정적 분석으로 "모순"이 표시되고, 도달 가능성 시뮬에서 0회로 보고된다.
- AC-06 [결정론]: 같은 콘텐츠·같은 시드로 도달 가능성 시뮬을 2회 돌린 이벤트별 발생 횟수 표가 같다.
- AC-07 [로직]: 출시 기준 시점에 카테고리 12개 모두 목표 수 이상, 린트 오류 0, 도달 확인율 [제안] 95% 이상, 지연·콜백 비율 30% 이상, 포지션군별 `match_career` 각 8개 이상. (출시 게이트 — 이 스펙의 최종 완료 조건)
- AC-08 [E2E]: 카테고리별 대표 이벤트 12개(카테고리당 1개)를 고정 픽스처에서 강제로 띄워 바텀시트를 캡처하면 텍스트 잘림·겹침·빈 치환 변수가 없다. 프로필: 전체 (ko/en). `compact-1366`·`phone-portrait`에서 가장 긴 본문도 스크롤 없이 또는 시트 내부 스크롤로 다 읽힌다.
- AC-09 [성능]: 성능 예산 표 항목이 예산 안.
