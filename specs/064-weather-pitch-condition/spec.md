## 배경
지금 모든 경기는 같은 하늘, 같은 마른 잔디, 같은 공 굴림에서 열린다. 12월 북쪽 원정 경기도, 8월 남쪽 홈 경기도 똑같아 시즌의 흐름과 장소의 차이가 느껴지지 않는다. 날씨는 커리어 서사(눈 속 결승골, 폭우 속 원정 승리, 폭설로 연기된 더비)를 만들고, 하이라이트 화면을 매번 다르게 보이게 하는 가장 값싼 다양성이다.

다만 근거가 분명하다: **날씨가 총득점을 바꾼다는 강한 근거는 없다.** 챔피언스리그 기상 분석에서 기온·습도·바람 중 기온만 "역습 슈팅"에 유의했고(OR 0.55, PMC11474995), 비·눈·바람이 득점·패스 정확도에 주는 동료평가 연구는 찾지 못했다. 고도 효과(1,000 m당 +0.5골, McSharry 2007)는 팀 전력 혼입 반론이 있다(reports § 맥락 효과). 그래서 이 스펙은 날씨를 **결과 승수가 아니라 작은 보정**(볼 물리·운동·체력·바람·판단 스타일)으로만 넣고, 대량 시뮬로 평균 득점 2.5~3.0과 "날씨별 득점 차 작음"을 함께 지킨다. 화면·소리·관중·경기 전 표시는 078이 이 스펙의 날씨 상태를 읽어 만든다.

### 현재 상태에서 확인한 사실 (2026-11-11, 스펙 작성 중 문서 대조)
- 004는 표면 조건(건조·젖음·인조·침수·긴 잔디) 파라미터를 입력으로 받지만, 누가 그 값을 정하는지는 비어 있다. 눈 덮임·서리 표면 파라미터는 없다.
- 005는 날씨·피치 상태가 가속·회전에 주는 영향을 `[미정]`으로 남겼다(리서치에 없음).
- 006 FR-10 경기 설정 입력에 "피치 상태(건조/젖음/인조)" 칸이 있으나 날씨 칸은 없다.
- 021은 "게임 날짜는 날짜만(시각 없음) [제안]"이고, 044는 조명 프리셋 낮·나이트 2종만 있다. 경기 시간대의 원본이 없다 → 021에 시간대 칸 추가를 후속 요청(Q4 정리됨).
- 020 가상 국가에는 기후·반구 속성이 없다 → 020에 필드 추가를 후속 요청(Q3 정리됨).

## 범위
- 포함:
  - **날씨 생성 (결정론)**: 입력 = 세계 시드 + 경기 id + 경기 날짜 + 연고지 기후대(가상) + 반구 + 경기 시간대. 출력 = 경기 날씨 상태(구름량, 강수 종류·강도, 기온, 바람 세기·방향, 시정(안개)). 표시 종류 [채택] 7개(맑음·흐림·비 약·비 강·눈·강풍·안개)는 상태에서 파생
  - **가상 기후대 표**: 공개 기후 분류 수준의 일반 유형만(실존 도시 관측 자료 복제 없음), 월별 분포 값은 튜닝 데이터 `[미정]`
  - **경기 중 변화**: 킥오프 전에 만든 날씨 타임라인, 종류 전환 최대 1회
  - **피치 상태**: 건조·젖음·물웅덩이(침수)·눈 덮임·서리(언 표면), 인조 잔디 예외, 경기 중 진행, 마모 값(078 화면 표현용, 시뮬 효과 0)
  - **경기 연기**: 킥오프 전 피치 점검 판정 → 021 재배치로 넘김
  - **시뮬 효과 (작게, 근거 등급 표기)**: 공 구름·바운드(004 표면 입력), 바람이 공 비행에 주는 영향, 선수 가속·회전·미끄러짐(005 입력), 더위·추위 체력 소모, 판단 스타일 보정(010 팀 지시 경로), 016 저정밀 시뮬 입력
  - **대량 시뮬 검증**: 날씨 종류별 평균 득점·날씨 간 득점 차
  - **078에 주는 출력**: 날씨 상태·타임라인·피치 상태·마모 지도·연기 결과(읽기 전용)
- 제외:
  - 화면(하늘 톤·입자·젖음·입김·안개·프리셋·예산), 소리 큐, 관중 옷차림·우산·수용률 입력, 경기 전 화면·HUD 표시 → **078**
  - 고도 효과 — 근거 논쟁, 사용 보류 `[미정]` (reports § F)
  - 날씨 → 부상·질병 배수 — 축구 특화 근거 없음(reports § F, 027 미정) — 027 후속
  - 경기 중 중단·몰수·재개 — 정리됨(Q2): 중단 없음
  - 실제 과거 기상 기록 재현 — 정리됨(Q3): 첫 시즌 실제 일정이어도 날씨는 생성
  - 날씨 예보·다일 예보 — 정리됨(Q8): 경기 당일 날씨만(078 표시)

## 사용자 시나리오
1. 12월 원정 경기 전, 경기 레코드의 날씨는 "눈 · −2°C · 피치 눈 덮임 일부"다. 같은 세이브를 다시 불러와도 같은 날씨다.
2. 여름 낮 경기는 맑고 덥다. 후반에 양 팀 선수가 평소보다 조금 빨리 지친다. 하지만 결과는 평소 경기와 크게 다르지 않다.
3. 전반은 흐렸는데 60분쯤부터 비가 내리기 시작하고, 70분에는 피치가 젖어 공이 더 미끄러지고 높이 튄다. 키 모먼트를 골라 재시뮬해도 비가 오는 시각은 같다.
4. 강풍 경기에서 바람을 안고 찬 롱패스가 짧게 떨어지고, 바람을 등진 크로스는 조금 더 멀리 간다. 팀이 짧은 패스를 조금 더 고른다.
5. 경기 당일 피치 점검으로 경기가 폭설 연기되고, 021이 같은 팀의 다음 예비일로 재배치한다. 새 날짜의 날씨는 다시 생성된다.
6. 개발자가 날씨 7종 각 1,000경기를 돌리면 모든 종류의 평균 득점이 2.5~3.0이고, 맑음과의 차이가 0.2골 이내다.

## 요구사항

### 날씨 상태와 생성 (결정론)
- FR-01: 경기 날씨 상태는 다음 값으로 이루어진다: 구름량(0~1), 강수 종류(없음·비·눈), 강수 강도(0~1), 기온(°C), 바람 세기(m/s)와 방향(피치 기준 방위), 시정(m, 안개). 범위는 `[미정]`이며 튜닝 데이터에 둔다.
- FR-02: 표시 종류 [채택] 7개 — 맑음·흐림·비 약·비 강·눈·강풍·안개 — 는 FR-01 상태에서 규칙으로 파생한다(임계값 `[미정]`). 한 상태가 여러 종류에 걸리면 우선순위 [채택] 눈 > 비 강 > 비 약 > 안개 > 강풍 > 흐림 > 맑음으로 대표 1개를 정하고, 나머지는 보조 표시(예: "비 강 · 강풍")로 둔다.
- FR-03: 날씨는 (세계 시드, 경기 id, 경기 날짜, 연고지 기후대, 반구, 경기 시간대)의 **순수 함수**다. 같은 입력이면 항상 같은 날씨, 같은 타임라인이다. 플랫폼·실행 순서·저장/불러오기에 따라 달라지지 않는다.
- FR-04: 날씨 생성은 경기 시뮬 난수 순서를 바꾸지 않는다. 날씨 기능을 추가해도 기준 날씨(FR-40)의 경기 결과는 064 이전 빌드와 같은 해시다.
- FR-05: 가상 기후대 표 [채택] 6종: 온대 해양성, 온대 대륙성, 지중해성, 아열대 습윤, 한랭(고위도), 건조. 기후대별·월별로 강수 확률·눈 확률(기온 조건부)·기온 분포·바람 분포·안개 확률을 가진다. 값은 공개 기후 분류의 일반 특성 수준에서 정한 튜닝 데이터 `[미정]`이며, 실존 도시의 관측 자료를 복제하지 않는다.
- FR-06: 기후대·반구는 **020이 국가·연고 도시에 부여**하고(정리됨 Q3, 020 후속 요청), 064는 기후대 표와 생성만 소유한다. 반구가 남쪽이면 월별 표를 6개월 밀어 쓴다(계절 반전). 입력이 없으면 대체 값 [채택] 온대 해양성·북반구를 쓰고 진단 로그 1건.
- FR-07: 눈은 기온이 [채택] 2°C 이하일 때만 생긴다. 기온이 [채택] 3°C를 넘으면 강수 종류는 비다(경계 사이는 표의 확률).
- FR-08: 경기 시간대는 낮·나이트 2종(044 FR-40)이며 **021 경기 레코드의 시간대 칸**에서 읽는다(정리됨 Q4, 021 후속 요청 — 배정 규칙은 021). 같은 날 낮과 나이트는 기온 분포가 다르다(나이트가 `[미정]` 낮다). 칸이 없으면 대체 값 낮 + 진단 로그 1건.
- FR-09: 첫 시즌 실제 일정(021)이어도 날씨는 FR-03으로 생성한다. 실제 과거 기상 기록은 쓰지 않는다(정리됨 Q3 — 자료 라이선스·정확도 문제 회피).

### 경기 중 변화 (타임라인)
- FR-10: 킥오프 전에 경기 전체(정규 90분 + 추가시간 + 연장 가능 구간)의 날씨 타임라인을 만든다. 경기 중 날씨는 이 타임라인을 경기 시각으로 읽는다. 경기 중 사건(골·카드·키 모먼트 재시뮬)은 타임라인을 바꾸지 않는다.
- FR-11: 변화 규칙(정리됨 Q1): 한 경기에서 날씨 종류 전환은 최대 1회, 전환은 [채택] 5~15분(경기 시각)에 걸쳐 강도가 서서히 바뀐다. 기온 변화는 경기 전체에서 [채택] ±3°C 이내. 바람 방향은 경기 중 [채택] ±30° 이내로만 흔들린다. 승부차기 중 전환 없음 [채택].
- FR-12: 키 모먼트 선택 → 같은 시드 재시뮬(006·019) 때도 같은 타임라인을 쓴다. 장면 재생·리플레이·건너뛰기·배속 변경은 날씨를 바꾸지 않는다.
- FR-13: 경기 중 중단 없음(정리됨 Q2): 타임라인 생성 때 경기 중 강수·적설·시정 강도를 연기 기준(FR-30) 미만으로 자른다. 천둥·번개는 생성하지 않는다(정리됨 Q6).

### 피치 상태
- FR-20: 피치 상태 종류: 건조, 젖음, 물웅덩이(004 "침수"), 눈 덮임(덮임 비율 0~1), 서리(언 표면), 인조. 마모는 별도 값(0~1, 위치별 지도)이다.
- FR-21: 킥오프 피치 상태는 경기 전 `[미정]` 시간의 날씨(같은 생성 함수의 앞 구간)와 경기장 조건(인조 여부)으로 정한다. 경기 중에는 강수 강도 × 지속 시간에 따라 단계가 오른다: 건조 → 젖음 → 물웅덩이, 눈 → 덮임 비율 증가. 경기 중 단계가 내려가는 것(건조해짐)은 [채택] 없음. 누적 계수 `[미정]`.
- FR-22: 인조 잔디는 물웅덩이·눈 덮임 누적·마모가 없고 [채택] 젖음과 인조 표면만 쓴다. 서리는 인조에서 연기 판정(FR-30) 대상이 아니다 [채택].

### 경기 연기
- FR-30: 킥오프 전 피치 점검: 다음 중 하나면 경기를 연기한다 — 눈 덮임 비율 ≥ `[미정]`, 물웅덩이 면적 ≥ `[미정]`, 서리(언 피치) & 기온 ≤ `[미정]`, 시정 ≤ `[미정]` m. 판정은 FR-03 입력의 순수 함수다.

- FR-32: 연기 빈도 목표 `[미정]`: 한 리그 한 시즌에 연기 0~`[미정]`경기. 대량 생성(시즌 단위)으로 빈도를 기록한다.
- FR-33: 컵 결승·대륙 대회 결승·국가대표 경기도 같은 규칙 [채택]. 재배치 날짜는 021 대회 규칙, 재배치 불가능하면 021 "예비일 없음" 규칙(조용히 삭제 금지).

### 경계 · 예외 상황
- 기후대·반구·시간대 입력 누락: 대체 값(FR-06·08) + 진단 로그 1건, 예외 0.
- 잘못된 튜닝 데이터(확률 합 ≠ 1, 배수 < 0, 기온 범위 뒤집힘): 로딩 시 거부, 기준 날씨로 대체 + 에러 1건(조용히 진행 금지).
- 2월 29일·연도 넘김 시즌(021 경계): 월 표 조회가 정상.
- 기온 2~3°C 경계(FR-07): 비/눈 판정이 결정론적이고 경계 값이 표 규칙대로.
- 인조 잔디 + 폭설: 덮임 누적 없음(FR-22), 연기 판정은 시정 기준만 [채택].
- 지붕 전체 경기장: 피치는 노출(044 지붕은 관중석만) — 피치 날씨 그대로.
- 연장전·승부차기: 타임라인이 연장 구간까지 있음(FR-10). 승부차기 중 전환 없음(FR-11).
- 경기 중 강도 심화: 타임라인 상한으로 연기 기준을 넘지 않음(FR-13).
- 재배치 예비일 없음: 021 "시즌 1주 연장 → 그래도 없으면 에러" 규칙.
- 키 모먼트 재시뮬: 날씨 동일(FR-12).
- 옛 세이브(날씨 칸 없음): 경기 기록에 날씨가 없으면 FR-03으로 다시 생성하거나 기준 날씨로 읽는다 [채택] — 저장된 결과는 바꾸지 않는다.

## 비기능 요구사항
- 결정론: 날씨·타임라인·피치 상태·마모 지도·연기 판정은 FR-03 입력의 순수 함수. 경기 시뮬 난수 순서를 바꾸지 않는다(FR-04). 같은 날씨 + 같은 경기 시드 → 같은 경기 해시.
- 코어 분리: 날씨 생성·피치 상태·연기 판정·시뮬 효과는 Unity와 분리된 결정론 코어 쪽(CLAUDE.md).
- 세이브 호환: 경기 레코드에 날씨 상태·피치 상태를 저장한다(reports § A Context 계층 "경기 레코드"). 형식 버전 필드(022). 옛 세이브는 경계 규칙대로.
- 법·등급: 기후 자료는 공개·가상 기후대만(실존 도시 관측 자료 복제 없음), 15세.

## 수용 기준
각 AC는 검증 종류를 하나 이상 단다: `[로직]` EditMode 테스트 · `[E2E]` 장면 스크린샷(mac-m1-1600p 1프로필) + 사용자 육안 승인 · `[성능]` 측정값 · `[결정론]` 같은 시드 2회 해시 비교. 화면 AC는 078.
- AC-01 [결정론] [로직]: 같은 (세계 시드, 경기 id, 날짜, 기후대, 반구, 시간대)로 날씨·타임라인·피치 상태·마모 지도·연기 판정을 2회(그리고 저장 → 불러오기 후 1회) 만들면 해시가 같고, 세계 시드나 날짜를 바꾸면 다르다. 입력 누락은 대체 값 + 진단 로그 1건·예외 0, 잘못된 튜닝 데이터는 로딩 거부 + 기준 날씨 + 에러 1건 (FR-03·06·08·43, 경계).
- AC-02 [결정론]: 기준 날씨(맑음·건조·무풍·기준 기온)로 고정 픽스처 경기 [채택] 20개를 돌리면 경기 해시가 064 이전 빌드 기록과 전부 같다. 같은 비·눈·강풍 날씨 + 같은 경기 시드 2회도 해시가 같다 (FR-04·40).
- AC-03 [로직]: 기후대 6종 × 12개월 × 시간대 2종 각각 [채택] 10,000회 생성에서 강수·눈·안개·기온 구간 빈도가 튜닝 표 ± [채택] 2%p 안, 기온 > 3°C에서 눈 0건, ≤ 2°C 경계 규칙대로, 남반구는 6개월 밀린 분포, 표시 종류 파생이 FR-02 우선순위대로, 첫 시즌 실제 일정 경기도 생성 날씨 (FR-02·05~09).
- AC-04 [로직]: 타임라인: 경기마다 종류 전환 ≤ 1회, 전환 구간 5~15분·기온 변화 ±3°C·바람 방향 ±30° 안, 연장 구간까지 존재, 승부차기 중 전환 0, 경기 중 강도가 연기 기준 미만, 천둥·번개 0. 골·카드·키 모먼트 재시뮬 전후로 타임라인 해시 동일 (FR-10~13, 경계).
- AC-05 [로직]: 피치 상태: 비 강도 × 지속 시간 픽스처에서 건조 → 젖음 → 물웅덩이 단계가 누적 규칙대로 오르고 내려가지 않음, 인조는 물웅덩이·눈 누적·마모 0, 매핑표대로 004 표면 입력이 전달되고 눈 덮임·서리는 004 추가 전 대체 값 + 진단 로그 1건, 공 위치별 표면 값이 물웅덩이 지도와 일치 (FR-20~25).
- AC-06 [로직]: 경기 연기: FR-30 조건 각각의 경계값 위·아래 픽스처에서 연기/진행이 정확히 갈리고, 연기 시 경기 시뮬 호출 0회·021 재배치에 사유 "날씨"로 전달·새 날짜 날씨 재생성, 예비일 없음은 021 규칙(조용히 삭제 0건). 시즌 단위 대량 생성 [채택] 100시즌에서 리그당 연기 수 분포가 기록된다 (FR-30~33).
