# 051 — 가상 이름 · 브랜드 생성 · 이름 필터

상태: 초안
브랜치: feat/051-name-brand-generation
기획 출처: docs/index.html § 기획서 4.7(실존 클럽/선수/리그 이름 사용 안 함, 대회명·로고는 상표라 변형 이름), § 4.10(소비·자산: 시계·패션·차, 스폰서 제안, SNS 게시), § 4.6.2(미디어·팬: SNS 논란, 파파라치 / 소비·자산: 집·차 구매), § 4.10 연령 등급(15세 내외, 암시적 표현) / 리서치 00 § 1(항목별 리스크: 선수 실명·경기장 이름 다수가 스폰서 상표), § 5(결정할 것 — 실명 정책 결정 대기) / 리서치 05 § 6.2(도시: 문화권별 음절 마르코프 체인, 클럽: [도시]+[문화권별 접미사 템플릿]), § 6.3(선수 이름: 공공 인구통계 빈도표, 성 마르코프 체인 order 2~3, 실존 유명 선수 블랙리스트 필터), § 7(소셜미디어: 팔로워 시뮬) / 리서치 07 § 3(뉴스·SNS 템플릿)

## 배경
게임 안의 모든 고유명사가 가짜여야 한다. 선수·감독뿐 아니라 심판, 에이전트, 기자와 매체, 시계·차 브랜드, 스폰서, SNS 서비스 이름까지. 하나라도 실존 이름이 나오면 퍼블리시티권·상표 문제가 생긴다(00 문서). 동시에 이름이 그 나라답게 들려야 몰입이 된다. 지금은 선수·도시·클럽 이름은 020이 정의했지만, 나머지 고유명사는 담당이 없었다(README "담당 스펙이 없는 것"). 이 스펙은 **이름을 만드는 공용 생성기와 이름 데이터, 필터**를 맡고, 020·032·034·012·050 등이 가져다 쓴다.

## 범위
- 포함:
  - 문화권별 이름 데이터 형식 (이름·성 빈도표, 음절 모델 학습 입력, 접미사·접두사 템플릿)
  - 사람 이름 생성: 선수·감독·코치·심판·에이전트·기자·연인·가족·동료 외 인물 (역할만 다르고 같은 생성기)
  - 장소·조직 이름 생성 템플릿: 도시, 클럽, 경기장, 대회, 리그, 언론 매체
  - 브랜드 이름 생성: 시계, 차, 패션, 음료·식품·통신 등 스폰서 업종, 부동산·투자 상품, 레스토랑·클럽 등 라이프 장소
  - 가상 SNS 서비스 이름과 계정 핸들 생성
  - 이름 필터: 실존 인물·브랜드·클럽·대회와 같은 이름 차단, 15세 등급 금칙어·비속어·차별 표현 차단, 문화권 오역(다른 언어로 읽으면 욕설) 차단
  - 이름 표기: ko/en 표기 (한글 음역·로마자), 짧은 표기(스코어버그 3글자 약칭, 유니폼 등번호 위 성)
- 제외:
  - 국가·리그·클럽 구조와 생성 순서 → 020 (이름 문자열은 이 스펙 생성기를 호출)
  - 클럽·경기장·리그·대회 변형 이름 작성 → 020 기본 세계 템플릿(사람 작성 데이터, A안 확정 (2026-11-02 사용자 결정)). 이 스펙은 그 이름이 FR-40 필터·FR-43 금칙어를 통과하는지 검사만
  - 실명 로스터 → 우리는 만들지 않는다. 사용자가 049로 가져옴 (덮어쓰기 팩 049 FR-28)
  - 브랜드 로고·이미지 → 044·037 (이 스펙은 이름과 업종·등급 메타데이터만)
  - 이벤트 문구의 금칙어 검수 → 031 콘텐츠 린트 (이 스펙의 금칙어 데이터를 공유)
  - 플레이어가 직접 입력한 이름의 검사 → 023이 이 스펙의 필터를 호출 (정책은 이 스펙)

## 사용자 시나리오
1. 새 커리어를 만들자 상대 팀 선수 명단이 나라마다 그럴듯한 이름으로 채워진다. 어디서 본 유명 선수 이름은 없다.
2. 라이프 탭에서 차를 사려고 보니 가상 브랜드 세 곳의 모델이 가격대별로 있다. 브랜드 이름이 실존 회사를 떠올리게 하지 않는다.
3. 골을 넣자 가상 SNS "○○" 피드에 팬 계정들이 반응한다. 계정 핸들이 다양하고 비속어가 없다.
4. 선수 생성 화면에서 이름을 직접 입력했는데 금칙어라 "다른 이름을 써 주세요"가 뜬다.

## 요구사항

### 이름 데이터
- FR-01: 문화권(언어·지역 단위, 국가보다 굵게 [제안]) 하나에 다음 데이터가 있다: 이름 빈도표(성별 구분 선택), 성 빈도표 또는 성 음절 모델 학습용 목록, 도시 음절 모델 학습용 목록, 클럽·대회·매체 접미사 템플릿, 로마자·한글 표기 규칙.
- FR-02: 이름 빈도표는 각국 공공 인구통계(출생 이름 순위 등 공개 통계, 리서치 05 § 6.3) 기반. 데이터마다 출처·라이선스를 데이터 출처 목록에 기록한다 [미정: 목록 위치 — 020과 공통].
- FR-03: 데이터 파일은 공개 포맷(022)으로 모드가 문화권을 추가·수정할 수 있다.
- FR-04: 출시 문화권 수 [미정] (020 국가 수와 맞춤). 최소 [제안 8]개.

### 사람 이름 생성
- FR-10: 이름 = 빈도표 가중 추첨. 성 = 빈도표 추첨 또는 음절·형태소 마르코프 체인(order 2~3) 합성 (리서치 05 § 6.3). 비율 [제안 빈도표 70% / 합성 30%] 문화권별 설정.
- FR-11: 합성 성은 길이·음절 수 제한과 발음 규칙(문화권별 금지 연쇄)을 통과해야 한다.
- FR-12: 역할(선수·감독·심판·에이전트·기자·가족 등)은 같은 생성기를 쓰되, 나이대에 따라 이름 빈도표 연대를 고를 수 있다 [제안] (오래된 세대에는 그 시대 흔한 이름).
- FR-13: 다문화 이름: 국적과 다른 문화권 이름을 [제안 국가별 비율]로 섞는다 (020 국가 설정 입력).
- FR-14: 같은 클럽 안 동명이인 금지, 세계 동명이인 비율 상한은 020 FR-35를 따른다. 이 스펙은 "중복 검사 질의"를 제공한다.
- FR-15: 가족 성 규칙: 자녀(033·036 뉴게임+)는 부모 성 승계 규칙을 문화권별로 따른다 [제안].

### 장소 · 조직 이름
- FR-20: 도시 = 문화권별 음절 마르코프 체인 (리서치 05 § 6.2).
- FR-21: 클럽 = `[도시] + [문화권별 접미사 템플릿]` (리서치 05 § 6.2, 020 FR-23의 문자열 생성 담당).
- FR-22: 경기장 = 지역명·지형·인물 아닌 일반 명사 템플릿 [제안] (리서치 00: 실존 경기장 이름은 스폰서 상표가 많음 → 상표형 이름 금지).
- FR-23: 대회·리그 = 국가·지역 + 등급 템플릿. 실존 대회명·상표와 같거나 그것을 떠올리는 고유 단어 금지 (기획서 4.7).
- FR-24: 언론 매체 = 도시·국가 + 매체 유형 템플릿 [제안] (일간지·방송·팬 블로그).

### 브랜드 · SNS
- FR-30: 브랜드는 업종(시계·차·패션·음료·통신·금융·부동산·식당·나이트클럽 등 032·034가 쓰는 목록 [미정])과 가격 등급(1~5)을 가진다. 등급별 [제안 2~4]개 브랜드.
- FR-31: 브랜드 이름은 조어 생성기(음절 조합 + 업종별 접미사 [제안])로 만들고 FR-40 필터를 통과해야 한다. 기본 배포 브랜드는 생성 후 사람이 검수해 고정 목록으로 둔다 [제안] (매 세계마다 랜덤 X — 상품 카드 UI·로고 일관성).
- FR-32: 스폰서는 브랜드에서 고른다 (034가 계약). 클럽 유니폼 스폰서도 같은 목록 [제안].
- FR-33: 가상 SNS 서비스 이름 [제안 1~2개], 고정 목록. 팬·기자·동료 계정 핸들 생성: 이름·숫자·클럽 약칭 조합 템플릿, 금칙어 필터 통과.

### 필터
- FR-40: 실존 이름 차단: 생성된 사람 이름(이름+성), 클럽·대회·경기장·브랜드 이름이 실존 목록과 일치하면 재생성 (020 FR-33·34의 필터 구현 주체).
- FR-41: 실존 목록을 저장소에 평문으로 두지 않는 방식 [미정] — 후보: 정규화 후 단방향 해시 목록 저장, 빌드 시 외부 파일 주입, 로컬 전용 파일. 어느 방식이든 **필터 동작과 테스트는 가상 테스트 목록으로 검증**한다 (실명 없이).
- FR-42: 정규화 규칙: 대소문자·악센트·공백·하이픈·음역 차이를 없앤 키로 비교 (예: 악센트 제거, 한글 음역 → 로마자 키 [제안]).
- FR-43: 15세 등급 금칙어·비속어·차별·성적 표현 목록 (ko/en 및 출시 문화권 언어). 부분 문자열 포함 검사 + 단어 경계 검사 둘 다 [제안], 오탐 예외 목록 유지.
- FR-44: 문화권 교차 검사: 한 문화권 이름이 다른 출시 언어에서 금칙어로 읽히는지 검사 (로마자 키 기준).
- FR-45: 재생성 상한 [제안 20회]. 넘으면 다른 이름 원천(빈도표 ↔ 합성)으로 강제 교체. 무한 루프 금지 (020 경계와 동일).
- FR-46: 사용자 입력 이름(023 선수 이름, 에디터 049) 검사 API: 결과 = 허용 / 금칙어 / 실존 의심 / 길이 초과. 실존 의심은 [제안] 경고만(차단 X — 사용자 본인 이름일 수 있음), 금칙어는 차단.

### 표기
- FR-50: 모든 이름은 ko·en 표기를 가진다. 생성 시 원어 → 로마자 → 한글 음역 규칙 [미정: 문화권별 음역표].
- FR-51: 짧은 표기: 클럽 3글자 약칭(039 스코어버그) — 같은 리그 안 중복 금지. 선수 등번호 위 표기(성, 길이 [제안 12자] 초과 시 축약 규칙).
- FR-52: 표기 길이 통계를 리포트로 낸다 (037 UI가 최장 이름 기준 레이아웃 검증에 사용).

### 경계 · 예외 상황
- 작은 문화권 빈도표가 고갈(클럽 안 동명이인 회피 실패) → 합성 비율 자동 상향, 그래도 실패면 다른 성으로 강제 교체 (FR-45).
- 합성 성이 빈도표 실존 성과 우연히 일치 → 허용 (흔한 성은 실명 문제가 아님). 문제는 "이름+성" 조합이 실존 유명인일 때만 (FR-40).
- 음역 결과가 빈 문자열·기호만 → 생성 실패로 재생성.
- 3글자 약칭 후보가 리그 안에서 모두 겹침 → 숫자·두 번째 단어 첫 글자 규칙 [제안], 그래도 실패면 명확한 오류.
- 금칙어 목록 갱신 후 기존 세이브의 이름이 금칙어가 됨 → 세이브 이름은 바꾸지 않고 로드 시 경고 로그 없이 그대로 (사용자 데이터 보존) [제안]. 신규 생성에만 적용.
- 모드가 넣은 이름 데이터에 금칙어 포함 → 가져오기(049) 단계에서 경고 표시, 기본 데이터와 동일 필터 적용 여부는 사용자 선택 [제안].
- 유니코드 정규화 차이(조합형 한글, NFC/NFD) → 비교 전 NFC 정규화.
- 오른쪽에서 왼쪽 문자(아랍어 등) 문화권 → 출시 범위 [미정]. 포함 시 UI(037) 양방향 텍스트 요구.

## 비기능 요구사항
- 결정론: (세계 시드, 문화권 데이터 버전, 생성기 버전, 요청 순서와 무관한 엔티티 id) → 같은 이름. 이름 생성은 엔티티별 파생 시드를 써서 한 엔티티 추가가 다른 엔티티 이름을 바꾸지 않는다 [제안] (020 FR-70 안정 식별자와 맞춤).
- 법적 안전: 저장소·빌드 산출물 어디에도 실존 인물 실명 목록이 평문으로 남지 않는다 (FR-41 결정 전까지 실존 필터는 비활성 + 테스트 목록만).
- 데이터 출처: 빈도표 등 외부 데이터는 출처·라이선스 기록 없이 추가 불가.

## 수용 기준
- AC-01 [결정론]: 같은 시드·데이터 버전으로 월드 이름을 2회 생성 → 모든 이름 해시 동일. 엔티티 1명을 추가해도 다른 엔티티 이름은 바뀌지 않는다.
- AC-02 [로직]: 가상 테스트 실존 목록(테스트 전용 가짜 이름 1,000개)을 넣고 100 시드 생성 → 목록과 정규화 일치하는 사람·클럽·브랜드 이름 0건. 악센트·대소문자·하이픈만 다른 변형도 차단된다.
- AC-03 [로직]: 금칙어 테스트 목록에 대해 생성 이름·브랜드·SNS 핸들 0건 포함. 단어 경계 오탐 예외 목록 단어(정상 단어 안의 부분 문자열)는 허용된다.
- AC-04 [로직]: 문화권 교차 검사: 테스트용으로 지정한 "다른 언어 금칙어" 로마자 키와 일치하는 이름 0건.
- AC-05 [로직]: 재생성 상한 도달 상황(빈도표 3개짜리 테스트 문화권으로 50명 클럽 생성)에서도 무한 루프 없이 끝나고 클럽 안 동명이인 0건.
- AC-06 [로직]: 같은 리그 클럽 3글자 약칭 중복 0건 (100 시드).
- AC-07 [로직]: 모든 생성 이름이 ko·en 표기를 갖고 빈 문자열·제어 문자가 없다. 최장 표기 길이 통계가 리포트로 나온다.
- AC-08 [로직]: 브랜드 목록이 업종 × 가격 등급마다 2개 이상 있고, 브랜드 이름끼리 정규화 중복 0건.
- AC-09 [로직]: 사용자 입력 검사: 금칙어 → 차단, 테스트 실존 목록 일치 → 경고만, 길이 초과 → 차단, 정상 → 허용. NFD로 입력한 한글도 NFC와 같은 결과.
- AC-10 [로직]: 저장소 전체를 검사했을 때 실존 이름 평문 목록 파일이 없다 (FR-41 방식 결정 전: 실존 필터 데이터 파일 자체 없음) — 린트 스크립트로 확인.
- AC-11 [E2E]: `e2e/051-names-roster` — 고정 시드 세계의 리그 순위표·상대 팀 명단·SNS 피드 화면에서 en/ko 최장 이름이 잘리지 않고 겹치지 않는다. 프로필: 전체.
- AC-12 [E2E]: `e2e/051-name-input` — 선수 생성 이름 입력에 금칙어를 넣으면 오류 문구가 보이고 다음 단계 버튼이 비활성인 화면이 기준 이미지와 일치. 프로필: smoke.
- AC-13 [성능]: 성능 예산 표 항목이 기준 프로필에서 예산 안.

## 검증 · 증거
- 로직: 필터·결정론·약칭 테스트 리포트 스크린샷 (`specs/051-name-brand-generation/evidence/logic.png`) + 이름 통계 표(문화권별 길이 분포, 재생성 횟수, 동명이인 비율).
- E2E: `e2e/051-names-roster`(전체 프로필 × ko/en), `e2e/051-name-input`(smoke).
- 성능: 생성·검사 측정 (`evidence/perf.json`).
- 결정론: 이름 해시 2회 비교.

## 미정 / 질문
- [미정] 실존 이름 목록 보관 방식(FR-41: 해시 / 빌드 주입 / 로컬 전용). 실명 정책 자체는 A안 확정 (2026-11-02 사용자 결정)이지만, 보관 방식은 별도 결정이 필요하다.
- [미정] 출시 문화권 수와 목록, 문화권 단위(언어 vs 국가).
- [미정] 이름 빈도표 데이터 출처별 라이선스 확인과 기록 위치 (020과 공통).
- [미정] 문화권별 한글 음역표 (외래어 표기법 적용 범위).
- [미정] 브랜드·SNS 이름을 고정 목록(사람 검수)으로 둘지 세계마다 생성할지 — [제안] 고정.
- [미정] 브랜드 업종 목록은 032(소비)·034(스폰서)와 확정.
- [미정] 오른쪽→왼쪽 문자 문화권 포함 여부.
