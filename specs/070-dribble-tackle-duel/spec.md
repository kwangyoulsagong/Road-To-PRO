## 배경
2026-11-11 사용자 결정("베스트 케이스로 다 진행")으로 008 액션 모델을 셋으로 나눴고, 이 스펙은 원래 008 Q6의 008b 범위다: 공을 몸에 붙이고 달리는 드리블, 수비수를 제치는 1v1 테이크온, 태클과 몸싸움, 그리고 그때 생기는 모든 접촉의 기록. 드리블 중독 윙어가 수비수를 제치는 장면, 늦은 슬라이딩 태클로 파울이 나는 장면은 하이라이트의 단골이고, 성패는 운이 아니라 드리블·태클·근력 같은 능력치와 각도·커버로 납득되어야 한다. 실패하면 볼을 잃고 역습을 맞는 대가도 있어야 한다.

현재 빌드는 대체 단계라 "주변에 아무도 없는데 태클 동작이 나온다". 태클은 상대 볼 캐리어가 도달 거리 안에 있을 때만 태클로 기록되고(008 FR-70, 이 스펙 FR-10·11), 다운·회복 지연은 005 운동 한계 안에서만 나타난다(008 FR-64).

공통 규칙(능력치 정규화·압박 강도·평가/실행 분리·출력·접촉 시각·실행 결과 종류·접촉 상세 기록 저장)은 008 FR-01~04, FR-60~72를 그대로 쓴다. 무엇을 할지(드리블할지·압박할지·태클을 시도할지)는 판단 AI(010 오프볼·압박, 072 온볼)가 정하고, 이 스펙은 시도의 결과만 판정한다.

의존: 008(공통 인터페이스), 005(TTI·이동 한계), 004(루즈볼). 002(능력치)·003(버릇 부가 효과·성향)·007(커버 PPCF)·012(파울 판정)·027(부상 위험)은 아직 구현 전이라 **대체 입력으로 먼저 구현**하고(2026-11-11 사용자 결정 '베스트 케이스', 008 Q3과 같은 방식) 연결 때 AC-12로 재확인한다. 다운 상태는 005 "이동 불가 시간"(005 수정 제안)을 쓴다.

## 범위
- 포함:
  - 드리블: 볼 운반 최고속도, 터치 거리·방향 오차, 터치 이격 중 탈취 판정
  - 1v1 테이크온 발동 조건·성공 확률·결과 분기, 저킹(jockey) 중 태클 조건
  - 태클: 스탠딩·슬라이딩 성공 확률, 도달 거리, 슬라이딩 다운, 파울 특징값(뒤에서 들어간 정도, 늦은 정도)
  - 접촉 이벤트(태클·경합·공중볼·몸싸움·충돌) 필드 정의
  - 압박 트리거 입력값(등진 수신, 불안한 첫 터치 등) 플래그
  - 몸싸움(어깨 경합·볼 지키기) 판정 (005 FR-24가 넘긴 것)
  - 핸드볼 판정 입력(팔 영역 접촉)
  - 성향 → 태클 스타일 세부 선택
- 제외:
  - 패스·첫 터치·인터셉션·공통 인터페이스 → 008
  - 크로스·공중볼 경합 판정·헤더·슈팅 → 071 (공중볼 경합의 접촉 이벤트는 이 스펙 FR-13 형식으로 071이 낸다)
  - 드리블·압박·태클 시도 여부 선택 → 010(오프볼·압박)·072(온볼)
  - 파울 여부·카드·어드밴티지·핸드볼 판정 → 012 (이 스펙은 특징값만 낸다)
  - 경기 중 부상 판정 → 027 (접촉 이벤트를 입력으로 읽음)
  - 압박 점수 결합·압박 인원 지정 → 009 FR-60~61
  - 3D 태클·드리블 동작 선택 → 058 FR-50~52, 054

## 사용자 시나리오
1. 드리블 중독 윙어가 수비수를 제치는 장면이 경기당 몇 번 나오지만, 실패하면 볼을 잃고 역습을 맞는다.
2. 공간으로 길게 밀어놓은 터치는 빠르지만, 수비수가 먼저 닿을 수 있으면 빼앗긴다.
3. 뒤에서 늦게 들어간 슬라이딩 태클은 공을 따내도 파울 특징값이 커서 012가 반칙을 줄 확률이 높다.
4. 근력 높은 공격수는 어깨 경합에서 공을 지켜 낸다.

## 요구사항

### 드리블 (리서치 02 §3) — 원래 008 FR-30~36
- FR-01: 볼 운반 최고속도 `vmax_ball = vmax × lerp(0.78, 0.92, a_Dribbling)` (감속 8~22%. 실측 근거: 20 yd 약 20% 느림, 5 m 스플릿 13~19% — 리서치 02 §3.1). vmax는 005가 제공. (원래 008 FR-30)
- FR-02: 터치 거리 `touchDist = lerp(0.8, 4.0, speedNorm) × lerp(1.25, 0.8, a_Dribbling·0.6 + a_FirstTouch·0.4)`. 압박 시 1~2 m, 공간 질주 시 공식 상한 5.0 m까지 밀어놓는다 (정리됨 (2026-11-11 사용자 결정 '베스트 케이스'): 원래 008 Q4 ① — 리서치 02 §3.2 본문의 "4~8 m" 대신 원문 공식 상한을 쓰고 017에서 튜닝). 터치 방향 오차 `σ = lerp(12°, 3°, a_Dribbling) × (1 + pressure)`. (원래 008 FR-31)
- FR-03: 드리블 중 공 상태 (정리됨 (2026-11-11 사용자 결정 '베스트 케이스'): 원래 008 Q2 ②): 공은 소유자의 "컨트롤" 상태를 유지한다(009 점유 판정·013·054가 쓰는 기존 상태 그대로). 터치마다 FR-02 이격을 두고, 이격이 열려 있는 동안에만 상대의 공 도달 시간(005 TTI)과 비교해 탈취를 판정한다(긴 터치일수록 빼앗길 위험이 커짐). 판정은 시드 RNG, 이격 구간의 공 위치는 004 굴림 예측을 쓴다. (원래 008 FR-32)
- FR-04: 1v1 테이크온 발동 조건: 수비수가 공격수와 골문 사이, 거리 < 3 m. (원래 008 FR-33)
- FR-05: `logit P_beat = c0 + 2.2·(a_Dribbling − a_Tackling·0.6 − a_Positioning·0.4) + 1.0·(a_Agility_or_Pace − defPace) + 0.8·angleAdv − 0.7·cover − 0.5·defSetFactor`, c0 = −0.55 (평균 능력치 대결 ≈ 37%) [설계값]. `a_Agility_or_Pace`·`defPace`는 002 FR-14 정규화 값(0..1). `cover` = 뒤 두 번째 수비수의 PPCF(007; 미구현 동안 005 TTI 근사), `defSetFactor` = 수비수 속도 < 1.5 m/s이고 정면이면 1, 돌진 중이면 0. (원래 008 FR-34)
- FR-06: 결과 분기 [설계값]: 성공 → 공격수 1~2 m 분리, 수비수 0.4 s 회복 지연(008 FR-64대로 이동 명령 중지로 표현). 실패 → 탈취 60%, 터치라인 아웃 15%, 파울 획득 10%, 루즈볼 15%. (원래 008 FR-35)
- FR-07: 저킹 이동은 005 FR-26(Offset-Arrive)을 쓴다. 저킹 중인 수비수는 `touchDist > 1.2 m`이고 공에 대한 TTI 우위일 때만 태클을 시도할 수 있다 (리서치 02 §3.4). 위치선정·침착성이 높을수록 기다리는 쪽 판단 가중치는 010에 제공. (원래 008 FR-36)

### 태클 · 압박 (리서치 02 §4) — 원래 008 FR-40~44
- FR-10: 스탠딩 태클 [설계값] (도달 거리 [미정], 슬라이딩은 +1.0 m): `logit P_win = −0.1 + 2.0·(a_Tackling − a_Dribbling·0.7 − a_Strength_att·0.3) + 1.2·ballExposure − 0.8·angleFromBehind`. `ballExposure`는 터치 거리·공-수비수 거리에서 계산 [미정: 정규화 식]. 태클은 상대 볼 캐리어(또는 직전 소유자)가 이 도달 거리 안에 있을 때만 시도·기록한다 (008 FR-70). (원래 008 FR-40)
- FR-11: 슬라이딩: 도달 +1.0 m, P_win logit −0.3, 실패 시 1.2 s 다운, 파울 확률 ×2.5(012가 읽는 특징값). 다운 동안 그 선수는 이동 명령을 받지 않고 005 감속 상한으로 멈춘다 (008 FR-64). 다운 상태는 005 "이동 불가 시간"으로 표현한다 (정리됨 (2026-11-11 사용자 결정 '베스트 케이스'): 원래 008 Q5 ① — 005 수정 제안, 012·027도 재사용). 다운 상태는 체크포인트·해시에 포함한다. (원래 008 FR-41)
- FR-12: 파울 여부는 이 스펙이 정하지 않는다 (012 FR-21이 소유). 리서치 02 §4의 `P_foul = sigmoid(−2.3 + 1.5·angleFromBehind + 1.0·(1 − a_Tackling) + 0.8·sliding + 0.5·lateness)`와 "평균 10~14%/태클, 슬라이딩 파울 ×2.5" 목표는 012 미정의 후보로 옮겼다. (원래 008 FR-42)
- FR-13: **접촉 이벤트**: 태클·경합·공중볼(071)·몸싸움·충돌마다(파울 여부와 무관하게) 접촉 이벤트를 낸다. 저장은 008 FR-72(SimEvent 1건 + 일련번호로 연결한 상세 기록, 체크포인트·해시 포함). 필드: 틱·서브스텝, 공격자·수비자, 공을 먼저 건드렸는지(0~1), 강도(0~1, 상대 속도·유효 질량), 뒤에서(angleFromBehind 0~1), 늦은 정도(lateness), 슬라이딩 여부, 발바닥 노출, 접촉 높이, 위치, 박스 안 여부, 득점 기회 저지 판정용 상황 스냅샷, 버릇 부가 효과(슬라이딩 장인 등, 003 FR-21). 소비자: 012(파울·징계), 027(경기 중 부상 위험). (원래 008 FR-43)
- FR-14: 압박 트리거 점수의 입력값(등진 수신, 불안한 첫 터치 > 1.5 m(008 FR-67), 백패스, 터치라인 근접, 상대 진영 볼)을 이벤트·상태 플래그로 제공한다 (점수 결합과 압박 인원 지정은 009 FR-60~61, 개인 실행 여부는 010). (원래 008 FR-44)

### 몸싸움 · 핸드볼 입력
- FR-20: **몸싸움**: 어깨 경합·볼 지키기 판정은 근력·밸런스와 [미정] 계수로 하고(005 FR-24가 넘김), 결과는 FR-13 접촉 이벤트로 낸다. 위치·속도 변화는 008 FR-64를 따른다. (원래 008 FR-68)
- FR-21: 공이 수비수 팔 영역에 닿으면 핸드볼 판정 입력(팔 실루엣 계수 0~1, 공과의 거리, 반응 가능 시간, 자기 몸·근거리 굴절 여부)을 FR-13 접촉 이벤트에 붙인다 (판정은 012 FR-50). 슈팅 블록(071 FR-15)에서 생긴 팔 접촉도 이 형식이다. 팔 실루엣 계수 산출식 `[미정]`. (원래 008 FR-56)

### 개성 연결
- FR-30: 능력치: 드리블 터치 거리·방향 오차(FR-02), 테이크온(FR-05), 태클(FR-10), 몸싸움(FR-20)은 002 FR-14 정규화 능력치만 쓴다 (008 FR-71 ①).
- FR-31: 성향(003 FR-10 "태클 스타일" 축)은 태클 시도가 정해진 뒤 스탠딩/슬라이딩 비율에만 들어간다 (008 FR-71 ③). 매핑 [미정]. 버릇 부가 효과(슬라이딩 장인 파울 확률 ×1.4)는 FR-13 필드로만 넘기고 012가 적용한다.

## 경계 · 예외 상황
- 같은 서브스텝에 태클 두 개(협력 압박) → 선수 id 순으로 판정, 첫 성공 이후 두 번째는 무효.
- 태클과 패스 동시(같은 서브스텝에 공이 떠남) → 공이 떠난 뒤의 태클은 "늦은 태클"(lateness 증가)로 파울 특징값만 내고 공 획득 없음.
- 상대 캐리어가 도달 거리 밖에서의 공 획득 → 태클이 아니라 인터셉트·공 회수 (008 FR-70).
- 테이크온 발동 조건 경계(정확히 3 m) → 3 m 미만만 발동, 고정 규칙.
- 터치 이격 0 m(정지 볼 보호) → 탈취 판정 없음, 몸싸움(FR-20)으로만.
- 다운 중인 선수가 다시 태클 대상·시도자가 됨 → 시도 불가, 대상은 가능.
- 능력치 극단값 → 확률 0.001~0.999로 자름 (008 공통).
- 접촉 이벤트에 득점 기회 스냅샷을 만들 수 없는 위치(피치 밖) → 스냅샷 비움 플래그, NaN 없음.

## 비기능 요구사항
- 결정론: 평가는 RNG 없음, 실행은 시드 RNG·액션당 고정 소비 (008 FR-61). 다운 상태·이격 상태는 체크포인트·해시에 포함.
- 할당: 드리블·태클·접촉 이벤트 경로 힙 할당 0.
- 튜닝 가능성: 모든 [설계값] 계수가 데이터에서 바뀐다.
