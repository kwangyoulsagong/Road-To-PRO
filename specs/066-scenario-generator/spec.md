# 066 — 시나리오 조합 생성기 · 필터 · 태그 · 압축 저장

## 배경
4만 개 시나리오를 손으로 쓰면 개당 10분만 잡아도 약 6,600시간이다. 그래서 사람(과 채굴·LLM 초안)은 기본 패턴 268개만 만들고(014), 이 스펙이 변주 축을 곱해 구체 시나리오를 **개발 때** 자동으로 만든다. 만든 조합은 헤드리스 시뮬로 수백 번씩 돌려 비정상(성공률 0%·100%)이거나 퇴화한 것을 버리고, 남은 것에 성공률·기대 xG·소요 시간을 (상대 블록·구역·점수 상황·능력 밴드)별 조건부 태그로 붙인다. 빌드된 게임은 이 결과를 압축 저장한 것을 골라 쓰기만 하고, 런타임에 새로 만들지 않는다(CLAUDE.md "경기 엔진" 행, 2026-11-11).

이 스펙은 014에서 2026-11-11 Q7 분할(추천 B 채택)로 나온 이전 "014b" 범위다. 다양성 검증은 067이 맡는다.

## 범위
- 포함:
  - 변주 축 정의와 조합 생성기 (시작 구역, 상대 포메이션, 마무리 분기, 배역 변형, 좌우 반전 + 수비 문서의 게임 상태·압박 강도·상대 대응 정책)
  - 규칙 필터(무효 조합 사전 제거), 헤드리스 필터(성공률 0%·100% 제거), 퇴화 패턴 필터 5종
  - 태그: 성공률, 기대 xG, 평균 소요 시간, 시작 수, 표본 수 — 능력 밴드·상대 블록·구역·점수 상황별 조건부
  - 런타임 선택이 배역 능력 밴드 태그를 쓰게 하는 013 연결 요구
  - 053 배치 검증과 같은 탈락 기준·태그 공유
  - 라이브러리 버전 관리 (생성 입력·시드·엔진 버전 → 같은 출력), 낡은 태그 감지
  - 구체 시나리오 압축 저장 구조와 4만 개 로딩 메모리 (013 성능 예산에서 이관)
- 제외:
  - 기본 패턴 수록·스키마 필드·배치 순서 (014), 런타임 선택·캐스팅·의도 실행 (013)
  - 다양성 검증·군집 (067)
  - 대량 시뮬 실행 인프라와 리그 통계 비교 (017이 제공, 여기서는 그 위에서 필터·태그만)
  - xT·피치 컨트롤(007), 기대 xG(015) 계산. 미구현인 동안은 013과 같은 대체 입력을 쓰고, 각 스펙이 구현될 때 태그를 재생성·재확인한다.
  - 런타임 생성·LLM 호출 (금지 — CLAUDE.md)

## 사용자 시나리오
1. 개발자가 새 기본 패턴 "하프스페이스 언더랩 → 컷백" 하나를 추가하고 생성 명령을 돌린다. 몇 분 뒤 이 패턴에서 나온 구체 시나리오 수, 규칙·0%/100%·퇴화 필터로 버려진 수와 이유, 남은 조합의 성공률·xG 분포(상대 블록별·능력 밴드별)가 리포트로 나온다.
2. 특정 조합이 로우블록 상대에서만 성공률 70%이고 나머지 블록에서는 5%다. 퇴화 필터가 "익스플로잇 의심"으로 버리고 리포트에 블록별 성공률을 남긴다.
3. 엔진 판정 로직이 바뀌면 라이브러리를 로드할 때 "재생성 필요"가 뜬다.

## 요구사항

### 변주 축과 생성
- FR-10: 변주 축 (scenarios.html § 구조 4, research[1] § 0. 기획서 5.1.1도 이 값으로 갱신됨 — 2026-11-11):

  | 축 | 값 수 (평균) | 비고 |
  |---|---|---|
  | 시작 구역 | 3~4 | 패턴이 허용하는 구역 중 유효한 것 |
  | 상대 포메이션 | 4~5 | 4백 / 3백 / 5백 계열 (4-4-2, 4-3-3, 3-5-2, 5-4-1 등) |
  | 마무리 분기 | 4~5 | 컷백 / 크로스 / 슈팅 / 스루패스 → FN 테이블 |
  | 배역 변형 | 3 | 누가 침투하나 |
  | 좌우 반전 | 2 | 대칭 패턴만 |
  | 게임 상태 · 압박 강도 · 상대 대응 정책 | 패턴별 선택 | 수비 문서 공통 변형축 |

  능력 밴드는 변주 축이 아니라 태그 차원이다(FR-24).
- FR-11: 패턴마다 적용할 축과 허용 값을 선언한다(014). 생성기는 선언된 축의 곱집합에서 **무효 조합을 규칙으로 먼저 거른다** (예: 좌측 전용 패턴의 우측 구역, 3백 전용 트리거에 4백 상대, 비대칭 패턴의 좌우 반전). 규칙 위반 조합은 시뮬하지 않는다.
- FR-12: 구체 시나리오 id는 `기본 id + 축 값`으로 사람이 읽을 수 있고 안정적이다 (같은 입력 → 같은 id). 축 값 순서가 바뀌어도 id는 같다.
- FR-13: 후보 수십만 개 → 필터 → 최종 약 4만 개가 목표 (scenarios.html § 구조 4). 최종 수가 목표의 ±25%를 벗어나면 생성 리포트에 경고 [제안].
- FR-14: 오픈플레이 수비 용도 DEF 패턴(014 FR-08 `형태 프리셋 원천`·`판단 AI 검증 픽스처`)은 조합 생성 대상이 아니다. `세트피스 수비` 용도 패턴은 SP 시나리오와 짝지어 생성한다.

### 필터
- FR-20: 남은 후보 조합마다 초기 배치를 그 조합 조건에 맞게 고정하고, 시드를 바꿔 N회 헤드리스 시뮬한다 [제안: N = 200, 기획서 "수백 번"]. 실행은 017 대량 시뮬 인프라를 쓴다. 이 N이 표본 수의 유일한 기준이며 053 배치 검증도 같은 값을 쓴다 (FR-52). 시뮬은 상대 블록 유형(HP/MB/LB/HL/UNB, 013 FR-10)을 섞어 돈다(성공률이 상대 조건부이므로).
- FR-21: 성공률(조합의 KPI 달성 비율)이 0% 또는 100%인 조합은 버린다 (기획서 5.1.1). 표본 수가 부족해 신뢰구간이 넓은 조합은 "보류"로 두고 표본을 늘린다 [제안: 95% 신뢰구간 폭 > 0.2이면 추가 실행].
- FR-22: **퇴화 패턴 필터** (출처: reports/축구 엔진 시나리오 방식.md § D): 아래 5종 중 하나에 걸리면 버리고 사유를 남긴다.
  1. 완주율 하한 미달: 시작 대비 complete·success 비율이 [미정] 미만(대부분 abort).
  2. 기여 0: 득점·전진(xT 증가) 기여가 표본 전체에서 0.
  3. 익스플로잇: 특정 상대 블록 한 유형에서만 성공률이 나머지 블록 평균의 [미정]배 이상.
  4. 중복 궤적: 같은 기본 패턴의 다른 변주와 대표 궤적 거리가 [미정] 이하(067 거리 정의 재사용).
  5. 과도한 시작 이동 비용: 배역 선수의 현재 위치 → 슬롯 시작점 평균 이동 거리가 [미정] m 초과(순간이동처럼 보이는 조합).
- FR-23: 버린 조합은 이유(규칙 위반, 0%, 100%, 퇴화 5종 중 무엇, 실행 오류·예외)와 함께 리포트에 남긴다. 실행 오류가 난 조합이 1개라도 있으면 생성 실패로 판정한다 (버그 은폐 금지).

### 태그
- FR-30: 남은 조합에 태그를 붙인다: 성공률, 기대 xG(시나리오 시작 후 슈팅까지 xG 합의 평균), 평균 소요 시간(초), 표본 수, 생성 시 엔진 버전·시드. 런타임(013)은 이 태그를 선택 점수의 상황 적합도에 쓴다.
- FR-24: 성공률·기대 xG 태그는 배역 선수의 능력 밴드(상·중·하 [제안])마다 따로 낸다. 능력 밴드는 구체 시나리오 id를 늘리지 않는 **태그 차원**이다 (2026-11-11 Q3 정리: 추천 A 채택. 변주 축으로 두면 구체 수가 약 3배가 되어 FR-13·FR-54·필터 시간 예산을 넘는다). 밴드 경계는 002 능력치(내부 0~100) 기준 [미정].
- FR-31: **조건부 태그**: 성공률·기대 xG는 (상대 블록 · 구역 · 점수 상황 · 능력 밴드) 조건별로 저장한다. 표본이 [미정]개 미만인 조건 칸은 상위 조건(예: 블록 무관)으로 병합하고 병합 표시를 남긴다.
- FR-25: 런타임(013) 선택 점수의 "성공 확률"은 현재 배역 선수들의 능력 밴드와 현재 상대 블록·구역·점수 상황에 맞는 조건부 태그를 쓴다. 같은 시나리오라도 상위 밴드 배역이 있으면 성공 확률이 높게 잡힌다. 런타임 반영은 013 재확인 FR-20a (2026-11-11 Q5 정리: 추천 B).
- 참고: 단계 실행 결과(패스 오차·슈팅 방향·드리블 성패)가 능력치로 갈리는 것은 008 액션 모델과 010 판단 AI가 맡는다. 008 연결 전에는 FR-24·25 AC가 구조만 검증하고, 008 연결 때 재확인한다.

### 053 연동
- FR-52: 053 워크벤치의 배치 검증은 이 스펙의 탈락 기준(FR-21·22)과 태그(FR-30·24·31)를 그대로 호출한다. 기준이 두 곳에 따로 있으면 안 된다. 태그에는 013 집계의 결과 4종(success·complete·abort·fail)·종료 사유 분포·기회주의 종료 비율·다음 시나리오 연결 비율·역습 허용률을 추가한다 `[제안]`.

### 버전과 저장
- FR-50: 같은 기본 패턴 파일 + 같은 생성 시드 + 같은 엔진 버전 → 같은 최종 라이브러리(파일 내용 해시 동일).
- FR-51: 라이브러리에는 생성 입력 해시·엔진 버전이 기록된다. 엔진 판정 로직이 바뀌면 태그가 낡았음을 감지해 재생성을 요구한다.
- FR-54: **압축 저장 구조** (013 성능 예산 "4만 개 메모리 ≤ 64 MB" 이관분, 2026-11-11 "개발 때 전부 만들고 빌드는 골라 쓰기만"): 구체 시나리오는 개별 정의로 펼쳐 저장하지 않고 `기본 패턴 268 참조 + 변주 축 인덱스 + 통과 조합 비트셋 + 조건부 태그`로 저장한다. 좌우 반전은 런타임 좌표 변환(적용이지 생성이 아님)으로 처리한다. 런타임은 필요할 때 기본 패턴에 축 값을 적용해 합성한다. 합성 결과는 펼친 정의와 실행 결과가 같아야 한다. 검증할 때 펼치고, 저장할 때 압축한다.

## 경계 · 예외 상황
- 변주 축이 0개인 패턴 → 구체 시나리오 1개(원본)로 생성.
- 축 곱이 상한을 넘는 패턴 [제안: 패턴당 2,000개] → 생성 전 경고, 축 값을 줄이라고 보고 (폭발 방지).
- 모든 조합이 필터에 걸린 패턴 → 그 패턴은 0개로 남고 리포트에 "전멸"로 표시. 원본 패턴이 엔진에서 깨진 신호이므로 경고.
- 성공률 정확히 0 또는 1이 아니지만 극단(예: 0.5%, 99.5%) → 0%/100% 필터로는 버리지 않는다(퇴화 필터는 별도로 본다).
- 생성 도중 중단 → 다시 실행하면 처음부터 같은 결과 (부분 결과가 섞이지 않게).
- 같은 구체 id가 두 경로로 생성 (축 표현 중복) → 오류.
- 좌우 반전이 비대칭 패턴에 선언 → 규칙 필터로 거부.
- 조건부 태그 칸의 표본 부족 → FR-31 병합, 병합 표시.
- 퇴화 기준 임계값이 [미정]인 동안 → 해당 기준은 "보고만"(버리지 않음) 모드로 돌고, 승인 뒤 켠다.

## 비기능 요구사항
- 결정론: 생성·필터·태그는 시드 고정이고, 병렬로 돌려도 결과가 같다 (조합 단위 병렬, 조합 안은 단일 스레드, 결과 정렬 후 저장).
- 재현성: 생성 리포트에 입력 해시·시드·엔진 버전·실행 시간을 남긴다.
- 데이터 크기: 최종 라이브러리 파일은 저장소에 커밋 가능한 크기 [제안: ≤ 20 MB, 텍스트 기반이면 LFS 불필요].
- 런타임 생성 없음: 출시 빌드는 이 스펙의 생성기·필터를 포함하지 않고 압축 저장 결과만 읽는다.
